布尔代数

1854 年，英国数学家乔治·布尔写了一本书，把“真”和“假”当成两个数来算：“与”像乘法（1 × 1 = 1，其余是 0），“或”像加法（只是 1 + 1 还是 1）。这套算法叫布尔代数。有一条规则特别有用，叫德摩根定律：“不是（下雨且刮风）”等于“不下雨或不刮风”；“不是（下雨或刮风）”等于“不下雨且不刮风”。写成式子：~(A & B) = ~A | ~B，~(A | B) = ~A & ~B。写程序的 if 条件、设计电路（第二部），都天天用它。

按位：每一位各算各的

对两个字节做“按位与”，就是把它们上下对齐，每一列单独做一次“与”：

  1100 1010   (A)
& 1111 0000   (B)
-----------
  1100 0000

注意看：B 的前四位是 1，后四位是 0。和它做“与”以后，A 的前四位原样留下，后四位全变成 0。B 像一张镂空的模板，只让 1 的位置透过来，这样的数叫掩码（mask）。第三章的 x & 0xFF，就是用 1111 1111 这张模板，只留下最低 8 位。

第五章说过，大写和小写字母正好差 32，也就是第 5 位（32 = 0010 0000）。所以 ord('a') ^ 32 就是 'A'，再异或一次又回到 'a'。异或有个神奇的性质：同一个数异或两次，就还原了。

移位：一步乘 2

十进制里，把一个数的所有数字往左挪一格、右边补 0，就是乘 10：37 → 370。二进制里往左挪一格就是乘 2：0000 0101（5）左移一位是 0000 1010（10）。往右挪一格是除以 2（把余数扔掉）：0000 1011（11）右移一位是 0000 0101（5）。写法是 x << 1 和 x >> 1。1 << n 就是 2n，常用来造“第 n 位是 1”的掩码。

异或藏宝

想一个 0 到 255 的“密码”k，再想一个“宝藏”数 x。算出 y = x ^ k 交给朋友。朋友只知道 y 不知道 k，猜不出 x；你把 k 告诉他，他算 y ^ k 就得到 x。用 Python 试一试，然后想想：这为什么灵？（这是最简单的加密，真正的加密会复杂得多。）

1 & 0 等于几？

与：两个都是 1 才是 1。

1 ^ 0 等于几？

异或：不一样就是 1。

0b1010 & 0b1100 的结果（二进制）是？

逐位：1&1=1，0&1=0，1&0=0，0&0=0：1000。

3 << 3 等于几？

左移 3 位是乘 23 = 8：24。

  1. x & 16
  2. x | 16
  3. x ^ 16

异或翻转。16 = 1 << 4。

德摩根定律：~(A | B) 等于？

  1. ~A & ~B
  2. ~A | ~B

逻辑移位和算术移位

  • 逻辑移位：把数当无符号的一串比特，左移低位补 0，右移高位补 0。
  • 算术移位：把数当有符号数，移位的同时保持符号，效果是乘或除以 2。补码的算术右移高位补符号位：1111 0110（−10）算术右移一位得 1111 1011（−5）；算术左移低位补 0，若移出的位与新的符号位不同则溢出。

408 常考各种机器数的算术移位规则（只看数值位，符号位不动）：

真值编码左移添补右移添补
正数原码、反码、补码00
负数原码00
补码01
反码11

记法：原码数值位就是绝对值，补 0；反码数值位是绝对值取反，补 1；补码介于两者之间：从右数第一个 1 左边和反码一样（右移补 1），右边和原码一样（左移补 0）。

注意：补码算术右移是向下取整（往负无穷），而 C 的整数除法是向零取整：−7 >> 1 = −4，−7 / 2 = −3。编译器把 x / 2 优化成移位时，对有符号数会先加一个修正值。

编程语言里：C 的 >> 对无符号数是逻辑右移，对负的有符号数由实现决定（实际上几乎都是算术右移；C23 之后仍未强制）；Java 和 JavaScript 用 >> 表示算术右移，另设 >>> 表示逻辑右移；Python 的整数没有固定位数，>> 总是算术右移。循环移位（rotate）把移出去的位从另一头补回来，常用于加密和哈希；ARM 有 ROR 指令，C 里一般写成 (x >> n) | (x << (32 - n))，编译器会认出来。

文件权限：九个比特

在终端里 ls -l，每行开头那串 -rw-r--r-- 是文件的权限。去掉第一个字符（文件类型），剩下九个字符分三组：文件主人、同组的人、其他所有人；每组三位：读 r、写 w、执行 x。有就写字母，没有就写 -。九个字符就是九个比特，每三位正好是一个八进制数字：rwx = 111 = 7，r-x = 101 = 5，r-- = 100 = 4。所以 chmod 755 文件 的意思是“主人可读写执行，其他人可读可执行”，chmod 644 是“主人可读写，其他人只读”。你在第二章建的 hi.txt 就是 644。这是八进制在今天最常见的用处。

面试常考的六个技巧

  1. 判断奇偶：x & 1。
  2. 清掉最低位的 1：x & (x - 1)。x − 1 会把最低位的 1 变成 0、它右边的 0 全变成 1，再一“与”就清掉了。由此：x 是 2 的幂当且仅当 x > 0 && (x & (x - 1)) == 0。
  3. 只留最低位的 1：x & -x（−x 是取反加一）。这就是树状数组里的 lowbit。
  4. 数 1 的个数：反复 x &= x - 1，做了几次就有几个 1，循环次数等于 1 的个数而不是位数。
  5. 不用临时变量交换：a ^= b; b ^= a; a ^= b;。（工程里别这么写：a 和 b 是同一个变量时会清零，也不比用临时变量快。）
  6. 找唯一落单的数：一个数组里别的数都出现两次，只有一个出现一次，把所有数异或起来就是它，因为 a ^ a = 0、a ^ 0 = a，而且异或满足交换律和结合律。
典型题 · 原创

（1）8 位补码 x = 1011 0101，分别求逻辑右移 2 位、算术右移 2 位、算术左移 1 位的结果，并说明真值。（2）unsigned short x = 0xABCD; 求 (x >> 4) & 0xF 和 x & ~0xFF。（3）写一个函数，返回 32 位无符号整数 x 中 1 的个数，要求循环次数等于 1 的个数。

看解答

（1）x = −75。逻辑右移 2 位：0010 1101 = 45（当无符号数看，181 ÷ 4 = 45）。算术右移 2 位：1110 1101 = −19（−75 ÷ 4 = −18.75，向下取整）。算术左移 1 位：0110 1010，符号位从 1 变成 0，溢出（−150 超出 8 位范围）。

（2）x >> 4 = 0x0ABC，& 0xF 得 0xC（取出从右数第二个十六进制数字）。x & ~0xFF = 0xAB00（清掉低 8 位）。

int popcount(unsigned x) {
    int n = 0;
    while (x) { x &= x - 1; n++; }
    return n;
}

8 位补码 1111 0110 算术右移一位是？

高位补符号位 1：1111 1011（−10 → −5）。

补码运算 −7 >> 1（算术右移）得几？

向下取整，−3.5 → −4。C 的 −7 / 2 则是 −3。

rwxr-xr-x 对应的八进制是？

111 101 101 → 7 5 5。

x & (x − 1) 的作用是？

  1. 只留最低位的 1
  2. 清掉最低位的 1
  3. 把 x 减一

只留最低位的 1 是 x & −x。

(0xABCD >> 4) & 0xF 等于？

0xC。

负数的反码做算术左移，低位补什么？

  1. 0
  2. 符号位的反
  3. 1

反码的数值位是绝对值取反，左右都补 1。

第三层 · 深入位运算在真实系统里约 30 分钟数 1 的个数有专门的指令；用位运算枚举子集；格雷码；位图、布隆过滤器和棋盘；一条指令同时算 16 个字节。

数 1：专门有一条指令

数 1 的个数（population count）用得太多了：海明距离（两个数有几位不同 = popcount(a ^ b)）、集合的大小、密码学、棋类程序。所以处理器专门提供了指令：x86 有 POPCNT，ARM 用向量指令 CNT 加上求和。C 里写 __builtin_popcount(x)，编译器会生成对应的指令；甚至你手写上面那个循环，开了优化的 Clang 也常常能认出来，替换成一条指令。在 Mac 上可以用 clang -O2 -S 看生成的汇编（第十四章教怎样读）。

用比特表示集合

一个 n 位整数可以表示 {0, 1, …, n−1} 的一个子集：第 i 位是 1 就表示 i 在集合里。于是并集是 |，交集是 &，差集是 & ~，判断属于是 >> i & 1。枚举一个集合 m 的所有子集有个漂亮的写法：

for (unsigned s = m; ; s = (s - 1) & m) {
    /* 处理子集 s */
    if (s == 0) break;
}

竞赛里的“状态压缩动态规划”就靠它：比如旅行商问题，用一个整数记下“已经去过哪些城市”。

格雷码

普通二进制从 0111 加到 1000，四位同时变。如果这是一个旋转编码器的读数，四个触点不可能同时切换，中间可能短暂读到 1111 之类的错值。格雷码让相邻的两个数只差一位：第 n 个格雷码是 n ^ (n >> 1)。0 到 7 依次是 000、001、011、010、110、111、101、100。它用在旋转编码器、模数转换器，第十章的卡诺图也按格雷码排行列。

位图和布隆过滤器

要记 40 亿个 QQ 号里哪些在线，一个号用一个比特，只要 40 亿 ÷ 8 = 5 亿字节，不到 500 MB，这叫位图。操作系统用位图记哪些磁盘块空着、哪些内存页空着（第四部）。布隆过滤器更进一步：用 k 个哈希函数把一个元素映射到位图里的 k 个位置并置 1；查询时 k 个位置全是 1 才说“可能在”，有一个是 0 就“一定不在”。它会误报、不会漏报，用很少的内存挡掉大量不必要的查询，数据库和浏览器（检查恶意网址）都用它。下国际象棋的程序则用 64 位整数表示棋盘，一个比特一个格子，“这个马能跳到哪些格”可以用几次移位和与运算一次算出来，这叫位棋盘。

一次算 16 个字节

Apple Silicon 的 CPU 有 128 位宽的 NEON 向量寄存器，一条指令可以同时对 16 个字节做按位与、加法或比较，叫 SIMD（单指令多数据）。图像处理（每个像素三个字节）、字符串查找、压缩解压都靠它提速。用一个整数的 64 位同时处理 8 个字节的小技巧，则叫 SWAR（寄存器内的 SIMD）。第十五章还会回来。

3 的格雷码（写 3 位）是？

3 ^ (3 >> 1) = 011 ^ 001 = 010。对照序列 000、001、011、010……从 0 数第 3 个正是 010。

布隆过滤器说“不在”，那么这个元素？

  1. 一定不在
  2. 可能在
  3. 一定在

有一个位置是 0，就一定没被加进来过。说“在”时才可能误报。

一个 128 位的 NEON 寄存器一次能装几个字节？

128 ÷ 8 = 16。
