命令也是数

早期的一些计算机，“程序”是用插线板和开关设定的：换一个题目，工程师就得重新插几天线。1945 年前后，冯·诺依曼等人想清楚了一件事：命令也可以写成数，和要处理的数据一起放进内存。机器从内存里一条一条取出命令，照着做。换一个题目，只要往内存里换一串数，几分钟的事。这就是存储程序，今天所有的电脑、手机都是这样工作的。

这样的一条命令叫指令（instruction）。每条指令说一件很小的事：“把第 14 格的数拿过来”“加上第 15 格的数”“如果结果是 0，就跳到第 5 条”。

小机

我们来造一台最小的机器，叫它小机（这是本书自己设计的教学用机器，不是真实存在的型号）。它有：

  • 一块 16 格的内存，每格 8 位（第十二章那块）。程序和数据都放在这里。
  • 一个累加器 ACC：8 位的寄存器，算出来的结果都放在这里。
  • 一个程序计数器 PC：4 位，记着“下一条指令在第几格”。每取一条指令，它就自动加一（第十一章的计数器）。
  • 一个指令寄存器 IR：放着正在执行的那条指令。
  • 一个 ALU（第十章），能加能减。

每条指令占一个字节：高 4 位是“做什么”（操作码），低 4 位是“对哪一格”（地址）。4 位操作码最多 16 种指令，小机只用了 10 种：

操作码写法意思
0HLT停机
1LDA a把第 a 格的数装进 ACC（load）
2STA a把 ACC 存进第 a 格（store）
3ADD aACC 加上第 a 格的数
4SUB aACC 减去第 a 格的数
5LDI n把数 n（0—15）直接装进 ACC
6JMP a跳到第 a 格去取下一条指令（把 PC 改成 a）
7JZ a如果 ACC 是 0，就跳到第 a 格
8JN a如果 ACC 是负数（最高位是 1，第三章），就跳到第 a 格
9OUT把 ACC 打印出来

例如字节 0x3F = 0011 1111：操作码 3 是 ADD，地址 15，意思是“ACC 加上第 15 格的数”。

取指、译码、执行

小机通电以后，永远在重复同样的三步：

  1. 取指：按 PC 指的格子，把那个字节从内存里取出来，放进 IR；PC 加一。
  2. 译码：看 IR 的高 4 位是哪种指令，低 4 位是哪一格。
  3. 执行：照着做。如果是跳转指令，就把 PC 改掉，下一次就从新的地方取。

就这么简单。所有的程序，不管是游戏还是浏览器，最终都是处理器在这三步里一圈一圈地转，只是真正的处理器每秒转几十亿圈。

CPU 里的寄存器

  • 运算器：ALU、累加器 ACC、乘商寄存器 MQ、通用寄存器组、程序状态字寄存器 PSW（存第三章的 ZF、SF、CF、OF 等标志）。
  • 控制器：程序计数器 PC、指令寄存器 IR、指令译码器、控制单元 CU（产生控制信号）。
  • 和主存打交道的两个：存储器地址寄存器 MAR（放要访问的地址，位数 = 地址线根数）和存储器数据寄存器 MDR（放读出或要写入的数据，位数 = 数据线根数）。CPU 访存一定要经过它们。

对程序员“可见”的（能用指令直接读写的）：PC、通用寄存器、PSW 的部分标志；不可见的：IR、MAR、MDR 等。408 常考这一区分。

指令周期

执行一条指令的全部时间叫指令周期，由若干个机器周期（CPU 周期）组成，每个机器周期又由若干个时钟周期组成。一条指令可能经过：

  • 取指周期（每条指令都有）：取出指令，PC 加一。
  • 间址周期（间接寻址时才有，第十四章）：再访存一次取出真正的操作数地址。
  • 执行周期：完成指令的功能。
  • 中断周期（有中断请求且允许时）：保存断点，转去中断服务程序（第二十五章）。

取指周期的微操作，用 (X) 表示“X 的内容”：

(PC) → MAR          ; 地址送出
1 → R，M(MAR) → MDR ; 读主存
(MDR) → IR          ; 指令进 IR
(PC) + 1 → PC       ; 指向下一条（按字节编址、指令长 k 字节时加 k）

“ADD X”（ACC 加上主存 X 单元）的执行周期：Ad(IR) → MAR，1 → R，M(MAR) → MDR，(ACC) + (MDR) → ACC。小机模拟器里同时显示了 MAR 和 MDR，可以对照着看。

数据通路和控制器

寄存器、ALU、主存之间用什么连起来，叫数据通路。最简单的是单总线：所有部件挂在一根内部总线上，同一时刻只能有一个部件往总线上送数据，所以 (ACC) + (MDR) 要先把一个操作数放进 ALU 前面的暂存器 Y，下一步再相加，结果先进暂存器 Z，再送回 ACC。多总线结构可以一步完成，硬件更多。

控制单元在每个时钟周期产生一组控制信号（哪个寄存器往总线送、哪个从总线收、ALU 做什么运算），有两种实现：硬布线（用组合逻辑直接产生，快，难改，RISC 多用）和微程序（把每条指令拆成一串“微指令”存在控制存储器里，一条一条读出来执行，灵活，CISC 传统上多用）。这部分是本系列《芯》的重点。

用 Python 写一个小机30 分钟
mem = [0x1F, 0x90, 0x4E, 0x75, 0x61, 0x00, 0, 0, 0, 0, 0, 0, 0, 0, 1, 5]  # “倒数”
pc, acc = 0, 0
while True:
    ir = mem[pc]; pc = (pc + 1) % 16            # 取指
    op, a = ir >> 4, ir & 15                    # 译码
    if   op == 0: break                         # 执行
    elif op == 1: acc = mem[a]
    elif op == 2: mem[a] = acc
    elif op == 3: acc = (acc + mem[a]) % 256
    elif op == 4: acc = (acc - mem[a]) % 256
    elif op == 5: acc = a
    elif op == 6: pc = a
    elif op == 7 and acc == 0: pc = a
    elif op == 8 and acc >= 128: pc = a
    elif op == 9: print(acc)

十几行就是一台计算机。可以加一条 print(pc, hex(ir), acc) 看每一步，或者给它加一条新指令（比如操作码 A 表示“ACC 左移一位”），再改装置里的程序验证。这种“用一个程序模拟另一台机器”的程序叫模拟器或解释器，第零章说的 Python 解释器做的也是这件事，只是复杂得多。

典型题 · 原创

某机指令字长 16 位，主存按字编址、容量 4K 字，指令格式为“操作码 + 一个直接地址”。问：（1）操作码最多几位？最多能有多少种指令？（2）MAR、MDR、PC、IR 各至少多少位？（3）若主存扩大到 64K 字而指令字长不变，直接寻址还够用吗？（4）写出“STA X”（把 ACC 存入主存 X 单元）执行周期的微操作。

看解答

（1）4K = 212 字，直接地址 12 位，操作码 16 − 12 = 4 位，最多 16 种指令。

（2）MAR 12 位，PC 12 位，MDR 16 位（等于字长），IR 16 位（等于指令字长）。

（3）不够：64K = 216 字要 16 位地址，整条指令都给了地址，操作码就没地方放了。要改用别的寻址方式，比如用寄存器提供一部分地址（基址、变址）或间接寻址，这正是第十四章各种寻址方式存在的原因之一。

（4）Ad(IR) → MAR；(ACC) → MDR；1 → W；MDR → M(MAR)。

冯·诺依曼瓶颈

1977 年，约翰·巴克斯（FORTRAN 的发明者）在图灵奖演讲中批评：处理器和内存之间只有一条窄窄的通道，程序把大部分时间花在一个字一个字地在通道里搬东西上，他称之为冯·诺依曼瓶颈。四十多年来，处理器变快的速度一直远远超过内存，这个瓶颈越来越窄，于是有了第十六章的缓存、第十五章的乱序执行，以及“把计算搬到数据旁边”的各种研究。

哈佛结构

指令和数据放在两块分开的存储器里、用两套总线同时访问，叫哈佛结构（得名于哈佛大学 1944 年的 Mark I，它从纸带读指令）。很多单片机和数字信号处理器用它。今天的通用处理器是“改良哈佛”：内存只有一块（存储程序），但一级缓存分成指令缓存和数据缓存，取指和读写数据可以同时进行。

自己改自己

既然指令就是数，程序当然能改写自己的指令（小机的“自己改自己”演示的就是这个）。早年为了省内存常这样做；今天它是安全隐患：攻击者只要能往数据区写一段字节，再骗处理器跳过去执行，就能控制程序。所以现代系统要求内存页“可写”和“可执行”二选一（W^X），处理器和操作系统配合，把栈和堆标成不可执行。要即时编译（JIT，比如浏览器的 JavaScript 引擎）的程序，必须向系统申请特殊的内存，在“写代码”和“执行代码”两种状态之间切换；Apple Silicon 的 macOS 对此要求更严格，提供专门的接口让线程在两种状态间切换，并要求程序声明相应的权限。

一条指令就够

小机有十条指令。到底最少要几条？理论上一条就够：比如 subleq a, b, c（“把 b 格减去 a 格的值，结果为负或零就跳到 c”），只靠它就能写出任何程序（只要内存足够大），这样的机器叫单指令计算机。这说明“能算什么”和“算得多方便、多快”是两回事：前者早在 1936 年图灵就回答了，后者才是处理器设计者每天在操心的事。

谁的结构

1945 年的《EDVAC 报告草稿》只署了冯·诺依曼的名字，在同事中流传开来，“冯·诺依曼结构”这个叫法也由此而来。但 ENIAC 的设计者埃克特和莫奇利认为，存储程序的想法是他们团队先提出的，报告的流传还让他们失去了申请专利的机会，双方从此分道扬镳。今天的历史学者一般认为这是一个团队集体讨论的成果。
