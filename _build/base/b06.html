给指令起名字

第十三章的小机，只认一个个字节：1E 是“把第 14 格装进 ACC”，3F 是“加上第 15 格”。这些数，人很难记。

于是人们给每种指令起了一个短名字：LDA 14、ADD 15。用这些名字写的程序，叫汇编语言（assembly）。

名字只是给人看的。要运行，还得把名字翻回数。做这件事的程序叫汇编器。它像查字典：LDA 是 1，14 是 E，拼起来就是 1E。

汇编翻成的字节意思
LDA 141E把第 14 格装进 ACC
ADD 153FACC 加上第 15 格
OUT90打印 ACC
HLT00停机
命令方块里的命令

在《一块一块》第六部里，你写过 /tp、/give 这样的命令：一个英文动词，后面跟着“对谁”“到哪儿”。汇编也是这样：LDA、ADD、JMP 是动词，后面的数是“对哪一格”。

自己当一回汇编器

拿出纸和笔，查第十三章的指令表，把下面三行翻成十六进制：

LDI 5
OUT
HLT
翻好了，对答案

LDI 是 5 号，后面跟 5，所以是 55；OUT 是 90；HLT 是 00。换成十进制是 85、144、0。

真电脑也有汇编

你的 Mac 的处理器也有自己的指令，比小机多得多，有好几百种，名字也不一样：add 是加，ldr 是装进来，str 是存进去，b 是跳。

不同家的处理器，指令不一样。Apple Silicon 用的是 ARM 家的指令；以前的英特尔 Mac 用的是 x86 家的指令。两家互相不认识对方的指令。

现在几乎没人用汇编写整个程序，太累了。人们写 Python、C，再交给别的程序一路翻成指令。第三部会讲 C 怎样被翻成指令；想现在就看看真的汇编长什么样，第二层开头有在 Mac 上看的办法。

跳一跳：判断和循环

小机有两种跳：JMP 是“一定跳”；JZ、JN 是“满足条件才跳”。Python 里的 if 和 while，翻成指令以后，就是这些跳。

n = 5
while n != 0:
    print(n)
    n = n - 1

拿它和小机的“倒数”程序比一比：print 变成了 OUT；n - 1 变成了 SUB；while 变成了两次跳：减到 0 就用 JZ 跳出去，没到 0 就用 JMP 跳回开头。

汇编：给指令起名字

小机的指令是一个个字节，0x1E、0x3F，人看不懂。所以我们给它们起了名字：LDA 14、ADD 15。这种“用名字写机器指令”的语言叫汇编语言（assembly language），把它翻译成字节的程序叫汇编器。汇编和机器指令基本上是一一对应的：一行汇编就是一条指令。

真正的处理器和小机比，主要多了这些：

  • 寄存器多：小机只有一个 ACC。Apple Silicon 用的 arm64 有 31 个 64 位通用寄存器，叫 x0 到 x30；只用低 32 位时叫 w0 到 w30。寄存器在处理器内部，读写只要不到一纳秒，比内存快一百倍左右，所以编译器会尽量把常用的变量放在寄存器里。
  • 内存大：地址是 64 位的，不再是 4 位。
  • 指令多、更灵活：一条指令可以指定两三个寄存器，比如 add w0, w1, w2 表示 w0 = w1 + w2。
  • arm64 的指令一律 4 个字节（32 位）。英特尔和 AMD 的 x86-64 指令长短不一，从 1 个字节到 15 个字节都有。

在 Mac 上看汇编

让编译器把 C 翻译成汇编15 分钟

    int s = 0;
    for (int i = 0; i < n; i++) s += a[i];

  2. 让 clang 只翻译到汇编为止（-S），开一级优化（-O1），输出到屏幕（-o -）：

条件跳转和标志位

注意 cmp 这条指令：它做一次减法，结果扔掉，只留下标志位（第三章的 N、Z、C、V）。紧跟着的条件跳转 b.lt（小于就跳）、b.ne（不等就跳）就看这些标志决定跳不跳。小机的 JZ、JN 是同一个思路的简化版。第三章说过，同一次减法，有符号数和无符号数看的标志不一样，所以 arm64 有两套条件：b.lt / b.gt 用于有符号数，b.lo / b.hi 用于无符号数。C 里把变量声明成 int 还是 unsigned，编译器选的跳转指令就不同。

指令格式

一条指令 = 操作码 + 地址码。按地址码的个数分：零地址（如 HLT，或者堆栈机里的 ADD，操作数隐含在栈顶）、一地址（如小机的 ADD a，另一个操作数隐含在累加器）、二地址（A1 ← A1 op A2，x86 常见）、三地址（A3 ← A1 op A2，arm64 的 add w0, w1, w2）。地址越多，一条指令做的事越完整，但指令越长。

扩展操作码：指令字长固定时，让操作码长度随地址个数变化——地址少的指令，把省下来的地址位挪给操作码。设计时，短操作码必须留出一些编码作为“扩展标志”，长操作码以它们开头，保证任何一个短操作码都不是长操作码的前缀，译码才不会混淆。

寻址方式

指令里的地址码 A 不一定就是操作数所在的地址。按什么规则求出操作数的真实地址（有效地址 EA），叫寻址方式：

方式有效地址 / 操作数取到操作数要访存几次（不算取指）用处
立即操作数就是 A0常数
直接EA = A1简单，但 A 的位数限制了寻址范围
间接EA = (A)2（一次间址）扩大寻址范围、指针
寄存器操作数在寄存器 Ri 里0最快
寄存器间接EA = (Ri)1指针、遍历
基址EA = (BR) + A1程序重定位，BR 由操作系统设定
变址EA = (IX) + A1数组：A 是首地址，IX 是下标
相对EA = (PC) + A，A 是带符号的偏移1（跳转指令则不访存数据）跳转、位置无关代码
堆栈EA 由栈指针 SP 隐含给出1（栈在内存时）函数调用（第二十章）

arm64 里的写法：mov w0, #5（立即）；ldr w0, [x1]（寄存器间接）；ldr w0, [x1, #8]（基址加偏移）；ldr w0, [x1, x2, lsl #2]（x1 + x2 × 4，相当于变址，正好是 int 数组 a[i]）；ldr w9, [x0], #4（先用 x0 取数，再让 x0 加 4，装置里 sum 函数就用了它）；b label、bl func（相对寻址的跳转）。arm64 是load/store 结构：只有 ldr、str 这类指令能访问内存，算术指令只能对寄存器操作。

精简和复杂

CISC（复杂指令集，代表 x86）：指令多、长度可变、一条指令可以直接对内存做运算、寻址方式丰富，历史上为了让汇编程序员写得方便、让程序更短。RISC（精简指令集，代表 ARM、RISC-V、MIPS）：指令少而规整、定长、只有 load/store 访存、寄存器多，便于流水线（下一章）和硬布线控制。今天两者的界限已经模糊：x86 处理器在内部把复杂指令拆成类似 RISC 的“微操作”来执行；ARM 也加了不少复杂指令。苹果从英特尔换到自研的 ARM 芯片，主要收益在每瓦性能，这和指令集有关，更和芯片设计、工艺、统一内存有关。

典型题 · 原创

（1）某机指令字长 16 位，每个地址码 4 位，采用扩展操作码。已有三地址指令 14 条、二地址指令 30 条，一地址指令最多能有多少条？若还要设置 16 条零地址指令，一地址指令最多多少条？（2）某转移指令采用相对寻址，指令长 2 字节、按字节编址，位于 2000H，第一个字节是操作码，第二个字节是 8 位补码偏移量。取指后 PC 自动加 2。要转移到 1FF0H，偏移量应为多少（十六进制）？（3）上题中，这条指令能转移到的地址范围是多少？

看解答

（1）三地址指令操作码 4 位，16 个编码用了 14 个，留 2 个作扩展；二地址指令操作码 8 位，可用 2 × 16 = 32 个，用了 30 个，留 2 个；一地址指令操作码 12 位，可用 2 × 16 = 32 个。不要零地址指令时最多 32 条；要 16 条零地址指令时，一地址必须留 1 个编码扩展（1 × 16 = 16 条零地址），最多 31 条。

（2）EA = (PC) + 偏移，取指后 PC = 2002H，偏移 = 1FF0H − 2002H = −12H = −18，8 位补码为 EEH。

（3）偏移 −128 ～ +127，范围 2002H − 80H = 1F82H 到 2002H + 7FH = 2081H。

一条指令的 32 个比特

add w0, w1, w0 编码为 0x0B000020。按 arm64 手册里“加法（移位寄存器）”的格式拆开：

位31302928—2423—222120—1615—109—54—0
字段sfopS01011shift0Rmimm6RnRd
值00001011000000000000000000100000
意思32 位加不设标志这一类不移位w0移 0 位w1结果写 w0

sf 改成 1 就是 64 位的 add x0, x1, x0；S 改成 1 就是会设标志位的 adds；op 改成 1 就是减法。cmp w0, w1 其实是 subs wzr, w0, w1：结果写进永远为零的寄存器（相当于扔掉），只留标志。规整的编码让译码电路简单，这正是 RISC 的好处。

调用约定（预告）

为什么参数在 w0、w1，返回值在 w0？这是 arm64 的调用约定规定的：前 8 个整数参数放 x0—x7，返回值放 x0，x30 存返回地址（bl 指令跳过去时自动把返回地址写进 x30，ret 就是跳回 x30），x29 是帧指针，sp 是栈指针。编译器和所有库都遵守同一个约定，不同人写的函数才能互相调用。第二十章讲函数调用和栈时细说。

Rosetta 2

2020 年 Mac 从英特尔换到 Apple Silicon，大量 x86-64 程序要继续能用。Rosetta 2 主要在程序第一次运行时把 x86-64 机器码整体翻译成 arm64 机器码并缓存起来，对运行时才生成的代码（比如 JIT）再即时翻译。两种指令集有一个麻烦的差别：多核同时读写内存时，x86 保证的顺序（TSO）比 ARM 严格。据公开的分析，Apple Silicon 在硬件里加了一个可以按线程打开的 TSO 模式，专门给翻译后的代码用，省掉了大量额外的同步指令。这是“为兼容老软件，在硬件里开后门”的一个漂亮例子。

想看一个干净的现代 RISC 指令集，可以读 RISC-V：它是开放的标准，基本整数指令集只有约四十条指令，手册写得很清楚，很多大学的计算机组成课已经改用它。
