洗衣服

洗一桶衣服有三步：洗 30 分钟，烘 30 分钟，叠 30 分钟。四桶衣服，一桶一桶地来，要 4 × 90 = 360 分钟。聪明的办法是：第一桶洗完放进烘干机，马上开始洗第二桶；第一桶烘完拿去叠，第二桶进烘干机，第三桶开始洗……三台“机器”同时都在忙。这样四桶只要 90 + 3 × 30 = 180 分钟。这就是流水线（pipeline）。

注意两件事：

  • 每一桶从开始到结束，还是要 90 分钟，没有变快。变快的是“每 30 分钟就有一桶洗好”，也就是单位时间里完成的数量（吞吐率）。
  • 桶数越多，越接近“三倍速”：开头要“灌满”流水线、结尾要“排空”，桶多了这点损失就可以忽略。

五段流水线

处理器把执行一条指令切成五段，每段用一个时钟周期，段和段之间用寄存器隔开（第十一章说的“把组合逻辑切开，中间插寄存器”）：

段做什么
IF 取指按 PC 从内存（指令缓存）取指令，PC 加 4
ID 译码看是什么指令，从寄存器里读出操作数
EX 执行ALU 运算，或者算出要访问的内存地址
MEM 访存ldr 读内存、str 写内存；别的指令这一段空着
WB 写回把结果写回寄存器

理想情况下，每个时钟周期都有一条新指令进入流水线，五条指令同时处在五个不同的段里。一条指令仍然要 5 个周期，但平均每个周期完成一条，比不用流水线快将近 5 倍。

性能指标

设流水线有 k 段，每段时间 Δt，连续输入 n 条指令（不考虑冒险）：

  • 总时间 T = (k + n − 1)Δt（前 k 个 Δt 灌满，之后每 Δt 出一条）。
  • 吞吐率 TP = n / T = n / ((k + n − 1)Δt)，n → ∞ 时趋于 1/Δt。
  • 加速比 S = 不用流水线的时间 / 用流水线的时间 = nkΔt / ((k + n − 1)Δt)，n → ∞ 时趋于 k。
  • 效率 E = 时空图里有效面积 / 总面积 = nkΔt / (k(k + n − 1)Δt) = n / (k + n − 1)。

各段时间不相等时，Δt 取最长的那一段（再加上段间寄存器的开销）。

三种冒险

  • 结构冒险：两条指令同时要用同一个硬件。例如只有一块存储器，IF 取指和 MEM 访存撞车。对策：指令缓存和数据缓存分开（第十三章的改良哈佛结构），或者停一拍。
  • 数据冒险：后一条指令要用前一条指令的结果，而结果还没写回。最常见的是“写后读”（RAW）。对策：停顿（插气泡，等前一条写回）；旁路（也叫转发，把 EX 或 MEM 段刚算出的结果直接送回 ALU 的输入，不等写回寄存器）；编译器重排指令，把无关的指令塞进去。
  • 控制冒险：遇到跳转，在跳转指令算出“跳不跳、跳到哪儿”之前，流水线不知道下一条该取哪一条。对策：停到结果出来；预测（先按猜测往下取，猜错了就把取错的指令清掉）；早期 MIPS 用“延迟槽”（跳转后面那一条无论如何都执行，由编译器填有用的指令）。

旁路解决不了的一种：load-use 冒险。ldr 要到 MEM 段结束才拿到数据，紧跟着的指令在 EX 段一开始就要用，时间上来不及，必须停一拍（装置里“加上旁路”那种模式可以看到）。编译器会尽量在 ldr 和使用它的指令之间塞一条别的指令。

动态分支预测：最简单的是给每条跳转指令配一个两位的饱和计数器，四个状态：强不跳、弱不跳、弱跳、强跳。每次实际跳了就加一、没跳就减一（到头不再变），预测看高位。比起“上次跳了就猜跳”，两位计数器在循环结尾只会错一次，不会连错两次。真实处理器的预测器要复杂得多，准确率常在 95% 以上。

典型题 · 原创

（1）某五段流水线各段时间为 80 ps、100 ps、120 ps、100 ps、80 ps，段间寄存器延迟 20 ps。求时钟周期、执行 100 条指令（无冒险）的总时间、吞吐率和相对于不用流水线（一条指令 480 ps、一条接一条）的加速比。（2）对下列指令序列，在五段流水线中（寄存器堆先写后读，同一周期内可以读到刚写的值），分别求不使用旁路和使用旁路时各要插入几个气泡：
I1: ldr x1, [x0]
I2: add x2, x1, x3
I3: sub x4, x2, x5

看解答

（1）周期 = 最长段 120 + 20 = 140 ps。总时间 = (5 + 100 − 1) × 140 = 14560 ps。吞吐率 = 100 / 14560 ps ≈ 6.87 × 109 条/秒。不用流水线：100 × 480 = 48000 ps，加速比 ≈ 3.30（小于 5，因为段不均衡、还有寄存器开销）。

（2）不用旁路：I2 要在 ID 读到 x1，最早与 I1 的 WB 同周期，I1 的 WB 在第 5 周期，I2 正常应在第 3 周期 ID，要停 2 拍；I3 依赖 I2 的 x2，同理再停 2 拍；共 4 个气泡。用旁路：I1 是 ldr，load-use 必须停 1 拍；I2 的结果在 EX 末尾就能转发给 I3，不用停；共 1 个气泡。可以在上面的装置里对照（装置用的序列不同，方法一样）。

面试题

为什么在一个大数组上，先排好序再执行 if (a[i] >= 128) sum += a[i]; 会快很多？

看要点

数据随机时，这个分支跳不跳像抛硬币，预测器大约一半猜错，每次猜错都要清空流水线、浪费十几个周期；排好序后，前一半一直不跳、后一半一直跳，预测几乎全对。解决办法：排序，或者把分支改成无分支的写法（条件选择、位运算），编译器有时会自己做（第十四章的 csel）。第三层有在 Mac 上动手测的实验。

第三层 · 深入真实处理器的“并行”约 35 分钟超标量；乱序执行和托马苏洛算法；寄存器重命名和重排序缓冲；M1 的宽度；幽灵漏洞；在 Mac 上测分支预测。

一个周期不止一条

流水线让每周期完成一条指令；要更多，就同时取好几条、配好几套 ALU，叫超标量。但相邻的指令常常互相依赖，不能同时做。乱序执行的办法是：一次看一大段指令（几百条），谁的操作数准备好了就先执行谁，不按程序顺序；最后再按原顺序“提交”结果，让程序看起来仍然是一条一条执行的。它的核心思想来自 1967 年罗伯特·托马苏洛为 IBM System/360 Model 91 的浮点部件设计的算法。

  • 寄存器重命名：程序只有 31 个寄存器名，同一个名字被反复使用会制造假的依赖（“写后写”“读后写”）。处理器内部有几百个物理寄存器，每次写都分配一个新的，假依赖就消失了。
  • 重排序缓冲（ROB）：记着所有正在飞的指令的原始顺序，按顺序提交；如果前面某条分支猜错了、或者出了异常，就把它后面所有“偷跑”的指令作废。

据公开的测评，Apple M1 的性能核每周期能译码 8 条指令，重排序缓冲有六百多项，在发布时都是同类处理器里最宽的之一；也就是说，它同时“看着”几百条指令，挑能做的先做。这是它主频不高却很快的主要原因之一。

幽灵

乱序和预测执行“偷跑”的指令虽然会被作废，但它们在偷跑时读过的数据已经被搬进了缓存（第十六章），而缓存里有没有某个数据，可以通过测量访问时间看出来。2018 年公开的幽灵（Spectre）和熔断（Meltdown）漏洞，就是故意训练分支预测器猜错、让处理器偷跑去读本不该读的数据，再从缓存的时间差里把它“看”出来。几乎所有高性能处理器都受影响。修补手段包括软件里插屏障、操作系统隔离内核地址、浏览器降低计时器精度等，代价是一些性能。这是“抽象会漏”（第零章）最惊人的例子：一个本来只影响速度的优化，泄露了数据。

在 Mac 上测分支预测15 分钟 · 需要第三部的 C 基础
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#define N (1 << 24)
static int cmp(const void *a, const void *b) { return *(int*)a - *(int*)b; }
static double run(int *a) {
    struct timespec t0, t1; long long s = 0;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    for (int r = 0; r < 10; r++)
        for (int i = 0; i < N; i++)
            if (a[i] >= 128) s += a[i];
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("(sum=%lld) ", s);
    return (t1.tv_sec - t0.tv_sec) + (t1.tv_nsec - t0.tv_nsec) / 1e9;
}
int main(void) {
    int *a = malloc(N * sizeof(int));
    for (int i = 0; i < N; i++) a[i] = rand() % 256;
    printf("随机：%.3f 秒\n", run(a));
    qsort(a, N, sizeof(int), cmp);
    printf("排序后：%.3f 秒\n", run(a));
    return 0;
}
% clang -O1 branch.c -o branch && ./branch
% clang -O3 branch.c -o branch && ./branch

用 -O1 时，随机的那次通常明显更慢。换成 -O3，两次可能差不多快：编译器把 if 改写成了无分支的条件选择或向量指令，没有分支，就谈不上预测。结果因芯片和编译器版本而异，这正是实验的意义：自己量，别光信书。
