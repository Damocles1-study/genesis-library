第一层 · 入门要会：内存（第十二章）约 45 分钟

越快越小

存储器有个躲不开的规律：快的贵，所以小；大的便宜，所以慢。于是电脑把它们叠成一层一层：

层大约多大访问一次大约多久如果 1 纳秒是 1 秒
寄存器几百字节不到 1 纳秒眨一下眼
一级缓存（L1）几十到一百多 KB约 1 纳秒1 秒：伸手拿桌上的书
二级缓存（L2）几 MB 到十几 MB几纳秒几秒：转身拿书架上的
内存（DRAM）几 GB 到几十 GB约 100 纳秒一分半：下楼去图书馆
固态硬盘几百 GB 到几 TB几十到一百多微秒一两天：等快递
机械硬盘几 TB约 10 毫秒四个月

数字只是数量级，每台机器不同。要记住的是“差多少倍”：从缓存到内存差约一百倍，从内存到固态硬盘又差约一千倍。

局部性

为什么叠起来就有用？因为程序访问数据有两个习惯，叫局部性：

  • 时间局部性：刚用过的东西，很快还会再用。比如循环里的变量 s，每一圈都要用。
  • 空间局部性：用了一个东西，很快会用它旁边的东西。比如数组 a[0] 用完用 a[1]，指令一条挨一条执行。

所以处理器每次从内存取数据时，不只取那一个字节，而是把它旁边一整块（Apple Silicon 上是 128 字节，很多英特尔机器是 64 字节）一起搬进缓存，这一块叫缓存行（cache line）。下次要的数据如果已经在缓存里，叫命中，很快；不在，叫缺失，要去内存搬，很慢。程序跑得快不快，很大程度上看命中率高不高。

按行还是按列

二维数组在内存里是一行接一行放的（C 和 Python 的 NumPy 默认如此）。按行遍历，访问的地址一个挨一个，一个缓存行搬进来，里面的数据全都用上了；按列遍历，每次跳过一整行，每访问一个数都可能落在不同的缓存行，刚搬进来的那一行只用了一个数，就被别的行挤掉了。数组一大，按列可以慢好几倍。下面的装置让你亲眼看看。

第二层 · 本科408 计组 · 高速缓冲存储器约 60 分钟命中率、平均访问时间；地址切成标记、组号（行号）、块内地址；直接映射、全相联、组相联；LRU 等替换算法；写回和写直达、写分配；Cache 总容量（含标记、有效位、脏位）怎样算；数组访问的命中率题。

命中率和平均访问时间

命中率 h = 命中次数 ÷ 访问总次数。设缓存访问时间 tc、主存访问时间 tm：如果缺失时先查缓存再访存（多数教材的约定），平均访问时间 = tc + (1 − h)tm；如果同时启动查缓存和访存，平均访问时间 = h·tc + (1 − h)tm。做题看清题目的说法。命中率从 95% 到 99%，缺失率从 5% 降到 1%，平均时间可能差一倍多：缺失率比命中率更能说明问题。

地址怎样切

主存和缓存都按“块”（缓存行）为单位交换。主存地址从低到高切成三段：块内地址（log2块大小 位），组号（log2组数 位；直接映射时叫行号，全相联时没有这一段），剩下的高位是标记（tag），存在缓存行旁边，用来核对“这一行装的是不是我要的那一块”。

  • 直接映射：主存第 j 块只能放进缓存第 j mod 行数 行。电路简单（只比较一个标记），但两块抢同一行时会反复互相挤掉（冲突缺失）。
  • 全相联：任何一块可以放在任何一行。冲突最少，但每次都要和所有行的标记比较，硬件贵，只用于很小的缓存（如 TLB）。
  • k 路组相联：缓存分成若干组，每组 k 行；主存块先按 j mod 组数 定组，组内随便放。折中方案，今天的缓存几乎都是 4—16 路组相联。

每一行除了数据，还有：有效位（这一行装没装东西）、标记、写回策略下的脏位（这一行被改过没有），使用 LRU 等替换算法时还有替换控制位。408 常考“Cache 的总容量（含这些位）是多少”。

替换和写

  • 组满了要放新块，扔谁？随机；先进先出（FIFO）；最近最少使用（LRU，扔最久没用的，最符合时间局部性，k 路要 log2k 位计数器左右的硬件）；直接映射没得选。
  • 写命中时：写直达（同时写缓存和主存，简单但慢，常配写缓冲）；写回（只写缓存、置脏位，这一行被换出时才写回主存，省带宽）。
  • 写缺失时：写分配（先把块调进缓存再写，通常配写回）；非写分配（直接写主存，通常配写直达）。
装置 · 第十六章 · 二

地址怎样切

设定主存地址位数、缓存容量、块大小和相联度，看地址怎样切成三段、缓存一共多少位（含有效位、脏位、标记）。再输入一个地址，看它落在哪一组、标记是多少。

典型题 · 原创

某计算机主存地址 32 位，按字节编址。数据 Cache 容量 32 KB（不含标记等），块大小 64 B，采用 4 路组相联、LRU 替换、写回和写分配。（1）主存地址怎样划分？（2）每行除数据外还有哪些控制位、各几位？Cache 总容量是多少位？（3）数组 int a[256][256] 按行优先存放，首地址 0x00800000，Cache 初始为空。程序按行遍历求和一次，命中率是多少？按列遍历呢？

看解答

（1）块内地址 6 位（64 B）；行数 32 K / 64 = 512，组数 512 / 4 = 128，组号 7 位；标记 32 − 7 − 6 = 19 位。

（2）有效位 1、脏位 1、LRU 位 2（4 路），标记 19，共 23 位。每行 64 × 8 + 23 = 535 位，总容量 512 × 535 = 273920 位。

（3）按行：一块 64 B 装 16 个 int，每 16 次访问 1 次缺失 15 次命中，命中率 15/16 = 93.75%。按列：每行 256 × 4 = 1 KB，同一列相邻两个元素相隔 1 KB；1 KB 是 16 块，地址每加 1 KB 组号加 16（mod 128），一列 256 个元素只映射到 128 / gcd(16,128) = 8 个组，每组 4 路共 32 行，远放不下一列用到的 256 个块，下一列再访问时早被换掉，命中率约为 0。这就是按列遍历慢的原因。

面试题

写回和写直达各有什么优缺点？多核下写回带来什么问题？

看要点

写直达简单、主存始终是最新的，但每次写都要访存，带宽压力大（常加写缓冲）；写回只在换出脏行时写主存，省带宽，但实现复杂、主存可能是旧的。多核各有私有缓存时，同一个地址可能在几个核的缓存里有不同版本，需要缓存一致性协议（如 MESI：修改、独占、共享、无效）来保证大家看到一致的值，这又引出第三层的伪共享和第二十九章的并发问题。

在 Mac 上量出缓存

思路：在一块大小为 S 的数组里反复随机地跳着读（每次读的位置由上一次读到的值决定，让处理器没法提前猜），S 小于某级缓存时，平均一次很快；S 一超过那级缓存，时间就跳上一个台阶。

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
static double now(void) { struct timespec t; clock_gettime(CLOCK_MONOTONIC, &t); return t.tv_sec + t.tv_nsec / 1e9; }
int main(void) {
    for (size_t kb = 4; kb <= 256 * 1024; kb *= 2) {
        size_t n = kb * 1024 / sizeof(size_t);
        size_t *a = malloc(n * sizeof(size_t));
        for (size_t i = 0; i < n; i++) a[i] = i;
        for (size_t i = n - 1; i > 0; i--) {          /* 打乱成一个大环 */
            size_t j = rand() % i, t = a[i]; a[i] = a[j]; a[j] = t;
        }
        size_t p = 0, steps = 20000000;
        double t0 = now();
        for (size_t s = 0; s < steps; s++) p = a[p];
        double ns = (now() - t0) / steps * 1e9;
        printf("%8zu KB  %6.2f ns  (%zu)\n", kb, ns, p);
        free(a);
    }
    return 0;
}
% clang -O2 cache.c -o cache && ./cache

把结果和第零章 sysctl 查到的缓存大小对照：时间大致会在一级缓存、二级缓存（以及 Apple Silicon 的系统级缓存）大小附近各跳一个台阶，最后停在一百纳秒左右（内存）。这个“随机打乱”的写法并不保证得到一个完整的大环，有时环会短一些，数会偏乐观；想更严谨可以改成生成一个随机排列再串起来。printf 里打印 p，是为了不让编译器发现结果没用而把循环删掉。

缺失的三种原因

强制缺失（第一次访问，谁也躲不掉）、容量缺失（要用的数据比缓存大）、冲突缺失（缓存没满，但几块抢同一组）。对策分别是预取、减小工作集（分块）、提高相联度或调整数据布局。处理器的硬件预取器会发现“你在按固定步长往后读”，提前把后面的行搬进来；随机访问它就无能为力，上面的程序正是故意让它失效。

伪共享

两个线程分别不停地改两个不同的变量，可这两个变量恰好在同一个缓存行里：每次一个核写，缓存一致性协议都要让另一个核的那一行失效，这一行就在两个核之间来回“弹”，两个毫不相干的线程互相拖慢好几倍。这叫伪共享。对策是让各线程的数据各占一个缓存行（填充或对齐到 128 字节），第二十九章会再遇到。

换个循环顺序

矩阵乘法 C = A × B 的三重循环有六种排列。最朴素的 i-j-k 顺序，最内层沿着 B 的列走，步长一行；改成 i-k-j，最内层沿 B 和 C 的行走，全是连续访问，同样的计算量常常快好几倍。再进一步把矩阵切成能放进缓存的小块（分块），每一块反复用够了再换下一块。高性能数学库（Mac 上的 Accelerate 框架）做的就是把这些做到极致，再加上第七章说的向量指令。

还有一层缓存要留到第四部：把虚拟地址翻译成物理地址也要查表，查表的结果缓存在 TLB 里，它也是一个缓存，常常是全相联的（第二十七章）。
