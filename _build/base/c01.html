为什么是 C

C 语言是 1972 年前后丹尼斯·里奇在贝尔实验室为了写 Unix 操作系统而设计的。五十多年过去，它还在一线：macOS 和 Linux 的内核、Python 解释器（官方版本叫 CPython，就是用 C 写的）、数据库、嵌入式设备里的程序，大多是 C 写的。它的特点是离机器很近：一个 int 就是内存里的 4 个字节，一次加法几乎就是一条 add 指令。所以它是看清“程序怎样在机器上跑”的最好窗口。

先编译，再运行

第一个 C 程序15 分钟
  1. 在 ~/base 里新建 hello.c： 
    #include <stdio.h>

int main(void) {
    printf("你好，C！\n");
    int age = 10;
    printf("我今年 %d 岁，明年 %d 岁。\n", age, age + 1);
    return 0;
}
  2. 编译，再运行： 
    % clang hello.c -o hello
% ./hello
你好，C！
我今年 10 岁，明年 11 岁。
    clang hello.c -o hello 把源代码翻译成机器指令，存进一个叫 hello 的新文件（-o 是 output）；./hello 运行它（./ 表示“当前文件夹里的”）。
  3. 和 Python 比一比：Python 是一边读一边执行（第零章的“解释”），C 是先整个翻译好、再运行（“编译”）。所以改了 hello.c 以后，要重新编译才会生效。编译好的 hello 可以拷到另一台同类的 Mac 上直接运行，不需要装 clang。

逐行看：#include <stdio.h> 把“标准输入输出”的说明书拿进来，里面有 printf；int main(void) 是程序的入口，运行时从这里开始；花括号 { } 圈出一段代码（Python 用缩进）；每句话以分号结尾；return 0; 告诉系统“我正常结束了”，在终端里输入 echo $? 能看到这个 0。

Python 里写 age = 10 就行；C 里要先说清楚它是什么类型：int age = 10;。类型决定了两件事：占几个字节，和这些字节怎样读（第一部的整数、补码、浮点）。在 Apple Silicon 的 Mac 上：

类型字节装什么printf 写法
char1一个字符（其实就是一个小整数，第五章的 ASCII）%c，或 %d 看它的编号
short2−32768 到 32767%d
int4约 ±21 亿（第三章的 32 位补码）%d，十六进制 %x
long8约 ±9.2 × 1018%ld

类型的尺子

选一种类型，输入一个值，看它在内存里占几个字节、每个字节是什么（小端，第二章），以及这种类型能装的范围。超出范围时看看会变成什么。

和 Python 不一样的地方

  • 整数除法：两个整数相除结果还是整数，小数直接扔掉。7 / 2 是 3（Python 3 里是 3.5，要写 7 // 2 才是 3）。想要小数，至少一边写成小数：7 / 2.0。
  • 会溢出：Python 的整数可以无限大，C 的 int 只有 4 个字节，加过头就“转过钟面”（第三章）。
  • char 就是数：char c = 'A'; c = c + 1; 之后 c 是 'B'。
  • if、while、for 的意思和 Python 一样，写法是 if (x > 0) { … } else { … }、for (int i = 0; i < 10; i++) { … }。i++ 是 i = i + 1 的简写。
量一量各种类型，再故意犯几个错20 分钟
#include <stdio.h>
int main(void) {
    printf("char %zu, int %zu, long %zu, double %zu\n",
           sizeof(char), sizeof(int), sizeof(long), sizeof(double));
    char c = 'A';
    printf("%c 的编号是 %d，下一个是 %c\n", c, c, c + 1);
    printf("7 / 2 = %d，7 / 2.0 = %f\n", 7 / 2, 7 / 2.0);
    int big = 2147483647;
    printf("最大的 int 是 %d，十六进制 %x\n", big, big);
    return 0;
}

sizeof 告诉你一个类型占几个字节，%zu 是打印它的格式。编译运行后，再故意改坏，看编译器怎样说：

  • 删掉某一行末尾的分号：报 error: expected ';'，并指出行号和列号。
  • 把 printf 拼成 prinft：报 call to undeclared function（用了没声明的函数）。
  • 把 %d 配上一个小数：多半只得到一个 warning（警告），程序照样编译出来，但打印的是乱数。警告也要看。加上 -Wall（打开所有常见警告）编译：clang -Wall sizes.c -o sizes。

报错信息里最重要的是第一条：文件名、行号、列号，后面是原因。从第一条开始改，改完重新编译，后面的报错常常跟着消失。

Windows 上可以装 Visual Studio（用 MSVC 编译器），或者在 WSL 里用 gcc / clang；有一处要小心：在 Windows 上 long 只有 4 个字节（第三层）。Linux 上用 gcc 或 clang，命令和这里几乎一样。

编译选项

平时练习建议：clang -std=c17 -Wall -Wextra -g -O0 x.c -o x。-std=c17 指定标准；-Wall -Wextra 打开警告；-g 带上调试信息（第二十四章）；-O0 不优化，调试时变量不会被优化掉。查函数用法：man 3 printf（第 3 节是 C 库函数）。

隐式类型转换

  • 整数提升：char、short 参与运算时先变成 int。所以 char a = 100, b = 100; int c = a + b; 得 200，不会在 char 里溢出。
  • 寻常算术转换：两个操作数类型不同时，转成“更大”的那个：int 和 double 运算转成 double；int 和 unsigned int 运算转成 unsigned（第三章的 -1 < 1u 为假就是这个）；int 和 long 运算转成 long。
  • 赋值截断：把大类型赋给小类型，只留低位字节：char c = 300; 得 300 − 256 = 44。把 double 赋给 int，小数部分向零截断：int i = -3.7; 得 −3。
  • 负数的除法和取余：C99 起规定整数除法向零取整：-7 / 2 == -3，-7 % 2 == -1（余数的符号跟被除数）；Python 是向下取整：-7 // 2 == -4，-7 % 2 == 1。在 C 里判断奇数要写 x % 2 != 0，不能写 x % 2 == 1（负奇数不成立）。

常见的未定义行为

第三章说过“未定义行为”：标准不规定结果，编译器可以假设它永远不发生。最常见的几种：有符号整数溢出；数组越界（第十九章）；使用未初始化的局部变量；解引用空指针或已释放的指针（第十八、二十一章）；同一个表达式里对一个变量改两次，如 i = i++ + 1;；printf 的格式和参数类型不匹配；除以零。程序“在我电脑上能跑”不代表没有它们。

典型题 · 原创

在 Apple Silicon 的 Mac 上（int 32 位、补码），下列各式的值是多少？（1）-17 / 5 和 -17 % 5；（2）(char)200（按 %d 打印，char 有符号）；（3）unsigned int u = 1; int i = -2; 时 u + i（按 %u 打印）；（4）(int)(2.9 + 0.5)；（5）3 / 2 * 2.0。

看解答

（1）−3 和 −2（向零取整，余数跟被除数同号，−3 × 5 + (−2) = −17）。

（2）200 − 256 = −56。（Apple Silicon 上 char 默认有符号；有些平台的 char 默认无符号，这一点标准没有规定。）

（3）i 转成 unsigned 为 232 − 2，加 1 得 4294967295。

（4）3.4 向零截断为 3。

（5）3 / 2 先算，整数除法得 1，再乘 2.0 得 2.0。运算顺序和类型一起决定结果。

面试题

sizeof 是函数吗？int a[10]; sizeof(a) 和 sizeof(a[0]) 各是多少？

看要点

sizeof 是运算符，在编译时求值（变长数组除外），不会真的计算括号里的表达式：sizeof(i++) 不会让 i 加一。sizeof(a) 是整个数组 40 字节，sizeof(a[0]) 是 4，常用 sizeof(a) / sizeof(a[0]) 求元素个数；但数组传进函数后变成指针，这个写法就失效了（第十九章）。

C 里 -7 / 2 等于？

向零取整。

C 里 -7 % 2 等于？

余数符号跟被除数。

unsigned char c = 300; 之后 c 是多少？

只留低 8 位：300 − 256 = 44。

int 和 double 做加法，结果是什么类型？

  1. int
  2. double
  3. 看大小

转成更大的 double。

下面哪个不是未定义行为？

  1. int 加到溢出
  2. 读未初始化的局部变量
  3. unsigned int 加到溢出

无符号溢出按模 2n 回绕，是定义好的。

第三层 · 深入数据模型和标准约 25 分钟LP64 和 LLP64：同一个 long 在 Mac 和 Windows 上不一样大；固定宽度类型；C 标准的演变；clang 其实是一串工具的“司机”。

同一个 long，两种大小

C 标准只规定了各种整数类型的最小范围，没规定确切的字节数。于是不同平台有不同的“数据模型”：macOS、Linux 等类 Unix 系统的 64 位版本用 LP64（long 和指针是 64 位，int 是 32 位）；64 位 Windows 用 LLP64（只有 long long 和指针是 64 位，long 仍是 32 位）。一个在 Mac 上好好的程序，拿到 Windows 上用 long 存文件大小，超过 2 GB 就溢出。跨平台代码的做法是用 <stdint.h> 里的固定宽度类型：int32_t、uint8_t、int64_t，以及表示大小的 size_t、表示指针差的 ptrdiff_t。

C 的演变

1978 年，克尼汉和里奇出版《C 程序设计语言》，书里描述的版本人称 K&R C。1989 年美国国家标准学会发布第一个正式标准（C89，次年成为国际标准 C90），之后有 C99（加了 // 注释、bool、可以在 for 里声明变量、变长数组）、C11（线程、原子操作、去掉了危险的 gets）、C17（修订）、C23（true、false、nullptr 成为关键字，规定整数用补码，<stdckdint.h>）。Apple 的 clang 默认采用较新的标准，加 -std= 可以指定。

clang 是一个“司机”

你敲的 clang hello.c -o hello 其实依次调用了好几个工具：预处理器、编译器本体、汇编器、链接器（第二十二章一个一个拆开）。加 -v 能看到它实际执行了哪些命令；加 -### 只打印命令不执行。macOS 上的 gcc 命令其实也是 clang（试试 gcc --version），真正的 GCC 要另外用 Homebrew 装。
