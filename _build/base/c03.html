第一层 · 入门要会：指针（第十八章）、ASCII（第五章）约 50 分钟

数组：一排挨着的格子

int a[4] = {10, 20, 30, 40}; 在内存里要 4 × 4 = 16 个连在一起的字节，a[0] 在最前面，a[1] 紧跟在后面……于是第 i 个元素的地址很好算：

a[i] 的地址 = a 的首地址 + i × 每个元素的字节数

这就是数组从 0 开始数的原因：a[0] 离开头 0 个元素。处理器算这个地址只要一条指令（第十四章的 ldr w0, [x1, x2, lsl #2]，左移 2 位就是乘 4），所以按下标访问数组非常快，不管数组多长。

C 不检查越界

a 只有 4 个元素，写 a[5] 会怎样？Python 会报错。C 不检查，它照样用“首地址 + 5 × 4”算出一个地址去读写，那里可能是别的变量、可能是函数的返回地址、也可能根本不属于你。读到的是乱七八糟的东西，写进去会悄悄破坏别的数据。这是 C 程序里最常见、也最危险的一类错误。

字符串：以 0 结尾的字符数组

C 没有专门的字符串类型，字符串就是一个 char 数组，最后多放一个值为 0 的字节作为结尾标记（写作 '\0'，不是字符 '0'，字符 '0' 是 48）。char s[] = "Hi!"; 占 4 个字节：72、105、33、0。strlen(s) 从头数到 0 为止，得 3；sizeof(s) 是整个数组，得 4。如果结尾的 0 丢了，所有字符串函数都会一直往后读，直到碰巧遇到一个 0 为止，第五章说的“烫烫烫”常常就是这么打出来的。

结构体：把几样东西捆在一起

struct student {
    char name[8];

};
struct student s = {"Xiao", 10, 1.42};
printf("%s %d %.2f\n", s.name, s.age, s.height);

结构体的成员也是挨着放的，用点号访问。通过指针访问写 p->age，等价于 (*p).age。

#include <stdio.h>
#include <string.h>
int main(void) {
    int a[4] = {10, 20, 30, 40};
    char s[] = "Hi!";
    printf("a 从 %p 开始，a[1] 在 %p，a[3] 在 %p\n", (void *)a, (void *)&a[1], (void *)&a[3]);
    printf("strlen = %zu，sizeof = %zu\n", strlen(s), sizeof(s));
    for (int i = 0; i <= 6; i++) printf("a[%d] = %d\n", i, a[i]);   /* 故意越界 */
    return 0;
}

第二层 · 本科数据结构的数组存储 · 408 计组的对齐约 50 分钟二维数组按行存和按列存的地址公式；对称和三角矩阵的压缩存储；数组名什么时候是指针；字符串函数和长度限制；内存对齐的规则和结构体大小。

二维数组的地址

int m[R][C] 在 C 里按行存放（行优先）：先放第 0 行的 C 个元素，再放第 1 行……所以 LOC(m[i][j]) = LOC(m[0][0]) + (i × C + j) × L（L 是每个元素的字节数）。Fortran、MATLAB 是按列存放的：LOC = LOC(m[0][0]) + (j × R + i) × L。第十六章说按行遍历快，就是因为 C 按行存。数据结构课的题目常把下标从 1 开始、或者给定 m[1..R][1..C]，套公式前先把下标换成“前面有几个元素”。

压缩存储：n 阶对称矩阵只存下三角（含对角线），共 n(n + 1)/2 个元素；按行存放时，aij（i ≥ j，下标从 1 开始）在一维数组里的下标（从 0 开始）是 i(i − 1)/2 + j − 1。三角矩阵、三对角矩阵同理推导。这类题的方法都一样：数清楚它前面有几个元素。

数组和指针

数组名在大多数表达式里会“退化”成指向首元素的指针，所以 int *p = a; 合法，a[i] 和 p[i] 写法相同。但它们不是一回事：sizeof(a) 是整个数组的字节数，sizeof(p) 是 8；&a 的类型是“指向整个数组的指针”，&a + 1 跳过整个数组；数组名不能被赋值。数组作函数参数时，void f(int a[]) 和 void f(int *a) 完全一样，函数里拿不到数组的长度，所以 C 的函数总要多传一个长度参数。

字符串函数的坑

strcpy(dst, src) 不管 dst 有多大，一直抄到 src 的 0 为止，dst 小了就越界；strcat 同理；gets 根本没法限制长度，C11 已经删掉。要用带长度的版本：snprintf(dst, sizeof dst, "%s", src)，或者 macOS 和 BSD 提供的 strlcpy、strlcat（保证结尾有 0）。strncpy 名字像安全版，但源串太长时不会补结尾的 0，是有名的陷阱。

内存对齐

处理器读一个 4 字节的 int，如果它的地址是 4 的倍数，一次就能读出来；不是的话，有的处理器要读两次再拼起来，有的干脆报错。所以编译器让每种类型放在它大小的整数倍的地址上（对齐）：char 随便放，short 放在 2 的倍数，int、float 放在 4 的倍数，long、double、指针放在 8 的倍数。结构体的规则：

  1. 每个成员的偏移量必须是它自身对齐要求的整数倍，不够就在前面插填充字节；
  2. 结构体的总大小必须是其中最大对齐要求的整数倍，不够就在末尾填充（这样结构体数组里每个元素也对齐）。

例：struct { char c; int i; char d; }：c 在偏移 0；i 要 4 的倍数，偏移 1—3 填充，i 在 4—7；d 在 8；总大小要是 4 的倍数，9—11 填充，sizeof 为 12。把字段按从大到小重排成 { int i; char c; char d; }，sizeof 就是 8。装置里的结构体就是前一种。

典型题 · 原创

（1）二维数组 double m[10][20] 按行存放，首地址 2000（十进制），m[3][5] 的地址是多少？若按列存放呢？（2）在 Apple Silicon 的 Mac 上（char 1、short 2、int 4、double 8，按自然边界对齐），求 struct A { char a; double b; short c; int d; }; 的 sizeof，并给出一种使它最小的字段顺序。（3）n 阶下三角矩阵（含对角线）按行优先压缩存入数组 B[0..]，aij（1 ≤ j ≤ i ≤ n）存在 B 的哪个下标？

看解答

（1）按行：2000 + (3 × 20 + 5) × 8 = 2000 + 520 = 2520。按列：2000 + (5 × 10 + 3) × 8 = 2000 + 424 = 2424。

（2）a 偏移 0；b 要 8 的倍数，偏移 8—15（1—7 填充）；c 偏移 16—17；d 要 4 的倍数，偏移 20—23（18—19 填充）；总大小 24，已是 8 的倍数，sizeof = 24。重排为 double b; int d; short c; char a; 偏移 0、8、12、14，共 15，补到 8 的倍数为 16。

（3）第 i 行前面有 1 + 2 + … + (i − 1) = i(i − 1)/2 个元素，本行 aij 前面还有 j − 1 个，下标为 i(i − 1)/2 + j − 1。

面试题

为什么要内存对齐？怎样取消对齐？

看要点

对齐让一次访存就能取出整个数据，避免跨缓存行、跨页的拆分读写，有的架构不支持非对齐访问；代价是结构体里多出填充字节。可以用 __attribute__((packed)) 或 #pragma pack 取消填充（常用于网络包、文件格式这类需要精确布局的场合），代价是访问可能变慢，指向成员的指针也可能是非对齐的。工程上更常见的做法是按成员大小从大到小排列字段。

写过头，改掉返回地址

函数的局部数组放在栈上，紧挨着的高地址处保存着函数的返回地址（下一章）。如果程序用 gets 或 strcpy 把一段比数组长的输入抄进去，多出来的字节就会盖掉返回地址。精心构造的输入能让返回地址指向攻击者想执行的代码：早年是直接塞在输入里的一段机器码，栈不可执行之后改成拼接程序里已有的指令片段（返回导向编程）。这就是缓冲区溢出攻击，几十年来最常见的漏洞类型之一。

莫里斯蠕虫和心脏出血

1988 年 11 月，康奈尔大学的研究生罗伯特·莫里斯放出了一个能自我复制的程序，它的传播手段之一，就是利用 Unix 上 fingerd 服务里一次没有长度限制的 gets 调用造成缓冲区溢出。当时互联网上大约六万台机器，据估计有几千台被感染、运行变得极慢。这是互联网上第一起广为人知的蠕虫事件，莫里斯成为美国依据《计算机欺诈和滥用法》被定罪的第一人。2014 年公开的“心脏出血”漏洞方向相反：加密库 OpenSSL 处理“心跳”请求时，相信了对方声称的长度，没有检查就把那么多字节回传，于是每次可以从服务器内存里多读出最多约 64 KB，可能包括密钥和密码。一行没写的边界检查，影响了互联网上相当比例的加密网站。

层层设防

  • 栈保护（stack canary）：编译器在局部数组和返回地址之间放一个随机数，函数返回前检查它有没有被改，被改了就立刻终止程序。clang 的 -fstack-protector 系列选项。
  • 不可执行栈：第十三章的 W^X，栈上的数据不能当代码执行。
  • 地址随机化：第十八章，攻击者不知道要跳到哪儿。
  • 指针签名：Apple Silicon 上用 PAC 给返回地址签名（下一章），改了就验不过。
  • 更安全的语言：Rust、Go、Swift 等默认检查数组边界，越界时报错而不是悄悄读写；Rust 还在编译时检查指针的有效期。美国网络安全机构近年多次建议新项目优先使用内存安全的语言。

  3. 把栈放到硬盘上
