第一层 · 入门要会：指针（第十八章）约 45 分钟

一摞盘子

食堂里摞着一叠盘子：新洗好的放在最上面，拿的时候也从最上面拿。后放的先拿，这种结构叫栈（stack）。函数调用正好就是这样：main 调用 A，A 调用 B，B 必须先结束，A 才能接着做，A 结束了才轮到 main。最后被调用的最先返回。

每调用一次函数，程序就在栈上划出一块地方，叫这个函数的栈帧，里面放着：

  • 返回地址：做完以后回到调用者的哪一条指令（门口的纸条）；
  • 这个函数的局部变量和参数（放不进寄存器的那些）；
  • 一些要暂时保存的寄存器的旧值。

函数返回时，它的栈帧就被整块收回。所以局部变量只在函数运行期间存在，第十八章说“返回局部变量的地址”是错的，原因就在这里。在 Mac 上，栈从高地址往低地址长（第三部封面的内存地图里，栈在上面、往下长）。

一步一步执行递归求阶乘的程序，看每调用一次 fact 就多出一个栈帧、每返回一次就少一个。每个栈帧里都存着“回到哪儿”。第二个程序是一个忘了写终点的递归。

递归和栈溢出

递归就是函数调用自己。每一层都有自己的栈帧和自己的 n，所以 fact(3) 里的 n 和 fact(2) 里的 n 互不干扰。递归一定要有终点（n ≤ 1 时直接返回），否则会一直叠下去。栈的大小是有限的，叠满了，程序就会访问到栈下面那片不许碰的内存，被系统立刻终止，这叫栈溢出（stack overflow，程序员问答网站 Stack Overflow 的名字就是这么来的）。

把栈撑爆10 分钟
#include <stdio.h>
int depth = 0;
void dive(void) {
    char pad[1000];              /* 每层栈帧多占 1000 字节 */
    pad[0] = (char)depth;
    depth++;
    if (depth % 1000 == 0) printf("已经 %d 层\n", depth);
    dive();
}
int main(void) { dive(); return 0; }
% ulimit -s
8176
% clang -O0 deep.c -o deep && ./deep

ulimit -s 显示主线程的栈有多大，单位是 KB，Mac 上多半是 8176（约 8 MB）。程序打印到八千层左右就会崩溃，报 Segmentation fault 或 Illegal instruction。估算一下：8 MB ÷ 每层一千多字节，大约就是这么多层。用 -O0 是怕编译器把递归优化掉（第三层）。

把递归改成循环

用 for 循环重写 fact，算 fact(10) 和 fact(13)，和递归版对比结果。再算 fact(13)，结果对吗？（提示：13! 超过了 int 的范围，第三章。）换成 long 再试。循环版不需要一层层的栈帧，再深也不会爆栈。

arm64 的栈帧

Apple Silicon 上（AAPCS64，Apple 略有调整）：前 8 个整数或指针参数放在 x0—x7，返回值放在 x0；x30（LR，链接寄存器）放返回地址，bl func 跳到 func 的同时把下一条指令的地址写进 x30，ret 就是跳回 x30；x29（FP）是帧指针，指向当前栈帧里保存旧 x29 的位置，一串 x29 连起来就能从内往外走遍所有栈帧（调试器的 bt 就靠它）；sp 是栈指针，必须始终 16 字节对齐。一个要调用别的函数的函数，开头结尾通常是这样：

fact:
    stp  x29, x30, [sp, #-32]!   ; sp 先减 32（栈往下长），把旧 x29 和返回地址存进去
    mov  x29, sp                 ; 新的帧指针
    …                            ; 函数体，局部变量放在 [sp, #16] 之类的地方
    bl   fact                    ; 递归调用：x30 被改写成这里的下一条
    …
    ldp  x29, x30, [sp], #32     ; 恢复旧 x29 和返回地址，sp 加回 32
    ret                          ; 跳回 x30

因为 bl 会改写 x30，所以凡是要调用别人的函数，都得先把自己的 x30 存到栈上，这就是“返回地址在栈里”的由来。叶子函数（不再调用别人的函数，比如第十四章的 add）可以不建栈帧，直接用 x30 返回。

谁来保存寄存器：x19—x28 是被调用者保存的，函数如果要用它们，得先把旧值存起来、返回前恢复，所以调用者可以放心地把值留在里面跨调用使用；x0—x18 中的大部分是调用者保存的，被调用的函数可以随便改，调用者如果调用后还要用，得自己先存。

x86-64 的版本（408 用的是它）

考研 408 的“程序的机器级表示”以 x86 为例。区别主要在：call f 把返回地址压到栈上（rsp 减 8，再写入），而不是放进寄存器；ret 从栈顶弹出返回地址跳过去。典型的开头和结尾：

f:  pushq %rbp            # 旧的帧指针压栈
    movq  %rsp, %rbp      # 新帧指针 = 当前栈顶
    subq  $16, %rsp       # 给局部变量留 16 字节
    …                     # 局部变量用 -4(%rbp)、-8(%rbp) 访问
    leave                 # 等于 movq %rbp, %rsp; popq %rbp
    ret                   # 弹出返回地址，跳回去

Linux 上 x86-64 的参数依次放在 rdi、rsi、rdx、rcx、r8、r9，返回值在 rax。408 题里还会出现 32 位 x86（IA-32），参数全部压栈、用 8(%ebp)、12(%ebp) 取参数（%ebp 上面 4 字节是返回地址，再上面才是第一个参数）。Intel 写法和 AT&T 写法操作数顺序相反，读题先看是哪种。

典型题 · 原创

（1）某递归函数每层栈帧 48 字节，主线程栈 8 MB（按 8 × 220 字节算，不计其他开销），最多能递归多少层？（2）IA-32 下，函数 int f(int a, int b) 采用标准的 push %ebp; mov %esp, %ebp 开头，进入函数体后，a 和 b 分别在 %ebp 加多少的位置？返回地址在哪里？（3）arm64 下，叶子函数为什么可以不把 x30 存到栈上？

看解答

（1）8 × 220 ÷ 48 ≈ 174762 层（实际会少一些，栈里还有 main 和启动代码的帧）。

（2）调用者先压 b、再压 a（参数从右往左压），call 压返回地址，f 再压旧 %ebp 并让 %ebp 指向它。所以 (%ebp) 是旧 %ebp，4(%ebp) 是返回地址，8(%ebp) 是 a，12(%ebp) 是 b。

（3）叶子函数不执行 bl，x30 不会被改写，ret 时 x30 里还是调用者给的返回地址。

面试题

递归和迭代各有什么优缺点？什么时候递归会爆栈？

看要点

递归代码贴近问题的数学定义，写树、分治、回溯很自然；代价是每层一个栈帧（时间上有调用开销，空间上占 O(深度) 的栈），深度过大会栈溢出，比如对一条退化成链表的二叉树递归、或者对几十万个元素递归求和。迭代需要自己维护状态（必要时自己用一个栈），没有爆栈风险。尾递归在支持尾调用优化的编译器下可以变成循环（第三层），但 C 标准不保证这件事。

arm64 里 bl 把返回地址写进哪个寄存器？

x30（LR）。

x86-64 的 call 指令把返回地址放在哪儿？

  1. rax
  2. 压到栈上
  3. rbp

ret 再从栈上弹出来。

arm64 里 x19—x28 是？

  1. 被调用者保存的寄存器
  2. 调用者保存的寄存器
  3. 参数寄存器

函数要用就得先存后恢复。

IA-32 下，标准开头之后第二个参数在 %ebp 加多少？

4 是返回地址，8 是第一个参数，12 是第二个。

arm64 要求 sp 始终按几字节对齐？

16 字节。

尾调用

如果一个函数的最后一步就是调用另一个函数并直接返回它的结果（return g(x);），当前的栈帧其实已经没用了，可以直接跳到 g，让 g 返回时直接回到我们的调用者。这叫尾调用优化。return n * fact(n - 1); 不是尾调用（调用完还要乘 n），改写成带累加器的 fact_acc(n - 1, acc * n) 就是。用 clang -O2 -S 看，尾递归版里根本没有 bl，只有一个跳回开头的 b。C 标准不保证这种优化，所以不要依赖它防止爆栈；有些语言（Scheme）则规定必须做。

线程的栈更小

主线程的栈约 8 MB，但 macOS 上用 pthread 新建的线程，默认栈只有 512 KB。在线程里放一个几百 KB 的局部数组，或者递归深一点，就会爆栈。大数组应该放到堆上（下一章），或者创建线程时用 pthread_attr_setstacksize 指定更大的栈。

保护返回地址

第十九章说过，攻击者最想改写的就是栈上的返回地址。除了栈保护（canary），硬件也来帮忙：

  • 指针签名：在 Apple Silicon 的 arm64e 程序里，函数开头多一条 pacibsp（或 paciasp），用密钥和当前 sp 给 x30 签名后再存进栈；结尾用 retab（或 autibsp 加 ret）验证签名后再跳。栈上的返回地址被改了，验签就失败，程序立刻崩溃，攻击者拿不到控制权。
  • 影子栈：英特尔的 CET 等技术在另一块受保护的内存里再存一份返回地址，ret 时两份对不上就报错。

可以试试：clang -arch arm64e -O1 -S f.c -o -，看看函数开头结尾是不是多了这些指令（arm64e 主要用于系统程序，普通 App 默认编译成 arm64）。
