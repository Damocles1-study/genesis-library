程序怎样被放进内存，要用到可执行文件的格式和内存地图，建议初中以后再细读。下面几段只讲个大概。

菜谱和做菜

硬盘上的程序文件，像一本菜谱：上面写着要做什么，可它自己不会动。你双击它，或者在终端里敲它的名字，操作系统才把它“做”起来：

  1. 打开文件，看开头几个字节对不对得上“程序”的暗号（第二章说的魔数）；
  2. 在内存里划出一块地方；
  3. 把菜谱里的指令和数据抄进去；
  4. 准备好栈（第二十章）；
  5. 跳到第一条指令，开始执行。

正在“做”的程序，有一个名字，叫进程（第二十六章）。同一本菜谱，可以同时做好几份：开两个终端窗口，就是两个进程。

看一眼程序文件的暗号
% xxd -l 4 /bin/ls
00000000: cafe babe                                ....

/bin/ls 就是你常用的 ls 命令。它开头的四个字节是 cafe babe，Mac 一看就知道：这是一个程序，而且里面装着给好几种处理器的版本。

敲下回车以后

  1. 终端里的 shell（zsh）请操作系统“新开一个进程，运行 ./prog”（第二十六章细讲）。
  2. 操作系统打开 prog，读开头的文件头：魔数对不对（第二章的 CF FA ED FE）、是不是这种处理器的程序、要装哪些段。
  3. 给这个进程准备一片全新的地址空间，把代码段、数据段映射进去，BSS 段清零，再准备好栈，把命令行参数和环境变量放在栈顶。
  4. 把动态链接器 dyld 也装进来，先运行它：它把 prog 需要的动态库（比如 printf 所在的 libSystem）接上，把那些 U 符号的地址填好（上一章）。
  5. dyld 跳到 main。你的代码开始执行。
  6. main 返回（或者调用 exit），操作系统收回这个进程的所有内存、关掉它打开的文件，把退出码交给 shell。

命令行参数和退出码

main 其实可以有两个参数：int main(int argc, char **argv)。argc 是参数个数，argv 是一个字符串数组（每个元素是一个 char 指针，第十八、十九章），argv[0] 是程序自己的名字。运行 ./prog hello 42 时，argc 是 3，argv[1] 是 "hello"，argv[2] 是 "42"（字符串，要数字得用 atoi 转换）。main 的返回值是退出码，0 表示成功，非 0 表示出了某种错，shell 里用 echo $? 查看，脚本用它判断上一步成没成功。

    printf("printf %p\n", (void *)printf);
    printf("参数有 %d 个，第一个是 %s\n", argc, argv[0]);

}

逻辑地址和三种装入

编译链接出来的程序，里面的地址都是从某个约定的起点算起的逻辑地址；程序最终在内存里的位置是物理地址。从前者到后者的转换叫重定位。408 操作系统把装入分为三种：

  • 绝对装入：编译时就知道程序会装在哪里，直接生成物理地址。只适合单道程序的简单系统。
  • 可重定位装入（静态重定位）：装入时一次性把程序里所有地址加上装入的起始地址。装好以后不能再移动。
  • 动态运行时装入（动态重定位）：装入后程序里仍是逻辑地址，每次访问内存时由硬件把逻辑地址加上重定位寄存器的值得到物理地址。程序可以在内存里移动（只要改寄存器），这是第二十一章“紧凑”在操作系统层面能做的前提。今天的分页（第二十七章）是它的推广：不是加一个基址，而是查一张表。

exec 做了什么

在类 Unix 系统里，“运行一个程序”是系统调用 exec 族（如 execve）完成的：它不新建进程，而是把调用它的那个进程的地址空间整个换成新程序的（代码、数据、堆、栈全部丢掉重来），进程号不变。shell 先 fork 出一个自己的复制品，再让复制品 exec 目标程序，这就是第二十六章的 fork + exec。

看真实的加载命令和内存布局15 分钟
% otool -l where | grep -A3 -E "LC_SEGMENT_64|LC_MAIN|LC_LOAD_DYLINKER" | head -40
% otool -l where | grep -A2 LC_LOAD_DYLIB

LC_SEGMENT_64 是一个一个要映射的段（__PAGEZERO、__TEXT、__DATA、__LINKEDIT）；LC_LOAD_DYLINKER 指明用 /usr/lib/dyld 当动态链接器；LC_MAIN 记着 main 在文件里的偏移；LC_LOAD_DYLIB 列出依赖的动态库。__PAGEZERO 是一大片不可访问的区域，从地址 0 开始，所以解引用空指针会立刻崩溃（第十八章）。

想看一个正在运行的进程的完整内存布局，在 where.c 的 return 前加一行 getchar();（让它停下等你按回车），运行后在另一个终端窗口里：

% vmmap where | head -60

vmmap 列出每一块区域的地址范围、权限（r-x 表示可读可执行）和用途（__TEXT、MALLOC、Stack……）。

典型题 · 原创

（1）某程序采用动态运行时装入，被装到物理地址 20000H 开始的区域，重定位寄存器的值是多少？程序中逻辑地址 0345H 处的一条指令访问逻辑地址 1A00H 的数据，实际访问的物理地址是多少？（2）若改为可重定位装入，程序装入后被操作系统移动到 40000H，会出现什么问题？

看解答

（1）重定位寄存器 = 20000H；物理地址 = 20000H + 1A00H = 21A00H（这条指令本身在 20345H）。

（2）可重定位装入在装入时已经把程序里的地址都改成了基于 20000H 的物理地址，移动后这些地址全都指向旧位置，程序会访问错误的内存。所以静态重定位的程序装入后不能移动；要能移动，必须用动态重定位。

代码签名

在 Apple Silicon 的 Mac 上，内核拒绝运行没有有效签名的原生代码。你自己编译的 where 能运行，是因为链接器自动给它做了一个“临时签名”（ad-hoc）：只记录了文件内容的哈希，不说明是谁签的。用 codesign -dv where 能看到 Signature=adhoc。如果你用十六进制编辑器改了 where 里的一个字节，签名就对不上，运行时会被系统直接杀掉（终端显示 killed）。发布给别人用的程序，要用开发者证书签名并提交给 Apple 公证。

隔离属性和门禁

从浏览器、聊天软件下载的文件，会被打上一个“隔离”扩展属性（xattr -l 文件 能看到 com.apple.quarantine）。第一次打开带这个属性的程序时，门禁（Gatekeeper）会检查它的签名和公证，不合格就拦下，弹出“无法验证开发者”。这是 macOS 防恶意软件的第一道门；遇到它时，先想清楚这个程序是从哪里来的，而不是急着找办法绕过。

系统完整性保护

系统完整性保护（SIP）让系统目录里的文件连管理员也改不了，并限制调试器附加到系统进程、限制某些动态链接器的环境变量对系统程序起作用。所以一些老教程里“用 DYLD_ 开头的环境变量注入代码”“用 dtrace 跟踪任何进程”的做法，在默认设置的 Mac 上不再管用。第二十五章要跟踪系统调用时，我们会改用 Linux 虚拟机。

#! 开头的脚本

第七章的 hi.sh 能直接运行，是因为内核在 exec 时发现文件以 #! 开头，就读出后面写的解释器路径（比如 #!/bin/zsh 或 #!/usr/bin/env python3），改为运行那个解释器、把脚本文件名作为参数交给它。脚本本身不是机器码，所以也不需要第二十二章的那四步。
