两种身份

如果每个程序都能随便指挥硬盘、改别人的内存，一个写错的程序就能把整台电脑搞垮，一个坏程序就能偷走所有人的数据。所以处理器有两种运行身份（在 arm64 上叫“异常级别”，EL0 和 EL1）：

  • 用户态：你的程序、浏览器、游戏都在这里。只能算数、读写自己的内存，有些指令根本不许执行（比如直接操作外设、改内存映射）。
  • 内核态：操作系统的核心部分（内核）在这里运行，什么都能做。macOS 的内核叫 XNU，Linux 的内核就叫 Linux。

这像银行：顾客（程序）不能自己走进金库（硬件），要在柜台填单子，由柜员（内核）检查后代办。

系统调用：柜台

程序要读文件、写屏幕、联网、要内存、开新程序，都要发起系统调用：把“我要办什么事”（一个编号）和参数放进约定的寄存器，执行一条特殊的指令（arm64 上是 svc），处理器立刻切换到内核态，跳到内核里事先设好的入口。内核检查请求合不合法、办完，再切回用户态，把结果交还给程序。printf 自己先把字排好，最后调用一次 write 系统调用，请内核把这些字节交给终端。

中断：硬件举手

反过来，硬件也有事要找内核：键盘被按下了、网卡收到了数据、硬盘读完了、定时器的时间到了。它们会发出中断信号，处理器放下手上的程序（不管它是谁），切到内核去处理，处理完再回来接着做。第零章“按下 A 键以后”的第四步就是它。定时器中断尤其重要：每隔几毫秒响一次，内核借机决定要不要换一个程序来跑（下一章）。

操作系统的特征和功能

408 的说法：操作系统的基本特征是并发（宏观上同时运行多个程序）、共享（资源被多个程序共用，分互斥共享和同时共享）、虚拟（把一个物理实体变成多个逻辑上的对应物，如虚拟处理器、虚拟内存）、异步（程序走走停停，以不可预知的速度推进），其中并发和共享是最基本的、互为存在条件。它的功能是管理处理器、存储器、文件、设备，并向上提供接口（命令接口和程序接口，后者就是系统调用）。

中断和异常

  • 中断（外中断）：来自处理器外部、和当前指令无关的事件，如 I/O 完成、定时器、键盘。处理完回到被打断的下一条指令。分为可屏蔽中断（可以暂时关掉不响应）和不可屏蔽中断（如掉电）。
  • 异常（内中断）：执行当前指令引起的。① 陷阱（陷入）：程序有意引起的，如系统调用、断点（第二十四章的 brk），处理完回到下一条指令；② 故障：可能被修复的错误，如缺页（第二十七章）、除以零，修复后重新执行引起故障的那条指令；③ 终止：无法恢复的错误，如硬件故障，程序被终止。

中断处理过程

408 计组常考的顺序（单重中断）：中断请求 → 中断判优（多个请求同时来，选优先级最高的）→ CPU 在一条指令执行完后响应（检查有无中断请求，且中断允许）→ 中断隐指令（硬件自动完成：关中断、保存断点（PC 和程序状态）、识别中断源并送出中断服务程序的入口地址）→ 中断服务程序：保存现场（通用寄存器等）→ 若允许多重中断则开中断 → 执行设备服务 → 关中断 → 恢复现场 → 开中断 → 中断返回。入口地址常通过中断向量表查得：每种中断一个编号，表里存着对应服务程序的地址。多重中断时，可以用中断屏蔽字动态调整各中断源的处理优先级。

特权指令

只能在内核态执行的指令叫特权指令：I/O 指令、开关中断、修改页表基址寄存器（换地址空间）、停机、设置时钟等。用户态程序执行它们会引发异常。“访管指令”（系统调用指令，arm64 的 svc、x86 的 syscall）本身不是特权指令，它恰恰是用户态程序进入内核的合法途径。

典型题 · 原创

（1）判断下列事件是中断还是异常，若是异常属于哪一类：① 程序执行 svc 请求读文件；② 访问的页不在内存中；③ 定时器时间片到；④ 整数除以零；⑤ 网卡收到一个数据包；⑥ 内存校验发现无法纠正的错误。（2）下列哪些指令只能在内核态执行：读时钟、写时钟、关中断、算术加法、修改页表基址寄存器、发出系统调用的指令。（3）把下列步骤按中断响应和处理的顺序排列：A 保存现场；B 关中断并保存断点（硬件）；C 执行中断服务；D 恢复现场；E 中断返回；F 识别中断源取得入口地址。

看解答

（1）① 异常 · 陷阱；② 异常 · 故障（缺页，处理后重新执行该指令）；③ 中断；④ 异常 · 故障（多数系统直接终止该程序）；⑤ 中断；⑥ 异常 · 终止。

（2）写时钟、关中断、修改页表基址寄存器。读时钟、加法、系统调用指令都可以在用户态执行。

（3）B → F → A → C → D → E（单重中断，开关中断的细节按题目要求补充）。

看要点

宏内核和微内核

宏内核把进程管理、内存、文件系统、网络协议、驱动全放在内核态的一个大程序里，彼此直接调用，快，但任何一个驱动出错都可能拖垮整个系统。Linux 是宏内核。微内核只在内核态保留最少的东西（进程间通信、基本调度和内存），文件系统、驱动等都作为用户态的服务进程，靠消息互相请求，更可靠但消息传递有开销。macOS 的 XNU 是混合的：底层是卡内基梅隆大学的 Mach 微内核，上面叠了来自 BSD Unix 的部分，但为了速度两者都运行在内核态。

同一件事，两种叫法

在 arm64 上，Linux 把系统调用号放在 x8、执行 svc #0；macOS 把调用号放在 x16、执行 svc #0x80。编号也不同（Linux 的 write 是 64 号，macOS 的 write 是 4 号）。这也是为什么 Linux 的程序不能直接在 macOS 上运行，即使处理器一样。macOS 不保证系统调用号稳定，程序应该通过系统库（libSystem）去调用。

一次系统调用有多贵

进出一次内核大约要几百纳秒，比一次普通函数调用贵一百倍以上。2018 年熔断漏洞（第十五章）公开后，很多系统在进入内核时还要切换一套页表（内核页表隔离），代价更大。所以有许多“少进内核”的办法：C 库的缓冲（上面的任务）；Linux 的 vDSO 把“读当前时间”这类只读的操作做成映射到每个进程里的一小段代码，根本不进内核；一次系统调用提交一批请求（Linux 的 io_uring）。
