程序和进程

硬盘上的 hello 是一个程序，一个静静躺着的文件。运行它，操作系统就造出一个进程：正在运行的程序，加上它的一切家当：自己的地址空间（第二十三章的那张内存地图）、寄存器的值、打开的文件、一个编号（进程号 PID）。同一个程序运行两次，就是两个进程，互不相干。内核为每个进程记一份档案，叫进程控制块（PCB）。

轮流，快到像同时

一个核同一时刻只能执行一个进程的指令。内核让每个进程跑一小段（比如几毫秒），定时器中断一响（第二十五章），就把它的寄存器存进它的档案，换另一个进程的寄存器进来接着跑。这叫上下文切换。一秒钟换几百上千次，在人看来就是所有程序同时在动。一个进程在等东西（等你按键、等硬盘、等网络）时，也会主动让出处理器，免得白占着。

看看你的 Mac 在跑什么10 分钟
% ps aux | wc -l
% ps -o pid,ppid,stat,comm -p $$
% top -o cpu -n 10

谁先跑：调度

好几个进程都等着用处理器，先给谁？这就是调度。像食堂排队：

  • 先来先服务：按到达顺序。公平，但一个要打很多菜的人排在前面，后面只买一个包子的人也得等他。
  • 短作业优先：活少的先做。大家平均等的时间最短，但活多的人可能一直被插队。
  • 时间片轮转：每人轮流服务一小会儿，没做完的回到队尾。谁都不会等太久，这是今天电脑最基本的做法。

进程的状态

五种状态：创建、就绪（万事俱备只差处理器）、运行、阻塞（等待某个事件，如 I/O 完成，给它处理器也没用）、终止。转换：就绪 → 运行（被调度选中）；运行 → 就绪（时间片用完或被抢占）；运行 → 阻塞（请求 I/O、等待资源，主动的）；阻塞 → 就绪（等的事件发生了，被动的）。注意阻塞不能直接变运行，必须先回就绪队列排队；就绪也不能直接变阻塞。PCB 里记着进程号、状态、寄存器现场、优先级、内存和打开文件的信息，是进程存在的唯一标志。

fork、exec、wait

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int main(void) {
    int x = 100;
    pid_t id = fork();                  /* 从这里开始，变成了两个进程 */
    if (id == 0) {                      /* 子进程里 fork 返回 0 */
        x++;
        printf("子进程 %d：x = %d\n", getpid(), x);
        execlp("echo", "echo", "我变成了 echo", (char *)NULL);   /* 换成另一个程序 */
    } else {                            /* 父进程里 fork 返回子进程的号码 */
        wait(NULL);                     /* 等子进程结束 */
        printf("父进程 %d：x = %d\n", getpid(), x);
    }
    return 0;
}

fork 把调用它的进程复制一份（地址空间、打开的文件都复制，现代系统用写时复制，第二十七章），两份都从 fork 返回处接着跑：子进程里返回 0，父进程里返回子进程的 PID。子进程改 x 不影响父进程（各有一份）。exec（第二十三章）把子进程换成别的程序。shell 运行每条命令都是这样：fork，子进程 exec，父进程 wait。子进程结束而父进程还没 wait，它的档案还留着，叫僵尸进程；父进程先死了，子进程被系统的第一个进程（macOS 上的 launchd）收养，叫孤儿进程。

进程和线程

线程是进程里的一条执行流。一个进程可以有好几个线程，它们共享同一个地址空间、打开的文件，各自有自己的栈和寄存器。所以线程之间传数据很方便（直接读写同一块内存），切换也比进程便宜；代价是一个线程写坏内存会拖垮整个进程，几个线程同时改同一个变量会出乱子（第二十九章）。408 的说法：进程是资源分配的基本单位，线程是调度的基本单位（引入线程以后）。浏览器给每个网页开一个进程，是为了一个网页崩了不连累别的。

调度算法和指标

周转时间 = 完成时间 − 到达时间；带权周转时间 = 周转时间 ÷ 实际运行时间；等待时间 = 周转时间 − 运行时间（不考虑 I/O）；响应时间 = 第一次被调度的时间 − 到达时间。算法：先来先服务（FCFS，非抢占，对长作业有利）；短作业优先（SJF，非抢占；抢占式叫最短剩余时间优先 SRTN）；高响应比优先（响应比 = (等待时间 + 要求服务时间) ÷ 要求服务时间，兼顾短作业和等得久的长作业，不会饥饿）；优先级调度（可抢占或不可抢占，可能饥饿，用“老化”缓解）；时间片轮转（RR）；多级反馈队列（多个队列优先级递减、时间片递增，新进程进最高队列，用完时间片还没完就降一级：照顾短作业和交互式进程，又不饿死长作业，是很多真实系统的原型）。装置里可以算前五种。

典型题 · 原创

四个进程到达时间和运行时间如下：P1(0, 7)、P2(2, 4)、P3(4, 1)、P4(5, 4)。分别求 FCFS、非抢占 SJF、时间片为 2 的 RR 下的平均周转时间。（RR 约定：同一时刻新到达的进程排在刚用完时间片的进程前面。）

看解答

FCFS：P1 0—7，P2 7—11，P3 11—12，P4 12—16。周转 7、9、8、11，平均 8.75。

SJF：0 时只有 P1，运行到 7；此时 P2(4)、P3(1)、P4(4) 都到了，选 P3（7—8），再在 P2、P4 中选先到的 P2（8—12），P4（12—16）。周转 7、10、4、11，平均 8。

RR(2)：0—2 P1；2 时 P2 到，P2 排在 P1 前：2—4 P2；4 时 P3 到，队列 P1、P3（P3 新到排在刚用完的 P2 前）、P2 → 4—6 P1；5 时 P4 到，6 时队列 P3、P2、P4、P1 → 6—7 P3（完成）；7—9 P2（完成）；9—11 P4；11—13 P1；13—15 P4（完成）；15—16 P1（完成）。周转 P1 16、P2 7、P3 3、P4 10，平均 9。具体顺序依赖约定，可以把这组数输进装置对照（装置采用同样的约定）。

切换不是免费的

上下文切换的直接开销是保存和恢复寄存器、进出内核，几微秒；更大的是间接开销：新进程的数据不在缓存里（第十六章），TLB 也要重新热起来（第二十七章）。所以时间片不能太短，否则大部分时间都花在切换上。

真实的调度器

Linux 从 2007 年起用“完全公平调度器”（CFS）：给每个进程记一个“虚拟运行时间”，总是挑虚拟时间最少的那个来跑，优先级高的虚拟时间涨得慢；2023 年起逐步换成更注重延迟的 EEVDF。macOS 让程序给每个任务标一个“服务质量”等级（用户交互、用户发起、实用工具、后台），调度器据此决定谁先跑、放在哪种核上。

Apple Silicon 有性能核和能效核（第零章第三层）。后台的照片索引、备份这类任务被放到能效核上慢慢做，省电；你正在点的界面放到性能核上。在活动监视器里打开“CPU 历史记录”窗口，能看到两组核分别有多忙。

fork 的代价

复制一个几 GB 的进程听起来很贵，实际上 fork 只复制页表，父子共享所有物理页面，标成只读；谁先写某一页，才真正复制那一页（写时复制，第二十七章）。fork 之后马上 exec 的话，几乎什么都不用复制。即便如此，对大进程 fork 仍有开销，所以有了一步完成“新建并运行”的 posix_spawn，macOS 上推荐用它。
