IP 地址：门牌号

网络上的每台设备都要有一个地址，包才知道送到哪儿。现在最常见的 IPv4 地址是 32 个比特，为了好读，每 8 位一组写成十进制，用点隔开：192.168.1.23 就是 11000000.10101000.00000001.00010111。32 位最多约 43 亿个地址（第一章），地球上的设备早就比这多了，怎么办？

家里的地址和路由器

有几段地址被规定为私有地址，只在家里、学校里用，不会出现在公网上，比如 192.168.x.x、10.x.x.x。你家的 Mac、手机、平板都拿到一个这样的地址，而整个家对外只有路由器上的一个公网地址。路由器替大家收发：你发出去的包，它把发件人地址换成自己的公网地址，记下“这是谁的”；回来的包再换回你的私有地址交给你。这叫地址转换（NAT）。所以全世界很多家庭的 Mac 都叫 192.168.1.x，互不冲突。

端口：哪个程序

IP 地址只送到电脑，可电脑上同时开着浏览器、聊天、游戏，这个包给谁？传输层用 端口号（0 到 65535 的一个数，16 位）区分。网页服务一般在 443 号端口（加密的 HTTPS）或 80 号（不加密的 HTTP）。“IP 地址 + 端口号”就像“小区地址 + 门牌号”。

挂号信和明信片

  • TCP：像挂号信。先打招呼建立连接（三次握手：“我想和你说话”“好，我也想和你说话”“好，那开始”），每个包编号，对方收到要回确认，没回就重发，最后按编号排好交给程序。保证不丢、不重复、按顺序，代价是慢一点。网页、文件、聊天消息都用它。
  • UDP：像明信片。不打招呼、不编号、不确认，丢了就丢了，但快、开销小。视频通话、网络游戏的实时位置用它：晚到的旧画面不如直接丢掉。

DNS：电话簿

人记得住 www.apple.com，记不住一串数字。DNS（域名系统）负责把名字查成 IP 地址。你的电脑先问家里的路由器或运营商的 DNS 服务器；它要是不知道，就从最上面的“根”服务器问起：“.com 归谁管？”，再问 .com 的服务器：“apple.com 归谁管？”，再问 apple.com 的服务器：“www.apple.com 的地址是多少？”。查到的结果会被各处缓存一段时间，下次就快了。

查地址、查电话簿、看连接15 分钟
% networksetup -getinfo Wi-Fi
% dig +short www.apple.com
% dig www.apple.com
% lsof -i -P -n | grep ESTABLISHED | head

第一行显示你的 Mac 在家里的 IP 地址、子网掩码和路由器地址（如果你用的是网线，把 Wi-Fi 换成 Ethernet）。dig +short 只打结果，不带 +short 会打出完整的问答，“ANSWER SECTION”里还能看到 CNAME（别名）和 TTL（这条结果可以缓存几秒）。最后一行列出你的 Mac 现在开着的网络连接，每一行有“本机地址:端口 -> 对方地址:端口”，很多对方端口是 443。

把 IP 写成二进制

把你 Mac 的 IP 地址和子网掩码（多半是 255.255.255.0）都写成 32 位二进制，上下对齐，做一次按位与（第七章）。得到的结果就是你家网络的“网络号”，和路由器地址的网络号一样吗？第二层会用这个办法判断两台电脑在不在同一个网络里。

子网和 CIDR

IP 地址分两部分：前面的网络号和后面的主机号。早年按首几位分成 A、B、C 类（网络号固定 8、16、24 位），太浪费，现在用 CIDR（无分类域间路由）：写成 192.168.1.0/24，“/24”表示前 24 位是网络号。对应的子网掩码是前 24 位全 1：255.255.255.0。用 IP 和掩码按位与就得到网络号；两台主机的网络号相同，才能直接通信，否则要交给路由器（默认网关）。

  • 网络地址：主机号全 0；广播地址：主机号全 1；两者都不能分给主机，所以 /n 的网络可用主机数为 232−n − 2。
  • 子网划分：从主机号借几位作子网号。/24 借 2 位得到 4 个 /26 子网，每个 62 台主机。
  • 路由聚合：几个连续的网络找出最长公共前缀，合并成一条路由；路由器转发时按最长前缀匹配。
  • ARP：同一个网络里，知道对方 IP 不够，链路层要 MAC 地址（第三十章）。ARP 广播问“谁是 192.168.1.1？”，主人回答自己的 MAC。终端里 arp -a 能看到缓存的对照表。

TCP

TCP 首部至少 20 字节：源端口、目的端口、序号（本报文段数据第一个字节的编号）、确认号（期望收到对方下一个字节的编号，即“这之前的我都收到了”）、首部长度、标志位（SYN、ACK、FIN、RST 等）、窗口（我还能收多少字节）、校验和。

  • 三次握手：客户端 SYN（seq = x）→ 服务器 SYN + ACK（seq = y，ack = x + 1）→ 客户端 ACK（seq = x + 1，ack = y + 1）。为什么要三次：双方都要确认对方能收也能发，并交换各自的初始序号；两次的话，一个迟到的旧 SYN 可能让服务器白白建立连接。SYN 和 FIN 虽然不带数据，也要消耗一个序号。
  • 四次挥手：A 发 FIN → B 回 ACK（此时 B 还可以继续发数据，叫半关闭）→ B 发完了也发 FIN → A 回 ACK，然后等 2MSL（报文最长寿命的两倍）才真正关闭（TIME_WAIT），以防最后的 ACK 丢了 B 重发 FIN 时没人应，也让旧连接的迟到报文在网络里消失。
  • 可靠传输：超时重传；累计确认；滑动窗口：不必每发一个就等确认，可以连续发出窗口允许的量（第十五章的流水线思想），窗口大小 = min(接收方通告的窗口, 拥塞窗口)。
  • 拥塞控制（408 必考）：慢开始，拥塞窗口 cwnd 从 1 个最大报文段开始，每经过一个 RTT 翻倍，到达门限 ssthresh 后进入拥塞避免，每个 RTT 只加 1；出现超时，ssthresh 设为当前 cwnd 的一半，cwnd 回到 1 重新慢开始；收到 3 个重复确认，快重传（不等超时立刻重发丢的那个），并快恢复：ssthresh 设为 cwnd 的一半，cwnd 设为新的 ssthresh，直接进入拥塞避免。

UDP 首部只有 8 字节（源端口、目的端口、长度、校验和），无连接、不可靠、没有拥塞控制。DNS 查询一般用 UDP 的 53 号端口；主机向本地 DNS 服务器的查询通常是递归的（“你帮我查到底”），本地服务器向根、顶级域、权威服务器的查询通常是迭代的（“我不知道，你去问它”）。

握手和挥手

一步一步看一次 TCP 连接的一生：三次握手、发一段数据、四次挥手。注意每一步的序号和确认号是怎样算出来的。

典型题 · 原创

（1）某主机的 IP 为 172.20.45.77/20，求网络地址、广播地址和可用主机数。（2）把 202.118.32.0/24 划分成 6 个子网，每个子网主机尽量多，子网前缀多长？每个子网可用多少主机？（3）TCP 连接中，拥塞窗口为 1 时开始慢开始，ssthresh = 16（单位：报文段），第 6 个 RTT 结束时发生超时。写出前 8 个 RTT 开始时的 cwnd。

看解答

（1）/20 的掩码是 255.255.240.0。45 = 0010 1101，与 1111 0000 得 0010 0000 = 32，网络地址 172.20.32.0；广播地址把后 12 位全置 1：172.20.47.255；可用主机 212 − 2 = 4094。

（2）6 个子网至少要借 3 位（23 = 8 ≥ 6），前缀 /27，每个子网 25 − 2 = 30 台主机。

（3）第 1 到 5 个 RTT 开始时：1、2、4、8、16（到达门限）；第 6 个：17（拥塞避免，加 1）；第 6 个 RTT 结束时超时，ssthresh = ⌊17 / 2⌋ = 8，cwnd = 1；第 7 个：1；第 8 个：2。

面试题

TCP 为什么是三次握手、四次挥手？TIME_WAIT 有什么用？

看要点

握手要让双方都确认“对方能收到我的、我能收到对方的”，并同步各自的初始序号；第二次把服务器的 SYN 和对客户端的 ACK 合在一起，所以是三次；也防止历史连接请求引起错误。挥手是因为 TCP 是全双工的，两个方向要分别关闭：收到 FIN 只说明对方不再发，自己可能还有数据要发，ACK 和 FIN 往往不能合并，所以是四次。TIME_WAIT 等 2MSL：保证最后一个 ACK 能被重传（若对方没收到会重发 FIN），并让本连接的旧报文在网络中消失，不干扰之后同一对端口的新连接。

/26 的子网掩码是？

最后 8 位里前 2 位为 1：11000000 = 192。

/26 的子网有多少可用主机地址？

26 − 2。

客户端发 SYN，seq = 1000。服务器回的 SYN + ACK 里，ack 是多少？

SYN 消耗一个序号：1000 + 1。

收到 3 个重复确认时，TCP 会？

  1. cwnd 回到 1
  2. 快重传，并快恢复
  3. 断开连接

超时才回到 1。

同一网络里通过 IP 找 MAC 地址的协议是？

  1. DNS
  2. NAT
  3. ARP

IPv6

IPv4 地址不够用，1990 年代就设计了 IPv6：128 位地址，写成 8 组十六进制，如 2001:db8::1（连续的零可以用 :: 省略）。地址多到可以给每台设备一个全球唯一的地址，不再需要 NAT。普及走了二十多年，至今仍和 IPv4 并存；networksetup -getinfo Wi-Fi 的输出里可能就有你的 IPv6 地址。

那把锁：TLS

TCP 只保证不丢、按顺序，不保证别人看不见、改不了。浏览器地址栏的锁表示这个连接用了 TLS：握手时服务器出示由可信机构签名的证书证明“我真的是 apple.com”，双方用公钥密码协商出一把只有它们知道的密钥，之后所有数据加密传输，还带校验防篡改。HTTPS 就是“HTTP 跑在 TLS 上”。下一章的 curl -v 能看到这段握手。

QUIC 和 HTTP/3

TCP 有两个老毛病：建立连接再加 TLS 握手要好几个来回；一个包丢了，后面所有数据都得等它（队头阻塞）。谷歌提出、后来标准化的 QUIC 干脆在 UDP 上重新实现可靠传输、拥塞控制和加密，握手合并成一两个来回，多条数据流互不阻塞，手机从 Wi-Fi 切到蜂窝网络连接也不断。HTTP/3 就跑在 QUIC 上。这是第三十章“端到端原则”的又一个例子：新功能做在两端，中间的网络不用改。

互联网也会“迷路”

各大网络之间用 BGP 协议互相宣告“哪些地址可以从我这儿走”。2021 年 10 月，一家大型社交网络公司在一次配置变更中，意外撤回了自己网络的路由宣告，它的 DNS 服务器随之从互联网上“消失”，旗下几个应用全球中断约六个小时，据报道员工连门禁卡都刷不开。DNS、BGP 这些底层系统平时没人注意，一出错就是全世界的大事。
