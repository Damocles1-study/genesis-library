按下回车以后

一步一步走。左边的五层楼会亮出这一步在哪层楼（“楼外”是网络），右边说发生了什么、是哪一章讲的。点章名可以跳回去复习。

这一切，通常在一两秒之内完成。最快的一步（一次加法）不到一纳秒，最慢的一步（跨越大洋的往返）要一百多毫秒，相差一亿倍以上；整个过程里，比特被翻译了无数次：按键码、字符、数据包、电压、光、无线电、HTML、像素。这就是“抽象”的力量：每一层只管自己的事，合起来却完成了一件谁也说不全的复杂事情。

用 curl 走一遍10 分钟
% curl -v -o /dev/null https://www.apple.com 2>&1 | head -40

curl 是一个不画网页的“浏览器”，-v 让它把过程都说出来，-o /dev/null 把网页内容扔掉。你会依次看到：解析域名得到的 IP 地址（第三十一章）、连接 443 端口（TCP 握手）、TLS 握手和服务器证书的名字（第三十一章第三层）、以 > 开头的请求（GET / HTTP/2 和一串首部）、以 < 开头的回复（状态码 200 或 301、内容类型、长度）。再试试 curl -w '%{time_namelookup} %{time_connect} %{time_appconnect} %{time_total}\n' -o /dev/null -s https://www.apple.com，看查 DNS、TCP 连接、TLS 握手、整个下载各用了多少秒。

一道题，四门课

“从在浏览器输入网址到页面显示，发生了什么？”几乎是每个后端、前端、系统岗位面试都会问的题。好的回答先给一个清楚的骨架，再看面试官的兴趣往某一步深挖：

  1. 输入和解析：键盘中断 → 浏览器进程收到事件；解析 URL（协议、域名、端口、路径），检查 HSTS、缓存。可展开：中断处理（第二十五章）、进程和线程（第二十六章）、字符编码（第五章）。
  2. DNS 解析：浏览器缓存 → 系统缓存 → 本地 DNS 服务器（递归）→ 根、顶级域、权威服务器（迭代）；UDP 53。可展开：第三十一章。
  3. 建立连接：socket、connect 系统调用；TCP 三次握手；TLS 握手（证书验证、密钥协商）；HTTP/3 则是 QUIC。可展开：拥塞控制、TIME_WAIT。
  4. 发送请求和传输：HTTP 请求报文 → 逐层封装 → 路由（最长前缀匹配）、ARP、NAT → 物理层编码。可展开：第三十章的时延计算、第八章的 CRC、第六章的奈奎斯特和香农。
  5. 服务器处理：负载均衡 → 服务器进程（线程池、并发和锁）→ 读文件或数据库（文件系统、页缓存）→ 生成响应。可展开：第二十六至二十九章。
  6. 接收和渲染：解析 HTML、CSS，构建 DOM 和渲染树，执行 JavaScript（解释和即时编译，W^X），布局、绘制、合成，GPU 写入帧缓冲，显示器刷新。可展开：内存分配（第二十一章）、虚拟内存（第二十七章）、指令和流水线（第十四、十五章）、缓存（第十六章）、像素和显存带宽（第六章）。

第三层 · 深入时间花在哪里，往下读什么约 20 分钟一次网页访问的时间账；为什么工程师总在和“往返”较劲；这套书之外的经典读物和公开课。

时间账

一次打开网页的时间，处理器算东西的部分通常只占很小的一块，大头在等：等 DNS、等 TCP 握手、等 TLS 握手、等服务器、等数据一包一包地到。每一次往返都要几十毫秒，所以现代网络技术的很多发明都在“省往返”：DNS 缓存、连接复用（一个 TCP 连接发很多请求）、TLS 1.3 把握手从两个往返减到一个、QUIC 把 TCP 和 TLS 的握手合并、内容分发网络（CDN）把服务器搬到离你近的城市。第十六章说“缓存让手边的小抽屉够用”，在网络上是同一个道理，只是“抽屉”变成了遍布世界的服务器。从晶体管到洲际光缆，计算机系统设计的大部分工作，都是在不同的层次上对付“远”和“慢”。
