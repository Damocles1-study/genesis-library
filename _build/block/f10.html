一句长长的命令

execute 是“执行”。它后面可以接好几段，每一段改一件事，最后用 run 接一条真正要做的命令：

那一段改了什么像英文句子里的
as @e[type=pig]以谁的身份：后面的 @s 变成每一头猪as：作为
at @s在哪儿：后面的 ~ 变成那个实体的位置at：在
positioned 0 -60 0换一个位置positioned：放在
if …如果条件成立，才往下走if：如果
unless …除非：条件不成立，才往下走unless：除非
run …就做这件事run：运行

几个例子，每个都先读成一句话：

  • /execute at @e[type=pig] run setblock ~ ~-1 ~ gold_block
    “在每一头猪那儿，都把它脚下那一块换成金块。”
  • /execute as @a at @s run summon chicken ~ ~3 ~
    “作为每一个玩家，在他自己那儿，在头顶三格召唤一只鸡。”
  • /execute if entity @e[type=zombie,distance=..8] run say 小心！
    “如果 8 格以内有僵尸，就喊‘小心！’”
  • /execute unless entity @e[type=zombie] run say 安全了
    “除非有僵尸……也就是：一只僵尸都没有，就喊‘安全了’。”
  • /execute if score @s coins matches 10.. run say 我有十个金币了
    “如果我的金币大于等于 10，就喊一声。”
  • /execute if block ~ ~-1 ~ gold_block run effect give @s speed 5
    “如果我脚下是金块，就给我 5 秒速度。”
if：程序会“选路”了以后学 · 编程的第二个核心

上一章的变量让程序“记住”东西；这一章的 if 让程序会根据情况选不同的路。几乎所有的游戏、App、机器人，都是由这两样（加上下一节的“循环”）搭起来的。同一件事，用 Python 写是这样：

if coins >= 10:
    print("我有十个金币了")

if 后面的那个条件，算出来只有两种结果：成立（true）或不成立（false）——第四十四章的布尔值。unless 就是 “if not”。

if 和 unless 的英文句子

“If it rains, I will stay at home.”（如果下雨，我就待在家。）“I will go out unless it rains.”（我会出门，除非下雨。）两句说的是一回事，一个从“会发生”说起，一个从“不会发生”说起。execute 也是这样：if 和 unless 正好相反。

三种命令方块

第十五章认识了命令方块（/give @p command_block 拿到）。右键打开它，左上角的按钮能换三种类型：

类型颜色什么时候执行编程里像
脉冲型橙色收到一次红石信号，执行一次按一下按钮，做一件事
连锁型绿色前面那个命令方块执行完，接着执行一行接一行
循环型紫色每一刻都执行一次（一秒 20 次）一直转的循环

循环型命令方块要设成“始终活动”（不需要红石），它才会一直转。连锁型命令方块要摆在循环型的箭头指向的地方，一个接一个排成一串，形成一个每刻都跑一遍的“小程序”。

还有一个“条件制约”选项：打开它，这个方块只在前一个方块执行成功时才执行。这也是一种 if。

项目：三十秒倒计时

想法是：用一个变量 time 记住“还剩几刻”。开始时设成 600（30 秒 × 20 刻，第四十三章算过）；循环型命令方块每一刻把它减 1；减到 1 的时候喊“时间到”。再用除法算出“还剩几秒”显示在右边栏。

准备（在聊天框里打一次就行）：

/scoreboard objectives add time dummy "剩余刻"
/scoreboard objectives add sec dummy "剩余秒"
/scoreboard objectives add const dummy
/scoreboard players set #20 const 20
/scoreboard objectives setdisplay sidebar sec

开始按钮：一个脉冲型命令方块 + 一个按钮，里面写：

scoreboard players set @p time 600

每一刻要做的事：一个循环型（始终活动）后面接三个连锁型，依次写：

execute if score @p time matches 1 run title @p title "时间到"
execute if score @p time matches 1.. run scoreboard players remove @p time 1
scoreboard players operation @p sec = @p time
scoreboard players operation @p sec /= #20 const

读一读这四行：如果只剩 1 刻，就打出大字“时间到”；如果还剩 1 刻以上，就减 1；把 time 抄给 sec；sec 除以 20，变成秒。为什么喊“时间到”要放在第一行？想一想：如果先减，time 从 1 变成 0，第一行就永远等不到“正好是 1”了。顺序很要紧，这也是编程最常出错的地方之一。

这一次练习台多了一个紫色框：它就是循环型命令方块，每走一刻，就把框里每一行执行一遍（你可以改里面的命令）。准备那几行已经替你打好了。先在黑框里打开始的命令，再点“走 1 秒”“走 10 秒”看右边栏怎么变。地图上的猪是给 execute at 练习用的。

做不出来很正常。照第四十章的办法：读报错、一样一样排除、记下来。做出来了，你就写了人生第一个“程序”。

出错了怎么办
循环型命令方块不动
没有设成“始终活动”，或者旁边没有红石信号。
时间一下子没了
两个循环型命令方块都在减，或者忘了 matches 1..，减成了负数。
“时间到”一直在喊
条件写成了 matches ..1（小于等于 1），time 停在 0 时每一刻都成立。
@p 选错了人
命令方块里的 @p 是离命令方块最近的玩家。

execute at @e[type=pig] run setblock ~ ~-1 ~ gold_block 做了什么？

  1. 在你脚下放一块金块
  2. 在每一头猪的脚下放一块金块
  3. 把猪变成金块

at 把位置换成每一头猪的位置，~ 就从猪那儿算。

“一只僵尸都没有，就说安全了”，用哪个？

  1. execute if entity @e[type=zombie] run say 安全了
  2. execute as @e[type=zombie] run say 安全了
  3. execute unless entity @e[type=zombie] run say 安全了

unless：条件不成立才执行。没有僵尸，“有僵尸”就不成立。

哪种命令方块每一刻都执行？

  1. 循环型（紫色）
  2. 脉冲型（橙色）
  3. 连锁型（绿色）

循环型，一秒 20 次。

倒计时 30 秒，time 一开始要设成多少刻？

30 × 20 = 600。

time 是 599 的时候，sec = time ÷ 20（只留商）是多少？

599 ÷ 20 = 29 余 19，只留商 29。

为什么“喊时间到”那一行要放在“减 1”那一行前面？

  1. 放哪儿都一样
  2. 如果先减，time 从 1 变成 0，后面的“等于 1”就永远等不到了
  3. 因为命令方块只能读第一行

同一刻里，命令按顺序执行。顺序变了，结果就变了。

给大人

/execute 的子命令（as、at、positioned、if/unless entity/block/score、run 等）与命令方块的三种类型、“始终活动”“条件制约”，见社区维基“/execute”“命令方块”条目。计时器的写法是常见做法之一（也可以用数据包的 tick 函数，第二十五章）。命令方块在单人世界开作弊即可用；服务器需要 enable-command-block。

第四十八到五十章，其实就是编程入门的三件事：筛选数据、变量、条件和循环。孩子做出倒计时以后，可以请他用自己的话讲一遍“每一刻发生了什么”，能讲清楚，就真的懂了。
