真的虫子

程序里的错误，英文叫 bug（虫子），找错叫 debug（除虫）。有一个著名的故事：1947 年，美国哈佛大学的一台马克二号电脑出了故障，工作人员在一个继电器里发现了一只飞蛾，把它粘在了工作日志上，旁边写着“第一次找到真的虫子”。这张日志现在还保存在美国的博物馆里。电脑先驱格蕾丝·霍珀（第四部讲过她）很爱讲这个故事。其实 bug 这个说法在那以前就有了，这只飞蛾只是让它变得有名。

读懂报错

File "main.py", line 3
TypeError: can only concatenate str (not "int") to str
  • 第一行：在哪儿。line 3，第 3 行。先去看那一行（有时候错在它的上一行）。
  • 第二行冒号前：什么错。TypeError，类型错误。
  • 冒号后：为什么。只能把字符串和字符串拼起来，不能拼一个 int。

英文看不懂？抄下关键的几个词，查一查，或者在大人陪着时问 AI（第四十章）。小蟒还会在下面加一句中文解释。

报错一般是因为先查什么
SyntaxError写法错了冒号、括号、引号配对；有没有中文标点
IndentationError缩进不对冒号下面缩进了没有；同一层对齐了没有
NameError名字没定义拼写、大小写；是不是在定义之前就用了
TypeError类型不对数和字相加；函数给的参数个数不对
IndexError下标超出范围是不是忘了从 0 数；循环多走了一圈
KeyError字典里没有这个键键拼对了吗；用 .get 试试
ZeroDivisionError除以 0除数是从哪来的，会不会是 0

最难的错，是不报错、但结果不对的错。比如本该加 100 次却加了 99 次（第四十一章的“差一错误”）。这时候要用下面的办法。

四个找错的办法

  1. 偷看：在怀疑的地方加一行 print("这里", x)，看看变量到底是多少。或者用小蟒的“一步一步”。
  2. 砍一半：程序很长、不知道错在哪？把后一半先注释掉（行首加 #），看前一半对不对。对，错就在后一半；不对，错在前一半。再砍一半……第七十九章的二分查找，用来找错也一样好用。
  3. 最小的例子：把问题缩到最小：一大段程序里出错，就新写三行只做那一件事，看能不能重现。
  4. 讲给鸭子听：第四十章的小黄鸭，一行一行讲“这一行在干什么”，讲到不对的地方，你自己就会停住。

我的错题本

记在这台电脑的浏览器里，只有你看得到。可以记编程的错，也可以记数学、英语、游戏里的错。

报错写着 NameError: name 'Coins' is not defined，可是你明明写了 coins = 10。最可能是？

  1. 电脑坏了
  2. 10 太大
  3. 大小写不一样：Coins 和 coins

名字大小写不同就是两个名字。

一段 100 行的程序结果不对，又不报错，用什么办法最快缩小范围？

  1. 砍一半：先看前 50 行的结果对不对
  2. 从头重写
  3. 一行一行删

像二分查找一样找虫子。

“找错、除虫”的英文是哪个词？

debug。

报错的第一行 line 7 告诉你什么？

  1. 一共有 7 个错
  2. 错误在第 7 行附近
  3. 要等 7 秒

先去看第 7 行，有时候错在它上一行。
