东西怎样摆

你有 100 张卡片，每张上写着一个同学的名字。现在要找“王小明”。

  • 卡片乱放在一个盒子里：只能一张一张翻，运气不好要翻 100 张。
  • 卡片按名字排好了：可以从中间翻开，看看王小明在前面还是后面，再翻一半……七八次就找到了。
  • 卡片按姓分进了不同的小格子：直接打开“王”那一格，里面只有几张。

东西一样多，摆法不一样，找起来就差很多。东西在电脑里怎样摆，叫数据结构。

怎样一步一步地找、一步一步地排，叫算法。算法就像菜谱：先做什么，再做什么，做到哪儿停。

摆法和做法是一对：摆法选对了，做法就简单；摆法选错了，再聪明的做法也快不起来。这本书讲的就是常用的摆法和做法。

小蟒里的列表

在《一块一块》第七十六章里，你用列表存过快捷栏，还用“列表里装列表”画过一块地。方格岛就是这样存的：一行是一个列表，十行装进一个大列表。

格子的门牌号

地图存成“列表的列表”：grid 里有 10 行，每一行是一个有 16 格的列表。要找第 3 行第 7 列，写 grid[3][7]：先说第几行，再说第几列。

行号常常叫 y（往下数），列号叫 x（往右数），所以写成 grid[y][x]。两个号码都从 0 开始数。

容易弄反

数学课上的坐标是 (x, y)，先横后竖；可是 grid[y][x] 是先竖后横。因为 grid 先装的是“行”，要先挑出一行，才能在这一行里挑一格。

几个基本词

  • 数据：能输入电脑、被程序处理的符号的总称。
  • 数据元素：数据的基本单位，通常作为一个整体处理，比如一个学生的记录。一个数据元素可以由若干数据项组成（学号、姓名、成绩），数据项是不可分割的最小单位。
  • 数据对象：性质相同的数据元素的集合，比如全班学生的记录。
  • 数据结构：相互之间存在某种关系的数据元素的集合。它有三个方面：逻辑结构、存储结构（物理结构）、数据的运算。

逻辑结构和存储结构

逻辑结构只管“元素之间是什么关系”，和电脑无关：

逻辑结构关系本书
集合同属一个集合，别无关系散列表、并查集
线性结构一对一：除了头尾，每个元素前后各一个第一部：数组、链表、栈、队列、串
树形结构一对多：一个上级，多个下级第二部
图状结构（网状结构）多对多第三部

存储结构是逻辑结构在内存里的实现，常见四种：

  • 顺序存储：逻辑上相邻的元素，物理位置也相邻（数组）。随机存取快，插入删除要挪动元素，可能有外部碎片。
  • 链式存储：不要求物理相邻，用指针表示关系（链表）。不会有碎片，但指针占空间，只能顺序存取。
  • 索引存储：另建一张索引表（关键字 → 地址）。检索快，索引表占空间，增删要改索引。
  • 散列存储：由关键字直接算出地址（散列表）。检索、增删都快，但有冲突要处理。
常考的混淆

“有序表”是逻辑结构上的说法（元素按关键字有序），它可以顺序存储，也可以链式存储；“顺序表”是存储结构（顺序存储的线性表）。“循环队列”是用顺序表表示的队列，属于存储结构层面的概念；“栈”“队列”本身是逻辑结构（受限的线性表）。

算法

算法是对特定问题求解步骤的描述，是指令的有限序列。五个特性：

  1. 有穷性：有限步之后结束，每步在有限时间内完成。（程序可以不满足，比如操作系统一直在跑；算法必须满足。）
  2. 确定性：每条指令含义明确，相同输入得到相同输出。
  3. 可行性：每一步都能用已经实现的基本运算执行有限次完成。
  4. 输入：零个或多个。
  5. 输出：一个或多个。

一个“好”算法还要做到：正确性、可读性、健壮性（输入非法时能妥善处理）、高效率和低存储量需求。最后一条就是下一章的时间复杂度和空间复杂度。

用 C 画地图

二维数组15 分钟
#include <stdio.h>
#define W 16
#define H 10
static const char *ISLAND[H] = {
    "~~~~~~~~~~~~~~~~", "~~....TT..::~~~~", "~...T.....:::~~~",
    "~..##..@...::~~~", "~..###......~~~~", "~~..~~~.....T.~~",
    "~~..~~~..T....~~", "~~~.......##..~~", "~~~~~::....~~~~~",
    "~~~~~~~~~~~~~~~~"
};
char grid[H][W];

int main(void) {
    for (int y = 0; y < H; y++)
        for (int x = 0; x < W; x++)
            grid[y][x] = ISLAND[y][x];
    printf("grid[3][7] = %c\n", grid[3][7]);
    printf("&grid[3][7] - &grid[0][0] = %td\n", &grid[3][7] - &grid[0][0]);
    for (int y = 0; y < H; y++) printf("%.*s\n", W, grid[y]);
    return 0;
}
% clang -Wall -O1 island.c -o island && ./island

第二行打出 55：grid[3][7] 离开头正好 3 × 16 + 7 个字节。C 的二维数组按行优先连续存放，grid[y][x] 的地址是 基址 + (y × W + x) × 元素大小。第二章会细讲，它也是《地基》第十六章“按行遍历比按列快”的原因。

%.*s 打印恰好 W 个字符：每行没有结尾的 '\0'，不能直接用 %s（《地基》第十九章）。

典型题 · 原创

（1）下列说法中，属于存储结构的是：A. 栈 B. 有序表 C. 循环队列 D. 二叉树。（2）以下哪一项违反了算法的特性：A. 一个算法有 0 个输入 B. 一个算法在某组输入下永远不停 C. 一个算法有 2 个输出 D. 一个算法的某一步要调用另一个算法。

看解答

（1）C。循环队列指明了“用数组首尾相接”来存队列，是存储结构；栈、有序表、二叉树都只说了元素之间的关系，是逻辑结构。

（2）B，违反有穷性。0 个输入是允许的（比如“打印 1 到 10”）；调用别的算法只要它也有穷，整体仍然可行。

面试题

数组和链表各有什么优缺点？什么时候用哪个？

看要点

数组：连续存放，按下标 O(1) 访问，缓存友好；中间插入删除要挪动 O(n)，扩容要整体搬家。链表：插入删除只改指针 O(1)（前提是已经拿到了位置），不需要连续空间；访问第 i 个要从头走 O(n)，每个结点多占指针，缓存不友好。读多写少、按位置访问用数组；频繁在已知位置插入删除、或者元素很大不想搬动用链表。可以补一句：实际工程里动态数组（vector、Python 的 list）用得多得多，因为缓存的影响很大。第二、三章细讲。

下列属于存储结构的是？

  1. 线性表
  2. 二叉树
  3. 顺序表
  4. 图

顺序表 = 顺序存储的线性表，指明了存储方式。

  1. 确定性
  2. 有穷性

抽象数据类型

抽象数据类型（ADT）只规定一组操作和它们的含义，不规定怎样实现。“栈”这个 ADT 就是：push、pop、看栈顶、判空，后进先出。你可以用数组实现它，也可以用链表实现它，用的人不用关心。这和《地基》第零章讲的“抽象”是同一个想法：上一层只看接口，下一层管实现。

同一个 ADT 的不同实现，操作的代价不一样。“有序的字典”这个 ADT，可以用有序数组（查找 O(log n)，插入 O(n)）、平衡搜索树（都是 O(log n)）、跳表或 B+ 树实现。选哪个，看哪种操作多、数据放在内存还是磁盘。这本书反复做的，就是这种取舍。
