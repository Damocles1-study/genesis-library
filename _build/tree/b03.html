第一层 · 入门要会：二叉树（第八章）、对半猜数字（第一章）约 30 分钟

左边小，右边大

二叉搜索树是一棵守规矩的二叉树：对每一个结点，它左边那一整片都比它小，右边那一整片都比它大。

找一个数：像猜数字

从根开始比：要找的数比它小，就往左走；比它大，就往右走；一样，就找到了；走到空的地方，说明树里没有。

每走一步，就把另一边一整片都排除掉了，和第一章“对半猜”一模一样。树如果长得匀称，一百万个数也只要走二十来步。

插一个数

插入和查找走的是同一条路：一路比下去，走到空的地方，就把新数挂在那里。不用挪动任何别的数，也不用重新排序。

中序遍历：从小到大

第九章的中序遍历是“左、自己、右”。在二叉搜索树上，左边都比自己小、右边都比自己大，所以中序遍历打出来的，正好是从小到大排好的。主线第 10 步用它给方格岛做了一本按拼音排序的图鉴。

第二层 · 本科对照 408：二叉排序树（BST）约 55 分钟查找、插入的递归和非递归写法；删除的三种情况；平均查找长度 ASL 的成功和失败；查找路径的合法性；最好和最坏的复杂度。

查找和插入

typedef struct BSTNode { int key; struct BSTNode *l, *r; } BSTNode;
BSTNode *search(BSTNode *T, int k) {
    while (T && k != T->key) T = k < T->key ? T->l : T->r;
    return T;
}
int insert(BSTNode **T, int k) {          /* 传指针的指针，才能改到空位本身 */
    if (*T == NULL) { *T = malloc(sizeof(BSTNode)); (*T)->key = k; (*T)->l = (*T)->r = NULL; return 1; }
    if (k == (*T)->key) return 0;         /* 已有，不插 */
    return insert(k < (*T)->key ? &(*T)->l : &(*T)->r, k);
}

删除的三种情况

  1. 被删的是叶子：直接删。
  2. 只有一棵子树：让这棵子树顶替它的位置。
  3. 有两棵子树：用它的中序后继（右子树里最小的，即右子树最左下的结点）或中序前驱（左子树最大的）的值替换它，再去删掉那个后继（后继最多只有右子树，转成情况 1 或 2）。
删了再插回去，树还一样吗？

删除一个叶子再插回来，树不变。删除一个非叶子再插回来，它会变成叶子，树一般就变了。408 常拿这个出判断题。

平均查找长度

查找成功的 ASL = Σ（每个结点的层数）/ n（等概率）。查找失败的 ASL：把每个空指针看成一个“失败结点”（n 个结点有 n + 1 个），失败时比较的次数等于失败结点所在的层数减一（也就是它双亲的层数），ASL失败 = Σ（失败结点双亲的层数）/ (n + 1)。最好情况（树高 ⌈log₂(n+1)⌉）ASL 是 O(log n)，最坏（单支树）是 (n + 1)/2，O(n)。

典型题 · 原创

（1）依次插入 45, 24, 53, 12, 37, 93, 30 构造二叉排序树，求查找成功和失败的 ASL。（2）在一棵二叉排序树上查找 58，下列哪个不可能是比较的序列：A. 90, 30, 70, 50, 58 B. 20, 80, 40, 70, 60, 58 C. 50, 70, 60, 65, 58 D. 10, 100, 30, 80, 50, 58。

看解答

（1）树：45 为根；24 左、53 右；12 是 24 的左、37 是 24 的右；93 是 53 的右；30 是 37 的左。层数：45 第 1 层；24、53 第 2 层；12、37、93 第 3 层；30 第 4 层。成功 ASL = (1 + 2×2 + 3×3 + 4) / 7 = 18/7。失败结点 8 个：12 的两个（双亲第 3 层）、37 的右（3）、30 的两个（4）、53 的左（2）、93 的两个（3）。合计 3+3+3+4+4+2+3+3 = 25，ASL失败 = 25/8。

（2）C。走到 70 往左到 60，意味着之后的数都在 (50, 70) 中且要和 58 一致：60 > 58 往左，之后所有数都要小于 60，可下一个是 65，矛盾。检查法：每一步之后，可能的范围收窄成一个区间，后面的数必须落在区间里。

面试题

判断一棵二叉树是不是二叉搜索树。“每个结点比左孩子大、比右孩子小”够吗？

看要点

不够：要求的是整棵左子树都比它小。反例：根 10，左孩子 5，5 的右孩子 15。正确做法：① 中序遍历，检查是否严格递增，只需记住上一个值；② 递归传下界和上界，ok(node, lo, hi)，左子树用 (lo, node.key)，右子树用 (node.key, hi)。都是 O(n)。

删除有两棵子树的结点 p，通常用什么替换它？

  1. 它的左孩子
  2. 它的中序后继（或前驱）
  3. 根

后继是右子树最左下的结点，最多只有右孩子。

n 个结点的二叉排序树，最坏查找长度是？

  1. O(1)
  2. O(log n)
  3. O(n)

退化成单支树。

n = 10 个结点的二叉排序树，有几个“失败结点”（空指针）？

n + 1 = 11。

二叉排序树中，最小的关键字在哪儿？

  1. 从根一直往左走到头
  2. 某个叶子，位置不定
  3. 根

最左下；它不一定是叶子（可能有右孩子）。

第三层 · 深入随机树的高度、语言里的有序容器约 20 分钟随机顺序插入时，期望高度约 4.311 ln n；树堆用随机优先级保持平衡；C++ 的 map 和 Java 的 TreeMap 是红黑树，Python 标准库里没有，常用 bisect 或第三方的 sortedcontainers。

随机插入有多高

n 个不同的数按随机顺序插入，平均查找长度大约 2 ln n ≈ 1.39 log₂n，和完美平衡的树只差约 39%；期望高度约 4.311 ln n（里德 2003 年给出了精确的渐近结果）。所以“数据本来就乱”的时候普通搜索树表现不错，怕的是有序或接近有序的输入：而现实里的数据偏偏常常是有序的（按时间来的编号、按字母排好的名单）。

树堆

树堆（Treap）给每个结点随机发一个“优先级”，要求按关键字是搜索树、按优先级是堆（第十二章），插入后用旋转（第十一章）维持。这样不管插入顺序如何，树的形状都相当于随机插入，期望高度 O(log n)。它好写，是算法竞赛里常用的平衡树。

语言里的有序容器

C++ 的 std::map、Java 的 TreeMap 都是红黑树（下一章），能按顺序遍历、找“比 x 大的最小的数”。Python 的标准库没有搜索树：常见做法是在排好序的列表上用 bisect 二分（插入 O(n)，但 n 不太大时很快，因为挪动的是连续内存），或者用第三方库 sortedcontainers，它用“分块的有序列表”实现，实测往往比树还快。这又是第二章“连续存放格外快”的一个例子。
