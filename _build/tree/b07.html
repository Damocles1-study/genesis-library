两个问题

方格岛上，常要回答两种问题：

  • 这两块地连着吗（能不能走过去）？
  • 一共有几座岛？

第七章的油漆桶能回答：从一块地开始涂，涂得到另一块就连着。可是每挖一条沟、每搭一座桥，都要从头涂一遍。有没有办法，地形变一点，答案就跟着改一点？

每块地记着自己的队长

想象每块地是一个小朋友。连在一起的小朋友组成一队，每队有一个队长。每个小朋友手里有一张纸条，写着“我听谁的”：可能直接写着队长，也可能写着另一个小朋友，那个小朋友再写着另一个……顺着纸条一直找上去，最后找到的那个“听自己的”人，就是队长。

  • 查找：顺着纸条一直往上找，找到队长。
  • 问两块地连不连着：各找各的队长，队长是同一个人，就连着。
  • 合并（搭了一座桥，两队连起来）：各找各的队长，让其中一个队长的纸条改成写另一个队长。两队就变成了一队。

这种结构叫并查集：“并”是合并，“查”是查找。每队其实是一棵树，队长是根，纸条就是第八章说的“指向双亲”。

走捷径：路径压缩

纸条一层套一层，找队长就要走好多步。办法是：找到队长以后，顺手让路上经过的每个人都把纸条改成直接写队长。下次再找，一步就到。这叫路径压缩。

第二层 · 本科对照 408：并查集（树的应用）约 45 分钟双亲数组表示；根结点存负的集合大小；查找、合并；按大小合并让树高 ≤ log n；路径压缩；两者合用的 α(n)；判环和连通分量。

双亲数组

用第八章的双亲表示法：数组 S[i] 存结点 i 的双亲下标，根的 S[i] 为负数，绝对值是这个集合的元素个数（只存 −1 的写法也常见）。

#define N 100
int S[N];
void init(void) { for (int i = 0; i < N; i++) S[i] = -1; }
int find(int x) {                       /* 路径压缩：两遍，先找根，再把路上的都直接挂到根 */
    int root = x;
    while (S[root] >= 0) root = S[root];
    while (x != root) { int t = S[x]; S[x] = root; x = t; }
    return root;
}
void unite(int a, int b) {              /* 按大小合并：小树挂到大树下面 */
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (S[ra] > S[rb]) { int t = ra; ra = rb; rb = t; }   /* S 是负数，越小表示越大 */
    S[ra] += S[rb];
    S[rb] = ra;
}

复杂度

做法find 最坏
朴素（随便挂）O(n)：可能挂成一条链
按大小（或按秩、按高度）合并O(log n)：一个结点所在的树每变深一层，树的大小至少翻倍
按大小合并 + 路径压缩均摊 O(α(n))，实际上可看成常数

408 的题常问：按大小（或高度）合并的并查集，n 个元素时树高最多 ⌊log₂n⌋ + 1（只算根是 1 层时）。

用处

  • 连通分量个数：每条边做一次合并，最后根的个数就是分量数。
  • 判断加边是否成环：边 (u, v) 的两个端点已经在同一集合，加上就成环。第十九章的克鲁斯卡尔算法就是这样挑边的。
  • 等价类：“a 等于 b、b 等于 c”这样的关系，问 a 和 c 等不等。
典型题 · 原创

元素 0—7，初始各自成集合，用“按大小合并、大小相同时把第二个参数的根挂到第一个参数的根下面”、不做路径压缩，依次执行 unite(0,1)、unite(2,3)、unite(4,5)、unite(6,7)、unite(1,3)、unite(5,7)、unite(3,7)。最后的树高是多少？find(7) 要经过几个结点？

看解答

unite(0,1)：0 为根、1 挂在 0 下；同理 2←3、4←5、6←7。unite(1,3)：根 0 和根 2，大小都是 2，2 挂到 0 下：0 的子树 {1, 2(3)}，大小 4。unite(5,7)：4 和 6，6 挂到 4 下。unite(3,7)：find(3) = 0，find(7) = 4，大小都是 4，4 挂到 0 下。最终树：0 是根；0 的孩子 1、2、4；2 的孩子 3；4 的孩子 5、6；6 的孩子 7。树高 4（根算第 1 层），find(7) 经过 7 → 6 → 4 → 0 共 4 个结点。8 个元素，树高 = log₂8 + 1 = 4，正好达到上界。

面试题

一个社交网络有 n 个人，给出一串“某年某月 a 和 b 成为好友”的记录（按时间排好）。问最早什么时候所有人都连在一起了？

看要点

按时间顺序逐条合并，用一个计数器记录当前集合个数（初始 n，每次真正合并减一）。计数器第一次变成 1 时，就是答案。O(m α(n))。如果记录没有排序，先按时间排序 O(m log m)。

并查集的双亲数组中，根结点的 S[i] 一般存什么？

  1. 0
  2. 负数（常为集合大小的相反数）
  3. 自己的下标

负数表示“没有双亲”；也有让根指向自己的写法。

只做按大小合并、不做路径压缩，find 的最坏复杂度是？

  1. O(1)
  2. O(n)
  3. O(log n)

每变深一层，所在树的大小至少翻倍。

判断无向图加入边 (u, v) 是否成环，用并查集怎样做？

  1. 看 find(u) 是否等于 find(v)
  2. 看 u、v 的度数

已经连通，再连就成环。

10 个元素，做了 7 次真正的合并（每次都合并了两个不同的集合），还剩几个集合？

10 − 7 = 3。

同时用按秩合并和路径压缩，单次操作的均摊复杂度是？

  1. O(log n)
  2. O(α(n))，几乎是常数
  3. O(n)

α 是反阿克曼函数，增长极慢。

第三层 · 深入α(n) 和真实用途约 20 分钟塔扬 1975 年的分析：α(n) 在宇宙里的原子数那么大时也不超过 4；而且这是下界；连通区域标记、编译器的类型合一、渗流模拟。

α(n) 有多小

1975 年，塔扬证明了按秩合并加路径压缩时，m 次操作的总时间是 O(m α(n))，α 是阿克曼函数的反函数。阿克曼函数增长快得吓人，所以它的反函数增长慢得吓人：对所有能想象的 n（比宇宙里原子的个数还大很多），α(n) ≤ 4。1989 年弗雷德曼和萨克斯又证明这是下界：任何并查集都做不到真正的常数。这是“理论上不是常数、实际上就是常数”的著名例子。

真实用途

  • 图像的连通区域标记：两遍扫描像素，第一遍给相邻的同色像素合并标签，第二遍统一成根的标签。OCR、医学图像里数细胞，都这样做。
  • 编译器的类型推断：“这个变量的类型和那个变量一样”就是一次合并（合一算法）。
  • 渗流模拟：一张随机打孔的网格，什么时候从上到下连通？物理学家用并查集算临界概率（约 0.5927）。
  • 迷宫生成：从“全是墙”开始，随机拆墙，只拆两边还不连通的墙，最后正好得到一个完美迷宫（这也是第十九章最小生成树的思想）。
