段数少，不等于近

上一章的广度优先，找的是段数最少的路：每走一格都算一步，所有的步一样长。可是岛上的路有长有短：家到石山 3 步，石山到码头 9 步；家到树林 5 步，树林到沙滩 4 步，沙滩到码头 2 步。

  • 家 → 石山 → 码头：2 段，3 + 9 = 12 步。
  • 家 → 树林 → 沙滩 → 码头：3 段，5 + 4 + 2 = 11 步。

段数多的那条反而近。路有长短的时候，要换一种办法。

迪杰斯特拉的办法

1956 年，荷兰的迪杰斯特拉在阿姆斯特丹一家咖啡馆里，二十分钟想出了一个办法（这是他后来自己讲的）：

  1. 每个地方先写一个“目前知道的最短距离”：起点写 0，别的都写“不知道”（∞）。
  2. 在还没定下来的地方里，挑一个距离最小的，把它定下来：它的最短距离不会再变了。
  3. 用刚定下的这个地方，去看它的邻居：经过它走过去，是不是比邻居现在写的距离更短？更短就改掉。
  4. 重复第 2、3 步，直到所有地方都定下来。

为什么第 2 步挑出来的那个一定定得下来？因为它是剩下的里面最近的；要想绕到别的地方再回来，只会更远（前提是路都不是负的）。这就像水从起点往外流，只是流过长路慢、流过短路快：哪儿先被水淹到，哪儿就是近。

第二层 · 本科对照 408：最短路径（迪杰斯特拉、弗洛伊德）约 60 分钟dist、path、final 三个数组；O(n²) 的写法和用堆的写法；负权边的反例；弗洛伊德的三重循环和 A⁽ᵏ⁾ 矩阵；三种算法的适用范围；典型的手算题。

迪杰斯特拉

void dijkstra(int G[][N], int n, int s, int dist[], int path[]) {   /* 邻接矩阵，INF 表示无边 */
    int final[N] = {0};
    for (int i = 0; i < n; i++) { dist[i] = G[s][i]; path[i] = G[s][i] < INF ? s : -1; }
    dist[s] = 0; final[s] = 1; path[s] = -1;
    for (int k = 1; k < n; k++) {
        int u = -1;
        for (int i = 0; i < n; i++)                       /* 挑未定的最小者 */
            if (!final[i] && (u == -1 || dist[i] < dist[u])) u = i;
        if (dist[u] == INF) break;                         /* 剩下的都到不了 */
        final[u] = 1;
        for (int v = 0; v < n; v++)                        /* 用 u 松弛 */
            if (!final[v] && G[u][v] < INF && dist[u] + G[u][v] < dist[v]) { dist[v] = dist[u] + G[u][v]; path[v] = u; }
    }
}

邻接矩阵、线性扫描：O(n²)，适合稠密图。邻接表加二叉堆：每条边最多一次入堆，O((n + e) log n)，适合稀疏图。path[v] 记最短路上 v 的前驱，倒着追溯即得路径。迪杰斯特拉求的是单源最短路径；对每个顶点各做一次就得到所有顶点之间的，O(n³)。

负权边

三个顶点 A、B、C，边 A→B = 2、A→C = 3、C→B = −2。迪杰斯特拉先定下 B（距离 2），再定下 C（3）；但 A→C→B = 1 才是最短，B 已经定了改不了。只要有负权边，“最小的那个不会再变”就不成立。

弗洛伊德

求所有顶点对之间的最短路径。A⁽⁰⁾ 是邻接矩阵；第 k 轮允许路径经过前 k 个顶点作中转：A⁽ᵏ⁾[i][j] = min(A⁽ᵏ⁻¹⁾[i][j], A⁽ᵏ⁻¹⁾[i][k] + A⁽ᵏ⁻¹⁾[k][j])。

for (int k = 0; k < n; k++)              /* k 必须在最外层 */
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (A[i][k] + A[k][j] < A[i][j]) { A[i][j] = A[i][k] + A[k][j]; path[i][j] = k; }

时间 O(n³)，空间 O(n²)。允许负权边，但不允许负权回路（有负回路时最短路不存在）。代码短，n 较小时很实用。

典型题 · 原创

有向带权图，顶点 0—4，弧：0→1 (10)、0→3 (5)、1→2 (1)、3→1 (3)、3→2 (9)、3→4 (2)、4→2 (6)、2→4 (4)。（1）用迪杰斯特拉求顶点 0 到其余顶点的最短路径，写出顶点被定下的顺序和最终的 dist。（2）对下面 3 个顶点的图做弗洛伊德：A⁽⁰⁾ = [[0, 4, 11], [6, 0, 2], [3, ∞, 0]]，写出 A⁽³⁾。

看解答

（1）初始 dist = [0, 10, ∞, 5, ∞]。定 3（5）：1 → min(10, 5+3) = 8，2 → 5+9 = 14，4 → 5+2 = 7。定 4（7）：2 → min(14, 7+6) = 13。定 1（8）：2 → min(13, 8+1) = 9。定 2（9）：4 已定。顺序 0、3、4、1、2；dist = [0, 8, 9, 5, 7]。路径：到 2 是 0 → 3 → 1 → 2。

（2）k = 0（经过 0）：[2][1] = min(∞, 3 + 4) = 7。A⁽¹⁾ = [[0,4,11],[6,0,2],[3,7,0]]。k = 1（经过 1）：[0][2] = min(11, 4 + 2) = 6。A⁽²⁾ = [[0,4,6],[6,0,2],[3,7,0]]。k = 2（经过 2）：[1][0] = min(6, 2 + 3) = 5。A⁽³⁾ = [[0,4,6],[5,0,2],[3,7,0]]。

贝尔曼-福特和负环

贝尔曼-福特算法把所有边松弛 n − 1 轮，O(ne)，允许负权边；如果第 n 轮还能松弛，说明有负回路。一个有趣的用法：把各种货币之间的汇率 r 取 −log r 当边权，负回路就是一个“换一圈钱变多了”的套利机会。互联网早期的路由协议 RIP 用的就是它的分布式版本（距离向量），后来的 OSPF 在每台路由器上跑迪杰斯特拉（链路状态，《地基》第三十一章）。

A*

迪杰斯特拉朝四面八方均匀地扩，哪怕目标明明在东边。A*（1968）挑下一个点时，看的不是“离起点多远”，而是“离起点多远 + 估计还要多远”。方格地图上常用曼哈顿距离 |dx| + |dy| 当估计。只要估计从不高估真实距离（可采纳），A* 找到的就是最短路，而且看的点通常少得多。估计取 0，A* 就退化成迪杰斯特拉。游戏里怪物找路大多用它。

def astar(grid, start, goal):
    h = lambda p: abs(p[0] - goal[0]) + abs(p[1] - goal[1])   # 曼哈顿距离，从不高估
    pq, g, came = [(h(start), start)], {start: 0}, {start: None}
    while pq:
        f, cur = heapq.heappop(pq)
        if cur == goal: break
        for nb in grid_neighbors(grid, *cur):
            ng = g[cur] + COST[grid[nb[1]][nb[0]]]
            if nb not in g or ng < g[nb]:
                g[nb], came[nb] = ng, cur
                heapq.heappush(pq, (ng + h(nb), nb))
    return g.get(goal), came

导航软件

一个国家的路网有几千万个路口，每次查询都跑迪杰斯特拉太慢。现代导航用“收缩层次”（contraction hierarchies）等预处理：事先把不重要的路口“收缩”掉、加上捷径边，查询时只在很小的图上搜索，毫秒级出结果；再叠加实时路况修改边权。
