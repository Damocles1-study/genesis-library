谁要等谁

造小屋要石砖、木板和灯；灯要玻璃和木棍；玻璃要沙子……把每一样东西画成一个点，从“材料”向“用它造出来的东西”画一个箭头：沙 → 玻璃 → 灯 → 小屋。箭头的意思是：箭头尾巴上的做好了，箭头那头的才能做。

这是一张有向图。我们要排出一个顺序，让每一样东西都排在它的所有材料后面。这叫拓扑排序。

每次挑一个“不用再等”的

给每样东西数一数“还差几样材料”（有几个箭头指着它）：

  1. 找出所有“还差 0 样”的：它们现在就能做（挖来的原料木、沙、石就是）。
  2. 做一样，排进顺序里。它做好了，用它的那些东西就“少差了一样”：把它们的数减 1。
  3. 有谁变成 0 了，就加进“现在就能做”的队伍。
  4. 重复，直到全部排完。

排出来的顺序可能不止一种：木、沙、石谁先挖都行。只要每样都排在材料后面，就是对的。

有圈就排不出来

要是配方写错了：木头要用木棍造，木棍又要用木头造。木头等木棍，木棍等木头，谁也等不到对方，永远排不出来。在图上，这就是一个圈。所以拓扑排序还能用来检查：排到最后，还有东西没排进去，就说明有圈。

第二层 · 本科对照 408：拓扑排序、关键路径约 60 分钟AOV 网；用入度和队列（或栈）的拓扑排序 O(n + e)；DFS 逆后序；唯一性和判环；AOE 网的 ve、vl、e、l、余量；关键路径和关键活动；缩短工期的注意事项。

拓扑排序

用顶点表示活动、有向边表示“前后关系”的 DAG（有向无环图）叫 AOV 网。

int topo(Graph *G, int order[]) {
    int indeg[MAXV] = {0}, S[MAXV], top = -1, cnt = 0;
    for (int v = 0; v < G->n; v++)
        for (ArcNode *p = G->adj[v].first; p; p = p->next) indeg[p->to]++;
    for (int v = 0; v < G->n; v++) if (indeg[v] == 0) S[++top] = v;   /* 用栈或队列都行 */
    while (top >= 0) {
        int v = S[top--]; order[cnt++] = v;
        for (ArcNode *p = G->adj[v].first; p; p = p->next)
            if (--indeg[p->to] == 0) S[++top] = p->to;
    }
    return cnt == G->n;          /* 输出的顶点数小于 n：有回路 */
}
  • 复杂度：邻接表 O(n + e)，邻接矩阵 O(n²)。
  • 另一种求法：DFS，按顶点“完成”的先后记下，再逆序输出（逆后序）就是拓扑序列。
  • 拓扑序列唯一的充分条件：每一步入度为 0 的顶点都只有一个（此时序列是一条哈密顿路径）。注意：拓扑序列唯一，不能推出图是一条链（比如 a→b、a→c、b→c 序列唯一但不是链）。
  • 若有向图的邻接矩阵是三角矩阵（主对角线以下全是 0），则一定存在拓扑序列；反之，存在拓扑序列的图，适当编号后邻接矩阵可以是三角矩阵。

关键路径

用边表示活动、边的权表示活动持续时间、顶点表示事件（“某些活动已经完成”）的带权 DAG 叫 AOE 网。只有一个入度为 0 的源点（开工）和一个出度为 0 的汇点（完工）。从源点到汇点的最长路径叫关键路径，它的长度就是完成整个工程的最短时间；关键路径上的活动叫关键活动，拖一天，整个工程就拖一天。

  1. 事件的最早发生时间 ve：按拓扑序，ve(源) = 0，ve(k) = max{ve(j) + 活动 j→k 的时间}。
  2. 事件的最迟发生时间 vl：按逆拓扑序，vl(汇) = ve(汇)，vl(k) = min{vl(j) − 活动 k→j 的时间}。
  3. 活动 a = (k → j) 的最早开始 e(a) = ve(k)，最迟开始 l(a) = vl(j) − 时间。
  4. 余量 d(a) = l(a) − e(a)。d = 0 的就是关键活动。
典型题 · 原创

方格岛上盖一间房，AOE 网有事件 v1—v6，活动：a1 = v1→v2（4 天）、a2 = v1→v3（3）、a3 = v2→v4（2）、a4 = v3→v4（4）、a5 = v2→v5（3）、a6 = v4→v6（3）、a7 = v5→v6（5）。求各事件的 ve、vl，各活动的余量，关键路径和工期。若把 a4 缩短 1 天，工期变吗？

看解答

ve：v1 = 0，v2 = 4，v3 = 3，v4 = max(4 + 2, 3 + 4) = 7，v5 = 4 + 3 = 7，v6 = max(7 + 3, 7 + 5) = 12。

vl：v6 = 12，v5 = 12 − 5 = 7，v4 = 12 − 3 = 9，v3 = 9 − 4 = 5，v2 = min(9 − 2, 7 − 3) = 4，v1 = min(4 − 4, 5 − 3) = 0。

余量 l − e：a1 0 − 0 = 0；a2 2 − 0 = 2；a3 7 − 4 = 3；a4 5 − 3 = 2；a5 4 − 4 = 0；a6 9 − 7 = 2；a7 7 − 7 = 0。关键活动 a1、a5、a7，关键路径 v1 → v2 → v5 → v6，工期 12 天。a4 不是关键活动，缩短它工期不变。

缩短关键活动不一定缩短工期

网里可能有好几条关键路径。缩短某个关键活动，只有它在所有关键路径上时才一定能缩短工期；缩得太多，它还可能变成非关键活动，关键路径换成了别的。

面试题

课程表：有 n 门课和若干“先修”关系，问能否修完所有课；能的话给出一个顺序。

看要点

建有向图（先修课 → 后续课），做拓扑排序：能排完 n 门就可以，序列就是修课顺序；排不完说明有环。O(n + e)。追问“最少要几个学期（每学期课数不限）”：就是 DAG 上的最长路径（以顶点数计），按拓扑序做一遍动态规划（第二十二章），也就是关键路径的思路。

第三层 · 深入真实世界的依赖约 15 分钟make 和构建系统；包管理器解依赖；电子表格按依赖重算；康 1962 年的算法和计划评审技术。

到处都是依赖图

  • 构建系统：make 读取“目标依赖哪些文件”（《地基》第二十二章的 Makefile），按拓扑序编译，只重编译那些依赖变了的；还能把没有先后关系的任务并行做。
  • 包管理器：pip、Homebrew 安装一个包之前，要先装好它依赖的包；版本约束让问题变得难得多（一般情况下是 NP 完全的，所以真实的包管理器要用 SAT 求解器之类的办法）。
  • 电子表格：A1 = B1 + C1，改了 B1，A1 要重算；表格软件维护单元格之间的依赖图，按拓扑序重算，发现循环引用就报错。

来历

入度加队列的拓扑排序常归功于康（A. B. Kahn）1962 年的论文。关键路径法（CPM）和计划评审技术（PERT）在 1950 年代末由杜邦公司和美国海军的北极星导弹项目分别发展出来，用来管理成千上万项任务的工程。
