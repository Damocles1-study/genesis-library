第一层 · 入门要会：递归（第七章）约 35 分钟

拣眼前最好的

商店找零钱，要找 18 元，硬币有 10 元、5 元、1 元。售货员会先拿一个最大的 10 元，还差 8 元；再拿最大的 5 元，还差 3 元；再拿三个 1 元。一共 5 个硬币，这就是最少的。

每一步都拣眼前看起来最好的那个，不回头、不反悔，这种想办法的套路叫贪心。前面已经见过好几次：哈夫曼每次合并最小的两个，迪杰斯特拉每次定下最近的，克鲁斯卡尔每次挑最短的路。它们都是对的。

贪心也会上当

换一套硬币：4 元、3 元、1 元，找 6 元。贪心先拿 4 元，还差 2 元，再拿两个 1 元：3 个硬币。可是两个 3 元只要 2 个！

背包也是：背包最多 8 斤，船桨 5 斤、有用程度 10；镐 4 斤、7；灯 4 斤、7；还有几样小零碎。贪心先拿“每斤最有用”的船桨，剩下 3 斤只能装零碎，一共 13；可是镐加灯正好 8 斤，一共 14。

贪心又快又简单，但它只看眼前。用之前要想清楚：眼前最好的，会不会把以后更好的路堵死了？

回溯：每条路都试一试

怎样才能保证找到最好的？笨办法是把所有可能都试一遍。可以像走迷宫一样有条理地试：

  • 第一样东西，先试“拿”，再往下想第二样；
  • 第二样，也先试“拿”……装不下了，就退回来，改成“不拿”，再往下试；
  • 每试完一种完整的装法，就和目前最好的比一比。

这种“往前试，走不通就退回上一步换一条路”的办法叫回溯。它和第十七章的深度优先是一回事：只是走的不是地图，而是“每样拿不拿”组成的一棵选择树。它一定能找到最好的，代价是可能要试很多很多次：六样东西就有 2⁶ = 64 种装法，三十样就有十亿多种。

聪明一点的回溯会剪枝：某条路已经装不下了，或者就算后面全拿也比不过目前最好的，就别再往下试了。

贪心什么时候对

一个问题能用贪心，通常要满足两条：

  1. 贪心选择性质：总存在一个最优解，它的第一步就是贪心的那个选择。
  2. 最优子结构：做出这一步以后，剩下的问题仍是同类问题，且原问题的最优解包含子问题的最优解。

证明第一条最常用交换论证：拿一个任意的最优解，把它的第一步换成贪心的选择，证明结果不会变差。

活动安排

一个场地，n 个活动各有开始和结束时间，互相重叠的不能都安排，最多安排几个？贪心：按结束时间从早到晚排序，能放就放。证明：设最优解里最早结束的活动是 x，贪心选的是结束最早的 g，f(g) ≤ f(x)；把最优解里的 x 换成 g，g 不会和后面的冲突（因为 g 结束得更早），个数不变，仍然最优。于是第一步贪心不吃亏，剩下的是同类子问题。O(n log n)。按“开始最早”或“持续最短”贪心都是错的，可以各举一个反例。

问题贪心对吗
分数背包（东西可以切开拿）对：按单位价值从高到低拿
0/1 背包（只能整个拿）不对：用动态规划（第二十二章）或回溯
找零钱（1、5、10、20、50、100 这类“规范”币制）对

回溯的框架

def backtrack(path, choices):
    if 到达终点(path):
        记录答案(path); return
    for c in choices:
        if 不合法(path, c): continue        # 剪枝
        path.append(c)                       # 做选择
        backtrack(path, 下一步的选择)
        path.pop()                           # 撤销选择

# 例：N 皇后（每行放一个，列和两条对角线都不能冲突）
def queens(n):
    cols, d1, d2, out = set(), set(), set(), []
    def go(r, place):
        if r == n: out.append(place[:]); return
        for c in range(n):
            if c in cols or r - c in d1 or r + c in d2: continue
            cols.add(c); d1.add(r - c); d2.add(r + c); place.append(c)
            go(r + 1, place)
            cols.remove(c); d1.remove(r - c); d2.remove(r + c); place.pop()
    go(0, [])
    return out

print(len(queens(8)))   # 92

子集（每个元素选或不选，2ⁿ 种）、排列（n! 种）、组合总和、数独，都是这个框架。剪枝是回溯的灵魂：可行性剪枝（已经违反约束）和最优性剪枝（就算剩下的都最好也超不过当前最优，即“分支限界”的思想）。

典型题 · 原创

（1）活动（开始, 结束）：(1, 4)、(3, 5)、(0, 6)、(5, 7)、(3, 9)、(5, 9)、(6, 10)、(8, 11)。用贪心最多能安排几个？是哪几个？（2）分数背包：容量 10，物品（重量, 价值）为 (5, 30)、(4, 20)、(6, 18)。最大价值是多少？

看解答

（1）按结束时间排序：(1,4)、(3,5)、(0,6)、(5,7)、(3,9)、(5,9)、(6,10)、(8,11)。选 (1,4)；下一个开始 ≥ 4 且结束最早的是 (5,7)；再下一个开始 ≥ 7 的是 (8,11)。共 3 个。

（2）单位价值 6、5、3。拿全部的 (5,30)、(4,20)，剩 1 的容量拿 (6,18) 的 1/6，价值 3。共 53。

拟阵

有没有一个统一的理由说明“为什么克鲁斯卡尔的贪心总是对的”？有：拟阵。粗略地说，如果一个问题里“可行的集合”满足：可行集的子集也可行、小的可行集总能从大的可行集里借一个元素扩充，那么“按权从大到小、能加就加”的贪心一定得到最优解。图里“不含圈的边集”就构成一个拟阵（图拟阵），所以最大（最小）生成树可以贪心。0/1 背包的可行集不满足第二条，所以贪心会上当。

难问题

0/1 背包是 NP 难的：至今不知道有没有对 n 和数字位数都是多项式时间的算法（这是“P 是否等于 NP”的一部分）。下一章的动态规划能在 O(n × 容量) 时间内解它，但容量是一个数值，写下它只要 log(容量) 位，所以这叫“伪多项式时间”：容量是十亿时就不行了。实践中对这类问题常用近似算法（保证不比最优差多少）、分支限界和整数规划求解器。
