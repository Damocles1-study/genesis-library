第一层 · 入门要会：递归（第七章）、列表约 40 分钟

爬楼梯

一段楼梯有 10 级，每次可以上 1 级或 2 级。一共有几种走法？

想最后一步：最后一步要么是从第 9 级上 1 级，要么是从第 8 级上 2 级。所以：

走到第 10 级的走法 ＝ 走到第 9 级的走法 ＋ 走到第 8 级的走法

每一级都是这样。走到第 1 级只有 1 种，走到第 2 级有 2 种（1+1 或 2）。用递归写，一下就写出来了：ways(n) = ways(n − 1) + ways(n − 2)。

直接递归，重复算了好多遍

可是这样跑，n 一大就慢得要命。算 ways(10) 要算 ways(9) 和 ways(8)；算 ways(9) 又要算一遍 ways(8)……同一个 ways(5)，被重复算了好几次。n 是 40 的时候，要调用一亿多次。

办法很简单：算过的写在一张表上。从下往上填：第 1 级 1 种，第 2 级 2 种，第 3 级 = 2 + 1 = 3 种，第 4 级 = 3 + 2 = 5 种……每一格只算一次，第 40 级只要 40 步。

这种“把大问题拆成同样的小问题，小问题的答案记下来、不算第二遍”的办法，叫动态规划。

走格子

方格岛上，从左上角走到右下角，只许往右、往下走，有几条路？

还是想最后一步：走到某一格，要么是从它左边那格往右走一步来的，要么是从它上面那格往下走一步来的。所以：

这一格的路数 ＝ 左边一格的路数 ＋ 上面一格的路数

从左上角开始，一行一行填。第一行、第一列都只有 1 条路（只能一直往右或一直往下）。有石头的格子填 0：走不进去。主线第 22 步算出：在方格岛上从 (2, 1) 走到 (13, 7)，一共 246 条路。

递归和表格

第七章说：递归要“相信自己”，假设小问题已经会做了。动态规划多做了一件事：把每个小问题的答案存起来。《一块一块》第八十章里画过“分叉的树”：直接递归的爬楼梯也是一棵分叉的树，树上一大半的枝是重复的。

两种写法比一比10 分钟
calls = 0
def ways(n):                 # 直接递归
    global calls
    calls += 1
    if n <= 2:
        return n
    return ways(n - 1) + ways(n - 2)

def ways_table(n):           # 填表
    t = [0, 1, 2]
    for i in range(3, n + 1):
        t.append(t[i - 1] + t[i - 2])
    return t[n]

print(ways(30), '直接递归调用了', calls, '次')
print(ways_table(30), '填表只算了 30 格')

把 30 改成 35，再改成 100（只跑填表那一行！）。直接递归跑 35 要好几秒，填表跑 100 一眨眼。

第二层 · 本科算法设计 · 面试和机试的重点约 65 分钟动态规划的两个前提和四个要素；记忆化搜索和自底向上；0/1 背包和一维滚动数组；完全背包；最长公共子序列；最长上升子序列 O(n²) 和 O(n log n)；编辑距离；怎样一步步拆一道新题。

两个前提，四个要素

能用动态规划的问题要有：最优子结构（大问题的最优解由小问题的最优解组成，第二十一章）和重叠子问题（同一个小问题会被反复用到，否则直接分治就行）。写一道动态规划，就是想清楚四件事：

  1. 状态：dp[…] 表示什么。这是最难的一步。
  2. 转移：dp[…] 怎样由更小的状态算出来。通常想“最后一步”。
  3. 起点：最小的状态是多少。
  4. 顺序：按什么顺序填表，保证用到的格子已经算好了。

两种写法：记忆化搜索（递归 + 一个字典，自顶向下，只算用得到的状态，Python 里可以加 @functools.cache）；自底向上填表（循环，没有递归开销，方便压缩空间）。

0/1 背包

状态 dp[i][c]：只考虑前 i 件物品、容量为 c 时的最大价值。转移：第 i 件不拿，dp[i−1][c]；拿（若 wᵢ ≤ c），dp[i−1][c−wᵢ] + vᵢ；取大者。起点 dp[0][c] = 0。O(n × C)。

def knap01(items, C):
    dp = [0] * (C + 1)                    # 一维：dp[c] 就是“到目前为止”的 dp[i][c]
    for w, v in items:
        for c in range(C, w - 1, -1):     # 倒着循环！保证 dp[c - w] 还是上一行的值
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[C]
正着循环就成了完全背包

一维写法里 c 从大到小，dp[c − w] 还没被这件物品更新过，相当于每件只用一次。c 从小到大，dp[c − w] 可能已经用过这件物品，相当于每件可以用无限次：这正是完全背包（比如找零钱的“最少硬币数”）。一个循环方向，两种问题。

三道经典题

  • 最长公共子序列（LCS）：两个串 a、b。dp[i][j] = a 前 i 个和 b 前 j 个的 LCS 长度。a[i] = b[j] 时 dp[i−1][j−1] + 1，否则 max(dp[i−1][j], dp[i][j−1])。O(mn)。
  • 最长上升子序列（LIS）：dp[i] = 以第 i 个数结尾的 LIS 长度 = 1 + max{dp[j] : j < i 且 a[j] < a[i]}，O(n²)。更快的办法：维护数组 tail[k] = “长度为 k+1 的上升子序列结尾最小是多少”，每来一个数用二分（第二十四章）找到位置替换，O(n log n)。
  • 编辑距离：把串 a 变成串 b 最少要几次插入、删除、替换。dp[i][j] = min(dp[i−1][j] + 1, dp[i][j−1] + 1, dp[i−1][j−1] + (a[i] ≠ b[j]))。拼写检查和 DNA 比对的基础。
典型题 · 原创

（1）容量 7，物品（重量, 价值）：(1, 1)、(3, 4)、(4, 5)、(5, 7)。用 0/1 背包求最大价值，写出最后一行 dp[4][0..7]。（2）求 "GRASS" 和 "GLASS" 的编辑距离、"GRASSLAND" 和 "GLASSBAND" 的 LCS 长度。

看解答

（1）逐行：只有 (1,1)：[0,1,1,1,1,1,1,1]。加 (3,4)：[0,1,1,4,5,5,5,5]。加 (4,5)：[0,1,1,4,5,6,6,9]。加 (5,7)：c=5：max(6, dp[0]+7=7)=7；c=6：max(6, dp[1]+7=8)=8；c=7：max(9, dp[2]+7=8)=9。dp[4] = [0,1,1,4,5,7,8,9]，最大价值 9（拿 (3,4) 和 (4,5)）。

（2）GRASS → GLASS 只要把 R 换成 L，编辑距离 1。"GRASSLAND" 和 "GLASSBAND" 的 LCS 是 GASSAND，长度 7（第一个串的 R、L 和第二个串的 L、B 各不在里面）。

面试题

碰到一道没见过的“最大／最小／有几种”的题，怎样判断能不能用动态规划、怎样下手？

看要点

① 先写暴力递归（回溯）：它在每一步做什么选择？② 看递归函数的参数：如果参数组合的种类不多（比如 i 和 c），而同一组参数会被反复调用，就有重叠子问题；这组参数就是状态。③ 加记忆化，就得到了动态规划；再看能不能改成循环、压缩空间。④ 说出状态数 × 每个状态的转移代价 = 时间复杂度。面试时把这个思路讲出来，比直接背出答案更受欢迎。

名字的来历

“动态规划”是 1950 年代美国数学家贝尔曼在兰德公司起的名字。据他在自传里的说法，当时的国防部长不喜欢“研究”“数学”这类词，他想找一个听起来很厉害、又没人会反对的名字：“规划”（programming）在当时指“制定计划、排表”，和写程序无关；“动态”听起来很积极。所以这个名字本身并不说明方法是什么。这个故事来自贝尔曼 1984 年的自传，细节有人质疑过。

到处都在用

  • diff 和 git：比较两个文件改了哪些行，本质上是最长公共子序列（实际用的是迈尔斯 1986 年更快的算法）。
  • 生物信息学：两条 DNA 或蛋白质序列的比对（尼德曼-翁施 1970、史密斯-沃特曼 1981），就是带打分规则的编辑距离。
  • 语音识别和通信：维特比算法在“隐藏状态”组成的网格上找最可能的那条路径，手机信号的纠错解码也用它。
  • 空间优化：LCS 的表是 m × n，两个长串时放不下。只求长度时用两行滚动；要求出序列本身，希尔施伯格（1975）用分治把空间降到 O(m + n)、时间不变。
