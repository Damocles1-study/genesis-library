第一层 · 入门要会：递归和分治（第七章）、简单排序（第二十五章）约 30 分钟

挑一个当标杆

  1. 从一堆数里挑一个当标杆（比如第一个）。
  2. 比标杆小的都放到它左边，大的都放到它右边。这一步叫划分。划分完，标杆就站在了它最终该站的位置。
  3. 左边那一堆、右边那一堆，各自再用同样的办法排（第七章的递归：相信自己）。
  4. 一堆只剩 0 个或 1 个，就不用排了（终点）。

这是 1959 年英国人霍尔想出来的，叫快速排序。它把一个大问题分成两个小问题，是第七章说的分治。

为什么快

如果每次标杆都正好在中间，一堆就分成差不多一样大的两堆：一千个分成两个五百，再分成四个二百五……分十来层就分到底了，每一层所有的数加起来只比较一遍：大约 1000 × 10 次。简单排序要大约 1000 × 1000 / 2 次。

什么时候慢

可是如果数本来就排好了，每次挑第一个当标杆，它就是最小的：左边一个都没有，右边是剩下的全部。每次只少了一个，要分一千层，比较五十万次，和简单排序一样慢。

办法是：随便挑一个当标杆（随机挑），或者挑头、中、尾三个里中间大的那个。这样不管数据长什么样，都很难每次都挑到最小的。

第二层 · 本科对照 408：交换排序（快速排序）约 55 分钟408 风格的划分（挖坑填数）；每趟结果；递归深度和空间；最好 O(n log n)、最坏 O(n²)；不稳定；“第 k 趟后有几个元素到了最终位置”；快速选择。

一趟划分

int partition(int a[], int lo, int hi) {
    int p = a[lo];                         /* 标杆，lo 处成了一个“坑” */
    while (lo < hi) {
        while (lo < hi && a[hi] >= p) hi--;
        a[lo] = a[hi];                     /* 右边比标杆小的填到左边的坑 */
        while (lo < hi && a[lo] <= p) lo++;
        a[hi] = a[lo];                     /* 左边比标杆大的填到右边的坑 */
    }
    a[lo] = p;                             /* 标杆归位 */
    return lo;
}
void quick_sort(int a[], int lo, int hi) {
    if (lo < hi) { int m = partition(a, lo, hi); quick_sort(a, lo, m - 1); quick_sort(a, m + 1, hi); }
}
  • 时间：每层划分共 O(n)。每次划分均匀时递归深度 log n，O(n log n)；每次划分极不均匀（初始有序或逆序，取首元素为标杆）时深度 n，O(n²)。平均 O(n log n)，是内部排序中平均性能最好的。
  • 空间：递归栈，最好 O(log n)、最坏 O(n)。（先递归短的那一段、长的用循环，可以保证 O(log n)。）
  • 不稳定：例如 {3, 2, 2'}，标杆 3，第一趟 2' 被填到最前面，得 {2', 2, 3}。
  • 每一趟（对每一段的一次划分）至少把一个元素（标杆）放到最终位置。408 常问“第二趟结束后，下列哪个序列可能是结果”：第 k 趟结束后，至少有 k 个元素在最终位置；若某一趟的标杆在一端（另一段为空），下一趟只对一段划分，最终位置的元素就少。
典型题 · 原创

（1）对 {38, 12, 61, 27, 50, 9, 44, 33} 用上面的 partition 做第一趟划分（标杆取第一个），写出结果。（2）一组数用快速排序（标杆取每段的第一个）排完前两趟以后，下面哪个不可能是当时的样子：A. {5, 2, 12, 28, 16, 32, 72, 60} B. {2, 16, 5, 28, 12, 60, 32, 72} C. {2, 12, 16, 5, 28, 32, 72, 60} D. {5, 2, 16, 12, 28, 60, 32, 72}。

看解答

（1）p = 38。hi 从 33 开始，33 < 38 填到 0 号：{33, 12, 61, 27, 50, 9, 44, _}；lo 往右，61 > 38 填到 7 号；hi 往左，44 ≥ 38 跳过，9 < 38 填到 2 号；lo 往右，27 跳过，50 > 38 填到 5 号；hi 左移碰到 lo（4 号），停，标杆放 4 号：{33, 12, 9, 27, 38, 50, 44, 61}。

（2）排好后是 {2, 5, 12, 16, 28, 32, 60, 72}。先在每个选项里找出“已在最终位置”的元素：左边的都比它小、右边的都比它大，而且位置和排好后一样。A：12、32；B：2、72；C：2、28、32；D：28、72。

再想两趟能产生什么：第一趟定下一个标杆。如果它不在两端，第二趟要对左右两段各划分一次，两段里各会再定下一个，至少共 3 个；如果它在一端，第二趟只划分一段，至少共 2 个，而且其中一个在最前或最后。A 只有 2 个，又都不在两端，不可能。B（2 和 72 在两端）、D（72 在末端、28 是第二趟的标杆）、C（第一趟 28，第二趟左段定下 2、右段定下 32）都可能。答案 A。做这类题的要领：先数“左小右大”的元素，再对照“不在端点就要 3 个、在端点至少 2 个”。

快速选择

找第 k 小的数，不必全排好：划分一次，标杆落在位置 m。若 m = k，就是它；若 k < m，只去左边找；否则只去右边找。每次只递归一边，平均 n + n/2 + n/4 + … = O(n)，最坏 O(n²)（同样用随机标杆避免）。还有一种最坏也是 O(n) 的“中位数的中位数”算法（1973），常数大，主要有理论意义。

面试题

只有 0、1、2 三种值的数组，一遍扫描排好（荷兰国旗问题）。

看要点

三个指针：lo 左边全是 0，hi 右边全是 2，i 扫描。a[i] = 0 就和 a[lo] 交换、lo 和 i 都加一；a[i] = 2 就和 a[hi] 交换、hi 减一（i 不动，换来的还没看）；a[i] = 1 就 i 加一。O(n)、O(1)。这就是快排的“三路划分”，迪杰斯特拉提出的，有大量重复元素时快排用它就不会退化。

快速排序在什么情况下最慢？

  1. 数据随机
  2. 每次划分都均匀
  3. 初始有序且总取首元素为标杆

每次划分一边为空，O(n²)。

快速排序的平均空间复杂度是？

  1. O(1)
  2. O(log n)
  3. O(n)

递归栈的深度。

快速排序稳定吗？

  1. 稳定
  2. 不稳定

远距离的填坑会打乱相同元素。

快速选择找第 k 小，平均时间复杂度是？

第三层 · 深入来历和工业界的快排约 20 分钟霍尔在莫斯科做机器翻译时想到快排；内省排序：快排太深就换堆排序；双轴快排和模式击败快排；Python 为什么不用快排。

来历

1959 年，霍尔作为交换学生在莫斯科国立大学，参与一个机器翻译项目，需要把要翻译的句子里的单词排好序，再去磁带上的词典里查。他先想到插入排序，觉得太慢，于是想出了快速排序；但当时用的 Mercury Autocode 语言不支持递归，直到回英国学了 ALGOL 60，才把它清楚地写了出来，1961 年发表在《ACM 通讯》上。

工业界的快排

  • 内省排序（introsort，1997）：先快排，递归深度超过 2 log n 时改用堆排序（第二十八章），保证最坏 O(n log n)；小段用插入排序。C++ 的 std::sort 多用它。
  • 双轴快排：Java 7 起对基本类型用两个标杆分成三段。
  • 模式击败快排（pdqsort，2016）：能识别已经有序、重复很多等模式，Rust 和 Go 的不稳定排序用它或它的变种。
  • Python 的 sorted 要求稳定，而快排不稳定，所以用的是归并加插入的 Timsort（第二十七章）。
