第一层 · 入门要会：递归和分治（第七章）、简单排序（第二十五章）约 30 分钟

两摞合成一摞

桌上有两摞牌，每一摞都已经从小到大排好，最小的在最上面。要合成一摞排好的：只要看两摞最上面那张，拿小的那张放到新的一摞上；再看两摞最上面那张，拿小的……一摞拿完了，另一摞剩下的直接放上去。

为什么只看最上面的？因为每一摞都排好了，最上面那张就是这一摞里最小的，两个“最小的”里更小的那个，一定是所有牌里最小的。这一步叫归并，两摞一共 n 张，最多比 n 次。

对半分到底，再一层层合起来

一摞乱的牌怎么办？把它分成两半，两半各自排好（第七章：相信自己），再归并成一摞。一半怎么排好？再分成两半……分到每摞只有一张，一张牌天然是排好的。然后一层一层往回合：一张一张合成两张，两张两张合成四张……这叫归并排序。

一千张牌，对半分大约 10 层；每一层把所有牌合一遍，最多比 1000 次。一共大约 1000 × 10 次。不管牌一开始是乱的、排好的还是倒着的，都是这么多：它不会像快速排序那样碰上最慢的情况。代价是合的时候要一块空地方放新的一摞。

桌子太小了：外部排序

图书馆要把一万本书按编号排好，可是桌子上一次只能摊开一百本。办法是：每次拿一百本到桌上排好，捆成一捆放回书架，这样得到一百捆排好的书；然后每捆只拿最上面一本到桌上，一百本里挑编号最小的放上新书架，再从那一捆补一本上来……这就是第十二章说的“多路归并”，用堆挑最小的最方便。

电脑也是这样：数据太多、内存装不下的时候，先一块一块读进内存排好、写回硬盘，再把这些排好的块归并起来。这叫外部排序。主线第 27 步假装内存一次只能装 4 个数，把 11 个数切成三段排好，再用堆归并。

稳定的排序

归并时，两摞最上面一样大，先拿左边那摞的，一样大的先后就不会变：归并排序是稳定的（第二十五章）。这也是 Python 的 sorted 选它当底子的原因。

二路归并排序

int B[MAXN];                                   /* 辅助数组 */
void merge(int A[], int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++) B[k] = A[k];
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) A[k++] = (B[i] <= B[j]) ? B[i++] : B[j++];   /* <= 保证稳定 */
    while (i <= mid) A[k++] = B[i++];
    while (j <= hi)  A[k++] = B[j++];
}
void merge_sort(int A[], int lo, int hi) {
    if (lo < hi) { int mid = (lo + hi) / 2; merge_sort(A, lo, mid); merge_sort(A, mid + 1, hi); merge(A, lo, mid, hi); }
}

n 个元素的二路归并排序要 ⌈log₂n⌉ 趟，每趟 O(n)，时间总是 O(n log n)（最好、最坏、平均都一样）；空间 O(n)；稳定。k 路归并排序的趟数是 ⌈logkn⌉。

典型题 · 原创

（1）对 {38, 12, 61, 27, 50, 9, 44, 33} 做自底向上的二路归并排序，写出每一趟的结果。（2）设内存工作区能放 3 个记录，对输入序列 {29, 14, 35, 8, 41, 22, 17, 50, 3, 26, 44, 11} 做置换-选择排序，得到哪几个初始归并段？（3）有 8 个初始归并段，长度（块数）为 2, 3, 6, 9, 12, 17, 18, 24，做 3 路归并，画出最佳归并树，求总的读写块数。

看解答

（1）第一趟：{12, 38}、{27, 61}、{9, 50}、{33, 44}；第二趟：{12, 27, 38, 61}、{9, 33, 44, 50}；第三趟：{9, 12, 27, 33, 38, 44, 50, 61}。

（2）工作区先放 29, 14, 35。每次输出工作区里“不小于上一个输出”的最小记录，再读入一个补位；没有可输出的，这一段结束。段一：14, 29, 35, 41（此时工作区为 8, 22, 17，都小于 41）；段二：8, 17, 22, 26, 44, 50；段三：3, 11。三段长度 4、6、2；内存只能放 3 个，却生成了长 6 的段：置换-选择排序生成的段平均长约为内存的两倍。

（3）(8 − 1) mod (3 − 1) = 1 ≠ 0，要补 3 − 1 − 1 = 1 个长度为 0 的虚段。像哈夫曼树一样每次合并最小的 3 个：{0, 2, 3} → 5；{5, 6, 9} → 20；{12, 17, 18} → 47；{20, 24, 47} → 91。带权路径长度 = 各次合并之和 = 5 + 20 + 47 + 91 = 163，每块读一次写一次，总读写 2 × 163 = 326 块。

外部排序

两个阶段：① 生成初始归并段（读入内存、内部排序或置换-选择排序、写回）；② 多趟归并。时间主要花在读写外存上，所以要减少归并的趟数：r 个初始段、k 路归并，趟数 = ⌈logkr⌉。两个办法：

  • 增大 k：但 k 路归并时，每选一个最小记录要比较 k − 1 次，k 大了内部比较变多。败者树解决这个问题：一棵完全二叉树，叶子是 k 个归并段当前的记录，分支结点记“比赛的败者”、胜者继续往上比，根上方记最终胜者。选出一个以后，只需沿它所在的叶子到根重新比一遍，比较 ⌈log₂k⌉ 次。总比较次数不再随 k 线性增长。
  • 减少 r：用置换-选择排序生成更长的初始段（平均是工作区大小的两倍）。

初始段长短不一时，合并的顺序影响读写总量。把每段的长度当成权，构造 k 叉哈夫曼树（第十三章），叫最佳归并树，读写次数 = 2 × 带权路径长度。若 (r − 1) mod (k − 1) = u ≠ 0，补 k − u − 1 个长度为 0 的虚段。

面试题

给一个链表排序，要求 O(n log n) 时间。用什么排序？

看要点

归并排序最合适：用快慢指针找中点断开（第三章），两半各自排好，再合并两个有序链表；合并时只改指针，不需要辅助数组。自底向上的写法（每次合并长度 1、2、4……的段）可以做到 O(1) 额外空间。快速排序在链表上不好选标杆、不能随机访问，堆排序需要随机访问。

8 个元素做二路归并排序，需要几趟？

⌈log₂8⌉ = 3。

归并排序的空间复杂度是？

  1. O(n)
  2. O(log n)
  3. O(1)

需要辅助数组。

有 100 个初始归并段，做 5 路归并，需要几趟？

⌈log₅100⌉ = 3（5² = 25 < 100 ≤ 125）。

败者树的作用是？

  1. 减少初始归并段的个数
  2. 让 k 路归并选最小值的比较次数降到 log₂k

减少段数的是置换-选择排序。

9 个初始归并段做 3 路归并，构造最佳归并树要补几个虚段？

(9 − 1) mod (3 − 1) = 0，正好，不用补。

Timsort

真实的数据很少是完全随机的：常常有一段已经排好、一段倒着排好。2002 年，彼得斯为 Python 写的 Timsort 抓住了这一点：先从左往右扫，找出天然的有序段（倒序的就翻过来），太短的段用折半插入排序补到一个最小长度；然后用一个栈管理这些段，按规则归并相邻的段，保证归并平衡。合并时如果发现一边连续赢了很多次，就切换到“飞奔”模式，用指数查找（第二十四章）一次跳过一大块。对已经排好的数据它是 O(n)，最坏仍是 O(n log n)，而且稳定。Java 对对象数组、Android、V8 引擎（JavaScript 的 sort）后来也用了它。2015 年，有研究者用形式化验证工具发现 Timsort 维持栈平衡的规则有一个漏洞，在特别构造的超大数组上会出错，Python 和 Java 随后都修正了。

大数据排序

数据库执行 ORDER BY 时内存不够，就做外部排序（写临时文件再归并）。MapReduce 和 Spark 的“洗牌”阶段，每台机器先把自己的数据按键排好、切块，再把同一个键范围的块送到同一台机器上归并：这就是第二层讲的两个阶段，只是“硬盘”换成了一整个机群。
