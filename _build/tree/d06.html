堆排序

第十二章的堆，最大（或最小）的总在最上面。那排序就简单了：把所有数放进一个堆，然后一个一个从堆顶拿出来，拿出来的顺序就是排好的。

聪明的做法是不用另开一块地方：就在原来的数组里建一个“大的在上面”的堆；把堆顶（最大的）和最后一个交换，最大的就到了最后；把剩下的修成堆，再把堆顶换到倒数第二个……这叫堆排序。每次修堆只走树的高度那么多步，一共大约 n × log n 步，而且不管数据长什么样都是这么多。

按位分桶：基数排序

邮局分信的办法：准备 10 个桶，编号 0 到 9。先看每个数的个位，扔进对应的桶；再从 0 号桶到 9 号桶按顺序倒出来。然后看十位，再分一次、倒一次；然后看百位……最后一次倒出来，就排好了。这叫基数排序。

为什么对？关键是“倒出来”要按先进先出（第五章的队列）：十位一样的数，在十位这一趟里保持着个位那一趟排好的先后。

比大小的排序有多快

只靠“比一比谁大”来排序，就像玩二十个问题的猜谜：每比一次，只能得到“是”或“不是”。n 个数有很多很多种排列，要从里面猜出唯一正确的那一种，至少要问大约 n × log n 次。所以快速排序、归并排序、堆排序已经是比大小的排序里最快的一类了。计数排序和基数排序快得多，是因为它们不比大小，而是利用了“数字只有 0 到 9”“成绩在 0 到 150 之间”这些额外的信息。

老式的分卡机

二十世纪初，霍勒瑞斯（他的机器帮美国统计了 1890 年的人口普查）的公司做出了打孔卡片分类机：每次按卡片上的一列孔位把卡片分进十几个槽里，再按顺序收起来，一列一列地分。这正是用机器做的基数排序（打孔卡片的故事见书房里的《计算机创世记》）。

堆排序

void heap_sort(int A[], int n) {               /* A[1..n]，大根堆；sift_down 见第十二章 */
    for (int k = n / 2; k >= 1; k--) sift_down(A, k, n);   /* 建堆 O(n) */
    for (int i = n; i > 1; i--) {
        int t = A[1]; A[1] = A[i]; A[i] = t;    /* 堆顶换到最后 */
        sift_down(A, 1, i - 1);                  /* 剩下的修成堆 */
    }
}

建堆 O(n)，n − 1 次调整各 O(log n)：总时间 O(n log n)（最好、最坏、平均都是）；空间 O(1)；不稳定。适合“从很多数里只要前几个”的场合（选出前 k 个只要 O(n + k log n)）。

基数排序

关键字拆成 d 位，每位取值有 r 种（十进制 r = 10）。最低位优先（LSD）：从最低位到最高位，每一趟先分配（按这一位扔进 r 个队列）、再收集（按队列顺序首尾相接）。一趟分配 O(n)、收集 O(r)，共 O(d(n + r))；空间 O(r)（用链式队列）；稳定。最高位优先（MSD）先按最高位分组，组内递归，适合字符串。基数排序不是基于比较的。

典型题 · 原创

（1）对 {38, 12, 61, 27, 50, 9, 44, 33}（下标从 0）用堆排序升序排序，写出初始大根堆和第一趟（堆顶换到最后并调整）以后的序列。（2）对 {218, 504, 73, 916, 342, 85, 507, 260} 做 LSD 基数排序，写出前两趟收集以后的结果。

看解答

（1）从下标 3 往前下沉：27 与孩子 33 交换；61 比孩子 9、44 都大；12 与较大的孩子 50 交换；38 与孩子 61 交换，再与孩子 44 交换。初始堆 {61, 50, 44, 33, 12, 9, 38, 27}。第一趟：61 与 27 交换，对前 7 个调整：27 与 50 交换，再与 33 交换，得 {50, 33, 44, 27, 12, 9, 38, 61}。

（2）按个位：0:260；2:342；3:73；4:504；5:85；6:916；7:507；8:218，收集得 {260, 342, 73, 504, 85, 916, 507, 218}。按十位：0:504, 507；1:916, 218；4:342；6:260；7:73；8:85，收集得 {504, 507, 916, 218, 342, 260, 73, 85}。（第三趟按百位后即有序。）

比较排序的下界

任何基于比较的排序都可以画成一棵判定树：每个内部结点是一次比较，每个叶子是一种排列。n 个元素有 n! 种排列，二叉树要有 n! 个叶子，高度至少 ⌈log₂ n!⌉ ≈ n log₂n − 1.44n。所以比较排序最坏至少要 Ω(n log n) 次比较。例如 n = 5：⌈log₂120⌉ = 7 次。

口诀之一：“快些（希尔）选一堆（堆）”不稳定。怎样选：n 小（≤ 50 左右）用直接插入或简单选择；基本有序用直接插入或冒泡；n 大用快速、堆或归并，要稳定选归并，要省空间选堆，平均最快是快速；关键字位数少、取值范围小用基数或计数。与初始序列无关的：简单选择的比较次数、堆排序和归并排序的时间。

面试题

一亿个手机号（11 位数字）要去重并排好序，内存有限，怎么做？

看要点

手机号的取值范围有限，可以用位图（《地基》第七章第三层）：每个可能的号码一个比特，出现过就置 1，最后从小到大扫一遍为 1 的位，天然去重且有序。按 1011 个可能值算约 12.5 GB，太大；可以按号段（前三位）分桶，每次只处理一个号段的位图（约 125 MB），这就是计数排序 + 分桶的思路。没有范围信息时，就用外部排序（第二十七章）。

第三层 · 深入线性时间排序的真实用法约 15 分钟桶排序的期望 O(n)；后缀数组和字符串排序；GPU 上的基数排序；标准库为什么还是用比较排序。

桶排序：数据在 [0, 1) 上均匀分布时，分成 n 个桶，每桶期望 O(1) 个元素，桶内插入排序，期望 O(n)。分布不均时退化。

基数排序的真实用法：GPU 上给几亿个整数或浮点数排序，最快的往往是基数排序（每一趟都是规整的并行计数和搬运，第十五章说的“规整访问”）；数据库给整数键排序、字符串处理里构造后缀数组，也常用基数排序的思想。

标准库为什么还用比较排序：比较排序只需要一个“比大小”的函数，适用于任何类型；基数排序要知道键的内部结构（多少位、什么编码），而且要额外的空间。所以 Python、C++、Java 的通用排序函数都是比较排序，专门的场合才用基数排序。
