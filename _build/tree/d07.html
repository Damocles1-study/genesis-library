如果只记六句

  1. 东西怎样摆，决定了事情做起来有多快。
  2. 数步数，看东西多了步数怎样跟着多。
  3. 挨着放拿得快，串起来插得快；后进先出是栈，先进先出是队列。
  4. 树让每一步排除一大片，但要保持两边一样高。
  5. 图上的问题：一圈圈找最近，每次定下最近的，从最短的挑起。
  6. 找东西：能算出位置就散列，排好了就二分；排序没有最好的，只有最合适的。

面试题的四步

  1. 先问清楚：数据有多大？要支持哪些操作，哪个最频繁？要不要有序、要不要稳定、内存有没有限制？
  2. 先说暴力解和它的复杂度，证明你理解了问题。
  3. 找瓶颈、换结构：瓶颈是“找”就想散列和树，是“取最值”就想堆，是“连通”就想并查集和搜索，是“重复子问题”就想动态规划。
  4. 说清取舍：时间和空间、平均和最坏、实现难度、常数和缓存（第二章第三层）。最后用一个小例子手跑一遍代码。

把主线变成你的项目

每一步主线框里的“第二层”那一行，合起来就是一个用 C 实现的小项目：用 git 记录每一步，给每个数据结构写单元测试，用 clock() 或 time 量运行时间，最后写一份 README，说明每个功能用了什么结构、为什么、复杂度多少。这样的项目，在复试和面试时比背出来的答案更有说服力。

面试题

设计一个排行榜：支持“给某个玩家加分”“查某个玩家的名次”“列出前 k 名”，玩家有一百万个。

看要点

散列表：玩家 → 分数（O(1) 找到玩家）；再加一个按分数有序的结构支持名次和前 k：平衡搜索树（每个结点记子树大小，名次 O(log n)）或跳表（Redis 的有序集合就是“散列表 + 跳表”）。加分 = 在有序结构里删旧分、插新分，O(log n)。分数范围小时，也可以用分数做下标的计数数组加树状数组。说出组合和取舍是这道题的重点。

既要按键快速查找，又要按顺序遍历和范围查询，最合适的是？

  1. 散列表
  2. 平衡搜索树（或 B+ 树）
  3. 堆

散列表无序，堆只管最值。

只需要反复取出最小值、并不断插入新值，最合适的是？

  1. 堆
  2. 有序数组
  3. 链表

取最值 O(1)、插入 O(log n)。

判断很多对点是否连通、并且不断加边，最合适的是？

  1. 邻接矩阵 + DFS
  2. 堆
  3. 并查集

每次加边和查询都近乎 O(1)。

LRU 缓存通常用什么组合？

  1. 堆 + 栈
  2. 散列表 + 双向链表
  3. 数组 + 二分

第三层 · 深入真实软件里的组合约 20 分钟一个数据库、一个操作系统、一个浏览器里各藏着哪些结构；往下读的书。

拆开一个真实的软件

  • 数据库：B+ 树索引（第十五章）、散列连接（第二十三章）、外部排序做 ORDER BY（第二十七章）、堆做“前 k 个”（第十二章）、LSM 树和布隆过滤器（第十五、二十三章）。
  • 操作系统：调度器的红黑树（第十一章）、定时器的时间轮和堆（第十二章）、页表这棵多级树（《地基》第二十七章）、文件系统的 B 树（第十五章）、空闲内存的链表（第三章）。
  • 浏览器：网页的 DOM 树（第八章）、JavaScript 的 Map 和 Set（散列表）、渲染时按依赖排出的计算顺序（第二十章）、V8 的排序（Timsort，第二十七章）。
  • 导航软件：路网图、迪杰斯特拉和 A*、预处理的收缩层次（第十八章）、空间索引树。
