      两种身份

      在学校里，学生不能自己进教务处改成绩，也不能自己去仓库搬新书。要办这些事，得到窗口去，请老师办。

      电脑里也分两种身份：

      • 内核：操作系统最核心的那部分程序。它什么都能碰：内存、硬盘、网络、屏幕、键盘。
      • 普通程序：浏览器、游戏、你写的 Python。它们只能在自己那块内存里算东西，碰不到硬件，也碰不到别的程序的内存。

      处理器自己就知道“现在是谁在跑”。普通程序要是想偷偷碰硬件，处理器会马上拦下，交给内核处理。这样，一个程序写错了，最多自己出错，不会把整台电脑弄坏。

      服务器的管理员

      在第二十九章开服务器的时候，你只把 op（管理员）给了自己：别的玩家不能用 /stop 关服务器，也不能给自己发钻石。内核就像管理员，普通程序就像普通玩家。

      系统调用：去柜台办事

      普通程序想读文件、往屏幕上写字、上网，怎么办？去“柜台”请内核帮忙。这叫系统调用。

      你在 Python 里写一句 print('hi')，Python 最后会去柜台说：“请把 h、i 和一个换行，写到屏幕上。”内核检查一下，帮它写上去，再回到 Python。

      中断：硬件举手

      你按下一个键，键盘怎样告诉电脑？它不等电脑来问，而是“举手”：发一个信号。处理器放下手里的事，先让内核看看是什么事，处理完再回去接着做。这叫中断。

      键盘、鼠标、网卡、计时的时钟，都靠举手来打断处理器。时钟每隔一小会儿就举一次手，内核就趁这个时候决定下一个让谁跑（第二十六章）。

      两种身份

      如果每个程序都能随便指挥硬盘、改别人的内存，一个写错的程序就能把整台电脑搞垮，一个坏程序就能偷走所有人的数据。所以处理器有两种运行身份（在 arm64 上叫“异常级别”，EL0 和 EL1）：

      • 用户态：你的程序、浏览器、游戏都在这里。只能算数、读写自己的内存，有些指令根本不许执行（比如直接操作外设、改内存映射）。
      • 内核态：操作系统的核心部分（内核）在这里运行，什么都能做。macOS 的内核叫 XNU，Linux 的内核就叫 Linux。

      这像银行：顾客（程序）不能自己走进金库（硬件），要在柜台填单子，由柜员（内核）检查后代办。

      系统调用：柜台

      程序要读文件、写屏幕、联网、要内存、开新程序，都要发起系统调用：把“我要办什么事”（一个编号）和参数放进约定的寄存器，执行一条特殊的指令（arm64 上是 svc），处理器立刻切换到内核态，跳到内核里事先设好的入口。内核检查请求合不合法、办完，再切回用户态，把结果交还给程序。printf 自己先把字排好，最后调用一次 write 系统调用，请内核把这些字节交给终端。

      中断：硬件举手

      反过来，硬件也有事要找内核：键盘被按下了、网卡收到了数据、硬盘读完了、定时器的时间到了。它们会发出中断信号，处理器放下手上的程序（不管它是谁），切到内核去处理，处理完再回来接着做。第零章“按下 A 键以后”的第四步就是它。定时器中断尤其重要：每隔几毫秒响一次，内核借机决定要不要换一个程序来跑（下一章）。

      操作系统的特征和功能

      408 的说法：操作系统的基本特征是并发（宏观上同时运行多个程序）、共享（资源被多个程序共用，分互斥共享和同时共享）、虚拟（把一个物理实体变成多个逻辑上的对应物，如虚拟处理器、虚拟内存）、异步（程序走走停停，以不可预知的速度推进），其中并发和共享是最基本的、互为存在条件。它的功能是管理处理器、存储器、文件、设备，并向上提供接口（命令接口和程序接口，后者就是系统调用）。

      中断和异常

      • 中断（外中断）：来自处理器外部、和当前指令无关的事件，如 I/O 完成、定时器、键盘。处理完回到被打断的下一条指令。分为可屏蔽中断（可以暂时关掉不响应）和不可屏蔽中断（如掉电）。
      • 异常（内中断）：执行当前指令引起的。① 陷阱（陷入）：程序有意引起的，如系统调用、断点（第二十四章的 brk），处理完回到下一条指令；② 故障：可能被修复的错误，如缺页（第二十七章）、除以零，修复后重新执行引起故障的那条指令；③ 终止：无法恢复的错误，如硬件故障，程序被终止。

      中断处理过程

      408 计组常考的顺序（单重中断）：中断请求 → 中断判优（多个请求同时来，选优先级最高的）→ CPU 在一条指令执行完后响应（检查有无中断请求，且中断允许）→ 中断隐指令（硬件自动完成：关中断、保存断点（PC 和程序状态）、识别中断源并送出中断服务程序的入口地址）→ 中断服务程序：保存现场（通用寄存器等）→ 若允许多重中断则开中断 → 执行设备服务 → 关中断 → 恢复现场 → 开中断 → 中断返回。入口地址常通过中断向量表查得：每种中断一个编号，表里存着对应服务程序的地址。多重中断时，可以用中断屏蔽字动态调整各中断源的处理优先级。

      特权指令

      只能在内核态执行的指令叫特权指令：I/O 指令、开关中断、修改页表基址寄存器（换地址空间）、停机、设置时钟等。用户态程序执行它们会引发异常。“访管指令”（系统调用指令，arm64 的 svc、x86 的 syscall）本身不是特权指令，它恰恰是用户态程序进入内核的合法途径。

      典型题 · 原创

      （1）判断下列事件是中断还是异常，若是异常属于哪一类：① 程序执行 svc 请求读文件；② 访问的页不在内存中；③ 定时器时间片到；④ 整数除以零；⑤ 网卡收到一个数据包；⑥ 内存校验发现无法纠正的错误。（2）下列哪些指令只能在内核态执行：读时钟、写时钟、关中断、算术加法、修改页表基址寄存器、发出系统调用的指令。（3）把下列步骤按中断响应和处理的顺序排列：A 保存现场；B 关中断并保存断点（硬件）；C 执行中断服务；D 恢复现场；E 中断返回；F 识别中断源取得入口地址。

      看解答

      （1）① 异常 · 陷阱；② 异常 · 故障（缺页，处理后重新执行该指令）；③ 中断；④ 异常 · 故障（多数系统直接终止该程序）；⑤ 中断；⑥ 异常 · 终止。

      （2）写时钟、关中断、修改页表基址寄存器。读时钟、加法、系统调用指令都可以在用户态执行。

      （3）B → F → A → C → D → E（单重中断，开关中断的细节按题目要求补充）。

      宏内核和微内核

      宏内核把进程管理、内存、文件系统、网络协议、驱动全放在内核态的一个大程序里，彼此直接调用，快，但任何一个驱动出错都可能拖垮整个系统。Linux 是宏内核。微内核只在内核态保留最少的东西（进程间通信、基本调度和内存），文件系统、驱动等都作为用户态的服务进程，靠消息互相请求，更可靠但消息传递有开销。macOS 的 XNU 是混合的：底层是卡内基梅隆大学的 Mach 微内核，上面叠了来自 BSD Unix 的部分，但为了速度两者都运行在内核态。

      同一件事，两种叫法

      在 arm64 上，Linux 把系统调用号放在 x8、执行 svc #0；macOS 把调用号放在 x16、执行 svc #0x80。编号也不同（Linux 的 write 是 64 号，macOS 的 write 是 4 号）。这也是为什么 Linux 的程序不能直接在 macOS 上运行，即使处理器一样。macOS 不保证系统调用号稳定，程序应该通过系统库（libSystem）去调用。

      一次系统调用有多贵

      程序和进程

      硬盘上的 hello 是一个程序，一个静静躺着的文件。运行它，操作系统就造出一个进程：正在运行的程序，加上它的一切家当：自己的地址空间（第二十三章的那张内存地图）、寄存器的值、打开的文件、一个编号（进程号 PID）。同一个程序运行两次，就是两个进程，互不相干。内核为每个进程记一份档案，叫进程控制块（PCB）。

      进程的状态

      五种状态：创建、就绪（万事俱备只差处理器）、运行、阻塞（等待某个事件，如 I/O 完成，给它处理器也没用）、终止。转换：就绪 → 运行（被调度选中）；运行 → 就绪（时间片用完或被抢占）；运行 → 阻塞（请求 I/O、等待资源，主动的）；阻塞 → 就绪（等的事件发生了，被动的）。注意阻塞不能直接变运行，必须先回就绪队列排队；就绪也不能直接变阻塞。PCB 里记着进程号、状态、寄存器现场、优先级、内存和打开文件的信息，是进程存在的唯一标志。

      fork、exec、wait

      #include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int main(void) {
    int x = 100;
    pid_t id = fork();                  /* 从这里开始，变成了两个进程 */
    if (id == 0) {                      /* 子进程里 fork 返回 0 */
        x++;
        printf("子进程 %d：x = %d\n", getpid(), x);
        execlp("echo", "echo", "我变成了 echo", (char *)NULL);   /* 换成另一个程序 */
    } else {                            /* 父进程里 fork 返回子进程的号码 */
        wait(NULL);                     /* 等子进程结束 */
        printf("父进程 %d：x = %d\n", getpid(), x);
    }
    return 0;
}

      fork 把调用它的进程复制一份（地址空间、打开的文件都复制，现代系统用写时复制，第二十七章），两份都从 fork 返回处接着跑：子进程里返回 0，父进程里返回子进程的 PID。子进程改 x 不影响父进程（各有一份）。exec（第二十三章）把子进程换成别的程序。shell 运行每条命令都是这样：fork，子进程 exec，父进程 wait。子进程结束而父进程还没 wait，它的档案还留着，叫僵尸进程；父进程先死了，子进程被系统的第一个进程（macOS 上的 launchd）收养，叫孤儿进程。

      进程和线程

      线程是进程里的一条执行流。一个进程可以有好几个线程，它们共享同一个地址空间、打开的文件，各自有自己的栈和寄存器。所以线程之间传数据很方便（直接读写同一块内存），切换也比进程便宜；代价是一个线程写坏内存会拖垮整个进程，几个线程同时改同一个变量会出乱子（第二十九章）。408 的说法：进程是资源分配的基本单位，线程是调度的基本单位（引入线程以后）。浏览器给每个网页开一个进程，是为了一个网页崩了不连累别的。

      调度算法和指标

      周转时间 = 完成时间 − 到达时间；带权周转时间 = 周转时间 ÷ 实际运行时间；等待时间 = 周转时间 − 运行时间（不考虑 I/O）；响应时间 = 第一次被调度的时间 − 到达时间。算法：先来先服务（FCFS，非抢占，对长作业有利）；短作业优先（SJF，非抢占；抢占式叫最短剩余时间优先 SRTN）；高响应比优先（响应比 = (等待时间 + 要求服务时间) ÷ 要求服务时间，兼顾短作业和等得久的长作业，不会饥饿）；优先级调度（可抢占或不可抢占，可能饥饿，用“老化”缓解）；时间片轮转（RR）；多级反馈队列（多个队列优先级递减、时间片递增，新进程进最高队列，用完时间片还没完就降一级：照顾短作业和交互式进程，又不饿死长作业，是很多真实系统的原型）。装置里可以算前五种。

      切换不是免费的

      上下文切换的直接开销是保存和恢复寄存器、进出内核，几微秒；更大的是间接开销：新进程的数据不在缓存里（第十六章），TLB 也要重新热起来（第二十七章）。所以时间片不能太短，否则大部分时间都花在切换上。

      真实的调度器

      Linux 从 2007 年起用“完全公平调度器”（CFS）：给每个进程记一个“虚拟运行时间”，总是挑虚拟时间最少的那个来跑，优先级高的虚拟时间涨得慢；2023 年起逐步换成更注重延迟的 EEVDF。macOS 让程序给每个任务标一个“服务质量”等级（用户交互、用户发起、实用工具、后台），调度器据此决定谁先跑、放在哪种核上。

      每个进程都以为自己住一整栋楼

      为什么要“假”地址

      如果几百个进程都直接用真实的物理地址，会有三个麻烦：谁都能改别人的内存（不安全）；每个程序都得知道自己被装在哪儿（第二十三章的重定位）；内存被切得七零八落（第二十一章的外部碎片）。虚拟内存一次解决三件事：给每个进程一片自己的、从 0 开始的、很大的虚拟地址空间；处理器每次访问内存时，由一个叫 MMU（内存管理单元）的硬件把虚拟地址翻译成物理地址。翻译表由操作系统维护，每个进程一张，别人的表你查不到，自然改不了别人的内存。

      分页

      一个字节一个字节地翻译，表太大了。所以把虚拟空间和物理内存都切成同样大小的块：虚拟的叫页，物理的叫页框。Apple Silicon 的 Mac 一页 16 KB（第十二章 pagesize 命令打出的 16384），很多 x86 电脑和手机是 4 KB。翻译表只要记“第几页放在第几个页框”，这张表叫页表。

      一个虚拟地址拆成两段：高位是页号，低位是页内偏移（页有 16 KB = 214 字节，偏移就是低 14 位）。用页号查页表得到页框号，再接上原来的偏移，就是物理地址。偏移原样不动，因为页和页框一样大。

      缺页：页不在家

      页表里还可以记“这一页暂时不在内存里，在硬盘上”。程序访问到这样的页，MMU 翻译不出来，产生一个缺页异常（第二十五章的“故障”）。内核接手：找一个空页框（没有就挑一页“请出去”写回硬盘），把需要的页从硬盘读进来，改好页表，再让那条指令重新执行一遍。程序完全感觉不到，只是那一下慢了很多。所以电脑能运行“比内存还大”的程序：常用的页留在内存，不常用的放在硬盘上。代价是：如果要用的页总在内存和硬盘之间来回搬，电脑会卡得几乎不动，这叫抖动。

      页表项和页表的大小

      页表项除了页框号，还有：有效位（在不在内存）、访问位（最近被访问过没有，置换算法用）、修改位（脏位，换出时要不要写回）、保护位（可读、可写、可执行，第十三章的 W^X 就靠它）。页表大小 = 页表项个数 × 每项字节数。32 位地址、4 KB 页：220 项 × 4 字节 = 4 MB，每个进程都要一张，而且大部分是空的。所以用多级页表：把页号再切成几段，第一级表指向第二级表，没用到的区域连第二级表都不必建。arm64 和 x86-64 常用四级页表（48 位虚拟地址）。代价是一次翻译要多访问几次内存，于是有了 TLB。

      TLB

      快表（TLB）是页表项的缓存（第十六章），通常是全相联或高相联度的小表，几十到上千项。翻译时先查 TLB，命中就直接得到页框号；不命中再查内存里的页表，并把结果放进 TLB。设 TLB 访问时间 t、内存访问时间 m、TLB 命中率 h，一级页表时：有效访问时间 = h(t + m) + (1 − h)(t + 2m)（若并行查 TLB 和页表，式子略有不同，按题意）。

      页面置换

      • OPT（最佳）：换出将来最长时间不会用到的页。缺页最少，但要预知未来，只能作为比较的基准。
      • FIFO：换出最早进来的页。简单，但可能把常用页换掉；会出现 Belady 异常：给更多的页框，缺页次数反而增加。
      • LRU（最近最久未使用）：换出最长时间没被访问的页。效果接近 OPT，但每次访问都要记时间或调整栈，硬件代价高。
      • CLOCK（最近未用）：页框排成一圈，每页一个访问位，指针转圈：访问位为 1 就清零跳过，为 0 就换出它。改进型 CLOCK 同时看访问位和修改位，优先换出 (0, 0)，其次 (0, 1)，因为没改过的页换出不用写回硬盘。

      工作集、抖动和分段

      进程在一段时间里经常访问的那些页叫工作集。分给它的页框少于工作集，就会频繁缺页（抖动）；系统应当减少同时运行的进程，让每个进程的工作集都放得下。另一种划分方式是分段：按程序的逻辑单位（代码段、数据段、栈段）分成大小不等的段，便于共享和保护，但会有外部碎片；段页式先分段再在段内分页，兼顾两者。

      页表能做的花样

      • 写时复制：fork（第二十六章）后父子进程的页表指向同一批页框，全部标为只读；谁先写，就触发一次保护异常，内核这才复制那一页、改成可写。
      • 内存映射文件：mmap 把一个文件映射进地址空间，读写内存就是读写文件，页按需从磁盘读入。程序的代码段就是这样从可执行文件映射进来的，所以 100 个进程运行同一个程序、用同一个共享库，物理内存里只有一份代码。
      • 按需分配：malloc 一大块内存时，系统只是在页表里记下“这一片归你了”，真正碰到某一页才分配页框。所以第一次写一个大数组会产生很多缺页（第一层 time -l 看到的大部分就是这种）。

      macOS：先压缩，再交换

      内存紧张时，macOS 不急着把页写到硬盘，而是先把不常用的页压缩（文本、零页压缩率很高），放在内存里一个专门的区域，需要时再解压，比读硬盘快得多。压缩也不够了，才写进固态硬盘上的交换文件。所以 8 GB 的 M1 Air 也能同时开不少东西；但长时间大量交换会增加固态硬盘的写入量。活动监视器里的“已压缩”和“已使用的交换”就是这两项。

      页的大小怎么选

      页大：页表小、TLB 能覆盖更多内存、读磁盘一次读得多；但页内浪费（内部碎片）大。Apple Silicon 选了 16 KB，一个 TLB 项覆盖的内存是 4 KB 页的四倍；数据库和虚拟机等大内存程序还会用 2 MB 甚至 1 GB 的“大页”。另外，第十五章说的熔断漏洞公开以后，很多系统把内核和用户态程序的页表彻底分开（内核页表隔离），每次系统调用都要切换页表，这是安全和速度的又一次交换。

      硬盘只认得“第几块”

      对硬盘来说，没有文件，也没有文件夹，只有一长排编了号的块（常见 4 KB 一块），能做的只是“读第 n 块”“写第 n 块”。把这些块组织成“名叫作业.txt、有 12345 字节、放在文稿文件夹里”的样子，是操作系统里文件系统的工作。Mac 用的文件系统叫 APFS，Windows 常用 NTFS，Linux 常用 ext4，U 盘常用 exFAT。

      名字不在文件里

      类 Unix 系统里，一个文件由三部分组成：

      • 数据块：文件真正的内容，散落在硬盘各处。
      • 索引节点（inode）：文件的“档案卡”，记着大小、权限（第七章的 rwx）、主人、修改时间，以及内容放在哪些块里。每个 inode 有一个编号。
      • 目录项：文件夹本身也是一个文件，内容是一张表，每行是“名字 → inode 编号”。

      所以打开 ~/base/hi.txt，是先找到 base 这个目录、在它的表里查到 hi.txt 对应的 inode 编号、再从 inode 找到数据块。改名只改目录表里的一行，移动到同一块盘的另一个文件夹只是把这一行从一张表挪到另一张，都与文件大小无关，所以一瞬间完成。拷贝要真的读出所有数据块再写一遍（APFS 有例外，第三层）。删除只是删掉目录里的那一行、把块标成“空闲”，数据还在原地，直到被新数据覆盖，所以误删的文件常常能恢复，要彻底清除则要另想办法。

      三种分配方式

      方式怎样记顺序访问随机访问问题
      连续分配起始块号 + 长度最快直接算出块号外部碎片（第二十一章）；文件难以增长
      隐式链接每块末尾存下一块的指针可以要从头一块一块找一块坏了后面全丢；指针占空间
      显式链接（FAT）把所有“下一块”指针集中成一张文件分配表，常驻内存可以在内存的表里跳着找，不用读盘表随磁盘变大而变大
      索引分配每个文件一个索引块，列出所有数据块号可以查索引块即得索引块本身占空间；大文件一个索引块不够

      大文件的索引块不够用，有三种办法：链接多个索引块、多级索引、混合索引。Unix 的 inode 用混合索引：比如 10 个直接指针直接指向数据块，1 个一级间接指针指向一个装满块号的索引块，1 个二级间接、1 个三级间接。小文件只用直接指针，访问快；大文件才动用间接索引。

      最大文件长度：设块大小 B、块号 p 字节，一个索引块能放 n = B / p 个块号，则最大块数 = 直接数 + n + n2 + n3，乘以 B 就是字节数。读文件某个位置要访问几次磁盘：先算它在第几块，判断落在直接、一级还是二级间接范围内，分别要再读 0、1、2 个索引块，再加 1 次读数据块（inode 是否已在内存按题意）。

      写到一半断电了

      往文件末尾加一块数据，至少要改三处：位示图（这块被占用了）、inode（大小和块列表）、数据块本身。如果只改了一两处就断电，文件系统就不一致了（块被标成已用却没人拥有，或者 inode 指向一块垃圾）。老办法是开机时用 fsck 扫描整个磁盘修复，硬盘越大越慢。日志文件系统（ext4、NTFS、macOS 以前的 HFS+）先把“我要改这三处”写进一块专门的日志区，再真正去改；断电后只要重放或丢弃日志里没完成的那条，几秒就恢复。

      写时复制：APFS

      2017 年起 Mac 用的 APFS 换了思路：永远不在原地改，要改的块写到新位置，再自下而上更新指向它的元数据，最后一步原子地切换根指针。断电时要么是旧版本、要么是新版本，没有半截。这个设计顺带带来几件好事：

      • 克隆：在访达里拷贝一个文件（同一个 APFS 宗卷内），新文件只是共享原来的数据块，几乎瞬间完成、不占额外空间；以后谁改了哪一块，才复制那一块（又是写时复制）。命令行里 cp -c 显式请求克隆。
      • 快照：把某一刻的根指针保存下来，就得到整个宗卷在那一刻的只读样子，“时间机器”的本地快照和系统更新都用它。
      • 空间共享：一块物理磁盘上的几个宗卷（比如系统宗卷和数据宗卷）共用剩余空间，不必事先分好大小。

      写了不等于写到盘上

      为了快，write 返回时数据常常只是进了内存里的缓存，过一会儿才真正写到硬盘。程序如果必须确保数据落盘（数据库提交一笔交易），要调用 fsync。在 macOS 上，连 fsync 也只保证交给了硬盘，硬盘自己还有缓存，要彻底落盘得用 fcntl(fd, F_FULLFSYNC)。这种“到底写没写进去”的层层缓存，是数据库工程师每天要和它较劲的事。

      count++ 是三步

      C 里的 count++ 看起来是一步，翻译成机器指令却是三步（第十四章）：读（把 count 从内存读进寄存器）、加（寄存器加一）、写（把寄存器写回内存）。两个线程同时做，可能这样交错：A 读到 5，B 也读到 5；A 加成 6 写回；B 也加成 6 写回。两个人各加了一次，count 却只多了 1。这种结果取决于“谁先谁后”的错误叫竞态（race condition），会改共享数据的那段代码叫临界区。

      锁

      解决办法是规定“同一时刻只许一个线程在临界区里”，叫互斥。最常用的工具是锁（mutex）：进临界区前先上锁，出来时开锁；锁已经被别人上了，就等着。像只有一把钥匙的厕所。C 里用 pthread 库：

#include <pthread.h>
long count = 0;
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
void *work(void *arg) {
    for (int i = 0; i < 1000000; i++) {
        /* pthread_mutex_lock(&m); */
        count++;
        /* pthread_mutex_unlock(&m); */
    }
    return NULL;
}
int main(void) {
    pthread_t a, b;
    pthread_create(&a, NULL, work, NULL);
    pthread_create(&b, NULL, work, NULL);
    pthread_join(a, NULL); pthread_join(b, NULL);
    printf("count = %ld（应该是 2000000）\n", count);
    return 0;
}

      临界区的准则和实现

      四条准则：空闲让进、忙则等待、有限等待、让权等待（进不去时让出处理器，不要空转）。软件办法有 Peterson 算法（两个线程，用 flag 和 turn 两个变量）；硬件办法有关中断（只适用于单处理器内核）和原子指令：TestAndSet、Swap（交换），用它们做的自旋锁会“忙等”，不满足让权等待。

      信号量

      信号量 S 是一个整数加一个等待队列，只能用两个原子操作访问：P(S)（wait）：S 减 1，若 S < 0 则把自己阻塞进队列；V(S)（signal）：S 加 1，若 S ≤ 0 则唤醒队列里的一个。S 为负时，其绝对值就是等待的进程数。用法：

      • 互斥：mutex 初值 1，临界区前 P、后 V。
      • 同步（前驱关系，A 做完 B 才能做）：S 初值 0，A 做完 V(S)，B 开始前 P(S)。
      • 资源计数：初值为资源个数。
      semaphore mutex = 1, empty = n, full = 0;
producer: while (1) { 生产一个; P(empty); P(mutex); 放进缓冲区; V(mutex); V(full); }
consumer: while (1) { P(full); P(mutex); 取出一个; V(mutex); V(empty); 消费它; }

      易错点：P(empty) 和 P(mutex) 的顺序不能颠倒，否则缓冲区满时生产者拿着 mutex 阻塞在 empty 上，消费者拿不到 mutex 取不走东西，死锁。V 操作的顺序则无所谓。读者写者（读者可以同时读，写者要独占）用一个 count 记读者数，第一个读者 P(rw)、最后一个读者 V(rw)；哲学家进餐（五个人五根筷子）的经典解法是限制最多四人同时拿筷子，或奇数号先拿左边、偶数号先拿右边。管程把共享数据和对它的操作封装在一起，同一时刻只允许一个进程在管程内，用条件变量 wait、signal 做同步（Java 的 synchronized 就是这个思想）。

      死锁

      四个必要条件（缺一个就不会死锁）：互斥、不剥夺、请求并保持、循环等待。对策：预防（破坏某个条件，如一次申请所有资源破坏“请求并保持”、按编号顺序申请破坏“循环等待”）；避免（每次分配前检查分配后是否仍处于安全状态，即存在一个让所有进程都能完成的顺序，银行家算法）；检测与解除（允许发生，定期画资源分配图化简找死锁，再撤销进程或剥夺资源）。安全状态一定不会死锁；不安全状态不一定会死锁，但有可能。

      原子指令

      锁本身是怎么做的？处理器提供“读、改、写一步完成、中间不会被插队”的原子指令。arm64 从 ARMv8.1 起有 ldadd（原子加）、cas（比较并交换：如果内存里还是我以为的那个值，就换成新值，否则失败）等。C11 的 <stdatomic.h> 里，atomic_fetch_add(&count, 1) 在 Apple Silicon 上会编译成一条 ldadd，比加锁快得多。用 clang -O2 -S 可以看到。

      内存顺序

      更隐蔽的问题：为了快，处理器和编译器会重排读写的顺序（第十五章的乱序执行），单线程看不出来，多线程就可能看到“先写的后到”。x86 的规则比较严格（TSO，第十四章 Rosetta 那一段），ARM 是弱序的，允许更多重排。所以在 Mac 上，一个“在 x86 上从没出过错”的无锁程序可能会出错。正确的做法是用原子变量并指定内存顺序（acquire、release），或者干脆用锁，让编译器和处理器插入必要的屏障。经典的反例是“双重检查锁定”：不加正确的屏障，另一个线程可能拿到一个指针却看到对象还没初始化完。

      别抢同一行

      第十六章的伪共享在这里正式登场：两个线程各自累加自己的计数器，计数器却挨在同一个缓存行里，两个核为了这一行来回抢，比真共享还慢。把每个线程的计数器放到不同的缓存行（Apple Silicon 上间隔 128 字节），各自算完最后再加起来，常常快得多。更进一步的思路是不共享：Go 语言的口号是“不要用共享内存来通信，要用通信来共享内存”，各线程通过消息队列（channel）传数据。

      几种分层模型

      国际标准化组织的 OSI 参考模型分七层：物理、数据链路、网络、传输、会话、表示、应用。实际流行的 TCP/IP 模型分四层：网络接口、网际（IP）、传输、应用（会话和表示的功能并入了应用层）。教材常用两者折中的五层：物理、数据链路、网络、传输、应用。各层的数据单元：应用层叫报文，传输层叫报文段（TCP）或用户数据报（UDP），网络层叫分组或 IP 数据报，链路层叫帧，物理层是比特。

      三个概念：协议是对等实体（两台机器的同一层）之间通信的规则，由语法、语义、同步三要素组成，是“水平”的；服务是下层为上层提供的功能，是“垂直”的；上下层之间交换信息的地方叫服务访问点（接口）。第 n 层使用第 n − 1 层的服务、按第 n 层的协议和对方的第 n 层通信。

      时延

      • 发送时延（传输时延）= 数据长度 ÷ 发送速率（带宽）：把一个包的所有比特推上线路要多久。
      • 传播时延 = 信道长度 ÷ 电磁波在信道中的传播速率（光纤和铜线里约 2 × 108 m/s）：一个比特从一头跑到另一头要多久。
      • 排队时延和处理时延：在路由器里排队等候、检查转发要多久，随拥塞情况变化。
      • 总时延是四者之和。时延带宽积 = 传播时延 × 带宽：“线路里能同时装下多少比特”。往返时间 RTT：从发出到收到确认的时间。

      直觉：带宽像马路的车道数，传播时延像马路的长度。车道再多，从北京开到广州也要那么久；文件很大时，发送时延（车流量）才是瓶颈。

      典型题 · 原创

      （1）主机 A 经一条长 2000 km 的光纤链路（传播速率 2 × 108 m/s，带宽 100 Mb/s）向 B 发送一个 106 字节的文件，忽略首部和处理时延，从 A 开始发送到 B 收完最后一个比特要多久？（2）这条链路的时延带宽积是多少比特？（3）若 A 和 B 之间经过一个存储转发的路由器（两段链路各 1000 km、带宽都是 100 Mb/s），文件作为一个整体转发，所需时间又是多少？

      看解答

      （1）发送时延 = 8 × 106 b ÷ 108 b/s = 0.08 s；传播时延 = 2 × 106 m ÷ 2 × 108 m/s = 0.01 s；共 0.09 s。

      （2）0.01 s × 108 b/s = 106 比特。

      （3）存储转发要先完整收下再发：两次发送时延 2 × 0.08 = 0.16 s，加两段传播 0.005 + 0.005 = 0.01 s，共 0.17 s。如果把文件切成很多小分组，分组可以在两段链路上“流水”地走（第十五章！），总时间接近 0.08 + 0.01 + 一个小分组的发送时延，这就是分组交换的好处之一。

      分组交换和端到端

      二十世纪六十年代，美国的保罗·巴兰和英国的唐纳德·戴维斯各自提出了把消息切成小块分别传送的想法，前者着眼于网络在部分节点被摧毁时仍能工作，后者起了“分组”这个名字。1969 年的阿帕网把它变成了现实（这段历史在《计算机创世记》里）。

      1984 年，萨尔茨、里德和克拉克的论文《系统设计中的端到端论点》总结了互联网的一个核心思想：像“保证不丢、按顺序、加密”这类功能，只有通信的两端才能真正做对，所以应该放在两端的电脑里（传输层、应用层），中间的网络只管尽力把包往前送，可以丢、可以乱序。“傻网络、聪明终端”让互联网能容纳当初没人想到的应用；代价是每个应用都得自己处理丢包和重传，下一章的 TCP 就是干这个的。

      IP 地址：门牌号

      寄信要写地址。网上的每台设备也有地址，叫 IP 地址。最常见的写法，是四个 0 到 255 的数，中间用点隔开，比如 192.168.1.23。每个数正好是一个字节（第二章），四个字节一共 32 个比特。

      家里的地址和路由器

      挂号信和明信片

      送信有两种寄法：

      • TCP 像挂号信：寄之前先打招呼（“在吗？”“在！”“好，我要寄了”）；寄出去的每一份，都要对方回一张收条，没收到收条就重寄；到了还要按顺序排好。打开网页、聊天，用的都是它。
      • UDP 像明信片：直接扔进邮筒，丢了就丢了，也不管先后，可是快。语音通话、很多网络游戏用它：晚到的声音，还不如不要。

      IP 地址：门牌号

      家里的地址和路由器

      有几段地址被规定为私有地址，只在家里、学校里用，不会出现在公网上，比如 192.168.x.x、10.x.x.x。你家的 Mac、手机、平板都拿到一个这样的地址，而整个家对外只有路由器上的一个公网地址。路由器替大家收发：你发出去的包，它把发件人地址换成自己的公网地址，记下“这是谁的”；回来的包再换回你的私有地址交给你。这叫地址转换（NAT）。所以全世界很多家庭的 Mac 都叫 192.168.1.x，互不冲突。

      挂号信和明信片

      • UDP：像明信片。不打招呼、不编号、不确认，丢了就丢了，但快、开销小。视频通话、网络游戏的实时位置用它：晚到的旧画面不如直接丢掉。

      子网和 CIDR

      IP 地址分两部分：前面的网络号和后面的主机号。早年按首几位分成 A、B、C 类（网络号固定 8、16、24 位），太浪费，现在用 CIDR（无分类域间路由）：写成 192.168.1.0/24，“/24”表示前 24 位是网络号。对应的子网掩码是前 24 位全 1：255.255.255.0。用 IP 和掩码按位与就得到网络号；两台主机的网络号相同，才能直接通信，否则要交给路由器（默认网关）。

      • 网络地址：主机号全 0；广播地址：主机号全 1；两者都不能分给主机，所以 /n 的网络可用主机数为 232−n − 2。
      • 子网划分：从主机号借几位作子网号。/24 借 2 位得到 4 个 /26 子网，每个 62 台主机。
      • 路由聚合：几个连续的网络找出最长公共前缀，合并成一条路由；路由器转发时按最长前缀匹配。
      • ARP：同一个网络里，知道对方 IP 不够，链路层要 MAC 地址（第三十章）。ARP 广播问“谁是 192.168.1.1？”，主人回答自己的 MAC。终端里 arp -a 能看到缓存的对照表。

      TCP

      TCP 首部至少 20 字节：源端口、目的端口、序号（本报文段数据第一个字节的编号）、确认号（期望收到对方下一个字节的编号，即“这之前的我都收到了”）、首部长度、标志位（SYN、ACK、FIN、RST 等）、窗口（我还能收多少字节）、校验和。

      • 三次握手：客户端 SYN（seq = x）→ 服务器 SYN + ACK（seq = y，ack = x + 1）→ 客户端 ACK（seq = x + 1，ack = y + 1）。为什么要三次：双方都要确认对方能收也能发，并交换各自的初始序号；两次的话，一个迟到的旧 SYN 可能让服务器白白建立连接。SYN 和 FIN 虽然不带数据，也要消耗一个序号。
      • 四次挥手：A 发 FIN → B 回 ACK（此时 B 还可以继续发数据，叫半关闭）→ B 发完了也发 FIN → A 回 ACK，然后等 2MSL（报文最长寿命的两倍）才真正关闭（TIME_WAIT），以防最后的 ACK 丢了 B 重发 FIN 时没人应，也让旧连接的迟到报文在网络里消失。
      • 可靠传输：超时重传；累计确认；滑动窗口：不必每发一个就等确认，可以连续发出窗口允许的量（第十五章的流水线思想），窗口大小 = min(接收方通告的窗口, 拥塞窗口)。
      • 拥塞控制（408 必考）：慢开始，拥塞窗口 cwnd 从 1 个最大报文段开始，每经过一个 RTT 翻倍，到达门限 ssthresh 后进入拥塞避免，每个 RTT 只加 1；出现超时，ssthresh 设为当前 cwnd 的一半，cwnd 回到 1 重新慢开始；收到 3 个重复确认，快重传（不等超时立刻重发丢的那个），并快恢复：ssthresh 设为 cwnd 的一半，cwnd 设为新的 ssthresh，直接进入拥塞避免。

      UDP 首部只有 8 字节（源端口、目的端口、长度、校验和），无连接、不可靠、没有拥塞控制。DNS 查询一般用 UDP 的 53 号端口；主机向本地 DNS 服务器的查询通常是递归的（“你帮我查到底”），本地服务器向根、顶级域、权威服务器的查询通常是迭代的（“我不知道，你去问它”）。

      面试题

      TCP 为什么是三次握手、四次挥手？TIME_WAIT 有什么用？

      看要点

      握手要让双方都确认“对方能收到我的、我能收到对方的”，并同步各自的初始序号；第二次把服务器的 SYN 和对客户端的 ACK 合在一起，所以是三次；也防止历史连接请求引起错误。挥手是因为 TCP 是全双工的，两个方向要分别关闭：收到 FIN 只说明对方不再发，自己可能还有数据要发，ACK 和 FIN 往往不能合并，所以是四次。TIME_WAIT 等 2MSL：保证最后一个 ACK 能被重传（若对方没收到会重发 FIN），并让本连接的旧报文在网络中消失，不干扰之后同一对端口的新连接。

      最后 8 位里前 2 位为 1：11000000 = 192。

      26 − 2。

      IPv6

      IPv4 地址不够用，1990 年代就设计了 IPv6：128 位地址，写成 8 组十六进制，如 2001:db8::1（连续的零可以用 :: 省略）。地址多到可以给每台设备一个全球唯一的地址，不再需要 NAT。普及走了二十多年，至今仍和 IPv4 并存；networksetup -getinfo Wi-Fi 的输出里可能就有你的 IPv6 地址。

      那把锁：TLS

      TCP 只保证不丢、按顺序，不保证别人看不见、改不了。浏览器地址栏的锁表示这个连接用了 TLS：握手时服务器出示由可信机构签名的证书证明“我真的是 apple.com”，双方用公钥密码协商出一把只有它们知道的密钥，之后所有数据加密传输，还带校验防篡改。HTTPS 就是“HTTP 跑在 TLS 上”。下一章的 curl -v 能看到这段握手。

      QUIC 和 HTTP/3

      TCP 有两个老毛病：建立连接再加 TLS 握手要好几个来回；一个包丢了，后面所有数据都得等它（队头阻塞）。谷歌提出、后来标准化的 QUIC 干脆在 UDP 上重新实现可靠传输、拥塞控制和加密，握手合并成一两个来回，多条数据流互不阻塞，手机从 Wi-Fi 切到蜂窝网络连接也不断。HTTP/3 就跑在 QUIC 上。这是第三十章“端到端原则”的又一个例子：新功能做在两端，中间的网络不用改。

      互联网也会“迷路”

      各大网络之间用 BGP 协议互相宣告“哪些地址可以从我这儿走”。2021 年 10 月，一家大型社交网络公司在一次配置变更中，意外撤回了自己网络的路由宣告，它的 DNS 服务器随之从互联网上“消失”，旗下几个应用全球中断约六个小时，据报道员工连门禁卡都刷不开。DNS、BGP 这些底层系统平时没人注意，一出错就是全世界的大事。

      一道题，四门课

      “从在浏览器输入网址到页面显示，发生了什么？”几乎是每个后端、前端、系统岗位面试都会问的题。好的回答先给一个清楚的骨架，再看面试官的兴趣往某一步深挖：

      1. 输入和解析：键盘中断 → 浏览器进程收到事件；解析 URL（协议、域名、端口、路径），检查 HSTS、缓存。可展开：中断处理（第二十五章）、进程和线程（第二十六章）、字符编码（第五章）。
      2. DNS 解析：浏览器缓存 → 系统缓存 → 本地 DNS 服务器（递归）→ 根、顶级域、权威服务器（迭代）；UDP 53。可展开：第三十一章。
      3. 建立连接：socket、connect 系统调用；TCP 三次握手；TLS 握手（证书验证、密钥协商）；HTTP/3 则是 QUIC。可展开：拥塞控制、TIME_WAIT。

      5. 服务器处理：负载均衡 → 服务器进程（线程池、并发和锁）→ 读文件或数据库（文件系统、页缓存）→ 生成响应。可展开：第二十六至二十九章。
      6. 接收和渲染：解析 HTML、CSS，构建 DOM 和渲染树，执行 JavaScript（解释和即时编译，W^X），布局、绘制、合成，GPU 写入帧缓冲，显示器刷新。可展开：内存分配（第二十一章）、虚拟内存（第二十七章）、指令和流水线（第十四、十五章）、缓存（第十六章）、像素和显存带宽（第六章）。

      第三层 · 深入时间花在哪里，往下读什么约 20 分钟一次网页访问的时间账；为什么工程师总在和“往返”较劲；这套书之外的经典读物和公开课。

      时间账

      一次打开网页的时间，处理器算东西的部分通常只占很小的一块，大头在等：等 DNS、等 TCP 握手、等 TLS 握手、等服务器、等数据一包一包地到。每一次往返都要几十毫秒，所以现代网络技术的很多发明都在“省往返”：DNS 缓存、连接复用（一个 TCP 连接发很多请求）、TLS 1.3 把握手从两个往返减到一个、QUIC 把 TCP 和 TLS 的握手合并、内容分发网络（CDN）把服务器搬到离你近的城市。第十六章说“缓存让手边的小抽屉够用”，在网络上是同一个道理，只是“抽屉”变成了遍布世界的服务器。从晶体管到洲际光缆，计算机系统设计的大部分工作，都是在不同的层次上对付“远”和“慢”。
