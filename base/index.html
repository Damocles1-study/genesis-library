    第一部 · 位

    一台电脑里只有一样东西：开和关。这本书从一个开关讲起：数、字、图片和声音怎样变成一串开关，开关怎样搭成会算数的电路、会执行指令的处理器，一行 C 代码怎样变成内存里跑着的程序，操作系统怎样管着它，网络怎样把它和世界连起来。

    它是“一层一层”系列的第一本，后面的数据结构、计算机组成、操作系统、计算机网络都站在它上面。写给两种读者：小学高年级起步的初学者（学过图形化编程、会一点 Python 就够了），和想把基础重新打牢的计算机专业学生。

      多级层次结构，翻译和解释

      教材里常把计算机画成一叠“虚拟机器”：最底下是硬件直接执行的机器语言（再往下是控制它的微程序或硬连线逻辑），往上依次是操作系统、汇编语言、高级语言，最上面是应用。每一级对上一级来说就是一台“机器”：写 Python 的人面对的是一台“Python 机器”。

      上一级的程序要变成下一级能执行的东西，有两种办法：

      • 翻译（编译）：一次性把整个程序翻成下一级的语言，存起来以后再执行。C 用 clang 编译成机器指令，就是翻译。汇编语言到机器语言的翻译叫汇编。
      • 解释：一边读一边执行，读一句做一句。传统的命令行脚本是解释执行的。

      真实系统常常混着用：CPython 先把 Python 源码编译成“字节码”，再由一个用 C 写的解释器一条一条执行字节码；Java 先编译成字节码，再由虚拟机解释或即时编译成机器指令。考题里问“翻译程序和解释程序的区别”，答“是否生成目标程序”即可。

      冯·诺依曼结构（预告）

      1945 年，冯·诺依曼起草的 EDVAC 报告草稿描述了一种结构：运算器、控制器、存储器、输入设备、输出设备五大部件；指令和数据都用二进制，放在同一个存储器里，按地址访问；指令按顺序执行（可以跳转）。这就是“存储程序”的思想，今天几乎所有电脑都还是这个样子。现代的说法常把运算器和控制器合起来叫 CPU，把存储器分成主存和外存。第十三章会亲手造一台这样的小机器。

      性能指标

      408 第一章必考的几个量：

      • 主频 f：时钟每秒跳几下，单位 Hz。3 GHz 就是每秒 3×109 下。时钟周期 T = 1/f。
      • CPI（每条指令平均几个时钟周期）。
      • CPU 时间 = 指令条数 × CPI × T = 指令条数 × CPI ÷ f。这是唯一靠得住的性能衡量：主频高不一定快，CPI 也要看。
      • MIPS（每秒百万条指令）= f ÷ (CPI × 106)。不同指令集的 MIPS 不能直接比，因为一条指令干的活不一样多。
      • 注意单位：说存储容量时 K、M、G 常按 210、220、230；说主频、速率时按 103、106、109。第二章细讲。
      典型题 · 原创

      某程序在一台主频 2 GHz 的机器上执行，共执行 4×109 条指令，其中 50% 是运算指令（CPI = 1），30% 是访存指令（CPI = 3），20% 是转移指令（CPI = 2）。求平均 CPI、CPU 时间和 MIPS。

      看解答

      平均 CPI = 0.5×1 + 0.3×3 + 0.2×2 = 0.5 + 0.9 + 0.4 = 1.8。

      CPU 时间 = 4×109 × 1.8 ÷ (2×109) = 3.6 秒。

      MIPS = 2×109 ÷ (1.8 × 106) ≈ 1111。

      常见错误：把各类 CPI 直接平均成 (1+3+2)/3 = 2，忘了按比例加权。

      面试题

      从按下电源键到看到登录界面，大致发生了什么？（以 Apple Silicon 的 Mac 为例）

      看要点

      芯片里固化的 Boot ROM 先运行，检查并加载下一级的引导程序（LLB、iBoot），每一级都校验下一级的签名；iBoot 加载 macOS 内核；内核初始化内存管理、驱动，启动第一个用户进程 launchd（进程号 1）；launchd 再按配置启动各种后台服务和登录窗口。PC 上类似：固件（UEFI）→ 引导程序 → 内核 → 第一个用户进程（Linux 上常是 systemd）。答出“固件 → 引导 → 内核 → 第一个用户进程”这条链和“逐级校验”就够了，第二十五章细讲。

      某机器上 60% 的指令 CPI 为 1，40% 的指令 CPI 为 3，平均 CPI 是多少？

      0.6×1 + 0.4×3 = 1.8。

      编译执行和解释执行的根本区别是？

      1. 编译执行更慢
      2. 编译会生成一个目标程序，解释不生成，边读边执行
      3. 解释只能用于汇编语言

      是否生成目标程序。

      冯·诺依曼结构最核心的思想是？

      1. 用晶体管代替电子管
      2. 用十进制计算
      3. 存储程序：指令和数据都以二进制放在同一个存储器里

      存储程序。

      主频 1 GHz，程序执行 109 条指令，平均 CPI = 2，CPU 时间是多少秒？

      109 × 2 ÷ 109 = 2 秒。

      为什么不同指令集的机器不能只比 MIPS？

      1. 一条指令完成的工作量不同
      2. MIPS 的单位不一样
      3. MIPS 只能用来比内存

      一条复杂指令可能顶好几条简单指令，比“每秒多少条”没有意义，要比完成同一个程序的 CPU 时间。

      抽象会漏

      2002 年，程序员乔尔·斯波尔斯基写了一篇短文，提出“抽象泄漏定律”：所有不平凡的抽象，在某种程度上都会漏。意思是，下面那层楼的细节总会在某个时候冒上来，逼你去懂它。这本书里会反复碰到：

      • 在 Python 里 0.1 + 0.2 == 0.3 是 False：浮点数的表示冒上来了（第四章）。
      • 两段一模一样的二维数组求和，一段按行遍历、一段按列遍历，速度可以差好几倍：缓存冒上来了（第十六章）。
      • 一个计数器加到二十一亿多突然变成负数：补码和字长冒上来了（第三章）。
      • 两个线程各自给同一个变量加一万次，结果不到两万：内存和指令的细节冒上来了（第二十九章）。

      所以“重打基础”不是背更多名词，而是在每个抽象漏掉的地方，知道往下看哪一层。

      问问 Mac 的缓存3 分钟
      % sysctl hw.cachelinesize hw.l1dcachesize hw.l2cachesize
% sysctl hw.perflevel0 hw.perflevel1 2>/dev/null | grep -i cache

      第一行给出缓存行大小和一级、二级数据缓存的大小（单位字节）。Apple Silicon 有“性能核”和“能效核”两种核心，第二行分别列出它们的缓存。缓存行在 Apple Silicon 上多半是 128 字节，英特尔机器多半是 64 字节。先记下来，第十六章会用程序把它“量”出来，和这里的数对一对。

      “抽象泄漏定律”说的是？

      1. 抽象层越多越安全
      2. 下层的细节总会在某些时候影响上层，逼你去了解它
      3. 内存会泄漏

      任何不平凡的抽象都会在某种程度上漏出底层细节。

      Apple Silicon 的 Mac 上有哪两种 CPU 核心？

      1. 性能核和能效核
      2. 整数核和浮点核
      3. 内核和外核

      性能核（performance）快、耗电多，能效核（efficiency）慢、省电；系统把任务在两种核之间分配。

      下面哪一件事不是本书举的“抽象会漏”的例子？

      1. 0.1 + 0.2 不等于 0.3
      2. 按列遍历数组更慢
      3. Python 的缩进必须对齐

      缩进是 Python 语法本身的规定，不是下层细节冒上来。

      一个比特，两种情况

      一盏灯，要么开，要么关。一个问题，要么“是”，要么“不是”。这种只有两种情况的东西，用 1 和 0 来记，一个这样的 1 或 0 就叫一个比特（bit，来自 binary digit，二进制数字）。

      一个比特只能分两种情况。两个比特呢？00、01、10、11，四种。三个比特：000 到 111，八种。每多一个比特，情况就翻一倍：

      比特数123481632
      能分几种2481625665536约 43 亿

      红绿灯有红、黄、绿三种情况，一个比特不够，两个比特够了（还空出一种）。一个班四十个同学，要给每人一个不重复的号码，五个比特只有 32 种，不够；六个比特有 64 种，够了。

      电压，和会抖的“手指头”

      电脑里的 1 和 0 是电。电线里的电压像水管里的水压：压力高，水就冲得猛。芯片里一根线，要么电压接近 0（记作 0），要么接近供电的电压（记作 1）。今天的芯片里，“高”往往还不到一伏。

      问题是：电压从来不是稳稳的。旁边的线在变、温度在变、电源有点波动，读出来的电压总在抖，这种乱抖叫噪声。如果只分“高”和“低”两档，中间留着一大段空当，抖一点也不会认错。如果像十进制那样分十档，档和档挨得很近，稍微一抖就从 6 抖成了 7。下面的装置让你亲眼看看。

      两档还是十档

      电线上送出 200 个信号，每个信号是某一档电压。接收的一方按虚线分档去认。把“噪声”往右拖，看哪种分法先开始认错。

      把噪声拖到中间，十档已经错了一大片，两档几乎还是全对。这就是电脑用二进制的根本原因：不是因为二进制好算，而是因为两档最不怕抖。好算是附带的好处。

      二进制怎样数数

      十进制里，每一位的“分量”是 10 的倍数：个位是 1，十位是 10，百位是 100。305 的意思是 3 个 100、0 个 10、5 个 1。

      二进制一样，只是每一位的分量翻一倍：从右往左是 1、2、4、8、16、32、64、128……这叫位权。二进制 1101 的意思是：1 个 8、1 个 4、0 个 2、1 个 1，加起来 8 + 4 + 1 = 13。

      反过来，十进制 13 怎样写成二进制？像用天平称东西，手里有一套砝码 8、4、2、1，从大的开始放：8 放得下（剩 5），记 1；4 放得下（剩 1），记 1；2 放不下，记 0；1 放得下（剩 0），记 1。读出来就是 1101。

      任意进制：基数和位权

      r 进制有 r 个数码（0 到 r−1），第 i 位（个位是第 0 位，小数点后第一位是第 −1 位）的位权是 ri。一个 r 进制数的值就是“按权展开”：

      (dn−1…d1d0.d−1d−2…)r = Σ di × ri

      例：(1011.01)2 = 8 + 2 + 1 + 0.25 = 11.25；(17)8 = 8 + 7 = 15；(2F)16 = 32 + 15 = 47。

      十进制转 r 进制

      • 整数部分：除 r 取余，倒着读。13 ÷ 2 = 6 余 1，6 ÷ 2 = 3 余 0，3 ÷ 2 = 1 余 1，1 ÷ 2 = 0 余 1，从下往上读：1101。道理：每除一次 r，就把最低位“挤”出来成为余数。
      • 小数部分：乘 r 取整，顺着读。0.375 × 2 = 0.75 取 0，0.75 × 2 = 1.5 取 1，0.5 × 2 = 1.0 取 1，得 0.011。道理：每乘一次 r，就把小数点后第一位“挤”到整数部分。
      • 有的十进制小数在二进制里写不尽：0.1 × 2 = 0.2 取 0，0.4 取 0，0.8 取 0，1.6 取 1，1.2 取 1，又回到 0.2……于是 (0.1)10 = (0.0001100110011…)2，无限循环。原因：十进制分母只含 2 和 5，二进制分母只能含 2，分母里有 5 的就除不尽。这是第四章“0.1 + 0.2 ≠ 0.3”的根。

      二、八、十六进制直接互换

      8 = 23，16 = 24，所以从小数点往两边，每 3 位二进制对应 1 位八进制，每 4 位对应 1 位十六进制，不够的补 0（整数部分往左补，小数部分往右补）。例：(1011010.1)2 → 001 011 010 . 100 → (132.4)8；→ 0101 1010 . 1000 → (5A.8)16。

      BCD 码

      有时候人们想让二进制“看起来像十进制”：每个十进制数字单独用 4 位二进制表示，这叫 BCD 码（二进制编码的十进制）。最常见的 8421 码就是每位按 8、4、2、1 加权：十进制 59 → 0101 1001。4 位能表示 16 种，只用了 0000—1001 十种，1010—1111 六种不用。两个 BCD 数相加，如果某一位结果大于 9 或产生进位，要加 6（0110）修正，跳过那六个不用的码。计算器、老式数码管、金融软件里还在用它，因为它避免了十进制小数转二进制的误差。

      表示 N 种状态要几位

      n 位二进制能表示 2n 种状态，所以表示 N 种状态至少要 ⌈log2N⌉ 位（⌈⌉ 是向上取整）。这个式子在 408 里到处出现：地址线有几根、指令操作码有几位、页号有几位，都是它。

      对数：乘方倒过来

      210 = 1024，反过来问“2 的几次方是 1024？”答案 10 就叫以 2 为底 1024 的对数，写作 log21024 = 10。常用的几个记住：log21024 = 10，log2(106) ≈ 20，log2(109) ≈ 30。一个数在二进制里有几位，大约就是它的 log2。

      噪声容限和再生

      数字电路规定了四个电压门槛：输出“低”时最多 VOL，输出“高”时至少 VOH；输入时，低于 VIL 才认作 0，高于 VIH 才认作 1。中间那段是“不许停留”的禁区。于是：

      低电平噪声容限 NML = VIL − VOL，高电平噪声容限 NMH = VOH − VIH

      只要线上叠加的噪声小于容限，下一个门就一定认得对。更妙的是，每个门的输出都会被“拉回”满幅的高或低，叫再生：信号每过一个门就被擦干净一次，噪声不会一级一级累积。模拟信号做不到这一点，复印一百次的照片会越来越糊，而复制一百次的文件一个比特都不差。这是“数字”真正的力量。

      多值是可以的，只是要付代价

      二进制不是物理定律。U 盘和固态硬盘里的闪存单元，靠困住的电荷多少来记数：只分两档叫 SLC，一格 1 比特；分 4 档叫 MLC，一格 2 比特；8 档 TLC，3 比特；16 档 QLC，4 比特。档越多越便宜（同样的芯片存得更多），可是档和档挨得越近，读写越慢、越容易出错、能擦写的次数越少，必须靠更强的纠错码（第八章）兜底。你 Mac 里的固态硬盘，多半就是 TLC 加纠错码。

      历史上也有人造过三进制计算机。1958 年莫斯科大学造出的 Сетунь（Setun）用“平衡三进制”，每一位是 −1、0、+1，负数不用额外的符号位。它造了几十台，后来被二进制机器取代，主要输在元件和生态上，不是输在数学上。

      信息量：一个比特到底是多少

      1948 年，香农在《通信的数学理论》里把“信息”变成了能算的量：从 N 个同样可能的结果里确定一个，得到的信息是 log2N 比特。抛一枚公平的硬币，1 比特；从 1 到 100 里猜一个数，log2100 ≈ 6.64 比特。所以“我心里想一个 1 到 100 的数，你只能问是或不是”，最少要问 7 次，每次把范围砍掉一半，这就是二分查找。“比特”这个词据说是统计学家约翰·图基起的，香农在这篇论文里用开了它。

      结果不是同样可能的时候，平均信息量是熵 H = −Σ pi log2 pi。一枚正面概率 0.9 的硬币，熵只有约 0.47 比特：结果太好猜，每次知道结果没得到多少新东西。压缩（第六章）能压多少，上限就由熵决定。

      有 1000 瓶酒，其中一瓶有毒，毒性在 24 小时后发作。你有一天时间，最少要几只小白鼠才能找出毒酒？

      看思路

      10 只。把瓶子编号 0—999，写成 10 位二进制；第 i 只老鼠喝所有第 i 位是 1 的酒。一天后，死了的老鼠记 1、活着的记 0，十只老鼠拼出的二进制就是毒酒的编号。210 = 1024 ≥ 1000，每只老鼠的生死正好是 1 比特信息。

      八个比特一捆

      一个比特太小，干不了什么事。电脑通常把八个比特捆成一捆来用，这一捆叫一个字节（byte）。一个字节有 28 = 256 种样子，可以表示 0 到 255 的一个数，或者一个英文字母、一个数字、一个标点（第五章讲怎样表示）。

      为什么是八个？早年的电脑各有各的捆法，六个、七个、九个都有。1964 年，IBM 推出 System/360 系列电脑，规定一个字节就是 8 位；这个系列卖得极好，大家就都跟着用了。8 还是 2 的整数次方，切成两半是 4 位，正好配十六进制。

      十六进制：给人看的二进制

      二进制对电脑方便，对人眼太累：1011010011110001，数都数不清。于是人们每 4 位分一组，每组换成一个符号。4 位有 16 种样子，0 到 9 不够用，就借 A、B、C、D、E、F 表示 10 到 15。这就是十六进制（hexadecimal，常简称 hex）。

      二进制00000001…1001101010111100110111101111
      十六进制01…9ABCDEF
      十进制01…9101112131415

      上面那串就变成：1011 0100 1111 0001 → B4F1。一个字节正好是两个十六进制数字，从 00 到 FF。为了不和十进制搞混，程序里写十六进制常在前面加 0x：0xFF 就是 255。网页上的颜色 #FF8800 也是十六进制，三个字节分别是红、绿、蓝（第六章）。

      只要背熟 A 到 F 是 10 到 15，再记住 8、4、2、1 四个位权，二进制和十六进制就能心算互换：C 是 12 = 8 + 4，所以是 1100。

      文件就是一串字节

      你电脑里的每一个文件，照片、歌、Word 文档、游戏存档，打开来看，都只是一长串字节。区别只在于怎样“读”这串字节：当成文字读，当成像素读，还是当成声音读。下面亲眼看看。

      字、字长、编址

      字长是 CPU 一次能处理的二进制位数，通常等于通用寄存器的宽度。Apple Silicon 是 64 位，寄存器 64 位，地址也按 64 位算。字的长度没有统一规定：408 题里一个“字”可能是 16 位或 32 位，要看题目；x86 的老传统里 word 是 16 位；ARM 的 word 是 32 位。

      现代机器几乎都按字节编址：每个地址对应一个字节，一个 4 字节的整数占四个连续地址，它的“地址”指最小的那个。按字编址的机器（每个地址一个字）在考题里也会出现，换算时注意：容量 ÷ 编址单位 = 地址个数，log2(地址个数) = 地址位数。

      大端和小端

      一个多字节的数放进按字节编址的内存，先放哪头？0x12345678 存在地址 0x100 开始的四个字节里：

      • 大端（big-endian）：高位字节放低地址。0x100 → 12，0x101 → 34，0x102 → 56，0x103 → 78。像人写数字一样“从大头开始”。网络协议规定在线上传输时用大端，所以大端也叫“网络字节序”。
      • 小端（little-endian）：低位字节放低地址。0x100 → 78，0x101 → 56，0x102 → 34，0x103 → 12。x86 和 Apple Silicon（ARM 在 macOS 下运行于小端模式）都是小端。

      字节序只影响“多字节的数在内存里的排法”，不影响一个字节内部的比特顺序，也不影响字符串（字符串本来就是一个字节一个字节按顺序放的）。

      两个词的来历

      “byte”是 IBM 的维尔纳·布赫霍尔茨 1956 年在设计 Stretch 计算机时起的，故意把 bite（咬一口）改拼成 byte，免得和 bit 看错。那时一个 byte 的位数还不固定。正因为 byte 曾经不一定是 8 位，网络标准里至今用 octet（八位组）来指“正好 8 位”。

      “大端、小端”出自《格列佛游记》：小人国为吃鸡蛋该先敲大头还是小头打了一场仗。1980 年，丹尼·科恩写了一篇《论圣战，并呼吁和平》，借这个典故讽刺工程师为字节序吵个不停，这两个词就这样留了下来。这件事本身也是一个教训：两种做法各有道理时，重要的不是谁对，而是大家约定好一种（网络字节序）。

      最直接的办法，和它的麻烦

      最容易想到的：拿出最左边一位当“符号”，0 表示正，1 表示负，剩下的位写大小。8 位里，0000 0011 是 +3，1000 0011 是 −3。这叫原码。

      它有两个麻烦。第一，0000 0000 是 +0，1000 0000 是 −0，一个零有两种写法，比较“等不等于零”时很别扭。第二，做加法前得先看符号：同号就加，异号就要比大小、大的减小的、再决定结果的符号。电路要为这些情况各造一套，又大又慢。有没有办法让减法也只用加法器？

      钟面的秘密

      墙上的钟现在指着 5 点。要往回拨 3 小时，可以逆着拨 3 格；也可以顺着拨 9 格，同样到 2 点。在钟面上，减 3 和加 9 是一回事，因为 3 + 9 = 12，正好转一整圈。数学上说：在“模 12”的世界里，−3 和 9 相等。

      模：转一圈回到原处

      “模 12”就是只关心除以 12 的余数。14 点就是下午 2 点，因为 14 除以 12 余 2。星期也是模 7：今天星期三，过 10 天是星期几？10 除以 7 余 3，星期三往后 3 天，星期六。电脑里 4 个比特的数，一共 16 种，从 0000 数到 1111 再加一就回到 0000，它活在“模 16”的世界里；8 个比特是“模 256”。

      4 个比特像一个有 16 格的钟面。我们约定：把钟面右半边（0 到 7）当正数，左半边（8 到 15）当负数。−3 写成哪一格？往回拨 3 格，就是 16 − 3 = 13，1101。这种写法叫补码。

      好处马上就来了：算 5 + (−3)，就是 0101 + 1101 = 1 0010，第五位放不下被扔掉，剩下 0010，正好是 2。减法变成了加法，而且零只有一种写法 0000。

      四位的钟面

      指针指着的那一格就是现在的 4 个比特。外圈是把它当成“没有负数”时的值（0 到 15），内圈是当成补码时的值（−8 到 7）。点按钮转动指针，看什么时候会“翻过头”。

      取反加一

      每次都去算“16 − 3”太累。有个速算法：先写出正数，把每一位都翻过来（0 变 1，1 变 0），再加一。

      • 4 位的 −3：3 是 0011，翻过来 1100，加一 1101。和上面一样。
      • 8 位的 −1：1 是 0000 0001，翻过来 1111 1110，加一 1111 1111。全是 1 就是 −1，这个值得记住。
      • 8 位的 −64（游戏里最低的 y）：64 是 0100 0000，翻过来 1011 1111，加一 1100 0000。

      为什么灵？把一个数和它“翻过来”的样子加在一起，每一位都是 1，也就是 1111，再加一就是 1 0000，转了一整圈回到 0。所以“翻过来再加一”正好是它的相反数。

      8 位补码能表示 −128 到 +127：正数最大 0111 1111 = 127，负数最小 1000 0000 = −128。负数比正数多一个，因为零占了正数那边的一格。看最左边一位就知道正负：0 是正（或零），1 是负。

      溢出：翻过头了

      127 再加 1 会怎样？0111 1111 + 1 = 1000 0000，这在补码里是 −128。一个很大的正数，加一变成了很小的负数，这叫溢出。电脑不会自己报错，它只是忠实地转过了那一格。

      求补和变号

      • 由原码求补码：符号位不变，数值位取反加一。快捷法：从右往左，第一个 1 及它右边的 0 不变，左边的数值位全取反。例：[−0101100]原 = 1 0101100 → 补码 1 1010100。
      • 由 [x]补 求 [−x]补：连同符号位一起取反加一。例：[x]补 = 1101 → [−x]补 = 0011。注意 −2n−1 变号后还是自己（8 位 −128 取反加一还是 1000 0000），这是溢出。
      • 由补码求真值：符号位为 1 时，真值 = −2n−1 + 其余各位的权值之和。例：1101 = −8 + 4 + 1 = −3。把最高位的权看成负的，这是最快的读法。

      扩展：变宽的时候补什么

      8 位变 16 位：无符号数高位补 0（零扩展）；补码高位补符号位（符号扩展）。−3 的 8 位补码 1111 1101 → 1111 1111 1111 1101，仍是 −3。原码扩展则是符号位移到最高位、中间补 0。C 里 char c = -3; int i = c; 做的就是符号扩展；unsigned char 赋给 int 做零扩展。

      补码加减和溢出判断

      [x + y]补 = [x]补 + [y]补（mod 2n），[x − y]补 = [x]补 + [−y]补。只要结果在范围内，这两个式子就成立；超出范围就是溢出。只有同号相加（或异号相减）才可能溢出。判断方法：

      1. 看符号：两个加数符号相同，结果符号却不同，就溢出。
      2. 看进位：最高位（符号位）产生的进位 Cn 和次高位向最高位的进位 Cn−1 不同，就溢出：V = Cn ⊕ Cn−1。这是硬件实际用的办法。
      3. 双符号位（变形补码、模 4 补码）：用两位符号位运算，结果符号位 00 正、11 负、01 正溢出、10 负溢出。

      标志位

      处理器做完加减法，会顺手在“标志寄存器”里记下几件事。以 x86 的叫法：

      • ZF（零）：结果全是 0。SF（符号）：结果最高位。
      • CF（进位/借位）：把操作数当无符号数时，加法最高位有进位，或减法不够减有借位。CF = 1 表示无符号运算溢出了。
      • OF（溢出）：把操作数当补码时溢出了，OF = Cn ⊕ Cn−1。

      同一次加法，硬件同时算出 CF 和 OF，它不知道你心里把这串比特当无符号还是有符号。条件跳转指令替你选：无符号比较看 CF（和 ZF），有符号比较看 SF ⊕ OF（和 ZF）。ARM 的四个标志叫 N、Z、C、V，对应 SF、ZF、CF、OF；有一处不同：ARM 做减法时 C = 1 表示没有借位，正好和 x86 相反，读汇编时留意。

      补码为什么是对的

      n 位整数的加减乘，本质上是在模 2n 的整数环里运算。在这个环里，每个数都有唯一的加法逆元，−x 和 2n − x 是同一个元素。补码只是给每个剩余类挑了一个代表：把 0 到 2n−1−1 那一半当正数，另一半当负数。因为加法、减法、乘法（取低 n 位）都和“挑哪个代表”无关，同一个加法器、同一个乘法器既能算无符号数也能算补码，只有比较、除法、右移和变宽时才需要知道符号。早年 CDC 6600、PDP-1、UNIVAC 1100 系列用反码；IBM System/360 用补码；到今天，几乎所有处理器都是补码，C23 和 C++20 标准也正式规定了有符号整数必须用补码表示。

      C 里的两种溢出

      C 标准规定：无符号整数溢出按模 2n 回绕，是合法的；有符号整数溢出是“未定义行为”（UB），标准不管会发生什么。即使 C23 规定了补码表示，溢出仍然是 UB。编译器会利用这一点做优化：既然“有符号数不会溢出”，那么 x + 1 > x 就永远为真，可以直接删掉判断。

      看编译器删掉你的检查10 分钟 · 需要第三部的 C 基础

      在 ~/base 里新建 ub.c（可以用 nano ub.c，写完按 ⌃+O 回车保存、⌃+X 退出）：

      #include <stdio.h>
#include <limits.h>
int will_wrap(int x) { return x + 1 < x; }   /* 想检查 x+1 会不会溢出 */
int main(void) {
    printf("%d\n", will_wrap(INT_MAX));
    int r;
    printf("%d\n", __builtin_add_overflow(INT_MAX, 1, &r));
    return 0;
}
      % clang -O0 ub.c -o ub && ./ub
% clang -O2 ub.c -o ub && ./ub
% clang -O2 -fsanitize=undefined ub.c -o ub && ./ub

      不优化时第一行常打印 1；开了 -O2，编译器认定 x + 1 < x 不可能成立，直接返回 0，你的检查就这样消失了。第二行用编译器内置的 __builtin_add_overflow，它保证正确报告溢出（打印 1）。第三条命令打开“未定义行为消毒器”，运行时会指出哪一行溢出了。具体打印什么取决于编译器版本，这正是“未定义”的意思。

      写安全代码的几个办法：用 __builtin_add_overflow 一类的内置函数（C23 里标准化成了 ckd_add）；运算前先比较，如 if (x > INT_MAX - y)；必须回绕时用无符号数；调试时打开 -fsanitize=undefined；GCC 和 Clang 还有 -fwrapv，让有符号溢出也按补码回绕，代价是少一些优化。

      二进制的小数

      十进制里，小数点右边第一位是十分之一，第二位是百分之一。二进制同理，只是每次除以 2：小数点右边第一位是 1/2，第二位是 1/4，第三位是 1/8……

      • 0.1（二进制）= 1/2 = 0.5
      • 0.01 = 1/4 = 0.25；0.11 = 1/2 + 1/4 = 0.75
      • 0.101 = 1/2 + 1/8 = 0.625
      • 10.1 = 2 + 0.5 = 2.5

      能用 1/2、1/4、1/8 这些“一半的一半”凑出来的数，二进制都能写完。可是十进制的 0.1，也就是十分之一，凑不出来：0.0001100110011……永远循环下去。就像十进制写不完 1/3 一样，二进制写不完 1/10。电脑的存储是有限的，只好在某一位截断，存进去的其实是一个“非常接近 0.1”的数。

      0.1 和 0.2 各差一点点，加起来的误差刚好露了出来，于是 0.30000000000000004。这不是 Python 的毛病，几乎所有编程语言、所有电脑都一样。

      小数点会浮动

      科学计数法

      光速约 300000000 米每秒，写成 3 × 108；一粒细菌约 0.000002 米，写成 2 × 10−6。前面那个数叫有效数字，后面 10 的几次方叫指数。指数一变，小数点就跟着左右挪：这就是“浮动的小数点”。

      电脑存小数也用科学计数法，只是底数是 2：先存一个正负号，再存指数，再存有效数字。比如 6.5 = 110.1（二进制）= 1.101 × 22，就存“正、指数 2、有效数字 1.101”。这种存法叫浮点数（floating point），Python 里带小数点的数（float）都是这样存的。

      定点和浮点

      定点数的小数点位置固定：定点整数（小数点在最低位之后）和定点小数（小数点在符号位之后），第三章的补码讲的都是定点数。定点数的问题是范围和精度只能二选一。浮点数把数写成 N = (−1)S × M × RE：S 是符号，M 是尾数，R 是基数（通常为 2），E 是阶码。阶码的位数决定范围，尾数的位数决定精度。

      规格化：为了让尾数的有效位尽量多、表示唯一，要求尾数最高位是有效数字（基数为 2 时，原码尾数最高数值位为 1）。尾数不满足时左移、阶码减一（左规）；尾数溢出时右移、阶码加一（右规）。

      IEEE 754

      符号 S阶码 e尾数 f偏置规格化数的值
      单精度（float，32 位）1 位8 位23 位127(−1)S × 1.f × 2e−127
      双精度（double，64 位）1 位11 位52 位1023(−1)S × 1.f × 2e−1023
      • 隐藏位：规格化数的尾数总是 1.xxx，开头的 1 不存，白赚一位精度。所以单精度实际有 24 位有效位（约 7 位十进制），双精度 53 位（约 15—17 位十进制）。
      • 偏置：阶码用移码的变体存，偏置是 2k−1 − 1（单精度 127），而不是第三章移码的 2k−1。这样全 0 和全 1 两种阶码可以留作特殊用途。
      • 特殊值：e 全 0、f = 0 表示 ±0；e 全 0、f ≠ 0 是非规格化数，值为 (−1)S × 0.f × 2−126（注意不是 −127）；e 全 1、f = 0 表示 ±∞；e 全 1、f ≠ 0 表示 NaN（不是一个数，如 0/0）。
      • 范围（单精度）：最大约 (2 − 2−23) × 2127 ≈ 3.4 × 1038；最小正规格化数 2−126 ≈ 1.18 × 10−38；最小正非规格化数 2−149 ≈ 1.4 × 10−45。双精度最大约 1.8 × 10308。

      十进制 → 单精度的步骤，以 −0.75 为例：① 写成二进制 −0.11；② 规格化 −1.1 × 2−1；③ S = 1，e = −1 + 127 = 126 = 0111 1110，f = 1000…0（23 位，去掉隐藏的 1）；④ 拼起来 1 01111110 10000000000000000000000，四位一组 → 0xBF400000。

      浮点加减的五步

      1. 对阶：小阶向大阶看齐，阶小的尾数右移、阶码加一，直到两个阶码相等。为什么不让大阶向小阶看齐？大阶的尾数要左移，高位会丢，误差大；小阶右移只丢低位。
      2. 尾数加减。
      3. 规格化：结果不是 1.xxx 的形式，就左规或右规。
      4. 舍入：右移时丢掉的低位要处理，IEEE 754 默认“就近舍入，一样近时取偶数”（第三层）。
      5. 溢出判断：阶码超过最大值是上溢（结果为 ±∞），小于最小值是下溢（变成非规格化数或 0）。浮点数的溢出看阶码，不看尾数。

      舍入到偶数

      IEEE 754 规定了几种舍入方式，默认是“就近舍入，一样近时取偶数”（尾数最后一位为 0 的那个）。为什么不用小学的四舍五入？因为“五入”总是往一个方向偏，大量运算后误差会系统性地往上漂；取偶数让一半往上、一半往下，平均下来抵消。硬件在做运算时会多留三位：保护位（guard）、舍入位（round）和粘滞位（sticky，右移时只要丢掉的位里有一个 1，它就是 1），用它们判断“是不是正好一半”。Python 的 round(2.5) 得 2、round(3.5) 得 4，也是这个规则。

      非规格化数

      没有非规格化数时，最小的正数 2−126 和 0 之间是一道悬崖：两个不相等的小数相减，结果可能直接变成 0，于是 x != y 而 x − y == 0，后面一除就出事。非规格化数用 0.f × 2−126 把这道悬崖铺成一段均匀的斜坡，叫“逐级下溢”。这是 IEEE 754 的主要设计者威廉·卡亨坚持加进去的，当年有厂商嫌它难实现而反对。代价是：一些处理器处理非规格化数很慢，图形和音频程序常打开“清零”（flush-to-zero）模式，主动放弃它换速度。

      加法不满足结合律

      (a + b) + c 和 a + (b + c) 可能不同：(1e16 + 1) − 1e16 得 0，1e16 + (1 − 1e16) 也不是 1。所以并行求和（把数组分给多个核各自加再合并）每次结果可能有细微差别，编译器默认也不敢重排浮点运算（除非你打开 -ffast-math）。大量小数累加时，可以用威廉·卡亨提出的补偿求和：额外用一个变量记下每一步被舍掉的部分，下一步再补回去。

      def kahan_sum(xs):
    s = 0.0; c = 0.0          # c 记着被舍掉的零头
    for x in xs:
        y = x - c
        t = s + y
        c = (t - s) - y       # (t - s) 是真正加进去的，减去 y 得到丢掉的
        s = t
    return s
print(sum([0.1] * 10000), kahan_sum([0.1] * 10000))

      Python 自带的 math.fsum 用的是更精确的办法，结果是“正确舍入”的。第一层的装置里也能切换到补偿求和看效果。

      每个字一个编号

      电脑只能存数。要存文字，就得先约定一张表：哪个数代表哪个字。存的时候查表把字换成数，显示的时候再查表把数换回字。这张表叫字符编码。

      最有名的一张是 1963 年美国定的 ASCII（美国信息交换标准代码，读作“阿斯克”）。它用 7 个比特，一共 128 个编号，装下了英文大小写字母、数字、标点，和一些控制用的符号（比如换行）：

      字符空格09ABZabz换行
      十进制324857656690979812210
      十六进制20303941425A61627A0A

      这张表排得很聪明：字母按顺序排，所以“B 比 A 大 1”，排序时直接比编号就行；大写和小写正好差 32，也就是只差一个比特（第七章用它玩一个小把戏）；数字 0 到 9 是 48 到 57，把字符 '7' 变成数 7，只要减去 48。第二章看到的 68 65 6c 6c 6f，就是 hello 五个字母的 ASCII 码。

      汉字怎么办

      128 个编号装不下汉字。常用汉字就有好几千个，一个字节 256 种也不够，得用两个字节（65536 种）。1980 年中国发布了 GB 2312（“国标”），收了 6763 个汉字，每个字两个字节。后来扩展成 GBK、GB 18030，收的字越来越多。日本、韩国、台湾也各有各的表。

      麻烦来了：同样两个字节，在这张表里是“中”，在那张表里是别的字。用 A 表写的文件拿 B 表去读，就是一堆莫名其妙的字，这叫乱码。

      一张表装下全世界：Unicode

      1991 年起，一群公司和专家开始编一张总表：Unicode（统一码）。它给世界上每一种文字的每一个字一个唯一的编号，叫码位，写成 U+ 加十六进制：A 是 U+0041，汉是 U+6C49，😀 是 U+1F600。今天这张表已经有十五万多个字符，包括甲骨文之外的很多古文字、数学符号和表情符号。

      编号有了，怎样存成字节？最流行的办法叫 UTF-8：英文字母还是 1 个字节（和 ASCII 完全一样），大部分汉字 3 个字节，表情符号 4 个字节。第二章的小侦探活里，echo -n 你好 | xxd 打出 6 个字节，就是因为两个汉字各占 3 个。今天绝大多数网页和 Mac 上的文本文件都用 UTF-8。

      字符集和编码是两回事

      字符集回答“有哪些字、各是几号”，Unicode 是字符集，码位范围 U+0000 到 U+10FFFF（约 111 万个位置，目前用了一小部分）。编码方案回答“几号怎样存成字节”：UTF-8、UTF-16、UTF-32 是同一个字符集的三种存法。GBK、GB 18030 则既是字符集又是编码。面试问“Unicode 和 UTF-8 的区别”，就答这一句。

      例：汉 U+6C49 = 0110 1100 0100 1001，落在第三行。把 16 位从左到右填进 11100110 10110001 10001001，得 E6 B1 89。

      这套规则的好处：① 和 ASCII 完全兼容，老的英文程序照样能用；② 第一个字节的开头几个 1 说明一共几个字节，后续字节都以 10 开头，从任何位置开始读都能找到下一个字的起点（“自同步”），丢了一个字节只坏一个字；③ 除了 U+0000 本身，编码里不会出现 0 字节，C 语言用 0 表示字符串结尾的老习惯不受影响；④ 按字节比较的顺序和按码位比较的顺序一致；⑤ 没有字节序问题。

      UTF-16 和代理对

      UTF-16 用 2 个字节存 U+0000—FFFF（这一段叫“基本多文种平面”，BMP），超出的部分用两个 2 字节单元（代理对）：码位减去 0x10000 得到 20 位，高 10 位加上 0xD800 作第一个单元，低 10 位加上 0xDC00 作第二个单元。😀 U+1F600：减去 0x10000 得 0xF600 = 0000111101 1000000000，高 10 位 0x3D → D83D，低 10 位 0x200 → DE00。Java、JavaScript、Windows 内部都用 UTF-16。

      UTF-16 有字节序问题，所以文件开头常放一个 BOM（字节序标记，U+FEFF）：大端存成 FE FF，小端存成 FF FE。UTF-8 不需要 BOM，但 Windows 的记事本以前爱在 UTF-8 文件开头加 EF BB BF，这三个字节会让一些 Mac 和 Linux 上的程序出错。

      区位码、国标码、机内码

      GB 2312 把汉字排在 94 × 94 的表里，“第几区第几位”就是区位码（十进制，如“啊”在 16 区 01 位，1601）。为了避开 ASCII 的控制字符，区号和位号各加 32（0x20），得到国标码（啊：0x10+0x20 = 0x30，0x01+0x20 = 0x21，国标码 3021H）。为了和 ASCII 区分（ASCII 的最高位是 0），两个字节的最高位都置 1，即再加 0x80，得到计算机里实际存的机内码（啊：B0A1H）。总结：国标码 = 区位码（各自转十六进制）+ 2020H，机内码 = 国标码 + 8080H。

      典型题 · 原创

      （1）é 的码位是 U+00E9，写出它的 UTF-8 编码。（2）某汉字的区位码是 2630，求它的国标码和机内码。（3）字符串 "Hi你好👋" 在 UTF-8 和 UTF-16（不含 BOM）下各占多少字节？在 Python 和 JavaScript 里长度各是多少？

      看解答

      （1）0xE9 = 000 1110 1001，落在两字节那行：11000011 10101001 = C3 A9。

      （2）区号 26 = 0x1A，位号 30 = 0x1E；国标码 = 1A1EH + 2020H = 3A3EH；机内码 = 3A3EH + 8080H = BABEH。

      （3）H、i 各 1 字节，你、好各 3 字节，👋（U+1F44B）4 字节：UTF-8 共 12 字节。UTF-16：前四个字各 2 字节，👋 是代理对 4 字节，共 12 字节（巧合相同）。Python len = 5，JavaScript length = 6。

      一个字，两种写法

      é 可以是一个码位 U+00E9，也可以是 e（U+0065）加上一个“组合用的尖音符”（U+0301）。屏幕上一模一样，字节却不同，直接比较会说它们不相等。Unicode 定义了规范化：NFC 尽量合成一个码位，NFD 尽量拆开。Mac 的老文件系统 HFS+ 存文件名时会把它们分解成近似 NFD 的形式，今天的 APFS 保留原样但比较时不区分；于是同一个带重音或带特殊符号的文件名，在 Mac 和 Linux 之间同步时偶尔会“变成两个文件”，Git 为此在 Mac 上默认打开了 core.precomposeunicode。Python 里用 unicodedata.normalize('NFC', s) 统一。

      用户眼里的“一个字”

      👨‍👩‍👧 看起来是一个表情，其实是“男人、零宽连接符、女人、零宽连接符、女孩”五个码位；🇨🇳 这样的国旗是两个“区域指示符”码位。用户眼里的一个字叫字素簇（grapheme cluster）。Python 的 len 数码位，所以 len('👨‍👩‍👧') 是 5；Swift 的 String.count 数字素簇，得 1。做文本编辑器、按“字数”截断评论时，要按字素簇来切，否则会把一个家庭表情切成一个孤零零的男人。

      长得一样的字母

      西里尔字母的 а（U+0430）和拉丁字母 a（U+0061）几乎看不出区别。坏人可以注册一个用西里尔字母拼的域名，看起来和某个银行的网址一模一样，这叫同形字攻击。浏览器的对策是：域名里混用多种文字时，显示成以 xn-- 开头的 Punycode 原形。2021 年，研究人员还公布了“特洛伊源码”攻击：在源代码的注释或字符串里藏进 Unicode 的“从右往左”方向控制符，让代码在编辑器里显示的顺序和编译器读到的顺序不一样，审代码的人看到的逻辑是假的。许多编辑器和编译器因此加了警告。

      屏幕是一张方格纸

      拿放大镜贴近屏幕看，会看到密密麻麻的小方格，每个方格只有一种颜色。这样的方格叫像素（pixel，picture element 的缩写）。一张图片，就是一张填满了颜色的方格纸。方格有多少，叫分辨率：13 英寸的 MacBook Air M1 屏幕是横 2560 个、竖 1600 个，一共四百多万个像素。

      红、绿、蓝三种光

      我们的眼睛里有三种感光细胞，分别对红光、绿光、蓝光最敏感。所以只要用这三种光按不同的强弱混在一起，就能骗过眼睛，让它看到几乎任何颜色：红加绿是黄，红加蓝是品红，三种开到最亮是白，全关是黑。这和画画调颜料不一样：颜料越混越暗，光越混越亮。屏幕上每个像素里，其实都有红、绿、蓝三个更小的发光点。

      每种光的强弱用一个字节表示，0 是不亮，255 是最亮。一个像素就是三个字节：(255, 136, 0) 是橙色。写成十六进制就是网页里常见的 #FF8800。三个字节一共能表示 256 × 256 × 256 = 16777216 种颜色，一千六百多万种。

      声音是空气在抖

      振动、频率和响度

      敲一下桌子，桌面在抖，推着旁边的空气一疏一密地传开，传到耳朵里推动鼓膜，你就听到了声音。每秒抖多少次叫频率，单位赫兹（Hz）：抖得越快，声音越尖。抖得越厉害，声音越响。人耳大约能听到每秒 20 次到 20000 次的振动；年纪越大，能听到的最高频率越低。

      麦克风把空气压力的变化变成电压的变化，画出来是一条弯弯曲曲的线。电脑存不了一条连续的线，只能每隔一小段时间量一次它有多高，记下一个数。这叫采样（sampling）。每次量出来的高度也不能无限精确，只能归到某一档，这叫量化。

      CD 的做法是：每秒采样 44100 次，每次用 16 位（65536 档）记高度，左右两个声道各记一份。一秒钟就是 44100 × 2 × 2 = 176400 字节，一首四分钟的歌约 42 MB。MP3、AAC 这些格式能把它压到几 MB，靠的是去掉人耳听不出来的部分。

      显存的容量和带宽

      显示器显示的画面先放在显示存储器（帧缓冲）里。容量 = 分辨率 × 每像素位数（色深）÷ 8；如果要同时存好几帧（双缓冲），再乘帧数。带宽 = 容量 × 刷新率，表示每秒至少要从显存读出多少数据送给屏幕。考题常加一个条件，例如“显示器读显存的时间只占 50%”，那么实际需要的带宽要再乘 2。

      色深和颜色数的关系：n 位能表示 2n 种颜色，所以“65536 色”是 16 位，“真彩色”是 24 位。

      音频的数据率

      数据率 = 采样频率 × 量化位数 × 声道数（单位比特每秒）。CD：44100 × 16 × 2 = 1411200 b/s，约 1411 kb/s。这就是为什么 128 kb/s 的 MP3 被说成“压缩了十倍左右”。

      采样要多快：奈奎斯特

      采样定理：要从采样值无失真地恢复一个最高频率为 fmax 的信号，采样频率必须大于 2fmax。采样太慢，高频信号会伪装成一个低频信号，叫混叠。电影里飞转的车轮看上去在慢慢倒转，就是摄像机每秒 24 帧的采样跟不上车轮的转速。CD 选 44.1 kHz，正是要大于人耳上限 20 kHz 的两倍，再留一点余量给滤波器。第一层装置里，把频率调高、采样率调低，就能看到红台阶变成一个慢得多的波。

      信道的极限：第一章的回声

      网络里有同样的问题，只是方向反过来：一根线每秒最多能送多少比特？408 计算机网络的物理层有两个定理：

      • 奈奎斯特定理（无噪声）：带宽为 W Hz 的理想低通信道，最多每秒传 2W 个码元；每个码元有 V 种状态（电平）时，极限数据率 = 2W log2V b/s。
      • 香农定理（有噪声）：信道容量 C = W log2(1 + S/N) b/s，S/N 是信噪比。信噪比常用分贝表示：dB = 10 log10(S/N)，30 dB 即 S/N = 1000。

      奈奎斯特说“电平分得越多越快”，香农说“噪声给分档的多少设了天花板”。这正是第一章“两档还是十档”的装置：没有噪声时，分十档每个信号带 3.32 比特；噪声一大，分多了就认不清。香农定理把这个直觉变成了一个精确的上限。

      压缩

      • 无损压缩：解压后一个比特都不差。游程编码（RLE）把连续重复的值写成“个数 + 值”；霍夫曼编码给常出现的符号短码、不常出现的长码（《链与树》讲）；ZIP、PNG 用的 DEFLATE 是“找重复出现过的片段，用‘往前多少、长多少’代替”加霍夫曼。文本、程序、表格只能用无损。
      • 有损压缩：丢掉人感觉不到（或不太在意）的信息，压缩比高得多。JPEG（照片）、MP3 / AAC（音乐）、H.264 / HEVC（视频）都是。反复有损压缩会越来越糊。
      • 压缩比 = 原始大小 ÷ 压缩后大小。像素画板里的“游程编码”就是最简单的无损压缩：一大片一样的颜色压得很好，花花绿绿的图可能反而变大（每个像素都要多存一个“个数”）。

      128 不是一半亮

      像素值 128 发出的光，并不是 255 的一半，而只有大约五分之一。原因是人眼对暗处的变化更敏感，sRGB 标准用一条约等于 2.2 次方的曲线（伽马）分配 256 档，让更多的档留给暗部。后果：如果直接拿像素值做平均（比如缩小图片、模糊、混合两种颜色），结果会偏暗，边缘出现灰黑的边。正确做法是先把像素值换算到“线性光”空间，算完再换回来。Mac 的屏幕和照片还常用比 sRGB 更宽的 Display P3 色域，同样的 (255, 0, 0) 在两种色域里是两种红。

      JPEG 的五步

      1. 把 RGB 换成亮度 Y 和两个色差 Cb、Cr。
      2. 人眼对颜色的细节远不如对明暗敏感，所以色差横竖各砍一半分辨率（4:2:0 子采样），数据一下少了一半。
      3. 把图切成 8 × 8 的小块，每块做一次离散余弦变换（DCT），把“64 个像素”变成“64 个由平缓到剧烈的花纹的强弱”。
      4. 量化：用一张表把每个系数除一下再取整，剧烈花纹（高频）除得狠，大多变成 0。只有这一步是有损的，“画质”滑块调的就是这张表。
      5. 按“之”字形把系数排成一串（让一长串 0 挨在一起），用游程编码加霍夫曼编码无损压缩。

      MP3 和 AAC 的思路类似，换成了“心理声学模型”：响的声音会把频率相近的弱声音“盖住”（掩蔽效应），被盖住的部分不用存。

      没有一种压缩能把所有文件都变小

      证明只要鸽笼原理：长度恰好为 n 比特的文件有 2n 个；长度小于 n 比特的文件一共只有 20 + 21 + … + 2n−1 = 2n − 1 个。如果一种无损压缩把每个 n 比特的文件都变短，就要把 2n 个文件放进 2n − 1 个“笼子”，必有两个文件压成同一个结果，解压时就分不清了。所以任何无损压缩都必然让一些文件变大（好的压缩器会加一个标记位，碰到压不动的就原样存，最多大一点点）。能压，是因为现实中的数据有规律、熵低；随机数据和已经压缩过的数据压不动。广告说“任何文件都能压缩 90%”的，一定是骗局。

      字体怎样变成像素

      第零章里“备忘录找出 a 的形状”：字体文件里存的不是像素，而是轮廓线，用贝塞尔曲线描述（TrueType 用二次曲线，PostScript 系的用三次曲线）。显示时要“光栅化”：算出哪些像素落在轮廓里面。边缘上只盖住一部分的像素，涂成介于字色和底色之间的颜色，叫抗锯齿。以前 macOS 还会分别控制每个像素里的红绿蓝小点来做“亚像素抗锯齿”，让字更锐利；2018 年的 macOS Mojave 默认关掉了它，因为高分辨率的 Retina 屏幕已经不需要了。

      布尔代数

      1854 年，英国数学家乔治·布尔写了一本书，把“真”和“假”当成两个数来算：“与”像乘法（1 × 1 = 1，其余是 0），“或”像加法（只是 1 + 1 还是 1）。这套算法叫布尔代数。有一条规则特别有用，叫德摩根定律：“不是（下雨且刮风）”等于“不下雨或不刮风”；“不是（下雨或刮风）”等于“不下雨且不刮风”。写成式子：~(A & B) = ~A | ~B，~(A | B) = ~A & ~B。写程序的 if 条件、设计电路（第二部），都天天用它。

      记法：原码数值位就是绝对值，补 0；反码数值位是绝对值取反，补 1；补码介于两者之间：从右数第一个 1 左边和反码一样（右移补 1），右边和原码一样（左移补 0）。

      注意：补码算术右移是向下取整（往负无穷），而 C 的整数除法是向零取整：−7 >> 1 = −4，−7 / 2 = −3。编译器把 x / 2 优化成移位时，对有符号数会先加一个修正值。

      编程语言里：C 的 >> 对无符号数是逻辑右移，对负的有符号数由实现决定（实际上几乎都是算术右移；C23 之后仍未强制）；Java 和 JavaScript 用 >> 表示算术右移，另设 >>> 表示逻辑右移；Python 的整数没有固定位数，>> 总是算术右移。循环移位（rotate）把移出去的位从另一头补回来，常用于加密和哈希；ARM 有 ROR 指令，C 里一般写成 (x >> n) | (x << (32 - n))，编译器会认出来。

      文件权限：九个比特

      在终端里 ls -l，每行开头那串 -rw-r--r-- 是文件的权限。去掉第一个字符（文件类型），剩下九个字符分三组：文件主人、同组的人、其他所有人；每组三位：读 r、写 w、执行 x。有就写字母，没有就写 -。九个字符就是九个比特，每三位正好是一个八进制数字：rwx = 111 = 7，r-x = 101 = 5，r-- = 100 = 4。所以 chmod 755 文件 的意思是“主人可读写执行，其他人可读可执行”，chmod 644 是“主人可读写，其他人只读”。你在第二章建的 hi.txt 就是 644。这是八进制在今天最常见的用处。

      面试常考的六个技巧

      1. 判断奇偶：x & 1。
      2. 清掉最低位的 1：x & (x - 1)。x − 1 会把最低位的 1 变成 0、它右边的 0 全变成 1，再一“与”就清掉了。由此：x 是 2 的幂当且仅当 x > 0 && (x & (x - 1)) == 0。
      3. 只留最低位的 1：x & -x（−x 是取反加一）。这就是树状数组里的 lowbit。
      4. 数 1 的个数：反复 x &= x - 1，做了几次就有几个 1，循环次数等于 1 的个数而不是位数。
      5. 不用临时变量交换：a ^= b; b ^= a; a ^= b;。（工程里别这么写：a 和 b 是同一个变量时会清零，也不比用临时变量快。）
      6. 找唯一落单的数：一个数组里别的数都出现两次，只有一个出现一次，把所有数异或起来就是它，因为 a ^ a = 0、a ^ 0 = a，而且异或满足交换律和结合律。

      用比特表示集合

      一个 n 位整数可以表示 {0, 1, …, n−1} 的一个子集：第 i 位是 1 就表示 i 在集合里。于是并集是 |，交集是 &，差集是 & ~，判断属于是 >> i & 1。枚举一个集合 m 的所有子集有个漂亮的写法：

      for (unsigned s = m; ; s = (s - 1) & m) {
    /* 处理子集 s */
    if (s == 0) break;
}

      格雷码

      普通二进制从 0111 加到 1000，四位同时变。如果这是一个旋转编码器的读数，四个触点不可能同时切换，中间可能短暂读到 1111 之类的错值。格雷码让相邻的两个数只差一位：第 n 个格雷码是 n ^ (n >> 1)。0 到 7 依次是 000、001、011、010、110、111、101、100。它用在旋转编码器、模数转换器，第十章的卡诺图也按格雷码排行列。

      位图和布隆过滤器

      要记 40 亿个 QQ 号里哪些在线，一个号用一个比特，只要 40 亿 ÷ 8 = 5 亿字节，不到 500 MB，这叫位图。操作系统用位图记哪些磁盘块空着、哪些内存页空着（第四部）。布隆过滤器更进一步：用 k 个哈希函数把一个元素映射到位图里的 k 个位置并置 1；查询时 k 个位置全是 1 才说“可能在”，有一个是 0 就“一定不在”。它会误报、不会漏报，用很少的内存挡掉大量不必要的查询，数据库和浏览器（检查恶意网址）都用它。下国际象棋的程序则用 64 位整数表示棋盘，一个比特一个格子，“这个马能跳到哪些格”可以用几次移位和与运算一次算出来，这叫位棋盘。

      一次算 16 个字节

      Apple Silicon 的 CPU 有 128 位宽的 NEON 向量寄存器，一条指令可以同时对 16 个字节做按位与、加法或比较，叫 SIMD（单指令多数据）。图像处理（每个像素三个字节）、字符串查找、压缩解压都靠它提速。用一个整数的 64 位同时处理 8 个字节的小技巧，则叫 SWAR（寄存器内的 SIMD）。第十五章还会回来。

      说三遍

      你在嘈杂的操场上喊同学，怕他听错，会怎么办？多喊几遍。电脑也可以这样：每个比特发三遍，0 发成 000，1 发成 111。收到 010，三个里两个是 0，就当它是 0。这样，三个里错一个也能改回来。

      可是代价太大了：要送 1 个比特的信息，得占 3 个比特的地方，三分之二都是“废话”。有没有更省的办法？

      奇偶校验：多带一位

      换一个思路：不求改正，先求发现。每发 7 个比特，后面加 1 个比特，让这 8 个比特里 1 的个数总是偶数。这个加上去的比特叫校验位。

      • 要发 1011001，里面有 4 个 1，已经是偶数，校验位填 0：发 10110010。
      • 要发 1011011，有 5 个 1，校验位填 1 凑成偶数：发 10110111。

      收的一方数一数 1 的个数：如果是奇数，就知道路上出错了，请对方再发一遍。只多带了 1 位，就能发现任何一个比特的错误。它的弱点是：如果正好错了两个比特，1 的个数又变回偶数，就发现不了；而且它只知道“有错”，不知道“错在哪一位”，改不回来。算校验位其实就是把所有比特异或起来（第七章）：异或的结果正好表示“1 的个数是不是奇数”。

      码距

      两个等长码字有几位不同，叫它们的海明距离（= popcount(a ^ b)）。一种编码里所有合法码字两两之间的最小距离，叫这种编码的码距 d。

      • 要能检出 e 位错误，需要 d ≥ e + 1（错 e 位跳不到另一个合法码字上）。
      • 要能纠正 t 位错误，需要 d ≥ 2t + 1（错 t 位后离原码字最近，不会被误认成别的码字）。
      • 要纠正 t 位同时检出 e 位（e > t），需要 d ≥ e + t + 1。

      不加校验的编码 d = 1，什么也检不出；奇偶校验 d = 2，能检 1 位；三遍重复 d = 3，能纠 1 位；海明码 d = 3，能纠 1 位而代价小得多；再加一个总的奇偶位，d = 4，可以纠 1 位同时检 2 位（SECDED）。

      海明码

      1950 年，贝尔实验室的理查德·海明受够了一件事：他周末提交给继电器计算机的计算任务，常常因为读卡出错被直接中止，没人在场重来。他想：机器既然能发现错，为什么不能自己改？于是有了海明码。

      1. 校验位个数：n 位数据配 k 位校验，要求 2k ≥ n + k + 1（k 位校验的“指认”结果要能区分“没错”和 n + k 个位置中任一个出错）。4 位数据要 3 位校验，8 位数据要 4 位，16 位要 5 位，64 位要 7 位。
      2. 位置：把码字从 1 开始编号，校验位放在 1、2、4、8……（2 的幂）上，数据位依次填进其余位置。
      3. 分组：位置号的二进制里第 i 位是 1 的所有位置，归第 i 组，由校验位 P2i 负责：P1 管 1、3、5、7……，P2 管 2、3、6、7……，P4 管 4、5、6、7……。每组做偶校验。
      4. 纠错：收方对每组重新做异或，得到的 k 位结果（从高到低排）叫校正因子。全 0 说明没错；否则它的值正好是出错的位置号，把那一位翻回来即可。

      CRC：循环冗余校验

      网络和磁盘上，错误常常是一小串连着坏（突发错误），海明码不擅长。CRC 把一串比特看成一个多项式的系数（1101 看成 x3 + x2 + 1），用“模 2 除法”求余数：

      模 2 运算：加法就是异或

      只有 0 和 1、算完只看奇偶的世界里，1 + 1 = 0，没有进位也没有借位，所以加法和减法都是异或。做“除法”时，每一步看当前最高位：是 1 就异或上除数，是 0 就异或上 0，然后往下移一位。比普通的长除法还简单。

      1. 收发双方约定一个 r + 1 位的生成多项式 G（最高位和最低位都是 1）。
      2. 发方在数据后面补 r 个 0，用 G 做模 2 除法，得到 r 位余数，这就是 CRC 校验码；把它接在数据后面发出去（补的 0 换成余数）。
      3. 收方用 G 去除收到的整串，余数为 0 就认为没错。

      为什么整串能被 G 整除？补 0 再加上余数，等于“被除数减去余数”，模 2 下减法就是加法，自然整除。r 位的 CRC 能检出所有单个错误、所有长度不超过 r 的突发错误；G 含因子 (x + 1) 时还能检出所有奇数个错误。以太网用的是 32 位的 CRC-32。CRC 只用来检错，发现错了就要求重发（第四部讲）。

      （1）2k ≥ 16 + k + 1：k = 5 时 32 ≥ 22 成立，k = 4 时 16 < 21 不成立，所以 5 位。SECDED 再加 1 位总校验，6 位。

      （2）G = 1101，r = 3，被除数 101001 000。模 2 除法余数为 001（装置里可以一步步看）。发送 101001 001。

      （3）d = 4：检错 e ≤ d − 1 = 3 位；纠错 t ≤ (d − 1)/2 = 1 位；纠 1 检 2 需要 d ≥ 2 + 1 + 1 = 4，可以。

      1011001 和 1001011 的海明距离是？

      异或得 0010010，有 2 个 1，距离是 2。

      8 位数据用海明码纠一位错，至少要几位校验位？

      24 = 16 ≥ 8 + 4 + 1 = 13。

      码距为 3 的编码最多能纠正几位错误？

      1. 0
      2. 1
      3. 2

      d ≥ 2t + 1，t = 1。

      （7, 4）海明码的校正因子算出来是 101，说明哪个位置出错？

      101 = 5，第 5 位。

      模 2 运算里，1 + 1 等于几？

      没有进位，就是异或：0。

      收方用生成多项式除收到的整串，余数为 0，说明？

      1. 一定没有错
      2. 一定有错
      3. 认为没有错（极少数错误恰好整除时漏检）

      CRC 不能保证 100% 检出，但对随机错误漏检的概率极低。

      内存真的会出错

      服务器普遍使用 ECC 内存：每 64 位数据配 8 位校验（72, 64），用的正是“海明码 + 总校验位”的 SECDED 思路，能纠正一位、发现两位错误，内存控制器在读的时候自动完成。多数笔记本和台式机的内存不带这种校验。2009 年谷歌发表了一项对自家数据中心内存的大规模研究，发现内存错误比人们以为的常见得多：每年大约三分之一的机器至少遇到一次可纠正的内存错误。没有 ECC 的机器，这些错误就悄悄地留在了数据里。

      来源之一是宇宙射线：高能粒子打到大气层产生的中子能翻转芯片里的一个存储单元。海拔越高越常见，所以飞机和卫星上的电子设备要特别加固。常被提起的一个例子是：2003 年比利时一次选举中，某地一位候选人凭空多出了 4096 票，正好是 212，调查认为是一个比特被翻转了，据说可能是宇宙射线所致（确切原因没有定论）。

      比特抢注

      2011 年，安全研究员阿尔乔姆·迪纳堡做了一个实验：他注册了一批和热门网站域名只差一个比特的域名（比如某个字母的 ASCII 码翻了一位），结果真的陆续收到了来自世界各地的访问请求，因为那些设备内存里的域名被翻错了一位，又没有 ECC 来纠正。他把这叫“比特抢注”。

      里德-所罗门码

      海明码一次只纠一位，划痕却会一下毁掉一大片。1960 年提出的里德-所罗门码按“字节”而不是比特来纠错，能纠正成片的错误。CD 用两层里德-所罗门码再加上交错存放，能修复长约两毫米的划痕；二维码有四个纠错等级（L、M、Q、H），最高可以在约 30% 的码块损坏时还原内容，所以有人在二维码中间放一个图标照样扫得出来；深空探测器回传数据，也靠它和别的编码叠在一起。

      校验和、CRC、哈希

      • 校验和：把数据按 16 位加起来。互联网的 IP、TCP、UDP 用的是“反码求和”，第三章的反码在这里还活着（第三十一章）。计算极快，检错能力较弱。
      • CRC：检测随机的、突发的传输错误很强，但它是线性的，任何人都能故意改数据再改 CRC 让它对上。
      • 密码学哈希（如 SHA-256）：设计成“故意找两个内容哈希相同”在计算上做不到，用来防篡改。下载软件时网站给出的 SHA-256 值，就是让你自己算一遍对一对。
      给文件算“指纹”5 分钟
      % cd ~/base
% cksum hi.txt
% shasum -a 256 hi.txt
% echo hellp > hj.txt && shasum -a 256 hj.txt

      cksum 打出一个 CRC 值和文件大小；shasum -a 256 打出 64 个十六进制数字的 SHA-256。把 hello 改成 hellp，只差一个字母（o 和 p 的 ASCII 码 6F、70 其实差了好几位），SHA-256 却面目全非，这叫“雪崩效应”。
