      数据包是什么

      第十五章讲过：把很多行命令写进一个文本文件，叫“函数”；把函数和别的设置装进一个文件夹，放进存档里，叫“数据包”。它不是模组，不用装任何东西，游戏本来就认识它。

      一个最小的数据包，只要这样几样：

      xiaoge_pack/                     ← 数据包的文件夹，名字随便起
  pack.mcmeta                    ← 一张“身份证”：我是数据包，适合哪个版本
  data/
    xiaoge/                      ← 名字空间：你自己的名字
      function/
        hello.mcfunction         ← 一个函数：里面一行一条命令

      一步一步

      1. 建一个实验世界。创造模式，打开“允许作弊”，名字用英文或拼音，比如 gongfang（文件夹名字里没有中文，后面少出错）。别在你辛苦盖的老世界里做实验。
      2. 找到数据包文件夹。回到“选择世界”，选中这个世界，点“编辑”，再点“打开世界文件夹”。访达里会打开一个文件夹，里面有一个叫 datapacks 的文件夹，进去。
      3. 让 Mac 显示后缀名。在访达的菜单里打开“设置”→“高级”，勾上“显示所有文件扩展名”。这一步很重要：文件到底叫 pack.mcmeta 还是 pack.mcmeta.txt，要看得见。
      4. 建文件夹。在 datapacks 里新建文件夹 xiaoge_pack，里面建 data，再里面建 xiaoge，再里面建 function。名字一律用小写字母、数字、下划线，不要空格、不要大写、不要中文。
      5. 写“身份证”。打开“文本编辑”，新建一个文档，先点菜单“格式”→“制作纯文本”（这就是舅舅说的那个坑：文本编辑默认写的是带格式的“富文本”，游戏读不懂）。写进下面这几行，存到 xiaoge_pack 文件夹里，名字叫 pack.mcmeta，编码选 UTF-8；如果电脑问你要不要加 .txt，选“使用 .mcmeta”。 
        {
  "pack": {
    "description": "小格的第一个数据包",
    "pack_format": 48
  }
}
        这里的 48 是 1.21 和 1.21.1 版本的数字。每个版本的数字都不一样，1.21.9 以后还改成了 min_format 和 max_format 两个数（下面的装置里有新写法的样子）。去社区维基搜“数据包格式”，找到你游戏版本的那一行。
      6. 写一个函数。同样用纯文本，写下面两行，存到 function 文件夹里，名字叫 hello.mcfunction。注意：函数文件里的命令，前面不加斜杠。 
        say 你好，工坊！
title @a title "欢迎来到工坊"
      7. 让游戏读进来。回到游戏，进入这个世界，在聊天框里输入 /reload（重新读取数据包），再输入 /datapack list，看看列表里有没有你的数据包。
      8. 运行它。输入 /function xiaoge:hello。冒号前面是名字空间，后面是函数的文件名（不带后缀）。

      出错了怎么办

      • /datapack list 里没有它：pack.mcmeta 是不是直接放在 xiaoge_pack 里（不是放进了 data）？是不是变成了 pack.mcmeta.txt 或者 .rtf？里面的大括号、引号、逗号有没有少？数字对不对？
      • 说“找不到函数”：文件夹是不是叫 function（1.21 以前的版本叫 functions，多一个 s）？名字里有没有大写字母？后缀是不是 .mcfunction？
      • 命令报错：函数里某一行写错了，游戏会在聊天框或者日志里告诉你是哪一行。先把那一行单独拿到聊天框里打一遍试试。
      • 改了文件，记得再 /reload 一次。

      这些错误，每一个程序员都犯过很多次。读报错、一样一样排除，就是第二十三章说的“调试”。

      让函数自己跑起来

      第十三章讲过，游戏一秒钟打 20 下拍子。数据包可以让一个函数每一下拍子都运行一次：只要在 data/minecraft/tags/function/ 里放一个叫 tick.json 的文件，写上你的函数名字。比如下面这个函数：每一刻检查每个玩家，脚下是草方块、站的地方是空气，就在那里种一朵花。

      execute as @a at @s if block ~ ~-1 ~ minecraft:grass_block if block ~ ~ ~ minecraft:air run setblock ~ ~ ~ minecraft:poppy

      这一行很长，拆开读就不难：“对所有玩家（as @a），在他站的地方（at @s），如果脚下是草（if block … grass_block），如果这里是空的（if block … air），就放一朵虞美人（run setblock … poppy）”。这就是第十章的“与”，也是第二十二章说的“如果”。

      名字空间：几百万人一起写，怎样不撞名字

      functions 文件夹

      2024 年的 1.21 版本，把数据包里好几个文件夹的名字从复数改成了单数：functions 变成了 function。很多网上的老教程、老数据包还写着 functions，照着做就会“找不到函数”。这也是为什么做任何事之前，都要先看清楚教程是哪个版本的。

      做数据包要先装模组假

      数据包是 Java 版本来就支持的东西，放进存档的 datapacks 文件夹，/reload 就能用，不用装任何模组，也不用改游戏本身。

      它能做的事也有边界：能用命令做到的事，它都能做；想加一种全新的方块、全新的生物模型，就要用模组或者资源包了。基岩版也有类似的东西，叫“行为包”，写法不一样。

      联系

      每秒二十次的函数，就是游戏自己的心跳

      第十三章讲过，游戏每一刻把整个世界检查一遍。你写的 tick 函数，就是挤进这一遍检查里的一小段“你的规则”。游戏本身，其实也是一个巨大的、每秒运行二十次的函数。你写的第一个 tick 函数，和做游戏的人写的程序，是同一种东西，只是小得多。

      这一章的新词
      纯文本只有字、没有字体颜色和格式的文件。程序只认纯文本。
      后缀名文件名最后一个点后面的部分，比如 .mcfunction，告诉电脑这是什么文件。
      名字空间名字前面的“姓”，比如 xiaoge:hello，防止和别人撞名字。
      JSONpack.mcmeta、tick.json 用的写法：大括号、引号、冒号、逗号，一个都不能错。
      给大人

      函数随 Java 版 1.12（2017）加入，数据包随 1.13（2018）。1.21（2024）把数据包内多个目录改为单数（functions → function，tags/functions → tags/function）。1.21.9 起 pack.mcmeta 改用 min_format / max_format，各版本的格式号见社区维基“Pack format”页面；书中的 48（1.21 / 1.21.1）和装置里的 88（1.21.9 / 1.21.10）只作举例，2026 年的新版本号码以维基为准。命令写法也偶有变化，书中命令按 1.21 系列的写法写成，没有在每个版本里逐一实测；建议先在实验世界里试。

      方格纸上的勾股定理

      怎样让电脑知道一块方块在不在球里面？先在方格纸上想一个圆。圆心在 (0, 0)，半径是 5。点 (3, 4) 在圆上吗？

      从圆心往右走 3 格，再往上走 4 格。这两段路和“从圆心直接走到那个点”的那条斜线，围成一个直角三角形。两千多年前人们就知道：3 × 3 + 4 × 4 = 5 × 5，也就是 9 + 16 = 25。所以 (3, 4) 离圆心正好是 5，正好在圆上。这叫勾股定理，中国古书《周髀算经》里有“勾三股四弦五”的说法，你要到初中才会正式学它。

      所以规则很简单：x × x + y × y 小于等于 r × r，这个点就在圆里面。到了立体的球，再加上一个 z × z 就行。电脑把球附近的每一格都这样检查一遍，几千格，一眨眼。

      你家在哪个小区、哪栋楼、几号，快递员才能把东西送来。网络上的每一台电脑也有一个“门牌号”，叫 IP 地址，是几组用点隔开的数字，比如 192.168.1.23。
      
    
      在 Mac 上查自己的 IP 地址：打开“系统设置”→“Wi-Fi”，点你连着的那个网络旁边的“详细信息”，就能看到。同一个家里的 Wi-Fi，常常是 192.168 开头的，这种地址只在你家里有用，出了家门就不认了，就像“3 号楼 201”只在你们小区里有意义。
      
    
      端口呢？一台电脑上同时开着很多程序：游戏、浏览器、聊天软件。门牌号找到了这台电脑，还要知道把东西交给哪个程序，端口就是“几号窗口”。我的世界服务器默认用 25565 号窗口；“对局域网开放”时，游戏会自己挑一个空着的号码。
      
  
      

  
      
    
      网上的第一句话，只说了两个字母
      
    
      1969 年 10 月，美国两所大学的电脑第一次通过一个叫阿帕网（ARPANET）的网络“说话”。那边的学生想输入 LOGIN（登录），刚打完 L 和 O，系统就崩溃了。所以网络上传出的第一句话，只有 “LO”。
      
    
      阿帕网用了一个聪明的办法：把要发的东西切成很多小包裹，每个包裹写上地址，各自找路送过去，到了再拼起来。今天的互联网、你和豆子的联机，用的还是这个办法。书房里的《计算机创世记》卷九讲了网络的故事。
      
  
      

  
      
    
      世界被拆成小包裹
      
    
      联机的时候，两台电脑并不是“看着同一个屏幕”。真正发生的是：
      
    
        
      
      • 开世界的那台电脑，当了“服务器”：世界真正的样子，只在它那里算。每一刻（一秒 20 次），它都在算怪物走到哪儿、方块变没变。
        • 
      
      • 豆子的电脑是“客户端”：豆子按了 W，他的电脑就寄一个小包裹给服务器，“我往前走了一步”；服务器算完，再把结果寄回来，也寄给小格。
        • 
      
      • 豆子挖掉一块石头，这个消息也要先寄到服务器，服务器同意了，小格的屏幕上那块石头才会消失。
        • 
    
      
    
      包裹寄过去、再寄回来，要花时间。从发出到收到要多久，叫延迟，单位是毫秒（一千分之一秒）。同一个 Wi-Fi 下，延迟往往只有几毫秒；隔着一个国家，可能要几十、上百毫秒。
      

    
      在终端里 ping 一下
      
    
      电脑自带一个能“敲门”的小工具，叫 ping：它寄一个小包裹给对方，看多久能收到回音。
      
    
        
      
      1. 打开“应用程序”→“实用工具”→“终端”。这是一个只能打字的窗口，程序员天天用它。
        2. 
      
      2. 在“Wi-Fi 详细信息”里找到“路由器”那一行的地址（常常是 192.168.1.1 或者 192.168.0.1），在终端里输入（换成你家的地址）：

        ping -c 4 192.168.1.1
        3. 
      
      3. 按回车。它会敲四次门，每一行最后的 time= 就是这一次花了多少毫秒。
        4. 
      
      4. 再试试 ping 豆子那台电脑的 IP 地址。比一比：哪个快？为什么？
        5.

      延迟是什么感觉
      
    
      你在左右来回跑。第一行是你自己屏幕上的你，马上就动；第二行是服务器收到消息以后知道的你；第三行是服务器再把消息寄给豆子以后，豆子屏幕上的你。拖动滑块，把延迟调大，看看三个你差了多远。
      
    
    
      单程延迟
      
    
      
    
      
    
      真实的游戏会用一些小技巧，让你自己屏幕上的画面先动起来、再等服务器确认，所以延迟不大时你几乎感觉不到。延迟一大，这些小技巧就盖不住了。一个游戏刻是 50 毫秒。

      网速越快，游戏就越不卡半真
      
    
      “网速”常常说的是带宽：一秒钟能送多少东西，像马路有多宽。下载大文件，路越宽越快。
      可是游戏要的是另一样：延迟，一个小包裹多快能送到，像路有多长、路上堵不堵。游戏的包裹都很小，路宽不宽没那么要紧，路长不长才要紧。所以有时候家里网速很快，游戏照样卡：可能是 Wi-Fi 信号差、离路由器太远，或者服务器在很远的地方。

      暑假第四周SERVER · 小格的工坊终端 + 游戏
      
    
      
      
      豆每次都要等小格开着游戏我才能进，他一下线，世界就没了。
      
      
      舅那就让世界单独“住”在一个程序里，叫服务器程序。谁玩不玩都没关系，只要它开着，世界就在。
      
      
      格服务器不是那种一屋子的大机器吗？
      
      
      舅大服务器是。可是“服务器”说到底就是一个程序。你这台 MacBook，就能跑一个给三四个人用的小服务器。
      
      
      终端里一行一行的白字往上滚，最后停在一行 Done。小格在游戏里输入 localhost，进去了。舅舅说：“现在，你是这个世界的管理员了。”
      
    
      
  
      

  
      难度★★★★
      大约多久1—2 小时
      要准备Java 运行环境、官方服务器程序、终端
      大人一定要，全程
      

  
      
    
      单人游戏里也藏着一个服务器
      
    
      上一章说，联机时开世界的那台电脑当了服务器。其实，从 2012 年的 1.3 版本起，你一个人玩的时候，游戏里也偷偷开着一个服务器：一部分负责算世界，一部分负责把世界画给你看，两部分在同一台电脑里互相寄包裹。“对局域网开放”，只是把这个藏着的服务器的门打开了一条缝。
      
    
      官方还提供一个单独的服务器程序，它不画画面，只算世界、收发包裹。下面就在小格的 Mac 上把它跑起来。
      

    
      一步一步（请大人全程在旁边）
      
    
        
      
      1. 建一个文件夹：在桌面上新建一个文件夹，叫 mc-server。服务器的所有东西都会放在这里。
        2. 
      
      2. 装 Java 运行环境：游戏启动器自带了一份 Java，可是服务器程序要自己准备一份。去 Minecraft 官网的“下载服务器”页面，看清楚你的版本要哪个版本的 Java（据报道，2026 年的新版本要 Java 25，1.20.5 到 1.21 系列要 Java 21），再从官方渠道装一个免费的 OpenJDK（比如微软或 Eclipse 发布的版本）。装好以后，在终端里输入 java -version，能看到版本号就对了。
        3. 
      
      3. 下载服务器程序：在同一个官方页面下载 server.jar，版本要和你的游戏一样，放进 mc-server 文件夹。别从别的网站下载“整合包”“一键开服”。
        4. 
      
      4. 第一次运行：打开终端，输入下面两行（第一行是“走进这个文件夹”，第二行是“用 Java 运行服务器，最多给它 2 GB 内存，不要窗口”）：

        cd ~/Desktop/mc-server
java -Xmx2G -Xms1G -jar server.jar nogui
        
        它会很快停下来，文件夹里多了几个文件，其中一个叫 eula.txt。
        5. 
      
      5. 读一读用户协议：eula 是“最终用户许可协议”，就是你同意遵守 Mojang 的规矩。请大人和你一起读一读（里面有链接），同意了，就用纯文本把 eula=false 改成 eula=true。
        6. 
      
      6. 改设置：用纯文本打开 server.properties，照着下面装置里的建议改几行。最重要的两行：white-list=true（白名单）和 online-mode=true（正版验证）。
        7. 
      
      7. 再运行一次：在终端里按上箭头键，刚才那行命令会出来，回车。等到出现 Done，服务器就开好了。第一次要生成世界，会慢一点。
        8. 
      
      8. 先把自己加进白名单：白名单打开以后，连你自己也要先加进去才能进。在终端里（服务器的“控制台”）直接打命令，不用加斜杠：

        whitelist add 小格的游戏名
whitelist add 豆子的游戏名
op 小格的游戏名
        
        whitelist add 把人加进白名单（名字要和游戏里的名字一模一样）；op 给自己管理员权限，只给自己。
        9. 
      
      9. 进去：打开游戏，“多人游戏”→“添加服务器”，地址填 localhost（意思是“我自己这台电脑”），进入。同一个 Wi-Fi 下的朋友，地址填你电脑的 IP 地址（上一章）。
        10. 
      
      10. 关服务器：玩完了，在控制台输入 stop，它会先保存世界再关掉。别直接关终端窗口，那样可能丢掉最后一会儿盖的东西（第十二章）。
        11. 
    
      
  
      

  
      
    
      装置 · 第二十九章
      
    
      服务器设置
      
    
      server.properties 里有几十行设置，这里挑了最重要的七行。点一点每一行的选项，右边（手机上是下面）会生成要写进文件的样子，并告诉你每一项是什么意思。红框说明有一项不太安全。
      
    
      
      
      
      
      
    
      
    
      只改你看懂了的那几行，其余保持默认。改完要重启服务器才会生效。motd 是在服务器列表里显示的一句话，可以写你喜欢的。
      
  
      

  
      
    
      为什么不对整个互联网开放
      
    
      网上有很多教程，教你在家里的路由器上设置“端口转发”，让全世界的人都能连进你的服务器。这本书不教，也请你不要这样做，原因是：
      
    
        
      
      • 那等于在你家的网络上开了一扇朝着全世界的门。网上有程序整天在找这样开着的门，有的只是来捣乱，有的会想办法钻进你的电脑。
        • 
      
      • 你的服务器会暴露你家的 IP 地址，别人能大致知道你在哪个城市。
        • 
      
      • 陌生人进来以后，会发生第二十一章讲的那些事，而你是管理员，要替所有人负责。
        • 
    
      
    
      想和住得远的同学一起玩，可以和大人商量用官方的 Realms：它是官方帮你开的私人服务器，只有你邀请的人能进来，但要按月付费。
      

    
      服务器里也能放数据包
      
    
      服务器的世界存在 mc-server 文件夹里的 world 文件夹中，里面也有一个 datapacks。把第二十五章的数据包放进去，在控制台输入 reload，你写的函数就在服务器上生效了，所有进来的朋友都会看到。备份也一样：先 stop，再把整个 world 文件夹复制一份。
      
  
      

  
      
    
      2012 年，单人游戏变成了“自己连自己”
      
    
      早期的版本里，单人游戏和多人游戏是两套不一样的代码，同一个功能常常要写两遍，有时候单人能用、联机就坏了。2012 年 8 月的 1.3 版本，开发者把单人游戏也改成了“一个藏起来的服务器，加一个连上它的客户端”。从此以后，一个人玩和大家一起玩，用的是同一套规则。
      
    
      这是程序员很喜欢的一种做法：与其让两套东西各自出错，不如把它们变成一套。

      下界的一比八
      
    
      第一部第五章讲过下界。它有一个特别的规矩：在下界走 1 格，等于在主世界走 8 格。所以老玩家要去很远的地方，会先钻进下界，走一小段，再开一扇传送门出来。

      谁掉得快
      
    
      在游戏里从高处跳下来，你会越掉越快；真实世界里，一块石头从高处掉下来，也是越掉越快。可是“快多少”，两边的规则不一样。
      
    
        
      
      • 真实世界：不算空气阻力，物体每过一秒，往下的速度就增加大约 9.8 米/秒。从 20 米高掉下来，大约 2 秒落地。这是一条自然规律，四百多年前伽利略开始认真研究它，后来牛顿把它写成了公式。
        • 
      
      • 方块世界：据社区资料，Java 版里，玩家每一刻（0.05 秒）往下的速度先加上一点点（0.08 格/刻），再乘以 0.98，假装有空气阻力。这是做游戏的人写的一条规则，他们想改就能改。

      从多高

      火把的光，和真的光
      
    
      游戏里的亮度从 0 到 15。一根火把是 14，往外每走一格，亮度就少 1，走 14 格就黑了。从 1.18 版本起，只有在亮度是 0 的地方，怪物才会生成，所以玩家会在家附近插很多火把。
      
    
      真实的光不是这样“一格少一点”地变暗的。离一盏灯远一倍，照到你身上的光会变成原来的四分之一；远三倍，变成九分之一。这叫“平方反比”，等你上了中学物理课会学到。游戏用了一个简单得多的规则，因为它要一秒钟算很多次。
      

    
      五十块沙砾
      
    
      在生存模式里挖沙砾，有时候会掉出一块燧石。据社区维基，Java 版里（不用“时运”附魔）这个机会是十分之一。
      
    
      做个实验：挖 10 块，数一数掉了几块燧石；再挖 50 块、100 块。挖得越少，结果越“乱”，可能一块都没有，也可能有三块；挖得越多，燧石的比例越接近十分之一。这就是概率，也是为什么科学家做实验要做很多次。

      AI 很快给出了一大段回答，有文件夹、有代码，还写着“这样就可以了”。小格照着做了，/reload，什么都没发生。
      
      
      格它骗人！

      大约多久40 分钟

      先说规矩：几岁能用，用谁的账号
      
    
      能聊天的 AI 程序，各家都有自己的年龄规定，写在服务条款里：很多要求至少 13 岁，未满 18 岁要家长同意；有的要求必须满 18 岁。四年级的你，还不到这些年龄。
      
    
      所以这一章的规矩是：用大人的账号，大人坐在旁边，一起问、一起看。这不是不信任你，而是 AI 有时候会说错、会说出不适合小孩的东西，大人在旁边，能一起判断。
      
    
        
      
      • 不在 AI 里写你的真名、学校、住址、照片、密码（第二十一章的那四样，对 AI 也一样）。
        • 
      
      • 不让 AI 替你写作业、写作文。用它来问“为什么”，而不是要“答案”。
        • 
      
      • 它说的话，尤其是事实和代码，要查证、要试过才算数。
        • 
    
      

    
      AI 是怎样“说话”的
      
    
      第十四章讲过 CraftGPT：一个用红石搭的小聊天程序，里面存着五百多万个数，是它从一大堆对话里“学”来的。你今天能用的那些大型 AI，原理是同一类，只是大了几千倍到几十万倍，学过的文字多到一个人几辈子都读不完。
      
    
      它们说话的办法，简单说就是：根据前面的字，一次一次地猜“下一个字最可能是什么”，一个字一个字接下去。它猜得非常好，所以说出来的话通顺、有道理，常常还很有用。
      
    
      可是“猜得通顺”不等于“说得对”。它没有真的打开你的游戏看过，不知道你是哪个版本；它学过的资料里，老教程比新教程多，就容易给你老写法。它说错的时候，语气和说对的时候一模一样，一本正经，非常自信。所以要检查。
      
  
      

  
      
    
      两个月，一亿人
      
    
      2022 年 11 月底，一个能聊天的 AI 程序公开让大家试用。据报道，只用了大约两个月，用过它的人就超过了一亿，比以前任何一个网上的新东西都快。从那以后，世界各地的公司都做出了自己的 AI 助手。
      
    
      它们是怎样一步一步发展出来的，从模仿脑细胞的想法，到会“接龙”的语言模型，书房里给大人看的《计算机创世记》下卷《第二次创世》从头讲了一遍。
      
  
      

  
      
    
      好的问法
      
    
      第十五章说过，电脑不会猜你的意思，所以命令一个字母都不能错。AI 会猜，可是猜的方向不一定对。你说得越清楚，它猜得越准。一个好问题通常有这几样：你用的是什么（版本）、你想做什么、你已经做到哪儿了、你希望它怎么帮你。下面的装置帮你拼一个好问题。
      
  
      

  
      
    
      装置 · 第三十一章
      
    
      怎样问 AI
      
    
      勾上你想加进问题里的几样，下面会拼出一段问话，并告诉你还缺什么。这个装置只是在网页上拼字，不会把任何东西发给 AI。
      
    
      
    
      
    
      
    
      注意“先给提示，别直接给答案”这一条：你自己想出来的，比别人告诉你的记得牢得多。好的老师也是这样教的。
      
  
      

  
      
    
      一起检查一段 AI 写的代码
      
    
        
      
      1. 读：先不急着复制。请 AI 一行一行解释它写的代码，你用自己的话再说一遍。哪一行说不清，就再问。
        2. 
      
      2. 对版本：文件夹的名字、pack.mcmeta 里的数字、命令的写法，和第二十五章、社区维基对一对。AI 最常错的就是这些和版本有关的地方。
        3. 
      
      3. 在实验世界里试：永远在 gongfang 这样的实验世界里试，别在你的主世界里试（AI 写的一行 fill，可能把你的房子填满）。
        4. 
      
      4. 看报错：出错了，把报错的那一行原样告诉 AI（别带个人信息），请它解释原因。慢慢地，你自己也能看懂报错了。
        5. 
      
      5. 记下来：在你的作品集（第二十三章）里写一句：这次 AI 哪里说对了，哪里说错了，你是怎样发现的。
        6. 
    
      
    
      比起“会用 AI”，更重要的是“能判断 AI 说得对不对”。要能判断，你自己得懂。所以前面那几章，一行一行敲代码、一个一个读报错，一点都没有白学。

      会跳出来的回形针
      
    
      二十多年前，电脑上写文档的软件里有一个小助手：一个长着大眼睛的回形针，你写字的时候它会跳出来问“看起来你在写一封信，需要帮忙吗？”很多人觉得它烦人，它猜得不准，又总在你不需要的时候出现。2007 年前后，它就被拿掉了。今天的 AI 助手比它聪明得多，可是那个教训还在：帮手要等你问了才帮，而且要帮在点子上。
      
  
      

  
      
    
      AI 说的都是对的假
      
    
      AI 会说错，而且说错的时候听起来和说对的时候一样自信。它可能编出一个不存在的命令，给你一个老版本的写法，说出一个错的年份，甚至编出一本不存在的书。
      所以用 AI 的人要像科学家一样：它说的是“假设”，你去验证。代码能不能跑，在游戏里一试就知道；事实对不对，去找可靠的来源。这本书里每一个年份，也是这样查过的。
      
  
      

  
      
    
      联系
      
    
      从红石小机器人到你手边的 AI
      第十四章的 CraftGPT，五百万个数，四亿块方块，回一句话要九年；你手边的 AI，大得多、快得多，一秒钟就回你一大段。它们干的是同一类事：从学过的文字里找规律，一个字一个字地接下去。机器越会说话，人越要会提问、会判断。这两样本事，AI 替不了你。

      AI 助手能用文字和你聊天、回答问题、写代码的程序。

      验证用实验或者可靠的资料，检查一句话对不对。

      建议：用家长账号、家长在场；先教“问为什么、要提示”，不要一开始就让 AI 直接给完整答案；把“AI 说错了，我是怎么发现的”当作一项值得表扬的成就。AI 写的代码一律在测试世界里运行。这一章和第二十五、二十六章是一组：孩子自己写过、错过，才有能力检查 AI。
