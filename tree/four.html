      名字算出抽屉号

      一排 8 个抽屉，编号 0 到 7。规定一个算法：把名字里每个字的编号（《地基》第五章）乘上它是第几个字，加起来，再除以 8，余数就是抽屉号。“沙”算出来是 1，就放进 1 号抽屉。

      以后要找沙，再算一遍，还是 1，直接打开 1 号抽屉。不用一个一个翻，抽屉再多也只要算一次。这样的一排抽屉叫散列表（也叫哈希表），把名字变成抽屉号的算法叫散列函数。

      撞到同一个抽屉

      名字有无数种，抽屉只有 8 个，总会有两个名字算出同一个号，叫冲突。两种办法：

      • 挂一串（拉链法）：每个抽屉里放一串链表（第三章），算到同一格的都挂上去。找的时候打开那一格，在这一小串里找。
      • 往后找空位（开放定址）：这一格被占了，就看下一格；还被占了，再看下一格……找的时候也照这样往后找，碰到空格就说明没有。

      只要散列函数把名字分得够匀、抽屉不太挤，每一串都很短，找起来几乎就是一步。东西太多、抽屉太挤的时候，就换一排两倍多的抽屉，把东西重新放一遍。

      第二层 · 本科对照 408：散列（Hash）表约 60 分钟散列函数的四种构造；除留余数法 p 的选取；线性探测、平方探测、双散列、伪随机序列；拉链法；堆积；开放定址的逻辑删除；装填因子；查找成功和失败的 ASL 怎样算。

      散列函数

      • 直接定址：H(k) = a·k + b。不会冲突，但关键字分布稀疏时浪费空间。
      • 除留余数（最常用）：H(k) = k mod p。p 取不大于表长 m、最接近 m 的质数，让余数分布得匀。
      • 数字分析：关键字的某几位分布均匀时，取这几位（比如手机号的后四位）。
      • 平方取中：取 k² 的中间几位，每一位都受 k 的所有位影响。

      处理冲突

      开放定址：Hᵢ = (H(k) + dᵢ) mod m，i = 1, 2, …

      • 线性探测：dᵢ = 1, 2, 3, …。简单，但会产生堆积（聚集）：一段连续被占的位置越来越长，后来的同义词和非同义词都挤在后面。
      • 平方探测：dᵢ = 1², −1², 2², −2², …（表长要是形如 4k + 3 的质数才能探测到所有位置）。能减少堆积，但不一定能探测到全部单元。
      • 双散列：dᵢ = i × H₂(k)，第二个散列函数决定步长。
      • 伪随机序列：dᵢ 取一个伪随机数列。

      开放定址法不能真的删除元素：删掉以后那一格变空，会截断别的元素的探测序列，使它们“找不到”。只能做删除标记（逻辑删除），定期整理。

      拉链法：同义词串成链表。不会堆积，适合经常插入删除、表长不确定的情况。

      装填因子 α = 表中记录数 n / 表长 m。散列表的平均查找长度只取决于 α，不直接取决于 n 或 m：α 越大越挤，冲突越多。

      典型题 · 原创

      关键字 {25, 13, 40, 7, 33, 18, 61, 2} 依次存入长度为 11 的散列表（下标 0—10），H(k) = k mod 11，用线性探测处理冲突。（1）画出散列表。（2）求等概率下查找成功和查找失败的平均查找长度（与空单元的比较也算一次）。（3）若改用拉链法（新结点插在链尾），查找成功的 ASL 是多少？

      看解答

      （1）25 → 3；13 → 2；40 → 7；7 → 7 冲突，→ 8；33 → 0；18 → 7、8 都占，→ 9；61 → 6；2 → 2、3 都占，→ 4。表：0:33、2:13、3:25、4:2、6:61、7:40、8:7、9:18，其余空。

      （2）各元素的比较次数：33:1、13:1、25:1、2:3、61:1、40:1、7:2、18:3，成功 ASL = 13/8。失败：从每个可能的散列地址 0—10 出发，数到碰上空单元为止：地址 0 → 2 次（0、1），1 → 1，2 → 4（2、3、4、5），3 → 3，4 → 2，5 → 1，6 → 5（6—10），7 → 4，8 → 3，9 → 2，10 → 1，合计 28，失败 ASL = 28/11。

      （3）链：0:33；2:13→2；3:25；6:61；7:40→7→18。成功 ASL = (1 + 1 + 2 + 1 + 1 + 1 + 2 + 3)/8 = 12/8 = 1.5。

      失败 ASL 的分母

      失败 ASL 的分母是“散列函数可能算出的地址个数”，即 p（模数），不一定是表长 m。表长 13、H(k) = k mod 11 时，失败只可能从 0—10 这 11 个地址出发，分母是 11。另外，拉链法查找失败时，和空指针比较一般不计次数，各教材口径不同，按题目说明为准。

      Python 的字典

      CPython 的 dict 用开放定址：探测序列不是简单加一，而是 i = (5·i + 1 + perturb) mod 2ᵏ，perturb 是散列值的高位、每次右移 5 位，这样散列值的每一位最终都会影响探测路线。表长总是 2 的幂（取模变成按位与），装填超过 2/3 就扩容。3.6 起，散列表里只存一个小小的下标，真正的键值对按插入顺序放在另一个紧凑数组里，省内存，也让字典保持插入顺序（3.7 起写进语言规范）。

      散列洪水

      如果攻击者知道你的散列函数，就能故意造出成千上万个散列值相同的键，让散列表退化成链表，每次插入 O(n)，服务器被拖垮。2011 年的一次安全演讲演示了很多网页框架都有这个问题。办法是给散列函数加一个每次启动随机生成的“种子”：Python 3.3 起字符串散列默认随机化（环境变量 PYTHONHASHSEED 可以固定它），3.4 起用 SipHash，这就是第一层试验里“每次打开 Python 都不一样”的原因。

      一致性散列和布隆过滤器

      把数据分到 N 台服务器上，用 k mod N 的话，加一台服务器几乎所有数据都要搬家。一致性散列（1997）把服务器和数据都散列到一个圆环上，每个数据归顺时针方向的下一台服务器，加减一台只影响相邻的一小段。布隆过滤器（1970，《地基》第七章第三层）用几个散列函数在一个比特数组上做记号，能用极少的内存回答“肯定没有”或“可能有”。

      一个一个找

      东西没排序，只能从头一个一个看，叫顺序查找。运气好第一个就是，运气差看到最后。n 个东西，平均要看一半。

      对半找

      东西排好了序，就能用第一章的“对半猜”：看中间那个，比要找的大就去左半边找，小就去右半边找。每看一次，剩下的少一半，叫二分查找。一百万个，最多看 20 次。

      可是它有个前提：必须先排好序。乱的东西对半猜，看了中间那个也不知道该往哪边走。

      排行榜上第几名

      方格岛的排行榜按“用了几步完工”从少到多排好。你用了 42 步，能排第几名？就是问：有几个人比你少？

      用两个指针：lo 和 hi，答案一定在它们之间。每次看中间 mid：

      • mid 那个人的步数比你少：答案在 mid 右边，lo = mid + 1；
      • 不比你少：答案在 mid 或它左边，hi = mid。

      lo 和 hi 碰到一起时，就是比你少的人数，再加 1 就是你的名次。

      二分查找；判定树

      “二分查找”：输入一个步数，点“走一步”，看 lo（蓝）、hi（橙）、mid（深色）怎样移动。“判定树”是第二层的：拖动 n，看折半查找每一步可能比较的位置组成的树。

      二分为什么难写对

      写二分最容易错在边界上：hi 是“最后一个还可能是答案的”还是“它后面那一个”？循环条件写 lo < hi 还是 lo <= hi？mid 加不加一？只要一处不配套，就会少找一个、多找一个，或者永远停不下来。办法是先说清楚“答案一定在 [lo, hi] 里”这句话，每一行都守住它。

      顺序查找

      在 a[0] 放要找的关键字作哨兵，从 a[n] 往前找，循环里不用判断越界，找到下标 0 就是失败。等概率时：成功 ASL = (n + 1)/2；失败要比 n + 1 次。若表有序，查找失败时遇到第一个比它大的就能停：失败结点有 n + 1 个，ASL失败 = (1 + 2 + … + n + n)/(n + 1) = n/2 + n/(n + 1)。顺序查找对顺序存储和链式存储都适用。

      折半查找

      int bsearch(int a[], int n, int key) {      /* a[0..n-1] 升序 */
    int lo = 0, hi = n - 1;
    while (lo <= hi) {                       /* 答案若在，一定在 [lo, hi] */
        int mid = lo + (hi - lo) / 2;         /* 不写 (lo+hi)/2，防止溢出（第三层）*/
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}

      折半查找只适用于有序的顺序表（链表不能随机访问）。把每次比较的 mid 画成一棵二叉树，叫判定树：根是第一次比较的位置，左子树是比它小的一半。判定树是一棵平衡二叉树（408 约定 mid = ⌊(low + high)/2⌋ 时，每个结点的右子树结点数等于或比左子树多一个），高度 ⌈log₂(n + 1)⌉；查找成功的比较次数是结点的层数，失败的比较次数是失败结点双亲的层数。

      二分查找的虫子

      本特利在《编程珠玑》（1986）里写道：他让上百个专业程序员当场写二分查找，大约九成的人写出了有虫子的代码。更有意思的是 2006 年：谷歌的布洛赫发现，Java 标准库（以及《编程珠玑》里的那个版本）里的二分查找有一个虫子，藏了将近二十年：mid = (low + high) / 2 在数组超过十亿个元素时，low + high 会超过 int 的上限变成负数（《地基》第三章的溢出）。改成 low + (high − low) / 2 或无符号右移才对。这也是《地基》第三章第三层提到的那个例子。

      别的查找

      • 插值查找：在电话簿里找“张”，你不会翻到正中间，而会翻到靠后的地方。按值估计位置：mid = lo + (x − a[lo]) × (hi − lo) / (a[hi] − a[lo])。数据均匀分布时平均 O(log log n)，分布不均时最坏 O(n)。
      • 指数查找：不知道数组多长（或答案离开头很近）时，先看 1、2、4、8……找到一个大于 x 的位置，再在最后一段里二分。O(log i)，i 是答案的位置。

      怎样选

      只查不改：排好序的数组加二分，省内存、对缓存友好。又查又改、要有序：平衡树（第十一章）或 B+ 树（第十五章）。只要“有没有”“是多少”、不要顺序：散列表（第二十三章），平均 O(1)。这本书的几十种结构，最后都落在这样的取舍上。

      插入类

      void insert_sort(int a[], int n) {                 /* 直接插入 */
    for (int i = 1; i < n; i++) {
        int x = a[i], j = i - 1;
        while (j >= 0 && a[j] > x) { a[j + 1] = a[j]; j--; }
        a[j + 1] = x;
    }
}
void shell_sort(int a[], int n) {                  /* 希尔：对每个间隔做插入排序 */
    for (int d = n / 2; d >= 1; d /= 2)
        for (int i = d; i < n; i++) {
            int x = a[i], j = i - d;
            while (j >= 0 && a[j] > x) { a[j + d] = a[j]; j -= d; }
            a[j + d] = x;
        }
}
      • 直接插入：最好（已有序）比较 n − 1 次、O(n)；最坏（逆序）O(n²)；平均 O(n²)；稳定。适用于顺序表和链表。
      • 折半插入：用二分找插入位置，比较次数降到 O(n log n)，但元素移动次数不变，总体仍 O(n²)；稳定。只适用于顺序表。
      • 希尔排序：按间隔 d 分组，组内插入排序，d 逐步缩小到 1。时间依赖于间隔序列，n 在某个范围内约 O(n1.3)，最坏 O(n²)；不稳定（相同元素可能被分到不同组）；只适用于顺序表。

      冒泡和简单选择

      • 冒泡：每趟把最大（或最小）的元素放到最终位置；某一趟没有交换就结束。最好 O(n)（一趟），最坏、平均 O(n²)；稳定。
      • 简单选择：比较次数总是 n(n − 1)/2，与初始序列无关；移动次数最多 3(n − 1)（每趟一次交换）；O(n²)；不稳定。例子：2, 2', 1，第一趟把 1 和 2 交换，得 1, 2', 2。

      挑一个当标杆

      1. 从一堆数里挑一个当标杆（比如第一个）。
      2. 比标杆小的都放到它左边，大的都放到它右边。这一步叫划分。划分完，标杆就站在了它最终该站的位置。
      3. 左边那一堆、右边那一堆，各自再用同样的办法排（第七章的递归：相信自己）。
      4. 一堆只剩 0 个或 1 个，就不用排了（终点）。

      这是 1959 年英国人霍尔想出来的，叫快速排序。它把一个大问题分成两个小问题，是第七章说的分治。

      为什么快

      如果每次标杆都正好在中间，一堆就分成差不多一样大的两堆：一千个分成两个五百，再分成四个二百五……分十来层就分到底了，每一层所有的数加起来只比较一遍：大约 1000 × 10 次。简单排序要大约 1000 × 1000 / 2 次。

      什么时候慢

      可是如果数本来就排好了，每次挑第一个当标杆，它就是最小的：左边一个都没有，右边是剩下的全部。每次只少了一个，要分一千层，比较五十万次，和简单排序一样慢。

      办法是：随便挑一个当标杆（随机挑），或者挑头、中、尾三个里中间大的那个。这样不管数据长什么样，都很难每次都挑到最小的。

      第二层 · 本科对照 408：交换排序（快速排序）约 55 分钟408 风格的划分（挖坑填数）；每趟结果；递归深度和空间；最好 O(n log n)、最坏 O(n²)；不稳定；“第 k 趟后有几个元素到了最终位置”；快速选择。

      一趟划分

      int partition(int a[], int lo, int hi) {
    int p = a[lo];                         /* 标杆，lo 处成了一个“坑” */
    while (lo < hi) {
        while (lo < hi && a[hi] >= p) hi--;
        a[lo] = a[hi];                     /* 右边比标杆小的填到左边的坑 */
        while (lo < hi && a[lo] <= p) lo++;
        a[hi] = a[lo];                     /* 左边比标杆大的填到右边的坑 */
    }
    a[lo] = p;                             /* 标杆归位 */
    return lo;
}
void quick_sort(int a[], int lo, int hi) {
    if (lo < hi) { int m = partition(a, lo, hi); quick_sort(a, lo, m - 1); quick_sort(a, m + 1, hi); }
}
      • 时间：每层划分共 O(n)。每次划分均匀时递归深度 log n，O(n log n)；每次划分极不均匀（初始有序或逆序，取首元素为标杆）时深度 n，O(n²)。平均 O(n log n)，是内部排序中平均性能最好的。
      • 空间：递归栈，最好 O(log n)、最坏 O(n)。（先递归短的那一段、长的用循环，可以保证 O(log n)。）
      • 不稳定：例如 {3, 2, 2'}，标杆 3，第一趟 2' 被填到最前面，得 {2', 2, 3}。
      • 每一趟（对每一段的一次划分）至少把一个元素（标杆）放到最终位置。408 常问“第二趟结束后，下列哪个序列可能是结果”：第 k 趟结束后，至少有 k 个元素在最终位置；若某一趟的标杆在一端（另一段为空），下一趟只对一段划分，最终位置的元素就少。

      找第 k 小的数，不必全排好：划分一次，标杆落在位置 m。若 m = k，就是它；若 k < m，只去左边找；否则只去右边找。每次只递归一边，平均 n + n/2 + n/4 + … = O(n)，最坏 O(n²)（同样用随机标杆避免）。还有一种最坏也是 O(n) 的“中位数的中位数”算法（1973），常数大，主要有理论意义。

      两摞合成一摞

      桌上有两摞牌，每一摞都已经从小到大排好，最小的在最上面。要合成一摞排好的：只要看两摞最上面那张，拿小的那张放到新的一摞上；再看两摞最上面那张，拿小的……一摞拿完了，另一摞剩下的直接放上去。

      为什么只看最上面的？因为每一摞都排好了，最上面那张就是这一摞里最小的，两个“最小的”里更小的那个，一定是所有牌里最小的。这一步叫归并，两摞一共 n 张，最多比 n 次。

      对半分到底，再一层层合起来

      一摞乱的牌怎么办？把它分成两半，两半各自排好（第七章：相信自己），再归并成一摞。一半怎么排好？再分成两半……分到每摞只有一张，一张牌天然是排好的。然后一层一层往回合：一张一张合成两张，两张两张合成四张……这叫归并排序。

      一千张牌，对半分大约 10 层；每一层把所有牌合一遍，最多比 1000 次。一共大约 1000 × 10 次。不管牌一开始是乱的、排好的还是倒着的，都是这么多：它不会像快速排序那样碰上最慢的情况。代价是合的时候要一块空地方放新的一摞。

      二路归并排序

      int B[MAXN];                                   /* 辅助数组 */
void merge(int A[], int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++) B[k] = A[k];
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) A[k++] = (B[i] <= B[j]) ? B[i++] : B[j++];   /* <= 保证稳定 */
    while (i <= mid) A[k++] = B[i++];
    while (j <= hi)  A[k++] = B[j++];
}
void merge_sort(int A[], int lo, int hi) {
    if (lo < hi) { int mid = (lo + hi) / 2; merge_sort(A, lo, mid); merge_sort(A, mid + 1, hi); merge(A, lo, mid, hi); }
}

      n 个元素的二路归并排序要 ⌈log₂n⌉ 趟，每趟 O(n)，时间总是 O(n log n)（最好、最坏、平均都一样）；空间 O(n)；稳定。k 路归并排序的趟数是 ⌈logkn⌉。

      外部排序

      两个阶段：① 生成初始归并段（读入内存、内部排序或置换-选择排序、写回）；② 多趟归并。时间主要花在读写外存上，所以要减少归并的趟数：r 个初始段、k 路归并，趟数 = ⌈logkr⌉。两个办法：

      • 增大 k：但 k 路归并时，每选一个最小记录要比较 k − 1 次，k 大了内部比较变多。败者树解决这个问题：一棵完全二叉树，叶子是 k 个归并段当前的记录，分支结点记“比赛的败者”、胜者继续往上比，根上方记最终胜者。选出一个以后，只需沿它所在的叶子到根重新比一遍，比较 ⌈log₂k⌉ 次。总比较次数不再随 k 线性增长。
      • 减少 r：用置换-选择排序生成更长的初始段（平均是工作区大小的两倍）。

      初始段长短不一时，合并的顺序影响读写总量。把每段的长度当成权，构造 k 叉哈夫曼树（第十三章），叫最佳归并树，读写次数 = 2 × 带权路径长度。若 (r − 1) mod (k − 1) = u ≠ 0，补 k − u − 1 个长度为 0 的虚段。

      Timsort

      真实的数据很少是完全随机的：常常有一段已经排好、一段倒着排好。2002 年，彼得斯为 Python 写的 Timsort 抓住了这一点：先从左往右扫，找出天然的有序段（倒序的就翻过来），太短的段用折半插入排序补到一个最小长度；然后用一个栈管理这些段，按规则归并相邻的段，保证归并平衡。合并时如果发现一边连续赢了很多次，就切换到“飞奔”模式，用指数查找（第二十四章）一次跳过一大块。对已经排好的数据它是 O(n)，最坏仍是 O(n log n)，而且稳定。Java 对对象数组、Android、V8 引擎（JavaScript 的 sort）后来也用了它。2015 年，有研究者用形式化验证工具发现 Timsort 维持栈平衡的规则有一个漏洞，在特别构造的超大数组上会出错，Python 和 Java 随后都修正了。

      大数据排序

      数据库执行 ORDER BY 时内存不够，就做外部排序（写临时文件再归并）。MapReduce 和 Spark 的“洗牌”阶段，每台机器先把自己的数据按键排好、切块，再把同一个键范围的块送到同一台机器上归并：这就是第二层讲的两个阶段，只是“硬盘”换成了一整个机群。

      堆排序

      void heap_sort(int A[], int n) {               /* A[1..n]，大根堆；sift_down 见第十二章 */
    for (int k = n / 2; k >= 1; k--) sift_down(A, k, n);   /* 建堆 O(n) */
    for (int i = n; i > 1; i--) {
        int t = A[1]; A[1] = A[i]; A[i] = t;    /* 堆顶换到最后 */
        sift_down(A, 1, i - 1);                  /* 剩下的修成堆 */
    }
}

      建堆 O(n)，n − 1 次调整各 O(log n)：总时间 O(n log n)（最好、最坏、平均都是）；空间 O(1)；不稳定。适合“从很多数里只要前几个”的场合（选出前 k 个只要 O(n + k log n)）。

      基数排序

      关键字拆成 d 位，每位取值有 r 种（十进制 r = 10）。最低位优先（LSD）：从最低位到最高位，每一趟先分配（按这一位扔进 r 个队列）、再收集（按队列顺序首尾相接）。一趟分配 O(n)、收集 O(r)，共 O(d(n + r))；空间 O(r)（用链式队列）；稳定。最高位优先（MSD）先按最高位分组，组内递归，适合字符串。基数排序不是基于比较的。

      比较排序的下界

      任何基于比较的排序都可以画成一棵判定树：每个内部结点是一次比较，每个叶子是一种排列。n 个元素有 n! 种排列，二叉树要有 n! 个叶子，高度至少 ⌈log₂ n!⌉ ≈ n log₂n − 1.44n。所以比较排序最坏至少要 Ω(n log n) 次比较。例如 n = 5：⌈log₂120⌉ = 7 次。

      桶排序：数据在 [0, 1) 上均匀分布时，分成 n 个桶，每桶期望 O(1) 个元素，桶内插入排序，期望 O(n)。分布不均时退化。

      基数排序的真实用法：GPU 上给几亿个整数或浮点数排序，最快的往往是基数排序（每一趟都是规整的并行计数和搬运，第十五章说的“规整访问”）；数据库给整数键排序、字符串处理里构造后缀数组，也常用基数排序的思想。

      标准库为什么还用比较排序：比较排序只需要一个“比大小”的函数，适用于任何类型；基数排序要知道键的内部结构（多少位、什么编码），而且要额外的空间。所以 Python、C++、Java 的通用排序函数都是比较排序，专门的场合才用基数排序。

      第四部的七句话

      1. 名字算出抽屉号，撞了就挂一串或往后找，挤了就换大。（第二十三章）
      2. 排好序就对半找；先说清答案在哪个范围里，再写代码。（第二十四章）
      3. 插入像整理牌，冒泡大的往后冒，选择每次挑最小；一样大的先后不变叫稳定。（第二十五章）
      4. 挑标杆，小的左、大的右；随便挑就不怕最慢的情况。（第二十六章）
      5. 对半分到底再合起来，总是 n log n、稳定；装不下就外部排序。（第二十七章）
      6. 堆排序拿最大的；不比大小也能排，但要知道数长什么样。（第二十八章）
      7. 真实的程序把几种结构组合起来用。（尾声）

      哪些是真的，哪些存疑

      全书讲的是技术原理，都能在书里提到的教材、论文和源码中核对；书桌上的两人对话、方格岛、团团、村子和排行榜上的人都是虚构的。第四部里有不同说法或细节不确定的地方：

      • 本特利“约九成程序员写不对二分查找”出自《编程珠玑》里的课堂经验，不是严格的统计。
      • 二分查找“1946 年首次提到、1962 年才有对所有 n 都正确的版本”出自克努特的考证。
      • 霍尔在莫斯科想到快排的经过出自他本人后来的回忆，各处讲法细节略有不同。
      • CPython 字典和 Timsort 的细节随版本变化（例如新版本的归并策略有调整），以源码为准。
      • InnoDB、Redis 等真实系统的实现细节只作举例，以各自的官方文档为准。
      • “打孔卡片分类机做的是基数排序”是对其工作方式的通俗说法。
      • 前三部的存疑见各部的部末。
