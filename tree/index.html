      几个基本词

      • 数据：能输入电脑、被程序处理的符号的总称。
      • 数据元素：数据的基本单位，通常作为一个整体处理，比如一个学生的记录。一个数据元素可以由若干数据项组成（学号、姓名、成绩），数据项是不可分割的最小单位。
      • 数据对象：性质相同的数据元素的集合，比如全班学生的记录。
      • 数据结构：相互之间存在某种关系的数据元素的集合。它有三个方面：逻辑结构、存储结构（物理结构）、数据的运算。

      逻辑结构和存储结构

      逻辑结构只管“元素之间是什么关系”，和电脑无关：

      逻辑结构关系本书
      集合同属一个集合，别无关系散列表、并查集
      线性结构一对一：除了头尾，每个元素前后各一个第一部：数组、链表、栈、队列、串
      树形结构一对多：一个上级，多个下级第二部
      图状结构（网状结构）多对多第三部

      存储结构是逻辑结构在内存里的实现，常见四种：

      • 顺序存储：逻辑上相邻的元素，物理位置也相邻（数组）。随机存取快，插入删除要挪动元素，可能有外部碎片。
      • 链式存储：不要求物理相邻，用指针表示关系（链表）。不会有碎片，但指针占空间，只能顺序存取。
      • 索引存储：另建一张索引表（关键字 → 地址）。检索快，索引表占空间，增删要改索引。
      • 散列存储：由关键字直接算出地址（散列表）。检索、增删都快，但有冲突要处理。
      常考的混淆

      “有序表”是逻辑结构上的说法（元素按关键字有序），它可以顺序存储，也可以链式存储；“顺序表”是存储结构（顺序存储的线性表）。“循环队列”是用顺序表表示的队列，属于存储结构层面的概念；“栈”“队列”本身是逻辑结构（受限的线性表）。

      算法

      算法是对特定问题求解步骤的描述，是指令的有限序列。五个特性：

      1. 有穷性：有限步之后结束，每步在有限时间内完成。（程序可以不满足，比如操作系统一直在跑；算法必须满足。）
      2. 确定性：每条指令含义明确，相同输入得到相同输出。
      3. 可行性：每一步都能用已经实现的基本运算执行有限次完成。
      4. 输入：零个或多个。
      5. 输出：一个或多个。

      一个“好”算法还要做到：正确性、可读性、健壮性（输入非法时能妥善处理）、高效率和低存储量需求。最后一条就是下一章的时间复杂度和空间复杂度。

      典型题 · 原创

      （1）下列说法中，属于存储结构的是：A. 栈 B. 有序表 C. 循环队列 D. 二叉树。（2）以下哪一项违反了算法的特性：A. 一个算法有 0 个输入 B. 一个算法在某组输入下永远不停 C. 一个算法有 2 个输出 D. 一个算法的某一步要调用另一个算法。

      看解答

      （1）C。循环队列指明了“用数组首尾相接”来存队列，是存储结构；栈、有序表、二叉树都只说了元素之间的关系，是逻辑结构。

      （2）B，违反有穷性。0 个输入是允许的（比如“打印 1 到 10”）；调用别的算法只要它也有穷，整体仍然可行。

      面试题

      数组和链表各有什么优缺点？什么时候用哪个？

      看要点

      数组：连续存放，按下标 O(1) 访问，缓存友好；中间插入删除要挪动 O(n)，扩容要整体搬家。链表：插入删除只改指针 O(1)（前提是已经拿到了位置），不需要连续空间；访问第 i 个要从头走 O(n)，每个结点多占指针，缓存不友好。读多写少、按位置访问用数组；频繁在已知位置插入删除、或者元素很大不想搬动用链表。可以补一句：实际工程里动态数组（vector、Python 的 list）用得多得多，因为缓存的影响很大。第二、三章细讲。

      抽象数据类型

      抽象数据类型（ADT）只规定一组操作和它们的含义，不规定怎样实现。“栈”这个 ADT 就是：push、pop、看栈顶、判空，后进先出。你可以用数组实现它，也可以用链表实现它，用的人不用关心。这和《地基》第零章讲的“抽象”是同一个想法：上一层只看接口，下一层管实现。

      同一个 ADT 的不同实现，操作的代价不一样。“有序的字典”这个 ADT，可以用有序数组（查找 O(log n)，插入 O(n)）、平衡搜索树（都是 O(log n)）、跳表或 B+ 树实现。选哪个，看哪种操作多、数据放在内存还是磁盘。这本书反复做的，就是这种取舍。

      频度和时间复杂度

      一条语句被重复执行的次数叫它的频度。所有语句频度之和记作 T(n)，n 是问题规模。我们只关心 n 很大时 T(n) 怎样增长，所以只保留增长最快的那一项、去掉系数：T(n) = 3n² + 5n + 7，记作 T(n) = O(n²)。通常只看最深层循环里“基本运算”的执行次数就够了。

      • 加法规则：T(n) = T₁(n) + T₂(n) = O(max(f(n), g(n)))。两段代码先后执行，取大的那个。
      • 乘法规则：T(n) = T₁(n) × T₂(n) = O(f(n) × g(n))。一段套在另一段的循环里，相乘。

      常见的阶从小到大：

      O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)

      口诀：“常对幂指阶”（常数、对数、幂函数、指数、阶乘）。log 的底数不影响阶（换底只差一个常数倍），一律写 log n，在计算机里默认以 2 为底。

      写法次数复杂度

      for (i = 1; i < n; i *= 2)2k < n，k ≈ log₂nO(log n)

      第四行最容易错

      外层 log n 次，内层看起来像“最多 n 次”，于是有人答 O(n log n)。其实内层次数随 i 翻倍，总数是等比数列 1 + 2 + 4 + … + 2k < 2 × 2k ≤ 2n，所以是 O(n)。遇到内层依赖外层变量的循环，老老实实把总次数加出来。

      算法的执行时间还可能和输入的样子有关。在一个长度为 n 的数组里顺序找一个数：第一个就是它，1 次（最好）；不在里面或在最后，n 次（最坏）；各位置等概率，平均 (n+1)/2 次（平均）。没有特别说明时，一般讨论最坏情况。

      空间复杂度

      S(n) 是算法所需存储空间（除去输入本身）随 n 的增长。只用了几个变量，S(n) = O(1)，叫原地工作。注意递归：每层递归占一个栈帧（《地基》第二十章），递归深度为 d 时，空间至少 O(d)。递归求阶乘的空间是 O(n)，不是 O(1)。

      递推式先看一眼

      递归算法的时间常写成递推式。例如“把规模 n 的问题分成两半，各递归一次，再花 n 步合起来”：T(n) = 2T(n/2) + n，解出来是 O(n log n)（归并排序，第二十七章）。“每次只剩一半、只递归一边”：T(n) = T(n/2) + 1，是 O(log n)（二分）。第七章细讲怎样解。

      典型题 · 原创

      求下列程序段的时间复杂度（n ≥ 2）：

      /* (1) */ int s = 0; for (int i = 1; i <= n; i *= 3) s += i;
/* (2) */ int c = 0; for (int i = 1; i <= n; i++) for (int j = i; j <= n; j += i) c++;
/* (3) */ int x = n; int y = 0; while (x >= (y + 1) * (y + 1)) y++;

      （1）i 取 1, 3, 9, …，3k ≤ n，循环 ⌊log₃n⌋ + 1 次，O(log n)。

      三个记号

      • f(n) = O(g(n))：存在正常数 c 和 n₀，使得对所有 n ≥ n₀，0 ≤ f(n) ≤ c·g(n)。上界。
      • f(n) = Ω(g(n))：存在 c > 0、n₀，n ≥ n₀ 时 f(n) ≥ c·g(n)。下界。
      • f(n) = Θ(g(n))：同时是 O 和 Ω。紧确界。

      严格地说，“二分查找是 O(n)”也是对的（上界松了），只是没用。日常和考试里说的 O，大多其实指 Θ。“比较排序最坏要 Ω(n log n) 次比较”（第二十八章）是一个下界，意思是任何比较排序都快不过它。

      均摊分析

      Python 的 append 偶尔要把整个列表搬到更大的地方，这一次是 O(n)。那 append 还算 O(1) 吗？

      假设每次满了就把容量翻倍。从空开始 append n 次，搬家发生在容量 1, 2, 4, …, 2k（≤ n）时，搬动的元素总数 1 + 2 + 4 + … + 2k < 2n。加上 n 次普通写入，总代价 < 3n，平均每次 O(1)。这叫均摊（聚合分析）。也可以用“记账法”：每次 append 预付 3 块钱，1 块付自己的写入，2 块存起来留给以后搬家，存款永远不会是负的。

      扩容倍数不一定是 2：只要按比例（而不是每次加固定几个）扩容，均摊就是 O(1)；每次只多加 10 个，均摊会退化成 O(n)。CPython 的 list 大约按 1.125 倍扩容，Java 的 ArrayList 是 1.5 倍。

      import timeit
for n in [1000, 10000, 100000]:
    data = list(range(n))
    s = set(data)
    t_list = timeit.timeit(lambda: (n - 1) in data, number=200)

      拿第 i 个：一步

      要拿第 i 个，电脑不用一格一格地数。它知道第 0 格在哪儿，每格多大，一算就知道：

      第 i 格的位置 ＝ 第 0 格的位置 ＋ i × 每格的大小

      一次乘法、一次加法，直接跳过去。所以不管数组有 10 个还是 100 万个，拿第 i 个都只要一步：常数。

      线性表和顺序表

      线性表是 n（≥ 0）个相同类型数据元素的有限序列。除第一个元素外每个元素有唯一的直接前驱，除最后一个外每个有唯一的直接后继。注意 408 的约定：线性表的位序从 1 开始，数组下标从 0 开始，写代码时别差一位。

      用顺序存储实现的线性表叫顺序表：

      #define MAXSIZE 100
typedef struct {
    int data[MAXSIZE];   /* 静态分配：大小编译时定死 */
    int length;
} SqList;

typedef struct {
    int *data;           /* 动态分配：用 malloc 申请，满了可以 realloc 换一块更大的 */
    int capacity, length;
} SeqList;

      动态分配仍然是顺序存储：换大以后元素还是连续的，只是整体搬到了一块新地方（《地基》第二十一章的堆）。

      插入和删除

      /* 在第 i 个位置（1 ≤ i ≤ length+1）插入 e */
int insert(SqList *L, int i, int e) {
    if (i < 1 || i > L->length + 1 || L->length >= MAXSIZE) return 0;
    for (int j = L->length; j >= i; j--)    /* 从最后一个往后挪 */
        L->data[j] = L->data[j - 1];
    L->data[i - 1] = e;
    L->length++;
    return 1;
}
/* 删除第 i 个（1 ≤ i ≤ length），用 *e 带回 */
int delete(SqList *L, int i, int *e) {
    if (i < 1 || i > L->length) return 0;
    *e = L->data[i - 1];
    for (int j = i; j < L->length; j++)     /* 后面的往前挪 */
        L->data[j - 1] = L->data[j];
    L->length--;
    return 1;
}

      在第 i 个位置插入要移动 n − i + 1 个元素。插入位置有 n + 1 种，等概率时平均移动 n/2 次；删除第 i 个移动 n − i 个，n 种位置，平均 (n − 1)/2 次。两者都是 O(n)。按位置取值 O(1)（随机存取），按值查找平均 (n + 1)/2 次比较，O(n)。

      三道经典题：双指针

      顺序表的算法题，很多都可以用“一个读、一个写”的两个下标在一遍之内做完，时间 O(n)、空间 O(1)。

      典型题 · 原创

      （1）删除顺序表中所有值在 [s, t] 之间的元素，要求时间 O(n)、空间 O(1)。（2）把数组 A[0..n−1] 循环右移 k 位（0 < k < n），空间 O(1)。（3）两个升序数组 A、B 各有 n 个数，找出合并以后的第 n 小的数（下中位数），要求尽量快。

      看解答

      （1）读指针 i 从头走到尾，写指针 k 记“留下的有几个”：A[i] 不在 [s, t] 内就 A[k++] = A[i]，最后 length = k。每个元素只看一次。

      int k = 0;
for (int i = 0; i < L->length; i++)
    if (L->data[i] < s || L->data[i] > t) L->data[k++] = L->data[i];
L->length = k;

      （2）三次逆置：先整体逆置，再分别逆置前 k 个和后 n − k 个。例如 1 2 3 4 5 右移 2：整体逆置 5 4 3 2 1，前 2 个逆置 4 5，后 3 个逆置 1 2 3，得 4 5 1 2 3。每次逆置是首尾两个下标往中间走、交换，总共约 n 次交换，O(n) 时间、O(1) 空间。（左移 k 位就是右移 n − k 位。）

      （3）O(n) 的做法：两个指针像合并一样往前走 n 步。更快的做法是二分：比较 A 和 B 的中位数 a、b；若 a = b 即为所求；若 a < b，答案不可能在 A 的前半段和 B 的后半段，各舍去相同的个数，规模减半，O(log n)。写对舍去时奇偶长度的处理是这题的难点：保证两边舍去的个数相等。

      Python 的 list 放的是什么

      CPython 的 list 是一块连续的数组，可里面存的不是数本身，而是指向对象的指针（每个 8 字节）。[1, 2, 3] 里的 1、2、3 是三个各自住在堆上的整数对象。所以 list 能装不同类型的东西，代价是每个元素多一次“照着纸条找过去”，而且对象散落在内存各处，缓存不友好。

      要存大量同类型的数，用标准库的 array.array('i')，或者 NumPy 的数组：它们把数直接挨着放，省空间、算得快，NumPy 还能用 SIMD 指令一次算好几个。

      结构体的数组，数组的结构体

      游戏里有一万只鸭子，每只有 x、y、颜色、名字。可以存成“一万个结构体排成一排”（AoS，array of structures），也可以存成“四个数组，各有一万个”（SoA，structure of arrays）。如果某个循环只更新所有鸭子的 x、y，SoA 让要用的数挨在一起，每次读进缓存的 128 字节（Apple Silicon 的缓存行，《地基》第十六章）全是有用的；AoS 会把名字、颜色也一起读进来，浪费带宽。游戏引擎和数据库的“列式存储”都是这个想法。

      为什么连续存放格外快

      现代处理器访问内存的代价，和“访问的是不是挨着的”关系极大：顺序访问能被预取器提前搬进缓存，随机跳着访问每次都可能要等上百个时钟周期。所以数组的常数常常比链表小一个数量级，这也是第三章链表的第三层要讨论的。

      寻宝纸条

      寻宝游戏里，第一张纸条写着“去书架”；书架上有第二张，写着“去冰箱”；冰箱上有第三张……最后一张写着“宝藏在这里”。

      这一串纸条可以藏在家里的任何地方，不用挨着。只要每一张都写清楚下一张在哪儿，就能一张一张找下去。

      这就是链表。链表里的每一个东西叫一个结点，每个结点里有两样：

      • 它自己的东西（比如一只鸭子的名字）；
      • 一张纸条，写着下一个结点在哪儿。最后一个结点的纸条是空的，表示“到头了”。

      另外还要记着第一个结点在哪儿，叫头（head）。没有头，就不知道从哪儿开始找。

      纸条就是指针

      《地基》第十八章说，写着柜子号码的纸条叫指针。链表就是一串用指针连起来的结点。在 Python 里不用写指针：一个变量“指着”一个字典或列表，就是一张纸条。

      鸭子队伍

      方格岛上，三只小鸭子跟在你身后。主线第 3 步就用链表来存这支队伍：每只鸭子记着自己站在哪儿，还拿着一张纸条，写着下一只是谁。

      你往前走一步，队伍怎样跟上？不用把每只鸭子都挪一遍，只要两件事：

      1. 在你刚才站的地方，加一只新的“头鸭子”，让它的纸条指着原来的第一只。
      2. 把最后一只拿走。

      看起来，就像整支队伍跟着你挪了一步。

      什么快，什么慢

      加到最前面很快：新结点的纸条写上“原来的头”，再把头改成新结点。两步，不管链表有多长。数组插到最前面，要挪一整串（第二章）。

      找第 k 个很慢：没有“开头 + k × 大小”这种算法，因为结点不挨着。只能从头开始，照着纸条一个一个走，走 k 步。数组一步就到。

      拿走最后一个也慢：要先从头走到倒数第二个，才能把它的纸条改成空的。

      数组链表
      拿第 k 个一步从头走 k 步

      放在内存里要一整块挨着的哪儿有空放哪儿

      单链表

      typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkList;

      多数教材和 408 默认带头结点：在第一个数据结点前面放一个不存数据的结点，头指针指着它。好处：① 在第一个位置插入删除和在别处一样，不用特殊处理；② 空表和非空表的处理统一（空表时头结点的 next 为 NULL）。判空：带头结点 L->next == NULL，不带头结点 L == NULL。

      /* 头插法：每个新结点插在头结点后面。读入顺序和链表顺序相反 */
LinkList build_head(int *a, int n) {
    LinkList L = malloc(sizeof(LNode)); L->next = NULL;
    for (int i = 0; i < n; i++) {
        LNode *s = malloc(sizeof(LNode)); s->data = a[i];
        s->next = L->next; L->next = s;
    }
    return L;
}
/* 尾插法：多一个尾指针 r，顺序和读入一致 */
LinkList build_tail(int *a, int n) {
    LinkList L = malloc(sizeof(LNode)); LNode *r = L;
    for (int i = 0; i < n; i++) {
        LNode *s = malloc(sizeof(LNode)); s->data = a[i];
        r->next = s; r = s;
    }
    r->next = NULL;
    return L;
}

      按序号查找、按值查找都要从头走，O(n)。插入：在第 i 个位置插入，先找到第 i − 1 个结点 p，再 s->next = p->next; p->next = s;，两句不能颠倒（颠倒了 p 原来的后继就丢了）。找位置 O(n)，真正插入 O(1)。删除第 i 个：找到第 i − 1 个 p，q = p->next; p->next = q->next; free(q);。

      只给了 p 本身，要在 p 前面插入或删除 p

      单链表找不到前驱。技巧是“偷梁换柱”：在 p 后面插入新结点 s，再交换 p 和 s 的数据，效果等同于插在 p 前面，O(1)。删除 p：把后继 q 的数据抄进 p，再删掉 q。但 p 是最后一个结点时不能这样删，只能从头找前驱。

      双链表和循环链表

      双链表每个结点多一个 prior 指针，可以 O(1) 找前驱。在 p 之后插入 s，四句的一种正确顺序：

      s->next = p->next;           /* ① s 先接上 p 的后继 */
if (p->next) p->next->prior = s;  /* ② 后继回指 s（p 是尾结点时没有后继）*/
s->prior = p;                 /* ③ */
p->next = s;                  /* ④ 最后才改 p->next */

      原则：在 p->next 被改掉之前，先用完它。删除 p 的后继 q：p->next = q->next; if (q->next) q->next->prior = p; free(q);。

      循环单链表：最后一个结点指回头结点，判空是 L->next == L。常只设尾指针 r：头是 r->next，这样在头和尾插入都是 O(1)。循环双链表：头结点的 prior 指向尾结点。

      静态链表：用数组存结点，“指针”是下一个元素的下标（游标），−1 或 0 表示结束。适合没有指针的语言，或者要预先分配好空间的场合（比如操作系统的 FAT 文件分配表，《地基》第二十八章）。

      快慢指针和几道高频题

      /* 原地逆置（带头结点）：一个一个摘下来，头插回去 */
void reverse(LinkList L) {
    LNode *p = L->next, *r; L->next = NULL;
    while (p) { r = p->next; p->next = L->next; L->next = p; p = r; }
}
/* 找中点：慢的走一步，快的走两步；快的到头时慢的在中间 */
LNode *middle(LinkList L) {
    LNode *slow = L->next, *fast = L->next;
    while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
    return slow;
}
/* 判环（弗洛伊德）：有环则快慢终会相遇 */
int has_cycle(LinkList L) {
    LNode *slow = L, *fast = L;
    while (fast && fast->next) {
        slow = slow->next; fast = fast->next->next;
        if (slow == fast) return 1;
    }
    return 0;
}
      • 倒数第 k 个：快指针先走 k 步，然后两个一起走，快的到头时慢的就是倒数第 k 个。一遍扫描。
      • 环的入口：相遇以后，一个指针回到头，两个都每次走一步，再次相遇处就是入口。（设头到入口 a、入口到相遇点 b、环长 c，快走的路程是慢的两倍：2(a + b) = a + b + kc，得 a = kc − b，即从相遇点再走 a 步正好回到入口。）
      • 合并两个有序链表：两个指针比较，小的接到结果后面，O(m + n)。
      • 两个链表的第一个公共结点：先求长度差 d，长的先走 d 步，再一起走到相遇。
      典型题 · 原创

      带头结点的单链表 L 有 n 个结点（n ≥ 2）。设计一个时间 O(n)、空间 O(1) 的算法，把它重排成 a₁, aₙ, a₂, aₙ₋₁, a₃, … 的顺序（第一个、最后一个、第二个、倒数第二个……交替）。

      看解答

      三步：① 用快慢指针找到中点，把链表断成前后两半；② 原地逆置后一半；③ 两个指针交替地把后一半的结点插进前一半。每一步都是 O(n)，只用了几个指针。

      void reorder(LinkList L) {
    LNode *slow = L, *fast = L;
    while (fast->next && fast->next->next) { slow = slow->next; fast = fast->next->next; }
    LNode *q = slow->next, *r; slow->next = NULL;   /* 断开，q 是后一半 */
    LNode *rev = NULL;
    while (q) { r = q->next; q->next = rev; rev = q; q = r; }   /* 逆置后一半 */
    LNode *p = L->next;
    while (rev) { r = rev->next; rev->next = p->next; p->next = rev; p = rev->next; rev = r; }
}

      自己用 1 2 3 4 5 走一遍：前一半 1 2 3、后一半 4 5 逆置成 5 4，交替插入得 1 5 2 4 3。

      侵入式链表

      教科书的链表是“结点里装着数据”。Linux 内核反过来：数据结构里嵌一个只有两个指针的 struct list_head { struct list_head *next, *prev; }。一个进程描述符可以同时挂在好几条链上（运行队列、父子关系、同一个组……），每条链用它里面不同的 list_head 字段。顺着链走到某个 list_head 以后，用 container_of(ptr, type, member) 宏减去这个字段在结构体里的偏移（offsetof），就得到整个结构体的地址。好处是链表代码只写一份、不用为每种数据单独 malloc 结点。

      #include <stddef.h>
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

struct list_head { struct list_head *next, *prev; };
struct duck { int x, y; struct list_head line; };   /* 鸭子挂在队伍链上 */
/* 给出 line 的地址 p，就能拿回整只鸭子：container_of(p, struct duck, line) */

      链表为什么常常更慢

      复杂度表上，链表在“已知位置插入删除”上赢数组。但实际程序要先找到那个位置，而沿着链表走，每一步都是一次难以预测的内存访问：结点散落在堆里，预取器猜不到下一个在哪儿，每一步都可能缓存未命中（《地基》第十六章）。C++ 之父斯特劳斯特鲁普做过一个有名的演示：随机位置插入删除几万个整数，vector 比 list 快得多，因为 vector 挪动的是连续内存，比追指针便宜。

      链表真正好用的场合：元素很大或不能移动（别处有指针指着它）；需要在已经拿在手里的位置 O(1) 拼接、摘除（LRU 缓存用“散列表 + 双链表”，第二十三章）；内存分配器的空闲链表（《地基》第二十一章）；无锁并发数据结构。

      第一层 · 入门要会：一摞盘子（《地基》第二十章）、Python 的列表约 30 分钟

      只许从一头进出

      一摞盘子：新的放在最上面，拿也从最上面拿。后放上去的，先被拿走。这种队伍叫栈（stack）。

      栈只有两个动作：

      顺序栈

      #define MAX 50
typedef struct { int data[MAX]; int top; } SqStack;
void init(SqStack *S) { S->top = -1; }            /* top 指向栈顶元素 */
int  empty(SqStack *S) { return S->top == -1; }
int  push(SqStack *S, int x) { if (S->top == MAX - 1) return 0; S->data[++S->top] = x; return 1; }
int  pop(SqStack *S, int *x) { if (S->top == -1) return 0; *x = S->data[S->top--]; return 1; }

      另一种约定是 top 初始为 0、指向栈顶元素的下一个位置：入栈 data[top++] = x，出栈 x = data[--top]，栈空 top == 0，栈满 top == MAX。做题先看清用的是哪一种，元素个数分别是 top + 1 和 top。

      共享栈：两个栈共用一个数组，一个从 0 往上长（top0 初值 −1），一个从 MAX − 1 往下长（top1 初值 MAX），栈满条件 top1 − top0 == 1。两个栈此消彼长时能更充分地用空间，但只适合两个栈。

      链栈：用不带头结点的单链表，所有操作都在表头做，push 是头插、pop 是删第一个结点。不会栈满（除非内存耗尽）。

      出栈序列

      1, 2, …, n 依次入栈，中间随时可以出栈，能得到哪些出栈序列？

      • 判断一个序列是否可能：模拟。按序列依次要出栈的数 x：若 x 还没入栈，就把它之前（含它）的数依次入栈，再弹出 x；若 x 已在栈里，它必须正好在栈顶，否则不可能。
      • 一个快速的必要条件：对出栈序列里的任意一个数 x，排在它后面、且比它小的数，必须按从大到小的顺序出现。所以 3, 1, 2 不可能（3 后面的 1、2 是从小到大）。
      • 个数是卡特兰数 Cn = C(2n, n) / (n + 1)：n = 3 时 5 种，n = 4 时 14 种，n = 5 时 42 种。

      表达式求值

      中缀表达式 3 + 4 × (2 − 1) 对人友好，对电脑不友好：要看优先级和括号。后缀表达式（逆波兰式）把运算符放在两个运算数后面：3 4 2 1 − × +，不需要括号，从左往右用一个栈就能算：遇到数压栈；遇到运算符弹出两个数（先弹出的是右操作数），算完把结果压栈；最后栈里剩下的就是答案。

      中缀转后缀，用一个运算符栈，从左往右扫：

      1. 遇到运算数，直接输出。
      2. 遇到 (，压栈。
      3. 遇到 )，依次弹出并输出栈里的运算符，直到弹出 (（括号不输出）。
      4. 遇到运算符 op，依次弹出并输出栈顶优先级大于或等于 op 的运算符（遇到 ( 或栈空停），再把 op 压栈。“等于也弹”保证了同级运算从左往右算。
      5. 扫完以后，把栈里剩下的运算符依次弹出输出。

      （1）a 输出；× 入栈；( 入栈；b 输出；+ 入栈（栈顶是 ( 不弹），此时栈为 × ( +，深度 3；c 输出；) 弹出 +，弹掉 (；− 来了，弹出优先级 ≥ − 的 ×，− 入栈；d 输出；/ 入栈（− 优先级低，不弹）；e 输出；最后弹出 /、−。结果 a b c + × d e / −，最大深度 3。

      单调栈

      面试题：给一列数，对每个数求它右边第一个比它大的数。笨办法 O(n²)。单调栈 O(n)：从左往右扫，栈里存“还没找到答案的下标”，并保持对应的值从栈底到栈顶递减；新来的数 x 比栈顶大，就说明栈顶的答案是 x，弹出，继续比，直到不比栈顶大，再把 x 的下标压栈。每个下标最多进出栈一次，所以是 O(n)。

      def next_greater(a):
    ans = [-1] * len(a)
    st = []                       # 存下标，对应的值从底到顶递减
    for i, x in enumerate(a):
        while st and a[st[-1]] < x:
            ans[st.pop()] = x
        st.append(i)
    return ans

print(next_greater([2, 7, 3, 5, 4, 6, 8]))   # [7, 8, 5, 6, 6, 8, -1]

      2. 从队头拿出一格，看它上下左右四个邻居：是草地的，变成水，排到队尾。

      用数组存队列，front 指队头元素，rear 指队尾元素的下一个位置。入队 rear++，出队 front++。问题是两个指针都只往后走：前面出队空出来的位置用不上，rear 到了数组末尾就“满了”，其实前面还空着，叫假溢出。

      办法是把数组首尾接成一个环，下标对 MaxSize 取模：

      #define M 8
typedef struct { int data[M]; int front, rear; } SqQueue;
void init(SqQueue *Q) { Q->front = Q->rear = 0; }
int  empty(SqQueue *Q) { return Q->front == Q->rear; }
int  full(SqQueue *Q)  { return (Q->rear + 1) % M == Q->front; }   /* 牺牲一个单元 */
int  enqueue(SqQueue *Q, int x) { if (full(Q)) return 0; Q->data[Q->rear] = x; Q->rear = (Q->rear + 1) % M; return 1; }
int  dequeue(SqQueue *Q, int *x) { if (empty(Q)) return 0; *x = Q->data[Q->front]; Q->front = (Q->front + 1) % M; return 1; }
int  length(SqQueue *Q) { return (Q->rear - Q->front + M) % M; }

      front == rear 既可能是空也可能是满，必须想办法区分：

      1. 牺牲一个单元（最常用）：约定“rear 的下一个是 front”就算满，最多存 M − 1 个。满：(rear + 1) % M == front；空：front == rear。
      2. 增设 size：空 size == 0，满 size == M。
      3. 增设 tag：最近一次是入队 tag = 1、出队 tag = 0。front == rear 时，tag == 1 是满，tag == 0 是空。
      rear 指哪儿

      有的题让 rear 指向队尾元素本身（初始 rear = M − 1、front = 0）。这时入队是先 rear = (rear + 1) % M 再存，长度是 (rear − front + 1 + M) % M。做题第一步：看清 front、rear 各指什么，用“队列里只有一个元素”的情况检验公式。

      链队列

      带头结点的单链表，加一个 front 指头结点、一个 rear 指最后一个结点。入队在 rear 后面接；出队删 front->next。要注意：出队的正好是最后一个结点时，要把 rear 改回指向头结点，否则 rear 变成悬空指针。判空：front == rear。

      双端队列

      两端都能进出的叫双端队列。还有两种受限的：输入受限（只能一端进、两端都能出）和输出受限（两端都能进、只能一端出）。408 常问“1, 2, 3, 4 依次进入，能不能得到某个输出序列”。做法是模拟：输出受限时，想好每个数从左还是从右进，看队头（出口那一端）的顺序；输入受限时，看每次该出的数是不是在两端之一。

      典型题 · 原创

      （1）循环队列存放在数组 A[0..19] 中，采用牺牲一个单元的办法，front 指队头元素、rear 指队尾元素的下一个位置。现在 front = 17、rear = 6，队列里有几个元素？再入队 12 个元素，会发生什么？（2）元素 1, 2, 3, 4 依次进入一个输出受限的双端队列（两端都能进，只能从左端出），能否得到输出序列 4, 2, 1, 3？能否得到 4, 1, 3, 2？

      看解答

      （1）(6 − 17 + 20) % 20 = 9 个。最多能存 19 个，还能入队 10 个，第 11 个入队时队满，入队失败。

      （2）只能从左端出，所以 4 先出，意味着 1, 2, 3, 4 都已进去，而且 4 在最左边：4 是从左端进的。要得到 4, 2, 1, 3：队里从左到右应是 4 2 1 3。试：1 进（队：1），2 从左进（2 1），3 从右进（2 1 3），4 从左进（4 2 1 3）。可以。要得到 4, 1, 3, 2：队里从左到右应是 4 1 3 2，但 1 和 2 的相对位置：2 进来时只能在 1 的左边或右边；若 2 在 1 右边，3 要插在 1 和 2 之间，而 3 只能从两端进，不可能。所以 4, 1, 3, 2 不行。

      2 的幂和按位与

      环形缓冲区在操作系统和网络里到处都是：网卡收包、音频播放、日志。取模 % M 要做除法，比较慢。如果 M 是 2 的幂，x % M 等于 x & (M − 1)（《地基》第七章的掩码），一条指令。Linux 的 kfifo 更进一步：in 和 out 两个计数器只增不减（无符号数自然绕回，《地基》第三章），元素个数就是 in − out，下标是 in & (M − 1)。这样满和空不会混淆，也不用牺牲一个单元。

      单生产者单消费者

      如果只有一个线程往里放（只改 in）、一个线程往外拿（只改 out），两个变量各只有一个写者，就不会出现《地基》第二十九章那种“两个人同时改一个数”的竞态。只要保证“先写好数据、再更新 in”的顺序被对方看到（需要内存屏障或原子操作的 release/acquire 语义，《地基》第二十九章第三层），就可以完全不加锁。多个生产者或多个消费者时，就要用原子的比较并交换或者加锁了。

      deque 是怎样做的

      CPython 的 collections.deque 是一个双向链表，但每个结点不是一个元素，而是一块能放 64 个元素的数组。这样两端操作都是 O(1)，又比“一个元素一个结点”省内存、对缓存更友好。代价是按下标访问中间的元素要 O(n)。C++ 的 std::deque 用的是“一组固定大小的块 + 一个块指针数组”，可以 O(1) 按下标访问。

      串和朴素匹配

      串是由零个或多个字符组成的有限序列。存储方式有定长顺序存储（定长数组，超长截断）、堆分配存储（malloc 一块，按需大小）、块链存储（链表，每个结点放若干字符，最后一块不满时用特殊字符补齐）。408 的串题几乎都是模式匹配：在主串 S（长 n）里找模式串 T（长 m）第一次出现的位置。

      朴素匹配：主串指针 i、模式指针 j；相等则都后移；不等则 i 回退到这一趟开始位置的下一个（i = i − j + 2，下标从 1），j 回到 1。最坏比较 (n − m + 1) × m 次，O(nm)；一般情况下比较次数接近 n + m。

      部分匹配值和 next

      一个串的前缀是除最后一个字符外的所有头部子串，后缀是除第一个字符外的所有尾部子串。部分匹配值（PM）是“最长的相等前后缀”的长度。对模式串的每一个前缀求部分匹配值，就得到部分匹配表。

      next[j] 的意思：在 T[j] 处失配时，下一次用 T[next[j]] 和主串的当前字符比（主串指针不动）。它等于“前 j − 1 个字符的部分匹配值 + 1”：已经匹配的 j − 1 个字符里，最长相等前后缀有 k 个，就让模式的前 k 个对着主串里已经匹配的后 k 个，下一个该比的是 T[k + 1]。规定 next[1] = 0：第一个字符就失配，模式不动、主串后移一位，再从 T[1] 比。所以 408 的 next 就是把 PM 表右移一位、第一个填 0（实际计算中填 −1 再整体加 1）。

      三种 next，先看清是哪一种

      ① 408 和严蔚敏教材：下标从 1，next[1] = 0，如上表；② 很多 0 下标的代码（包括本书主线）：直接用部分匹配表 pm[j]，失配时 j = pm[j − 1]；③ 有的书把②整体右移，next[0] = −1。三种只差一个平移，本质相同。考试按第一种，答题前看清题目给的下标起点。

      nextval：若失配位置的字符 T[j] 和 T[next[j]] 相同，那跳过去以后必然再失配一次，不如直接跳得更远。规则：nextval[1] = 0；j ≥ 2 时，若 T[j] == T[next[j]]，nextval[j] = nextval[next[j]]，否则 nextval[j] = next[j]。

      /* 下标从 1：T[1..m]，S[1..n]。T[0]、S[0] 不用 */
void get_next(const char *T, int m, int next[]) {
    int i = 1, j = 0; next[1] = 0;
    while (i < m) {
        if (j == 0 || T[i] == T[j]) { i++; j++; next[i] = j; }
        else j = next[j];
    }
}
int kmp(const char *S, int n, const char *T, int m, const int next[]) {
    int i = 1, j = 1;
    while (i <= n && j <= m) {
        if (j == 0 || S[i] == T[j]) { i++; j++; }
        else j = next[j];           /* 主串指针 i 不回退 */
    }
    return j > m ? i - m : 0;      /* 匹配成功返回位置，否则 0 */
}

      复杂度：求 next 是 O(m)，匹配是 O(n)，合计 O(n + m)。为什么匹配是 O(n)？i 只增不减，最多增 n 次；j 每次增加都伴随 i 增加，每次 j = next[j] 都让 j 至少减 1，而 j 不会小于 0，所以减的次数不超过增的次数。

      滚动哈希

      把长度为 m 的子串看成一个 b 进制的大数，对一个大素数取模，得到它的“指纹”。窗口往右滑一格时，新指纹可以由旧指纹 O(1) 算出：减去最左边那个字符的贡献，乘 b，加上新字符。先比指纹，指纹相同再逐字核对（不同的串可能撞上同一个指纹）。期望 O(n + m)，最坏 O(nm)。它的长处是能同时找很多个等长的词，以及判断两个长串里有没有相同的长片段（论文查重、文件去重）。

      def rabin_karp(s, t, b=256, mod=1_000_000_007):
    n, m = len(s), len(t)
    if m > n: return -1
    hi = pow(b, m - 1, mod)
    ht = hs = 0
    for i in range(m):
        ht = (ht * b + ord(t[i])) % mod
        hs = (hs * b + ord(s[i])) % mod
    for i in range(n - m + 1):
        if hs == ht and s[i:i + m] == t: return i
        if i + m < n:
            hs = ((hs - ord(s[i]) * hi) * b + ord(s[i + m])) % mod
    return -1

      从后往前比

      Boyer-Moore（1977）反过来，从模式的最后一个字符开始比。如果主串里对着的字符根本不在模式里，模式可以一下跳过整整 m 格。英文文本里这种情况很常见，所以平均比较次数常常少于 n：模式越长，跳得越远。它的简化版 Horspool 只用“坏字符”一张表，好写又快，很多 grep 和编辑器的查找用的是它的变种。

      一次找很多个词

      聊天过滤要在一句话里同时找几千个敏感词。一个一个用 KMP 找太慢。AC 自动机（Aho-Corasick，1975）把所有词建成一棵字典树（第八章的树），再给每个结点加上类似 next 的“失配指针”，扫一遍文本就能找出所有词的所有出现，O(文本长 + 词的总长 + 出现次数)。fgrep 最早就是用它实现的。

      真实的库函数往往混合使用：CPython 的 str.find 在 3.10 以后对长模式用“双向”（Two-Way）算法，短模式用简化的 Boyer-Moore-Horspool；glibc 的 memmem 也用 Two-Way，它在最坏情况下也是线性的，而且只用 O(1) 额外空间。

      def fill_stack(grid, x, y):
    todo = [(x, y)]               # 还要去看的格子
    while todo:
        x, y = todo.pop()
        if y < 0 or y >= len(grid) or x < 0 or x >= len(grid[0]) or grid[y][x] != '~':
            continue
        grid[y][x] = ':'
        todo.extend([(x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)])

      递推式和递归树

      递归算法的时间，常写成 T(n) = a·T(n/b) + f(n)：分成 a 个规模为 n/b 的子问题，分和合花 f(n)。画递归树：根的代价 f(n)，下面 a 个孩子各 f(n/b)，树高 logbn，把每层的代价加起来。例如 T(n) = 2T(n/2) + n：每层合计 n，共 log₂n 层，总共 O(n log n)。

      主定理（简化版）：比较 f(n) 和 nlogba。

      1. f(n) 比 nlogba 小一个多项式因子：T(n) = Θ(nlogba)（叶子主导）。
      2. 两者同阶，f(n) = Θ(nlogba)：T(n) = Θ(nlogba log n)（每层一样多）。
      3. f(n) 大一个多项式因子（且满足正则条件）：T(n) = Θ(f(n))（根主导）。
      递推式例子结果
      T(n) = T(n/2) + 1二分查找O(log n)
      T(n) = 2T(n/2) + 1分治求最大值、二叉树遍历O(n)
      T(n) = 2T(n/2) + n归并排序、快排的最好情况O(n log n)
      T(n) = T(n−1) + n快排的最坏情况、选择排序O(n²)（不能用主定理，直接展开）
      T(n) = 2T(n−1) + 1汉诺塔2ⁿ − 1
      T(n) = T(n−1) + T(n−2) + 1直接递归求斐波那契指数级，约 1.618ⁿ

      汉诺塔和快速幂

      void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;
    hanoi(n - 1, from, to, via);      /* 上面 n-1 个先挪到中间 */
    printf("%d: %c -> %c\n", n, from, to);
    hanoi(n - 1, via, from, to);      /* 再从中间挪到目标 */
}
long long power(long long x, int n) {  /* 快速幂：O(log n) */
    if (n == 0) return 1;
    long long h = power(x, n / 2);
    return n % 2 ? h * h * x : h * h;
}

      汉诺塔移动次数 M(n) = 2M(n−1) + 1，M(0) = 0，解得 M(n) = 2ⁿ − 1；递归深度 n，空间 O(n)。快速幂每次把指数减半，乘法 O(log n) 次。注意 power 只递归一次，再用 h × h；写成 power(x, n/2) * power(x, n/2) 会变成 T(n) = 2T(n/2) + 1 = O(n)，白费了。

      递归改非递归

      通用办法是用栈模拟调用栈：每个栈元素记下“参数 + 这一层做到哪一步了”（相当于返回地址）。循环：取栈顶，按它的进度做下一步；要递归就把新的一层压栈；这一层做完就弹出。油漆桶这类“各个子调用之间互不依赖、也不用汇总结果”的递归，可以直接把所有子任务压栈，像上面的 fill_stack。需要先算子问题再汇总的（比如后序遍历，第九章），要多记一个“进度”。

      尾递归：递归调用是函数的最后一步、返回以后什么也不做（比如 return f(n−1, acc*n)）。这时当前栈帧可以复用，编译器能把它变成循环（《地基》第二十章第三层）。C 编译器在优化时常做，Python 解释器不做。

      主定理的来历和限制

      “主定理”（Master Theorem）这个名字因《算法导论》而流行，其内容来自 1980 年本特利、哈肯和萨克斯的一篇论文。它只能处理 a ≥ 1、b > 1、子问题规模相等的情形；T(n) = T(n−1) + n 这种“减一”的不行，T(n) = T(n/3) + T(2n/3) + n 这种不等分的也不行（后者可以画递归树：每层不超过 n、高约 log3/2n，结果 Θ(n log n)；更一般的有 Akra-Bazzi 定理）。f(n) 和 nlogba 只差一个 log 因子的“缝隙”情形，简化版主定理也不适用。

      卡拉楚巴乘法

      小学的竖式乘法，两个 n 位数相乘要 n² 次一位乘法。1960 年，23 岁的苏联学生卡拉楚巴发现：把两个数各劈成高低两半，x = a·B + b，y = c·B + d，那么 xy = ac·B² + (ad + bc)·B + bd，而 ad + bc = (a + b)(c + d) − ac − bd。于是只要 ac、bd、(a + b)(c + d) 三次乘法，而不是四次。T(n) = 3T(n/2) + O(n) = O(nlog₂3) ≈ O(n1.585)。据说他的老师柯尔莫哥洛夫原本猜想 n² 是下界，这个结果出来以后他亲自把论文推荐发表。CPython 的大整数在位数较多时就用卡拉楚巴乘法（源码 Objects/longobject.c 里的 k_mul）。

      别随便调高递归上限

      sys.setrecursionlimit(100000) 能让 Python 不再早早报 RecursionError，但它不会让 C 层面的栈变大：Python 函数调用会占用解释器自己的 C 栈，叠得太深时整个进程会直接段错误崩溃（新版本 CPython 对此有所改进，但仍不建议依赖）。深度可能很大时，改写成显式栈才是正路。
