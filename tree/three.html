      第二层 · 本科对照 408：图的基本概念、图的存储约 55 分钟简单图、完全图、子图、连通、强连通、生成树和生成森林、度和握手定理、路径和回路；邻接矩阵、邻接表、十字链表、邻接多重表；几道边数的计算题。

      基本概念

      • 图 G = (V, E)，|V| = n 个顶点、|E| = e 条边；408 讨论的都是简单图（无重边、无自环）。线性表可以是空表、树可以是空树，但图的顶点集不能为空（边集可以）。
      • 完全图：无向完全图有 n(n − 1)/2 条边；有向完全图有 n(n − 1) 条弧。
      • 连通（无向）：任意两点之间有路径。极大连通子图叫连通分量。强连通（有向）：任意两点 u、v 之间，u 到 v、v 到 u 都有路径；极大的叫强连通分量。
      • 生成树：连通图的极小连通子图，包含全部 n 个顶点、恰好 n − 1 条边；多一条边就有回路，少一条就不连通。非连通图的各分量的生成树组成生成森林。
      • 度：无向图中所有顶点的度之和 = 2e（握手定理）；有向图中入度之和 = 出度之和 = e。
      • 路径长度是边数；第一个和最后一个顶点相同的叫回路；顶点不重复的叫简单路径。n 个顶点的图，边数大于 n − 1 就一定有回路。
      典型题 · 原创

      （1）无向图有 16 条边，度为 4 的顶点 3 个、度为 3 的顶点 4 个，其余顶点的度都小于 3，问图至少有几个顶点？（2）n = 8 个顶点的无向图，至少要几条边才能保证它一定连通（不管边怎么连）？（3）有向图有 n 个顶点，要保证它是强连通的，至少要几条弧？

      看解答

      （1）度之和 = 32；已知 3 × 4 + 4 × 3 = 24，剩下 8 要由度 ≤ 2 的顶点提供，每个至多 2，至少 4 个。共 3 + 4 + 4 = 11 个。

      （2）最坏情况：7 个顶点组成完全图（21 条边），第 8 个孤立。再加 1 条就一定连通：(n − 1)(n − 2)/2 + 1 = 22。

      （3）n 条，连成一个有向环。（n 个顶点的无向图要连通至少 n − 1 条边，这是另一个问法。）

      CSR

      邻接表用链表，每条边一个结点、一个指针，又散又慢（第三章第三层）。真正处理大图的程序常用 CSR（压缩稀疏行）：把所有顶点的邻居一个接一个排进一个大数组 adj，再用一个长 n + 1 的数组 start 记着第 i 个顶点的邻居从 adj 的哪里开始。顶点 i 的邻居就是 adj[start[i] : start[i+1]]，连续存放、对缓存友好。缺点是加边删边很贵，适合“建好以后只读”的图。科学计算里的稀疏矩阵、图神经网络框架都用它。

      def to_csr(n, edges):
    deg = [0] * n
    for a, b in edges: deg[a] += 1
    start = [0] * (n + 1)
    for i in range(n): start[i + 1] = start[i] + deg[i]
    adj, fill = [0] * len(edges), start[:-1]
    for a, b in edges:
        adj[fill[a]] = b; fill[a] += 1
    return start, adj

      走遍一张图

      从一个点出发，把能走到的点都走一遍，叫图的遍历。和树的遍历（第九章）不一样的是：图里可能有圈，绕着绕着会回到走过的地方。所以要做记号：走过的点记下来，下次碰到就不再走。

      广度优先：一圈一圈往外

      第五章倒水时已经见过它了：先看离起点一步远的所有点，再看两步远的，再看三步远的……用一个队列排队，先看到的先往外扩。

      因为是一圈一圈往外找的，第一次碰到目标时，走的一定是步数最少的路。

      深度优先：一条路走到黑

      走迷宫的老办法：看到一条没走过的路就走进去，一直往前走；走到死路，就退回上一个岔口，换一条没走过的路。用一个栈记着回去的路（第七章的油漆桶用的就是这个办法）。

      深度优先也能走遍所有的点，但它找到目标时走的路，不一定最短。

      把路画出来

      找到了目标，可是怎么知道路是怎么走的？办法是：每走到一个新的格子，都记一下“我是从哪一格走过来的”。找到目标以后，从目标开始，顺着“从哪来”一格一格倒着走回起点，再把这串格子反过来，就是路。

      代码和复杂度

      int visited[MAXV];
void BFS(Graph *G, int v) {                 /* 邻接表 */
    int Q[MAXV], f = 0, r = 0;
    visit(v); visited[v] = 1; Q[r++] = v;
    while (f < r) {
        int u = Q[f++];
        for (ArcNode *p = G->adj[u].first; p; p = p->next)
            if (!visited[p->to]) { visit(p->to); visited[p->to] = 1; Q[r++] = p->to; }
    }
}
void DFS(Graph *G, int v) {
    visit(v); visited[v] = 1;
    for (ArcNode *p = G->adj[v].first; p; p = p->next)
        if (!visited[p->to]) DFS(G, p->to);
}
void traverse(Graph *G) {                   /* 非连通图：每个没访问过的顶点开一次 */
    for (int v = 0; v < G->n; v++) visited[v] = 0;
    for (int v = 0; v < G->n; v++) if (!visited[v]) BFS(G, v);   /* 调用次数 = 连通分量个数 */
}

      BFS 是在入队时就标记 visited，否则同一个顶点可能被多次入队。复杂度：邻接表 O(n + e)，邻接矩阵 O(n²)（每个顶点要扫一整行）。空间：BFS 的队列、DFS 的递归栈，最坏都是 O(n)。

      • 无权图的单源最短路径：BFS，d[v] = d[u] + 1，第一次被发现时就是最短。

      迪杰斯特拉的办法

      1956 年，荷兰的迪杰斯特拉在阿姆斯特丹一家咖啡馆里，二十分钟想出了一个办法（这是他后来自己讲的）：

      1. 每个地方先写一个“目前知道的最短距离”：起点写 0，别的都写“不知道”（∞）。
      2. 在还没定下来的地方里，挑一个距离最小的，把它定下来：它的最短距离不会再变了。
      3. 用刚定下的这个地方，去看它的邻居：经过它走过去，是不是比邻居现在写的距离更短？更短就改掉。
      4. 重复第 2、3 步，直到所有地方都定下来。

      为什么第 2 步挑出来的那个一定定得下来？因为它是剩下的里面最近的；要想绕到别的地方再回来，只会更远（前提是路都不是负的）。这就像水从起点往外流，只是流过长路慢、流过短路快：哪儿先被水淹到，哪儿就是近。

      迪杰斯特拉

      void dijkstra(int G[][N], int n, int s, int dist[], int path[]) {   /* 邻接矩阵，INF 表示无边 */
    int final[N] = {0};
    for (int i = 0; i < n; i++) { dist[i] = G[s][i]; path[i] = G[s][i] < INF ? s : -1; }
    dist[s] = 0; final[s] = 1; path[s] = -1;
    for (int k = 1; k < n; k++) {
        int u = -1;
        for (int i = 0; i < n; i++)                       /* 挑未定的最小者 */
            if (!final[i] && (u == -1 || dist[i] < dist[u])) u = i;
        if (dist[u] == INF) break;                         /* 剩下的都到不了 */
        final[u] = 1;
        for (int v = 0; v < n; v++)                        /* 用 u 松弛 */
            if (!final[v] && G[u][v] < INF && dist[u] + G[u][v] < dist[v]) { dist[v] = dist[u] + G[u][v]; path[v] = u; }
    }
}

      邻接矩阵、线性扫描：O(n²)，适合稠密图。邻接表加二叉堆：每条边最多一次入堆，O((n + e) log n)，适合稀疏图。path[v] 记最短路上 v 的前驱，倒着追溯即得路径。迪杰斯特拉求的是单源最短路径；对每个顶点各做一次就得到所有顶点之间的，O(n³)。

      负权边

      三个顶点 A、B、C，边 A→B = 2、A→C = 3、C→B = −2。迪杰斯特拉先定下 B（距离 2），再定下 C（3）；但 A→C→B = 1 才是最短，B 已经定了改不了。只要有负权边，“最小的那个不会再变”就不成立。

      弗洛伊德

      求所有顶点对之间的最短路径。A⁽⁰⁾ 是邻接矩阵；第 k 轮允许路径经过前 k 个顶点作中转：A⁽ᵏ⁾[i][j] = min(A⁽ᵏ⁻¹⁾[i][j], A⁽ᵏ⁻¹⁾[i][k] + A⁽ᵏ⁻¹⁾[k][j])。

      for (int k = 0; k < n; k++)              /* k 必须在最外层 */
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (A[i][k] + A[k][j] < A[i][j]) { A[i][j] = A[i][k] + A[k][j]; path[i][j] = k; }

      A*

      迪杰斯特拉朝四面八方均匀地扩，哪怕目标明明在东边。A*（1968）挑下一个点时，看的不是“离起点多远”，而是“离起点多远 + 估计还要多远”。方格地图上常用曼哈顿距离 |dx| + |dy| 当估计。只要估计从不高估真实距离（可采纳），A* 找到的就是最短路，而且看的点通常少得多。估计取 0，A* 就退化成迪杰斯特拉。游戏里怪物找路大多用它。

      def astar(grid, start, goal):
    h = lambda p: abs(p[0] - goal[0]) + abs(p[1] - goal[1])   # 曼哈顿距离，从不高估
    pq, g, came = [(h(start), start)], {start: 0}, {start: None}
    while pq:
        f, cur = heapq.heappop(pq)
        if cur == goal: break
        for nb in grid_neighbors(grid, *cur):
            ng = g[cur] + COST[grid[nb[1]][nb[0]]]
            if nb not in g or ng < g[nb]:
                g[nb], came[nb] = ng, cur
                heapq.heappush(pq, (ng + h(nb), nb))
    return g.get(goal), came

      性质

      • 最小生成树不一定唯一；当图中各边权值互不相等时唯一。权值有相同的也可能唯一。

      两种算法

      int prim(int G[][N], int n) {             /* 邻接矩阵；lowcost[v] = v 到已选集合的最小边权 */
    int lowcost[N], in[N] = {0}, total = 0;
    in[0] = 1;
    for (int v = 0; v < n; v++) lowcost[v] = G[0][v];
    for (int k = 1; k < n; k++) {
        int u = -1;
        for (int v = 0; v < n; v++) if (!in[v] && (u == -1 || lowcost[v] < lowcost[u])) u = v;
        in[u] = 1; total += lowcost[u];
        for (int v = 0; v < n; v++) if (!in[v] && G[u][v] < lowcost[v]) lowcost[v] = G[u][v];
    }
    return total;
}

      典型题 · 原创

      无向带权图顶点 A—F，边：AB 6、AC 1、AD 5、BC 5、BE 3、CD 5、CE 6、CF 4、DF 2、EF 6。（1）用普里姆从 A 出发，依次加入的边是？总权值？（2）用克鲁斯卡尔，依次加入的边是？（3）这棵最小生成树唯一吗？

      看解答

      （1）A 的边中 AC 1 最小，加 C；集合 {A,C} 的外连边：AB 6、AD 5、BC 5、CD 5、CE 6、CF 4 → CF 4，加 F；再看 DF 2 → 加 D；剩 B、E：AB 6、BC 5、CE 6、EF 6、（D 的边 AD、CD 两头都在集合里）→ BC 5，加 B；最后 BE 3 → 加 E。依次 AC、CF、DF、BC、BE，总权 1+4+2+5+3 = 15。

      （2）按权排序：AC 1、DF 2、BE 3、CF 4，再 5 的有 AD、BC、CD：AD 两头 A、D 已连通（A-C-F-D），跳过；BC 连接 {A,C,D,F} 和 {B,E}，加入；CD 已连通跳过。依次 AC、DF、BE、CF、BC，总权 15。

      为电网而生

      最早的最小生成树算法是捷克数学家博鲁夫卡 1926 年为摩拉维亚地区设计电力网络时提出的：每一轮，每个连通块各自挑出连向外面的最短边，同时加上，块的个数至少减半，O(e log n)。1930 年贾尼克提出了后来被称为“普里姆算法”的办法（普里姆 1957 年、迪杰斯特拉 1959 年各自重新发现），1956 年克鲁斯卡尔提出了按边排序的办法。博鲁夫卡的算法因为每个块可以同时挑边，今天在并行计算里又重新流行。

      迷宫和聚类

      给方格地图上每两个相邻格子之间的“墙”随机一个权值，求最小生成树，把树边上的墙拆掉：得到的就是一个“完美迷宫”（任意两格之间恰好一条路）。用随机化的克鲁斯卡尔或普里姆，能生成风格不同的迷宫。数据分析里的单链接聚类：先求最小生成树，再删掉最长的 k − 1 条边，剩下的 k 块就是 k 个簇。

      拓扑排序

      用顶点表示活动、有向边表示“前后关系”的 DAG（有向无环图）叫 AOV 网。

      int topo(Graph *G, int order[]) {
    int indeg[MAXV] = {0}, S[MAXV], top = -1, cnt = 0;
    for (int v = 0; v < G->n; v++)
        for (ArcNode *p = G->adj[v].first; p; p = p->next) indeg[p->to]++;
    for (int v = 0; v < G->n; v++) if (indeg[v] == 0) S[++top] = v;   /* 用栈或队列都行 */
    while (top >= 0) {
        int v = S[top--]; order[cnt++] = v;
        for (ArcNode *p = G->adj[v].first; p; p = p->next)
            if (--indeg[p->to] == 0) S[++top] = p->to;
    }
    return cnt == G->n;          /* 输出的顶点数小于 n：有回路 */
}
      • 复杂度：邻接表 O(n + e)，邻接矩阵 O(n²)。
      • 另一种求法：DFS，按顶点“完成”的先后记下，再逆序输出（逆后序）就是拓扑序列。
      • 拓扑序列唯一的充分条件：每一步入度为 0 的顶点都只有一个（此时序列是一条哈密顿路径）。注意：拓扑序列唯一，不能推出图是一条链（比如 a→b、a→c、b→c 序列唯一但不是链）。
      • 若有向图的邻接矩阵是三角矩阵（主对角线以下全是 0），则一定存在拓扑序列；反之，存在拓扑序列的图，适当编号后邻接矩阵可以是三角矩阵。

      关键路径

      用边表示活动、边的权表示活动持续时间、顶点表示事件（“某些活动已经完成”）的带权 DAG 叫 AOE 网。只有一个入度为 0 的源点（开工）和一个出度为 0 的汇点（完工）。从源点到汇点的最长路径叫关键路径，它的长度就是完成整个工程的最短时间；关键路径上的活动叫关键活动，拖一天，整个工程就拖一天。

      1. 事件的最早发生时间 ve：按拓扑序，ve(源) = 0，ve(k) = max{ve(j) + 活动 j→k 的时间}。
      2. 事件的最迟发生时间 vl：按逆拓扑序，vl(汇) = ve(汇)，vl(k) = min{vl(j) − 活动 k→j 的时间}。
      3. 活动 a = (k → j) 的最早开始 e(a) = ve(k)，最迟开始 l(a) = vl(j) − 时间。
      4. 余量 d(a) = l(a) − e(a)。d = 0 的就是关键活动。
      典型题 · 原创

      方格岛上盖一间房，AOE 网有事件 v1—v6，活动：a1 = v1→v2（4 天）、a2 = v1→v3（3）、a3 = v2→v4（2）、a4 = v3→v4（4）、a5 = v2→v5（3）、a6 = v4→v6（3）、a7 = v5→v6（5）。求各事件的 ve、vl，各活动的余量，关键路径和工期。若把 a4 缩短 1 天，工期变吗？

      看解答

      ve：v1 = 0，v2 = 4，v3 = 3，v4 = max(4 + 2, 3 + 4) = 7，v5 = 4 + 3 = 7，v6 = max(7 + 3, 7 + 5) = 12。

      vl：v6 = 12，v5 = 12 − 5 = 7，v4 = 12 − 3 = 9，v3 = 9 − 4 = 5，v2 = min(9 − 2, 7 − 3) = 4，v1 = min(4 − 4, 5 − 3) = 0。

      缩短关键活动不一定缩短工期

      回溯：每条路都试一试

      怎样才能保证找到最好的？笨办法是把所有可能都试一遍。可以像走迷宫一样有条理地试：

      • 第一样东西，先试“拿”，再往下想第二样；
      • 第二样，也先试“拿”……装不下了，就退回来，改成“不拿”，再往下试；
      • 每试完一种完整的装法，就和目前最好的比一比。

      这种“往前试，走不通就退回上一步换一条路”的办法叫回溯。它和第十七章的深度优先是一回事：只是走的不是地图，而是“每样拿不拿”组成的一棵选择树。它一定能找到最好的，代价是可能要试很多很多次：六样东西就有 2⁶ = 64 种装法，三十样就有十亿多种。

      聪明一点的回溯会剪枝：某条路已经装不下了，或者就算后面全拿也比不过目前最好的，就别再往下试了。

      贪心什么时候对

      一个问题能用贪心，通常要满足两条：

      1. 贪心选择性质：总存在一个最优解，它的第一步就是贪心的那个选择。
      2. 最优子结构：做出这一步以后，剩下的问题仍是同类问题，且原问题的最优解包含子问题的最优解。

      证明第一条最常用交换论证：拿一个任意的最优解，把它的第一步换成贪心的选择，证明结果不会变差。

      活动安排

      一个场地，n 个活动各有开始和结束时间，互相重叠的不能都安排，最多安排几个？贪心：按结束时间从早到晚排序，能放就放。证明：设最优解里最早结束的活动是 x，贪心选的是结束最早的 g，f(g) ≤ f(x)；把最优解里的 x 换成 g，g 不会和后面的冲突（因为 g 结束得更早），个数不变，仍然最优。于是第一步贪心不吃亏，剩下的是同类子问题。O(n log n)。按“开始最早”或“持续最短”贪心都是错的，可以各举一个反例。

def queens(n):
    cols, d1, d2, out = set(), set(), set(), []
    def go(r, place):
        if r == n: out.append(place[:]); return
        for c in range(n):
            if c in cols or r - c in d1 or r + c in d2: continue
            cols.add(c); d1.add(r - c); d2.add(r + c); place.append(c)
            go(r + 1, place)
            cols.remove(c); d1.remove(r - c); d2.remove(r + c); place.pop()
    go(0, [])
    return out

      拟阵

      有没有一个统一的理由说明“为什么克鲁斯卡尔的贪心总是对的”？有：拟阵。粗略地说，如果一个问题里“可行的集合”满足：可行集的子集也可行、小的可行集总能从大的可行集里借一个元素扩充，那么“按权从大到小、能加就加”的贪心一定得到最优解。图里“不含圈的边集”就构成一个拟阵（图拟阵），所以最大（最小）生成树可以贪心。0/1 背包的可行集不满足第二条，所以贪心会上当。

      难问题

      0/1 背包是 NP 难的：至今不知道有没有对 n 和数字位数都是多项式时间的算法（这是“P 是否等于 NP”的一部分）。下一章的动态规划能在 O(n × 容量) 时间内解它，但容量是一个数值，写下它只要 log(容量) 位，所以这叫“伪多项式时间”：容量是十亿时就不行了。实践中对这类问题常用近似算法（保证不比最优差多少）、分支限界和整数规划求解器。

      第二层 · 本科算法设计 · 面试和机试的重点约 65 分钟动态规划的两个前提和四个要素；记忆化搜索和自底向上；0/1 背包和一维滚动数组；完全背包；最长公共子序列；最长上升子序列 O(n²) 和 O(n log n)；编辑距离；怎样一步步拆一道新题。

      两个前提，四个要素

      能用动态规划的问题要有：最优子结构（大问题的最优解由小问题的最优解组成，第二十一章）和重叠子问题（同一个小问题会被反复用到，否则直接分治就行）。写一道动态规划，就是想清楚四件事：

      1. 状态：dp[…] 表示什么。这是最难的一步。
      2. 转移：dp[…] 怎样由更小的状态算出来。通常想“最后一步”。
      3. 起点：最小的状态是多少。
      4. 顺序：按什么顺序填表，保证用到的格子已经算好了。

      两种写法：记忆化搜索（递归 + 一个字典，自顶向下，只算用得到的状态，Python 里可以加 @functools.cache）；自底向上填表（循环，没有递归开销，方便压缩空间）。

      0/1 背包

      状态 dp[i][c]：只考虑前 i 件物品、容量为 c 时的最大价值。转移：第 i 件不拿，dp[i−1][c]；拿（若 wᵢ ≤ c），dp[i−1][c−wᵢ] + vᵢ；取大者。起点 dp[0][c] = 0。O(n × C)。

      def knap01(items, C):
    dp = [0] * (C + 1)                    # 一维：dp[c] 就是“到目前为止”的 dp[i][c]
    for w, v in items:
        for c in range(C, w - 1, -1):     # 倒着循环！保证 dp[c - w] 还是上一行的值
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[C]
      正着循环就成了完全背包

      一维写法里 c 从大到小，dp[c − w] 还没被这件物品更新过，相当于每件只用一次。c 从小到大，dp[c − w] 可能已经用过这件物品，相当于每件可以用无限次：这正是完全背包（比如找零钱的“最少硬币数”）。一个循环方向，两种问题。

      三道经典题

      • 最长公共子序列（LCS）：两个串 a、b。dp[i][j] = a 前 i 个和 b 前 j 个的 LCS 长度。a[i] = b[j] 时 dp[i−1][j−1] + 1，否则 max(dp[i−1][j], dp[i][j−1])。O(mn)。
      • 最长上升子序列（LIS）：dp[i] = 以第 i 个数结尾的 LIS 长度 = 1 + max{dp[j] : j < i 且 a[j] < a[i]}，O(n²)。更快的办法：维护数组 tail[k] = “长度为 k+1 的上升子序列结尾最小是多少”，每来一个数用二分（第二十四章）找到位置替换，O(n log n)。
      • 编辑距离：把串 a 变成串 b 最少要几次插入、删除、替换。dp[i][j] = min(dp[i−1][j] + 1, dp[i][j−1] + 1, dp[i−1][j−1] + (a[i] ≠ b[j]))。拼写检查和 DNA 比对的基础。

      名字的来历

      “动态规划”是 1950 年代美国数学家贝尔曼在兰德公司起的名字。据他在自传里的说法，当时的国防部长不喜欢“研究”“数学”这类词，他想找一个听起来很厉害、又没人会反对的名字：“规划”（programming）在当时指“制定计划、排表”，和写程序无关；“动态”听起来很积极。所以这个名字本身并不说明方法是什么。这个故事来自贝尔曼 1984 年的自传，细节有人质疑过。

      到处都在用

      • diff 和 git：比较两个文件改了哪些行，本质上是最长公共子序列（实际用的是迈尔斯 1986 年更快的算法）。
      • 生物信息学：两条 DNA 或蛋白质序列的比对（尼德曼-翁施 1970、史密斯-沃特曼 1981），就是带打分规则的编辑距离。
      • 语音识别和通信：维特比算法在“隐藏状态”组成的网格上找最可能的那条路径，手机信号的纠错解码也用它。
      • 空间优化：LCS 的表是 m × n，两个长串时放不下。只求长度时用两行滚动；要求出序列本身，希尔施伯格（1975）用分治把空间降到 O(m + n)、时间不变。

      图，读完了

      七章，一件事：谁都可以和谁连着的时候，怎样存、怎样走、怎样找最好的。图用名单或表格存；一圈一圈（广度）或一条路走到黑（深度）地走遍它；路有长短就每次定下最近的那个；用最少的路连起所有点就从最短的挑起、不成圈；谁等谁就每次挑一个不用再等的。最后两招：贪心拣眼前最好的，可能上当；动态规划把算过的记下来，不算第二遍。
