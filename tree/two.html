      术语和树的性质

      结点的度是它的孩子个数，树的度是各结点度的最大值。度为 0 的是叶子（终端结点），度大于 0 的是分支结点。408 约定根在第 1 层（有的教材从 0 开始，看清题目），树的高度（深度）是最大层数。孩子有左右次序、不能交换的是有序树。森林是 m（≥ 0）棵互不相交的树。

      1. 结点数 = 所有结点的度之和 + 1（除了根，每个结点上面恰好一条边）。
      2. 度为 m 的树（m 叉树）第 i 层至多 mi−1 个结点。
      3. 高度为 h 的 m 叉树至多 (mh − 1)/(m − 1) 个结点。
      4. n 个结点的 m 叉树最小高度为 ⌈logm(n(m − 1) + 1)⌉。
      “度为 m 的树”和“m 叉树”

      度为 m 的树至少有一个结点的度是 m，而且至少有 m + 1 个结点；m 叉树只说“每个结点最多 m 个孩子”，可以是空树，也可以所有结点的度都小于 m。另外 m 叉树的孩子分次序，度为 m 的树不一定。

      二叉树的性质

      1. 非空二叉树上，n₀ = n₂ + 1（叶子比度为 2 的结点多一个）。证明：n = n₀ + n₁ + n₂，边数 n − 1 = n₁ + 2n₂，两式相减。
      2. 第 i 层至多 2i−1 个结点；高为 h 至多 2h − 1 个。
      3. 满二叉树：每层都满，共 2h − 1 个结点。完全二叉树：除最后一层外都满，最后一层的结点都靠左。
      4. 完全二叉树按层从 1 编号：结点 i 的双亲是 ⌊i/2⌋，左孩子 2i，右孩子 2i + 1（若 ≤ n）；i ≤ ⌊n/2⌋ 的是分支结点，其余是叶子；度为 1 的结点最多一个（n 为偶数时有一个）。
      5. n 个结点的完全二叉树，高度为 ⌈log₂(n + 1)⌉，也等于 ⌊log₂n⌋ + 1。

      完全二叉树的编号

      拖动 n，看完全二叉树的样子；点一个结点，看它的双亲、孩子的编号，和它是不是叶子。下面一排是顺序存储的数组（下标从 1）。

      存储

      顺序存储：按完全二叉树的编号放进数组，适合完全二叉树（堆，第十二章）；一般二叉树要补空位，最坏一个高 h 的“单支树”要 2h − 1 个位置。二叉链表：struct BiTNode { int data; struct BiTNode *lchild, *rchild; };，n 个结点有 2n 个指针域，用掉 n − 1 个，空指针 n + 1 个（第九章的线索二叉树就利用这些空指针）。

      一般的树有三种表示：

      • 双亲表示法：数组里每个结点记着双亲的下标（根记 −1）。找双亲 O(1)，找孩子要遍历整个数组。第十四章的并查集就是这种。
      • 孩子表示法：每个结点挂一个孩子链表。找孩子方便，找双亲难。
      • 孩子兄弟表示法（二叉树表示法）：每个结点两个指针，一个指向第一个孩子，一个指向右边的下一个兄弟。这样任何树都变成了一棵二叉树。

      树、森林和二叉树的转换

      树转二叉树就是孩子兄弟表示法：“左孩子右兄弟”。口诀：兄弟相连，只留长子（和第一个孩子的连线），整体顺时针转 45°。树转成的二叉树，根没有右孩子。森林转二叉树：每棵树先各自转，再把第二棵树的根当作第一棵树根的右孩子，第三棵当作第二棵的右孩子……反过来也一样。

      典型题 · 原创

      （1）一棵度为 3 的树，有 4 个度为 3 的结点、2 个度为 2 的结点、3 个度为 1 的结点，叶子有几个？（2）一棵完全二叉树有 700 个结点，叶子有几个？高度是多少？（3）一个森林有 3 棵树，结点数分别为 6、4、5，转成二叉树以后，根结点的右子树有几个结点？

      看解答

      （1）总度数 = 4 × 3 + 2 × 2 + 3 × 1 = 19，结点数 = 20，叶子 = 20 − 4 − 2 − 3 = 11。

      （2）分支结点是编号 1 到 ⌊700/2⌋ = 350，叶子 350 个。（也可以：n 为偶数，有一个度为 1 的结点，n₀ + n₂ = 699，n₀ = n₂ + 1，得 n₀ = 350。）高度 ⌈log₂701⌉ = 10（2⁹ = 512 ≤ 700 < 1024）。

      （3）根是第一棵树的根，它的左子树是第一棵树的其余 5 个结点，右子树是后两棵树：4 + 5 = 9 个。

      二叉树有 10 个度为 2 的结点，叶子有几个？

      n₀ = n₂ + 1 = 11。

      完全二叉树有 100 个结点，高度是？

      2⁶ = 64 ≤ 100 < 128，⌊log₂100⌋ + 1 = 7。

      完全二叉树（从 1 编号）中，结点 i 的左孩子编号是？

      1. i + 1
      2. 2i
      3. 2i + 1

      左 2i，右 2i + 1，双亲 ⌊i/2⌋。

      二叉链表存储 20 个结点的二叉树，有几个空指针？

      2n − (n − 1) = n + 1 = 21。

      树转成二叉树以后，根结点的右子树？

      1. 一定为空
      2. 一定不空

      字典树

      把一组单词按字母一层一层挂起来：根下面是首字母，第二层是第二个字母……一条从根往下的路就是一个单词（在结点上做个“到此是一个词”的标记）。这叫字典树（Trie）。查一个长度为 m 的词只要走 m 步，和一共有多少个词无关；更妙的是，走到某个结点，它下面的所有词都有同一个前缀，所以特别适合自动补全和输入法联想。第六章第三层的 AC 自动机就建在字典树上。网络路由器按 IP 地址前缀查路由表（《地基》第三十一章的最长前缀匹配），用的是它的变体（二进制字典树、压缩字典树）。

def complete(trie, prefix):
    node = trie
    for c in prefix:
        if c not in node: return []
        node = node[c]
    out = []
    def dfs(n, s):
        if '$' in n: out.append(prefix + s)
        for c in n:
            if c != '$': dfs(n[c], s + c)
    dfs(node, '')
    return out

      走遍一棵树

      按一个固定的顺序，把树上每个结点都看一遍，不漏也不重，叫遍历。走法有好几种，区别只在于：先看自己，还是先看孩子。

      • 先序：先看自己，再一个一个看孩子（每个孩子也照这样做）。像读目录：先读章名，再读章里的小节。
      • 后序：先把孩子都看完，最后看自己。像盖房子：材料都备齐了，才能造这一样东西。
      • 层序：一层一层看：先看根，再看第二层的所有结点，再看第三层……要用第五章的队列。

      二叉树还有一种：中序，先看左孩子那一边，再看自己，最后看右孩子那一边。下一章会看到，它有一个神奇的用处。

      非递归遍历

      递归遍历的时间 O(n)，空间是递归深度 O(h)（最坏 O(n)）。非递归写法用一个栈模拟：

      void inorder(BiTree T) {           /* 中序：一路向左压栈，弹出访问，转向右子树 */
    BiTNode *st[100]; int top = -1; BiTNode *p = T;
    while (p || top >= 0) {
        if (p) { st[++top] = p; p = p->lchild; }
        else { p = st[top--]; visit(p); p = p->rchild; }
    }
}
void preorder(BiTree T) {          /* 先序：访问放在压栈的时候 */
    BiTNode *st[100]; int top = -1; BiTNode *p = T;
    while (p || top >= 0) {
        if (p) { visit(p); st[++top] = p; p = p->lchild; }
        else { p = st[top--]; p = p->rchild; }
    }
}
void postorder(BiTree T) {         /* 后序：要知道右子树是不是刚访问过 */
    BiTNode *st[100]; int top = -1; BiTNode *p = T, *r = NULL;
    while (p || top >= 0) {
        if (p) { st[++top] = p; p = p->lchild; }
        else {
            p = st[top];
            if (p->rchild && p->rchild != r) p = p->rchild;
            else { top--; visit(p); r = p; p = NULL; }
        }
    }
}

      后序非递归有一个重要的性质：访问某个结点时，栈里从底到顶正好是从根到它的路径。所以“求根到某结点的路径”“求两个结点的最近公共祖先”都可以用它。层序遍历用队列：根入队；出队一个就访问它，再把它的左右孩子入队。

      由遍历序列构造二叉树

      先序 + 中序、后序 + 中序、层序 + 中序都能唯一确定一棵二叉树；先序 + 后序不能（分不清只有一个孩子时是左还是右）。做法：先序的第一个（或后序的最后一个）是根；在中序里找到根，左边是左子树、右边是右子树；按个数把先序（后序）也切开，递归。

      典型题 · 原创

      （1）二叉树的先序序列为 E B A D C F H G，中序序列为 A B C D E F G H，求后序序列。（2）一棵二叉树的先序和后序序列正好相反，这棵树有什么特点？（3）设计算法求二叉树中值为 x 的结点的所有祖先，说明为什么用后序非递归遍历。

      看解答

      （1）根 E；中序里 E 左边 A B C D 是左子树、右边 F G H 是右子树。左子树先序 B A D C：根 B，中序 A | B | C D，左 A；右子树先序 D C，根 D，中序 C D，C 是 D 的左孩子。右子树先序 F H G：根 F，中序 F 右边 G H，F 没有左子树；H 为根，中序 G H，G 是 H 的左孩子。后序：A C D B G H F E。

      （2）先序“根左右”、后序“左右根”。两者正好相反，要求每个结点都只有一个孩子（左右都可以），也就是说树的高度等于结点数，是一条“单支”。

      （3）后序非递归访问到 x 时，栈里从底到顶就是根到 x 的路径，把栈里的结点依次输出就是所有祖先。O(n) 时间，O(h) 空间。

      线索二叉树

      二叉链表有 n + 1 个空指针（第八章）。把空的左指针改成指向某种遍历次序下的前驱，空的右指针指向后继，并用两个标志位 ltag、rtag 区分“是孩子还是线索”，就得到线索二叉树。以中序线索为例，找结点 p 的后继：若 rtag = 1，右指针就是后继；否则后继是右子树里“最左下”的结点。这样不用栈就能 O(1) 空间地按中序走遍整棵树。先序线索树找后继容易，找前驱要知道双亲；后序线索树找后继要知道双亲（408 常问这一点：后序线索二叉树仍需要栈或三叉链表才能完整遍历）。

      Morris 遍历

      1979 年，莫里斯提出一种不用栈、也不改变树最终形状的中序遍历：走到结点 p 时，如果它有左子树，就找到左子树里最右的结点（p 的中序前驱），把那个结点空着的右指针临时指回 p（一条临时线索），然后去左子树；等从那条线索回到 p 时，再把它改回空。每条边最多走三次，时间 O(n)，额外空间 O(1)。面试偶尔会问“O(1) 空间中序遍历”，答的就是它。

      def morris_inorder(root):
    out, p = [], root
    while p:
        if p['left'] is None:
            out.append(p['k']); p = p['right']
        else:
            q = p['left']
            while q['right'] and q['right'] is not p:
                q = q['right']
            if q['right'] is None:           # 第一次来：搭线索，往左走
                q['right'] = p; p = p['left']
            else:                            # 顺着线索回来：拆线索，访问，往右走
                q['right'] = None; out.append(p['k']); p = p['right']
    return out

      生成器

      Python 里可以把遍历写成生成器，用的人一次拿一个结点，不用先把所有结点放进列表：

      def inorder(node):
    if node:
        yield from inorder(node['left'])
        yield node['k']
        yield from inorder(node['right'])

      这其实是把递归的“走到哪儿了”交给生成器保存。编译器处理语法树时常用的“访问者模式”（visitor pattern），也是把“怎样走”和“走到每个结点做什么”分开。

      查找和插入

      typedef struct BSTNode { int key; struct BSTNode *l, *r; } BSTNode;
BSTNode *search(BSTNode *T, int k) {
    while (T && k != T->key) T = k < T->key ? T->l : T->r;
    return T;
}
int insert(BSTNode **T, int k) {          /* 传指针的指针，才能改到空位本身 */
    if (*T == NULL) { *T = malloc(sizeof(BSTNode)); (*T)->key = k; (*T)->l = (*T)->r = NULL; return 1; }
    if (k == (*T)->key) return 0;         /* 已有，不插 */
    return insert(k < (*T)->key ? &(*T)->l : &(*T)->r, k);
}

      删除的三种情况

      1. 被删的是叶子：直接删。
      2. 只有一棵子树：让这棵子树顶替它的位置。
      3. 有两棵子树：用它的中序后继（右子树里最小的，即右子树最左下的结点）或中序前驱（左子树最大的）的值替换它，再去删掉那个后继（后继最多只有右子树，转成情况 1 或 2）。

      平均查找长度

      查找成功的 ASL = Σ（每个结点的层数）/ n（等概率）。查找失败的 ASL：把每个空指针看成一个“失败结点”（n 个结点有 n + 1 个），失败时比较的次数等于失败结点所在的层数减一（也就是它双亲的层数），ASL失败 = Σ（失败结点双亲的层数）/ (n + 1)。最好情况（树高 ⌈log₂(n+1)⌉）ASL 是 O(log n)，最坏（单支树）是 (n + 1)/2，O(n)。

      第一层 · 入门要会：二叉搜索树（第十章）约 30 分钟

      两边一样高

      上一章看到：搜索树如果歪成一根棍，找东西就和一个一个看一样慢。我们希望它一直匀称：每个结点左边那一片和右边那一片，高度差不多。这叫平衡。

      1962 年，两位苏联数学家阿杰尔松-韦利斯基和兰迪斯想出了第一种会自己保持平衡的搜索树，用他们名字的头一个字母，叫 AVL 树。规矩是：每个结点左右两边的高度，最多差 1。

      歪了就转一下

      每插进一个新数，就从它往上一个一个看：有没有哪个结点，左右两边的高度差变成了 2？有，就在那里做一次旋转。

      旋转像跷跷板：一边太重了，就把这一边的那个孩子提上来当“爸爸”，原来的爸爸降下去当它的孩子。神奇的是，转完以后，左小右大的规矩一点没坏，树却矮了一层。

      例子：依次插 1、2、3。插完 3 以后，1 的右边高 2、左边高 0，歪了。把 2 提上来：2 当根，1 当它的左孩子，3 当它的右孩子。1 < 2 < 3，规矩没坏，树从 3 层变成 2 层。

      平衡因子和四种调整

      结点的平衡因子 = 左子树高度 − 右子树高度，AVL 树里只能是 −1、0、1。插入后，从新结点往上找到第一个平衡因子绝对值为 2 的结点 A，以 A 为根的子树叫最小不平衡子树，只调整它就够了（调整后它的高度恢复成插入前，上面的结点也就都平衡了）。按新结点插在 A 的哪一边分四种：

      类型新结点插在调整
      LLA 的左孩子 B 的左子树右旋一次：B 上升为根，A 成为 B 的右孩子，B 原来的右子树挂到 A 的左边

int H(N *p) { return p ? p->h : 0; }
void upd(N *p) { p->h = 1 + (H(p->l) > H(p->r) ? H(p->l) : H(p->r)); }
N *rotR(N *a) { N *b = a->l; a->l = b->r; b->r = a; upd(a); upd(b); return b; }
N *rotL(N *a) { N *b = a->r; a->r = b->l; b->l = a; upd(a); upd(b); return b; }
N *insert(N *p, int k) {
    if (!p) { p = calloc(1, sizeof(N)); p->key = k; p->h = 1; return p; }
    if (k < p->key) p->l = insert(p->l, k); else if (k > p->key) p->r = insert(p->r, k); else return p;
    upd(p);
    int bf = H(p->l) - H(p->r);
    if (bf == 2)  { if (k > p->l->key) p->l = rotL(p->l); return rotR(p); }   /* LR 先左旋；LL 直接右旋 */
    if (bf == -2) { if (k < p->r->key) p->r = rotR(p->r); return rotL(p); }   /* RL 先右旋；RR 直接左旋 */
    return p;

      红黑树

      408 从近年起考红黑树的基本性质。红黑树是一棵二叉搜索树，每个结点是红或黑，满足五条：

      1. 每个结点是红色或黑色。
      2. 根是黑色。
      3. 叶结点（虚构的外部结点，即空指针 NIL）都是黑色。
      4. 红结点的两个孩子都是黑色（不能有两个相连的红结点）。
      5. 从任一结点到它下面每个 NIL 的路径上，黑结点个数相同。

      从某结点出发（不含它本身）到 NIL 路径上的黑结点数叫它的黑高 bh。由性质 4、5：从根到 NIL 的最长路径（红黑相间）不超过最短路径（全黑）的两倍；n 个内部结点的红黑树高度 ≤ 2 log₂(n + 1)。红黑树只是“大致平衡”，所以插入删除时的旋转次数少：插入最多 2 次旋转，删除最多 3 次；其余调整只是改颜色。新插入的结点一律先涂红（不破坏性质 5），再按叔叔结点的颜色分情况：叔叔红，就把父亲和叔叔染黑、爷爷染红，问题上移；叔叔黑，就像 AVL 一样旋转一次或两次再改色。

      来历

      红黑树源于 1972 年拜尔提出的“对称二叉 B 树”，1978 年吉巴斯和塞奇威克给它涂上了红黑两色，名字就这样来了。它其实是 2-3-4 树（第十五章的 B 树的一种）的二叉表示：一个黑结点加上它的红孩子，合起来就是 B 树的一个大结点。2008 年塞奇威克又提出“左倾红黑树”，只允许红链接朝左，代码短了很多，是教学里常用的版本。

      Linux 内核

      Linux 内核的 lib/rbtree.c 被大量使用：完全公平调度器 CFS 按“已经跑了多久”把进程挂在红黑树上，每次挑最左边（跑得最少）的那个（《地基》第二十六章）；进程的内存区域（mmap 出来的一段段虚拟地址，《地基》第二十七章）、高精度定时器、epoll 管理的文件描述符，也都用红黑树。这里用的是第三章说过的“侵入式”写法：rb_node 嵌在各种结构体里。

      为什么数据库不用它

      平衡二叉树一个结点只放一个关键字，一百万个数要二十层。在内存里二十次比较很快，可如果树放在硬盘上，每走一层就要读一次硬盘，二十次读盘就太慢了（《地基》第十六章的存储层次：硬盘比内存慢几个数量级）。所以放在硬盘上的索引，要让每个结点装下成百上千个关键字，树只有三四层高：这就是第十五章的 B 树和 B+ 树。

      爸爸比孩子小

      堆是一棵完全二叉树（第八章：一层一层排满，最后一层靠左），规矩只有一条：每个结点都比它的孩子小（或者相等）。

      这样，根比它的孩子小，孩子又比孙子小……最小的那个一定在根上。要拿最早的事件，看一眼根就行。

      注意：堆不要求左边比右边小，兄弟之间谁大谁小都行。它只是“大致”排好，所以维护起来特别便宜。

      放进去：上浮

      新来的放在最后一层最右边的空位（数组的末尾）。然后和爸爸比：比爸爸小，就和爸爸换位置。一直换，直到不比爸爸小，或者到了根。像一个气泡往上浮。

      拿走最小的：下沉

      拿走根以后，根空了。把最后一个结点搬到根上，然后和两个孩子里更小的那个比：比它大，就换下去。一直换，直到比两个孩子都小，或者到了最下面。

      不管放还是拿，最多只走树的高度那么多步：一千件事，十来步。

      定义和建堆

      n 个关键字的序列 L[1..n]，若对所有 i 满足 L[i] ≥ L[2i] 且 L[i] ≥ L[2i+1]，叫大根堆；都 ≤ 叫小根堆。（408 的堆题多用大根堆、下标从 1。）

      自底向上建堆：从最后一个分支结点 ⌊n/2⌋ 开始，往前依次对每个结点做“下沉”（筛选）。下沉时，先比较两个孩子谁大（1 次比较），再和大的那个比（1 次比较），所以每下沉一层最多 2 次比较；只有一个孩子时 1 次。

      void sift_down(int A[], int k, int n) {   /* 大根堆，下标从 1 */
    int x = A[k];
    for (int i = 2 * k; i <= n; i *= 2) {
        if (i < n && A[i] < A[i + 1]) i++;     /* 挑大的孩子 */
        if (x >= A[i]) break;
        A[k] = A[i]; k = i;                    /* 孩子上移，继续往下 */
    }
    A[k] = x;
}
void build(int A[], int n) { for (int k = n / 2; k >= 1; k--) sift_down(A, k, n); }

      为什么建堆是 O(n)：高度为 h 的结点最多 ⌈n / 2h+1⌉ 个，每个下沉至多 h 层，总代价 Σ h · n / 2h+1 ≤ n · Σ h/2h+1 = n（级数 Σ h/2h = 2）。直觉：一半的结点是叶子，根本不动；只有很少的结点要下沉很多层。逐个插入建堆是 O(n log n)。

      插入：放在末尾，上浮，O(log n)。删除堆顶：用最后一个元素替换堆顶，n 减 1，再从堆顶下沉，O(log n)。

      d 叉堆和更花哨的堆

      每个结点 d 个孩子的堆更矮（logdn 层），上浮更快，下沉时每层要比 d 个孩子。插入多、删除少的场景（比如第十八章的迪杰斯特拉算法）用 4 叉堆常常更快，而且对缓存更友好。斐波那契堆（1984）把“减小某个关键字”做到均摊 O(1)，让迪杰斯特拉的理论复杂度降到 O(E + V log V)，但常数大、实际很少用；配对堆写起来简单，实测表现很好。

      heapq 的几个用法

      heapq 只有小根堆。要大根堆，就把数取负再放进去。heapq.nlargest(k, data) 就是“大小为 k 的小根堆”的做法；heapq.merge(*lists) 是多路归并。元组按第一个元素比较，相同再比第二个：这就是主线第 12 步里“同一刻发生的两件事”能按名字排开的原因。如果第二个元素不能比较（比如是字典），要在中间加一个递增的序号。

      定时器

      操作系统和网络协议里有成千上万个定时器（TCP 的重传、连接超时……），大多数还没到期就被取消了。用堆，每次添加和删除都是 O(log n)。Linux 内核的普通定时器用的是时间轮（timer wheel）：像钟面一样分成很多格，每格挂一个链表，加入和取消都是 O(1)，代价是精度变粗；需要高精度的 hrtimer 则用第十一章的红黑树。Go 语言的运行时用的是 4 叉堆。

      造一棵哈夫曼树

      1952 年，麻省理工学院的研究生哈夫曼在一门课的期末作业里想出了最好的编法（据说老师说，写出来就可以不用考期末考试）：

      1. 数一数每个字出现几次。每个字是一棵只有一个结点的小树，结点上写着次数。
      2. 挑出次数最少的两棵，合成一棵：新的根上写两棵次数的和，两棵分别当它的左右孩子。
      3. 重复第 2 步，直到只剩一棵树。

      然后从根往下走：往左走记一个 0，往右走记一个 1。走到某个字，一路记下的 0 和 1 就是它的码。出现得多的字合并得晚，离根近，码就短；出现得少的离根远，码就长。

      WPL 和性质

      结点的带权路径长度 = 从根到它的路径长度（边数）× 它的权。树的 WPL = 所有叶子的带权路径长度之和。给定 n 个权值，WPL 最小的二叉树叫哈夫曼树（最优二叉树）。用哈夫曼编码时，WPL 就是编码后的总比特数（权 = 出现次数）。

      • n 个叶子要合并 n − 1 次，新增 n − 1 个结点，共 2n − 1 个结点。
      • 哈夫曼树里没有度为 1 的结点（每个新结点都有两个孩子）。
      • 权越小的叶子离根越远；权最小的两个叶子是兄弟，在最深的一层。
      • 树不唯一（相同权值怎样挑、谁左谁右都可以），但 WPL 唯一。
      • WPL 也等于所有非叶结点的权值之和（每次合并产生的那个和）。这是手算 WPL 最快的办法。

      推广：m 叉哈夫曼树每次合并 m 个最小的。若 (n − 1) 不能被 (m − 1) 整除，要先补若干个权为 0 的“虚叶子”，让最后一次正好合并 m 个。

      import heapq
def huffman_wpl(weights):
    h = list(weights); heapq.heapify(h)      # 小根堆
    wpl = 0
    while len(h) > 1:
        a = heapq.heappop(h); b = heapq.heappop(h)
        wpl += a + b                         # 每次合并的和加起来就是 WPL
        heapq.heappush(h, a + b)
    return wpl

print(huffman_wpl([5, 9, 12, 13, 16, 45]))   # 224

      用小根堆，构造的时间是 O(n log n)。

      熵：压缩的下限

      香农 1948 年证明（《地基》第一章第三层的信息量）：一个字出现的概率是 p，它至少要 log₂(1/p) 位；一组字平均至少要 H = Σ p·log₂(1/p) 位，叫信息熵。任何无损编码的平均码长都不会低于 H，哈夫曼编码的平均码长在 H 和 H + 1 之间。方格岛地图的熵约 1.66 位每字，哈夫曼做到了 281/160 ≈ 1.76 位。

      DEFLATE

      单靠哈夫曼只利用了“有的字常见”，没有利用“有的片段重复出现”。DEFLATE（1990 年代，卡茨为 PKZIP 设计，RFC 1951）先用 LZ77 把重复的片段换成“往回多远、复制多长”，再对结果做哈夫曼编码。zip、gzip、PNG 图片、HTTP 的 gzip 压缩都是它。为了不用把整棵树存进文件，DEFLATE 用规范哈夫曼码：只记下每个字的码长，码本身按“码长从短到长、同长按字的顺序”重新排出来，解码器能还原出同样的码。

      比哈夫曼更好

      哈夫曼每个字至少 1 位；一个字的概率是 0.99 时，它浪费很大。算术编码把整条消息编成一个小数，能逼近熵到小数位；新一代的 ANS（非对称数字系统，杜达 2009 年起提出）速度接近哈夫曼、压缩率接近算术编码，被 Facebook 的 zstd、苹果的 LZFSE 采用。

      双亲数组

      用第八章的双亲表示法：数组 S[i] 存结点 i 的双亲下标，根的 S[i] 为负数，绝对值是这个集合的元素个数（只存 −1 的写法也常见）。

      #define N 100
int S[N];
void init(void) { for (int i = 0; i < N; i++) S[i] = -1; }
int find(int x) {                       /* 路径压缩：两遍，先找根，再把路上的都直接挂到根 */
    int root = x;
    while (S[root] >= 0) root = S[root];
    while (x != root) { int t = S[x]; S[x] = root; x = t; }
    return root;
}
void unite(int a, int b) {              /* 按大小合并：小树挂到大树下面 */
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (S[ra] > S[rb]) { int t = ra; ra = rb; rb = t; }   /* S 是负数，越小表示越大 */
    S[ra] += S[rb];
    S[rb] = ra;
}

      复杂度

      做法find 最坏
      朴素（随便挂）O(n)：可能挂成一条链
      按大小（或按秩、按高度）合并O(log n)：一个结点所在的树每变深一层，树的大小至少翻倍
      按大小合并 + 路径压缩均摊 O(α(n))，实际上可看成常数

      408 的题常问：按大小（或高度）合并的并查集，n 个元素时树高最多 ⌊log₂n⌋ + 1（只算根是 1 层时）。

      硬盘喜欢一次读一大块

      《地基》说过，内存很快，硬盘慢得多。而且硬盘每次读，都是读一大块（叫一页，常见是几 KB 到十几 KB），哪怕你只要其中一个字节。

      所以，放在硬盘上的东西，最要紧的不是“比较几次”，而是读几次硬盘。

      二叉搜索树一个结点只放一个数，一百万个数要二十层，找一个数就要读二十次硬盘。太多了。

      又矮又胖的树

      办法是：让一个结点正好占一页，里面装很多个排好序的数，还有很多个孩子。一个结点装 1000 个数、1001 个孩子，第二层就有一千个结点，第三层一百万个……三层就能装下十亿个数。找一个数，只要读三次硬盘。

      这种树叫 B 树。在一个结点里面，数是排好序的，可以用第一章的“对半猜”很快找到该往哪个孩子走。

      满了就劈开

      新数总是插在最下面一层的结点里。结点装满了怎么办？从中间劈成两半：左边一半、右边一半各自成一个结点，正中间那个数升到上一层，夹在这两个结点中间。如果上一层也满了，就接着劈；一直劈到根，根也满了，就劈开根，在上面再长出一个新的根，树就高了一层。

      B 树是从上面长高的，所以它的所有叶子永远在同一层：永远是平衡的。

      m 阶 B 树

      1. 每个结点至多 m 棵子树，即至多 m − 1 个关键字。
      2. 若根不是终端结点，则至少有 2 棵子树（1 个关键字）。
      3. 除根以外的所有非叶结点至少有 ⌈m/2⌉ 棵子树，即至少 ⌈m/2⌉ − 1 个关键字。
      4. 结点内关键字有序：K₁ < K₂ < …，子树 Pᵢ₋₁ 中的关键字都小于 Kᵢ，Pᵢ 中的都大于 Kᵢ。
      5. 所有叶结点都在同一层，不带信息（408 把它们看作查找失败到达的外部结点，计算高度时一般不算这一层）。

      例：5 阶 B 树，每个结点 2—4 个关键字（根 1—4 个）、非叶结点 3—5 棵子树。

      高度

      n 个关键字的 m 阶 B 树（n ≥ 1），高度 h（不含外部结点层）满足：

      • 最矮：每个结点都满，n ≤ mh − 1，所以 h ≥ logm(n + 1)。
      • 最高：每个结点都最少。第 1 层 1 个结点，第 2 层至少 2 个，第 3 层至少 2⌈m/2⌉ 个……第 h + 1 层（外部结点）至少 2⌈m/2⌉h−1 个；外部结点个数正好是 n + 1，所以 n + 1 ≥ 2⌈m/2⌉h−1，h ≤ log⌈m/2⌉((n + 1)/2) + 1。

      插入和删除

      插入：先查找，定位到某个最底层的非叶结点，插进去。若该结点的关键字数超过 m − 1（变成 m 个），从中间位置 ⌈m/2⌉ 分裂：左边 ⌈m/2⌉ − 1 个关键字留在原结点，右边的放进新结点，第 ⌈m/2⌉ 个关键字插入父结点；父结点满了继续分裂，根分裂时树高加一。

      删除：若被删关键字不在最底层，用它的前驱或后继（必在最底层）替换，转成删最底层的关键字。在最底层删除后，若关键字数不少于 ⌈m/2⌉ − 1，结束；否则：

      • 兄弟够借（相邻兄弟的关键字数 ≥ ⌈m/2⌉）：父结点里夹在中间的那个关键字下移到本结点，兄弟里最靠近的关键字上移到父结点（一次“左旋”或“右旋”）。
      • 兄弟不够借：本结点、相邻兄弟、父结点里夹在中间的关键字，三者合并成一个结点。父结点少了一个关键字，可能又不够了，继续向上调整；根的关键字被并完时，树高减一。

      B+ 树

      408 采用的 m 阶 B+ 树定义：每个分支结点至多 m 棵子树；非叶根至少 2 棵子树，其他分支结点至少 ⌈m/2⌉ 棵；结点的子树个数和关键字个数相等；所有叶结点包含全部关键字和指向记录的指针，叶结点内关键字有序，相邻叶结点按大小链接；分支结点只有子结点的最大（或最小）关键字和指针，相当于索引。

      估算一棵真实的 B+ 树

      MySQL 的 InnoDB 存储引擎默认一页 16 KB。分支结点里每项是“关键字 + 子页号”，以 8 字节整数主键加 6 字节指针、再加一些开销估算，一页能放约一千多项；叶子页里放的是整行数据，每行 1 KB 的话一页放十几行。三层：1170 × 1170 × 16 ≈ 两千多万行，根页常驻内存，查一行最多读两三次硬盘。这是常见的教学估算，实际数字随行的大小、填充率而变。

      InnoDB 的主键索引是聚簇索引：叶子里直接放整行；其他列上的二级索引的叶子里放的是主键值，查到以后还要回到主键索引里再查一次（“回表”）。这也是为什么主键最好是递增的：新行总追加在最右边的叶子，不会让中间的页频繁分裂。

      LSM 树

      B+ 树每次写都要找到那一页、原地修改，随机写多的时候很吃力。LevelDB、RocksDB、HBase、Cassandra 用的 LSM 树（日志结构合并树）反过来：新数据先写进内存里的有序表，攒满了整块顺序写到硬盘成为一个有序文件，后台再把多个文件归并（第二十七章的归并）成更大的。写入快得多，读的时候可能要查好几个文件（用布隆过滤器加速，《地基》第七章第三层）。读多写少选 B+ 树，写多选 LSM 树。

      八章，一件事：让东西一层管一层。树能表示“谁由谁组成”（配方），能按固定顺序走遍（遍历），能把“找”变成每次排除一半（搜索树），还要时时保持两边一样高（平衡树）；换个规矩，它又能让最急的事总在最上面（堆）、让常用的字用短码（哈夫曼树）、一眨眼回答“连不连着”（并查集）、让硬盘上的东西三四步找到（B 树）。
